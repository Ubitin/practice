# std::array 详解：operator[] 与定长数组的 STL 包装

> 前置：STL 讲义 §3（vector）、`vector迭代器失效与reserve.md`。`std::array` 是 C++11 引入的"定长数组的 STL 包装"，头文件 `<array>`（`<bits/stdc++.h>` 已含）。
> 演示程序：`test_\13.cpp`（全部结论已用 g++ C++17 实测）。

---

## 0. 一句话本质

**`std::array<T, N>` = 大小固定为 N（编译期确定）的数组，但拥有 STL 容器的接口**——能用 `operator[]`、`size()`、`begin()/end()`、`sort`、`==`，还能整体拷贝。

```cpp
array<int, 5> a;      // 5 个 int，大小永远不能变
```

## 1. 案例：operator[] 的完整用法（本讲义主角）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    array<int, 5> a = {10, 20, 30};   // 只给 3 个，剩余自动补 0

    // ① 读：a[i] 返回第 i 个元素
    cout << a[1];                     // 20

    // ② 写：operator[] 返回"引用"，所以可以赋值
    a[1] = 99;                        // a 变成 {10, 99, 30, 0, 0}

    // ③ 参与运算后再写回
    a[4] = a[0] + a[2];               // a[4] = 40

    // ④ 遍历：范围 for / 下标都行
    for (int x : a) cout << x << " "; // 10 99 30 0 40

    // ⑤ 传给 STL 算法（C 数组做不到）
    sort(a.begin(), a.end());         // {0, 10, 30, 40, 99}
    return 0;
}
```

## 2. 初始化规则（和 char 数组"自动补零"一个道理）

```cpp
array<int, 5> a = {1, 2, 3};   // 剩余两个自动补 0 → {1,2,3,0,0}（实测）
array<int, 5> b = {};          // 全 0
array<int, 5> c;               // ⚠️ 未初始化：局部的是垃圾值！
```

## 3. 越界：operator[] 不检查，at() 才抛异常（本讲义最重要的事项）

```cpp
array<int, 5> a = {1,2,3,4,5};

a[5] = 100;    // ❌ 不报错！越界写（未定义行为，可能悄悄写坏内存）——和 vector 的 [] 一样
a.at(5) = 100; // ✅ 抛 out_of_range 异常（实测：catch 后打印 "array::at: __n >= _Nm"）
```

**为什么 [] 不检查**：为了速度（和 C 数组、vector 的 `[]` 一样零开销）；`at()` 每次检查、慢一点但安全。

> 铁律：**下标确定合法用 `[]`，可能越界（如来自用户输入）用 `at()` 或先判 `i < a.size()`。**

## 4. 与 C 数组、vector 的对比（一张表）

| | `int a[5]` | `std::array<int,5>` | `std::vector<int>` |
|---|---|---|---|
| 大小 | 固定 | 固定（编译期） | 动态（可扩容） |
| `size()` | 无（sizeof/a[0] 算） | ✅ | ✅ |
| `begin()/end()` | 无（退化） | ✅ | ✅ |
| 整体拷贝/传参 | ❌ 退化成指针 | ✅ `auto b = a;` | ✅ |
| `==` 比较 | ❌ 比地址 | ✅ 逐元素比 | ✅ |
| `sort(a.begin(),a.end())` | ❌ 写不了 | ✅ | ✅ |
| 越界检查 | 无 | `[]`无 / `at()`有 | 同左 |
| 内存 | 栈（定长） | 栈（定长） | 堆（有 capacity） |
| `sizeof` | 5*4=20 | 20（无额外开销） | 24（含指针等） |

**使用场景**：大小**编译期就确定**且不会变 → array；运行期才知道 / 要增删 → vector；C 课程按教材用 C 数组。

## 5. 三个补充技巧

**① 与 C 函数互操作**：`a.data()` 返回底层指针，可传给 C 风格函数：
```cpp
printf("%d", a.data()[0]);   // 等价 a[0]
```

**② tuple 接口 `get<N>`**（编译期下标）：
```cpp
array<int, 3> t = {7, 8, 9};
get<0>(t);   // 7（下标必须是编译期常量）
```

**③ 整体拷贝互不影响**（实测）：
```cpp
auto copyA = a;   // 值拷贝
copyA[0] = -1;    // 改副本，原 a 不受影响
```

## 6. 诚实提醒：竞赛里用得少

`STL讲义-02` 里我把它归入"过滤"内容——原因是：竞赛中"定长数组"直接用 C 数组就够（`int a[100005]` 全局开），array 的 STL 接口在刷题场景用得不多。**但**：课程/项目/面试里它很常用（现代 C++ 规范推荐用它替代 C 数组，避免数组退化问题），所以这份讲义补上了。**掌握 operator[] + at() 的区别，就是这份讲义的核心。**

## 7. 习题（答案已实测）

**E1** 写出输出：
```cpp
array<int, 4> a = {1, 2};
for (int x : a) cout << x << " ";
```

**E2** 选择：哪个访问方式在越界时会抛异常？
```cpp
A. a[i]    B. a.at(i)    C. get<i>(a)    D. a.data()[i]
```

**E3** 判断：`array<int,3> a = {1,2,3}; auto b = a; b[0]=100;` 之后 `a[0]` 是多少？C 数组 `int c[3]={1,2,3}; int* d=c; d[0]=100;` 之后 `c[0]` 是多少？

**E4** 补全：把 `array<int, 5> a = {3,1,4,1,5}` 排序：
```cpp
sort(____, ____);
```

**E5** 读程序写输出：
```cpp
array<int, 3> a = {10, 20, 30};
a[0] = a[1] + a[2];
cout << a[0] << " " << a.at(2);
```

---

## 答案与解析

**E1** → `1 2 0 0`
只初始化 2 个，剩余自动补 0（实测）。

**E2** → **B**。`at()` 带边界检查抛异常；`[]` 和 `data()[i]` 不检查；`get<i>` 的越界是编译期错误（不会运行）。

**E3** → array 版：`a[0]` 仍是 1（整体拷贝，互不影响）；C 数组版：`c[0]` 变成 100（`d` 和 `c` 是同一个数组，指针没拷贝数据）——这就是 array 相对 C 数组"整体传值"的优势。

**E4** → `sort(a.begin(), a.end());`

**E5** → `50 30`
a[0] = 20+30 = 50；a.at(2)=30（合法下标，正常返回）。

---

**一句话总结**：`std::array` = **编译期定长的数组 + STL 接口**；`operator[]` 快但不查越界，`at()` 安全但慢一点——**"下标确定合法用 []，可能越界用 at()"**；初始化只给部分值会自动补 0，整体拷贝/比较/排序是它相对 C 数组的三大优势。
