## 1. 算法和数据结构到底是什么（第 1 章）[必学，5 分钟]

书中定义：

- **算法**：在有限时间内解决特定问题的一组指令或操作步骤。
- **数据结构**：组织和存储数据的方式，涵盖数据内容、数据之间关系和操作方法。

书里有个"拼积木"类比，很适合你：

| 概念 | 拼积木类比 |
|---|---|
| 输入数据 | 未拼装的积木 |
| 数据结构 | 积木的组织形式（形状、连接方式） |
| 算法 | 把积木拼成目标的一系列步骤 |
| 输出数据 | 拼好的模型 |

一个非常重要的观念（书中原话）：**数据结构设计是一个充满权衡的过程**——想在速度上占便宜，往往要在空间或别的方面付出代价。后面数组 vs 链表、哈希表 vs 有序表，全是这个"权衡"的体现。

## 2. 复杂度分析（第 2 章）[必学，本讲最重要的一节]

### 2.1 为什么不能直接测时间

书中指出：实测运行时间受机器、编译器、数据规模影响，不可靠。所以我们用**渐近复杂度分析**：只看"操作次数随数据量 n 增长的趋势"，记作 O(…)。

### 2.2 时间复杂度：两个例子就懂

```cpp
// 例 1：一层循环 → O(n)
for (int i = 0; i < n; i++) sum += i;

// 例 2：两层循环 → O(n²)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) cnt++;
```

书中给出的常见量级，**从快到慢背下来**：

$$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n) < O(n!)$$

- O(1)：不管 n 多大，操作数固定（比如取 `v[5]`）
- O(log n)：每轮砍半（二分查找、set/map）
- O(n)：一遍循环
- O(n log n)：排序（sort）
- O(n²)：双重循环
- O(2ⁿ)、O(n!)：暴力枚举所有方案——n 稍大就完蛋

**机试换算表（重点中的重点）**：主流评测机 1 秒约执行 1e8 次基本操作。

| 数据规模 n | 允许的最坏复杂度 | 说明 |
|---|---|---|
| n ≤ 30 | O(2ⁿ) 都行 | 放心暴力 |
| n ≤ 1000 | O(n²) | 双重循环没问题 |
| n ≤ 1e5 | O(n log n) | sort/set/map/二分 |
| n ≤ 1e6 | O(n) 为主 | 常数也要注意 |

**读到题先看数据范围，就能猜出正解复杂度**——这是机试最重要的读题习惯。

补充：复杂度分最差/平均/最佳，竞赛里**看最差（大 O）**；两个算法都是 O(n) 时才有"常数"的差别。

### 2.3 空间复杂度 [必学，但简单]

同样用 O 记号描述内存增长趋势：开了个 int a[n] 就是 O(n)；只开几个变量是 O(1)；递归深度 n 时栈帧占 O(n)（见 2.4）。输入本身占的空间不计入。

### 2.4 迭代与递归 [必学]

**迭代**就是循环（你已经会了）。**递归**是函数调用自己，书中把它分为"递"和"归"两个阶段，写递归必须凑齐三要素：

1. **终止条件**（没有它 = 无限调用 = 程序崩溃）
2. **递归调用**（传更小的参数）
3. **返回结果**（逐层返回）

```cpp
// 递归求和 1+2+...+n
int sum(int n) {
    if (n == 1) return 1;      // ① 终止条件
    return n + sum(n - 1);     // ② 递归调用 ③ 返回结果
}
```

书中对迭代/递归的总结：

- **迭代 = 自下而上**：从基础步骤开始，不断重复。
- **递归 = 自上而下**：把问题拆成同形式的子问题，直到基本情况。

**递归的代价**（书中"调用栈"一节）：每层递归占一段栈帧内存，递归又深又慢。深度太大（竞赛中约 1e5 以上）会**栈溢出**直接崩溃。

**递归树**（书中以斐波那契为例，这是本讲最重要的"直觉"）：

```cpp
int fib(int n) {
    if (n <= 2) return n - 1;        // fib(1)=0, fib(2)=1
    return fib(n - 1) + fib(n - 2);  // 一次调用分出两个分支！
}
```

fib(50) 会算到天荒地老——因为同一子问题被重复计算了无数次（书中图 2-5 的递归树）。这个现象记在心里，第三讲学"记忆化/动态规划"时你会发现 DP 就是为了解决它。

> [暂缓] 尾递归：书中说了"大多数编译器不优化尾递归"，考试不考，跳过。

## 3. 数据结构地图（3.1 数据结构分类）[必学]

书中把常见数据结构从两个维度分类，这张地图建议刻在脑子里：

- **逻辑结构**：线性（数组、链表、栈、队列、哈希表）与非线性（树、堆、图）
- **物理结构**：连续空间存储（数组）与分散空间存储（链表）

一个贯穿全书的结论：**所有数据结构都是基于数组、链表或二者组合实现的**——栈、队列、哈希表、树、堆、图，全都如此。看懂这句话，后面每一章都会轻松很多。

> 3.2 基本数据类型 [了解]：int/long long/char/double/bool 的大小范围你在 C++ 里已学过，书里是跨语言对照，扫一眼即可。竞赛记住：**int 约 ±2.1e9，超过就换 long long（约 ±9.2e18）**。
> 3.3 数字编码、3.4 字符编码 [暂缓]：原码反码补码、浮点 IEEE754、UTF-8 等——这是计算机组成原理的内容，机试不考，等你大二学计组时回来看反而更有用。

## 4. 数组（4.1）[必学]

你已经会用的数组，书中讲了它"为什么快、为什么慢"：

- **连续内存 → O(1) 随机访问**：元素地址 = 首地址 + 元素长度 × 索引。这也是**下标从 0 开始**的原因（偏移量）。
- **插入/删除中间 O(n)**：后面的元素都要整体挪一位。
- **长度不可变**：扩容只能"新开一个更大的数组 + 整体复制"，O(n)。

书里列的"数组典型应用"有个竞赛常用的概念——**查找表**：用数组下标当"key"直接存值（比如 `cnt[x]` 统计出现次数）。你后面学的哈希表、计数排序都源于这个思想。

> 4.4 内存与缓存 [了解]：结论只有一句——**数组内存连续，CPU 缓存命中率高，所以通常比链表快**。知道这句话就够，细节进队后再说。

## 5. 链表（4.2）[必学思想，实现用"数组模拟"]

链表节点 = 存的值 + 指向下一个节点的"箭头"（指针）。特点是：

- 找到位置后**插入/删除 O(1)**（改改箭头就行，不用搬元素）
- 但**查找 O(n)、不能下标随机访问**
- 类型：单向 / 双向 / 环形

**竞赛实战结论（重要）**：OI 里几乎不写指针链表，而是**数组模拟链表**——用一个 `next[i]` 数组存"i 号元素的下一个是谁"：

```cpp
const int N = 100005;
int val[N], nxt[N], head = 0;   // head: 第一个元素的下标

// 删除 x 的下一个元素：nxt[x] = nxt[nxt[x]];
// 在 x 后插入新元素 y：
//   val[++tot] = y; nxt[tot] = nxt[x]; nxt[x] = tot;
```

**例题**：洛谷 **P1160 队列安排**（双向数组模拟链表）。
> 对应 STL：`list` 存在但竞赛很少用（书里 Q&A 专门解释了原因：额外指针占空间 + 缓存不友好）。我们之前过滤它是对的。

## 6. 列表（4.3）[必学] = 动态数组 = 你的 vector

数组长度不可变 → 列表（C++ 的 `vector`）解决问题：**装满了就新开更大空间（通常 ×1.5~×2）整体搬过去**。所以：

- 末尾插入（push_back）：平时 O(1)，偶尔触发扩容才 O(n)，**均摊下来 O(1)**
- 保留了下标随机访问 O(1) 的全部优势

这就是 `STL讲义-01` 里 vector 复杂度的原理。书中还提醒：提前开大一点（`resize`/`reserve`）能避免反复扩容。

## 7. 栈与队列（第 5 章）[必学，和 STL 讲义完全对应]

- **栈**：后进先出（LIFO）。push/pop/top 全 O(1)。应用：括号匹配、表达式求值、撤销/重做（书里 Q&A 讲了双栈实现撤销）。
- **队列**：先进先出（FIFO）。front/back/push/pop 全 O(1)。应用：排队模拟、**BFS**（第二讲图会用）。
- **双向队列 deque**：两端都能进出，C++ 的 deque 还支持下标访问。应用：滑动窗口（P1886，进阶）。

C++ 写法回顾（详见 `STL讲义-01`）：

```cpp
stack<int> st;        st.push(x); st.top(); st.pop();
queue<int> q;         q.push(x); q.front(); q.pop();
deque<int> dq;        dq.push_front(x); dq.push_back(x); dq.front(); dq.back();
```

**例题**：P1739 括号匹配、P1449 后缀表达式、P1996 约瑟夫问题、P1540 机器翻译；进阶 P5788 单调栈、P1886 滑动窗口。

## 8. 哈希表（第 6 章）[必学]

书中用"学号 → 姓名"的例子引出核心思想：把 key 喂给**哈希函数**，算出一个数组下标，把 value 存在那个"桶"里。所以查询不需要遍历，**平均 O(1)**。

书中给的效率对比（这就是它存在的意义）：

| 操作 | 数组/链表 | 哈希表 |
|---|---|---|
| 查找 | O(n) | **O(1)** |
| 添加 | O(1) | O(1) |
| 删除 | O(n) | O(1) |

几个"结论式"知识点（书中 6.2 哈希冲突）：

- **哈希冲突**：两个不同 key 算出同一个下标。两种解法：链式地址（桶里挂链表）/ 开放寻址（顺延找空位）——知道名字即可。
- **负载因子** = 元素数 ÷ 桶数，太大就扩容（对应 unordered_map 的 rehash）。
- **最坏 O(n)**：冲突严重时退化；个别毒瘤题会故意构造数据"卡哈希"，此时换回 map 保底。

C++ 写法（对应 `STL讲义-02`）：

```cpp
unordered_map<int, string> m;    // key→value
m[12836] = "小哈";               // 添加
cout << m[12836];                // 查询
m.erase(12836);                  // 删除
if (m.count(x)) ...              // 判断存在（别用 m[x] 判断！）
unordered_set<int> s;            // 只存 key 的集合版
```

**哈希优化套路**（对应书中 10.4"哈希优化策略"）："在一个数组里找两个数之和等于 target"这类题，把"查数"从 O(n) 的线性查找换成哈希 O(1)。
**例题**：P1918 保龄球、P1102 A-B 数对、P3879 阅读理解（进阶）。

> 6.3 哈希算法 [暂缓]：MD5、SHA、雪崩效应、抗碰撞性——密码学内容，机试不考，了解"哈希不等于加密"即可。

## 本讲小结

你现在的知识地图应该是：

1. **复杂度**：读题先看数据范围 → 反推允许的复杂度 → 选数据结构/算法。这是机试第一思维。
2. **递归三要素**：终止条件 + 递归调用 + 返回结果；递归树解释了"为什么朴素递归会爆炸"。
3. **线性结构全家桶**：数组（连续，随机访问快）→ vector（动态数组）→ 链表（插删快，用数组模拟）→ 栈/队列/双端队列（受限的线性结构）→ 哈希表（key 直接映射，平均 O(1)）。
