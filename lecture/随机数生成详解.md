## 0. 为什么学随机数（三视角）

| 视角 | 用途 |
|---|---|
| [竞赛] | **生成对拍测试数据**（验证暴力解 vs 正解）、随机化算法（随机快排基准、Treap、模拟退火入门） |
| [课程] | 模拟题（掷骰子、抽奖、洗牌）、随机数据实验 |
| [项目] | 测试用例生成、加密/密码学（真随机） |

## 1. 三种方式总览

| 方式 | 写法 | 特点 |
|---|---|---|
| 老式 rand | `rand() % n` + `srand(time(0))` | 简单但**有缺陷**（见 §2） |
| 现代 <random> | `mt19937` + `uniform_int_distribution` | 质量高、范围精确、可复现，**推荐** |
| 真随机种子 | `random_device{}()` | 每次不同，用于给引擎播种 |

## 2. 老式 rand()：会用的同时要知道它三个坑

```cpp
srand(time(0));                // 播种（用当前秒数）
int x = rand() % 100;          // 0~99
```

**坑①：不播种 → 每次运行结果一模一样**（实测：连跑两次都是 `41 67 34 0 69`）
```cpp
// 忘了 srand → rand 每次程序启动都从同一个默认种子开始
```

**坑②：`time(0)` 精度是"秒" → 同一秒内运行结果相同**（实测！两次运行在同秒执行，输出完全一样）
> 后果：对拍时两个程序同一秒启动，生成的数据一样，某些 bug 测不出来；或同秒开多线程各得相同序列。

**坑③：`rand() % n` 有分布偏差 + 范围只有 32767**
- `RAND_MAX` 通常只有 **32767**（实测），想要 1e9 级别的数做不到；
- `% n` 让余数小的值略多（当 RAND_MAX+1 不能整除 n 时）。

**结论：竞赛里建议直接跳过 rand()，用下面的 C++11 写法。**

## 3. 现代 C++11：mt19937 + 分布（推荐，背模板）

```cpp
#include <random>   // <bits/stdc++.h> 已包含

mt19937 rng(42);                          // ① 引擎（梅森旋转），参数 = 种子
uniform_int_distribution<int> dis(1, 6);  // ② 分布：均匀整数 [1, 6]
int dice = dis(rng);                      // ③ 用引擎喂分布，得一个随机数
```

**种子怎么选（两个用途，两种选择）：**

```cpp
// 用途 A：对拍/调试 → 固定种子（可复现，出 bug 能重跑同一数据）
mt19937 rng(42);              // 种子 42，每次运行序列相同

// 用途 B：真正随机 → random_device 取种子（每次不同）
mt19937 rng2(random_device{}());
```

实测：固定种子 `mt19937(42)` 两次运行都是 `3 5 6 2 5 5`（可复现 ✅）；random_device 种子两次不同（真随机 ✅）。

**浮点随机：**

```cpp
uniform_real_distribution<double> dis3(0.0, 1.0);   // [0,1) 的浮点
double p = dis3(rng);
```

## 3.5 拒绝采样：让 rand() 也等概率（进阶，原理值得懂）

**问题**：`rand() % n` 的取模偏差。当 `RAND_MAX+1`（32768）不能整除 `n` 时，余数小的值会偏多。实测（`test_\23.cpp`，1e6 次，n=10000）：

| 方法 | 0~2767 组均值 | 2768~9999 组均值 |
|---|---|---|
| 取模法 `rand()%10000` | **121.7**（偏多） | **91.7**（偏少） |
| 拒绝采样 | 99.9 | 100.0（均匀） |

**为什么有偏差**：32768 = 3×10000 + 2768，余数 0~2767 各对应 4 个原值，2768~9999 只对应 3 个——**多出来的 2768 个原值全落在小余数上**。

**拒绝采样原理**：截断 + 重试——

```cpp
const int RANGE = 10000;
int k = (RAND_MAX + 1) / RANGE * RANGE;   // 32768 内最大的 10000 倍数 = 30000
int x;
do { x = rand(); } while (x >= k);        // x ∈ [30000, 32767] → 拒绝，重新采样
int r = x % RANGE;                        // 现在 [0, k) 内均匀，k 是 RANGE 整数倍 → 无偏差
```

**为什么这样就均匀**：接受区 `[0, k)` 的长度 k 恰好是 RANGE 的整数倍（30000 = 3×10000），所以每个余数分到相同数量的原值；被拒绝的只是 `[k, RAND_MAX]` 那 2768 个"零头"。代价是少量重试——实测拒绝占比约 **9.2%**，即平均每次成功采样只需 ~1.1 次 rand()，开销可忽略。

**和现代写法打通**：`uniform_int_distribution` 的**内部实现就是拒绝采样**（标准要求无偏差，编译器用截断+重试实现）。所以你在用 mt19937 时其实一直在享受拒绝采样——这份讲义只是把"引擎盖下"的原理拆给你看。

**拒绝采样的通用思想**（不只用于整数）：想从"难直接生成的分布"采样时，先从"容易的分布"采样，落在目标区域外的就拒绝重来。经典应用——**蒙特卡洛求 π**：在 [0,1]² 均匀撒点，统计落在单位圆内（x²+y²≤1）的比例，≈π/4（实测 1e7 点 → π≈3.141427）。

```cpp
mt19937 rng(7);
uniform_real_distribution<double> u(0.0, 1.0);
long long inside = 0, total = 10000000;
for (long long i = 0; i < total; i++) {
    double x = u(rng), y = u(rng);
    if (x * x + y * y <= 1.0) inside++;     // 接受/拒绝
}
// π ≈ 4.0 * inside / total
```

> 记忆钩子：**拒绝采样 = "范围取整倍数 + 零头重试"**——整数版消除取模偏差；思想版（接受-拒绝）是蒙特卡洛、随机化算法的基础。

## 4. 竞赛核心场景：对拍数据生成器（模板背下来）

```cpp
mt19937 rng(2024);                          // 固定种子，方便复现
uniform_int_distribution<int> n_dis(1, 1000);      // 数据量范围
uniform_int_distribution<int> v_dis(-1e9, 1e9);    // 数值范围（rand 做不到这么大）

int n = n_dis(rng);
cout << n << "\n";
for (int i = 0; i < n; i++) cout << v_dis(rng) << " \n"[i == n - 1];
```
配合 `freopen("in.txt","w",stdout)` 把随机数据写进文件，就能喂给"暴力解"和"正解"对拍。

**随机洗牌：**

```cpp
vector<int> cards = {1, 2, 3, 4, 5, 6, 7};
shuffle(cards.begin(), cards.end(), mt19937(5));   // C++11 的 std::shuffle
```
（替代已被 C++17 移除的 `random_shuffle`。）

## 5. 常见坑清单

1. **忘 `srand`** → 每次运行结果一样（实测坑①）；
2. **`time(0)` 当种子** → 同一秒内结果一样（实测坑②），比赛/对拍密集启动时踩雷；
3. **`rand() % n`** → 范围小（32767）+ **取模偏差**（见 §3.5），要么用 mt19937，要么手写拒绝采样；
4. **`rand()` 不能生成负的大数** → 用 `uniform_int_distribution(-1e9, 1e9)`；
5. **每次 `mt19937 rng(time(0))` 放循环里** → 同秒内循环生成的全一样！引擎只创建一次；
6. **用 `random_shuffle`** → C++17 已移除，用 `shuffle`（多传一个引擎参数）。

## 6. 习题（答案可自行编译验证）

**E1** 概念：`rand()` 前忘记调用 `srand`，程序每次运行输出会怎样？
**E2** 补全：生成 [1, 100] 的随机整数，用 mt19937：

uniform_int_distribution<int> dis(____, ____);
int x = dis(rng);
```

A. 固定常数（如 42）   B. time(0)   C. random_device{}()   D. 随便
```
**E5** 改错：下面的洗牌代码有什么问题？

```

int x;

```

## 答案与解析

**E1** → 每次运行生成**完全相同**的序列（rand 从固定默认种子开始）。对拍时等于"数据没换"。

**E2** → `uniform_int_distribution<int> dis(1, 100);`（闭区间 [1,100]，含两端）。

**E3** → 同一秒内循环每轮重建引擎，种子相同 → **生成的全是同一个数**（或同一小段序列）。引擎只创建一次，循环里只调用 `dis(rng)`。

**E4** → **C**（random_device 真随机）。B 的 time(0) 只到秒，同秒启动仍相同；A 固定种子是可复现场景才用。

**E5** → `random_shuffle` 在 C++17 已移除，且老用法不指定随机源。改：
```cpp
shuffle(v.begin(), v.end(), mt19937(42));   // 或 random_device 种子
```

**E6** →
```cpp
do { x = rand(); } while (x >= k);   // 拒绝 [k, RAND_MAX] 的零头
int r = x % RANGE;
```

**E7** → 接受区 [0, k) 的长度 k 是 RANGE 的整数倍（30000 = 3×10000），每个余数分到相同数量的原值（各 3 个），所以等概率；被拒绝的是 [k, RAND_MAX] 的 2768 个"零头"（不参与分配），只是浪费约 9.2% 的 rand() 调用。

---

**一句话总结**：随机数三件套——**引擎（mt19937）+ 分布（uniform_int_distribution）+ 种子（固定=可复现 / random_device=真随机）**；对拍数据生成器和 `shuffle` 是竞赛两大用途；`rand()` 的三个坑（忘播种、同秒同种子、32767 上限）知道即可，能不用就不用。若被迫用 `rand()%n`，用**拒绝采样**（截断到最大整数倍 + 零头重试）消除偏差——`uniform_int_distribution` 内部就是这么干的。
