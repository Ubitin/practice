# Haversine 球面距离 —— 角度/弧度排错实战（WA 定位）

> 触发点：用 Haversine 公式算两点的球面距离，样例应输出 `5793.2236km`，实际输出 `8775.0745km`，WA。
> 一句话：**唯一的致命 bug 是输入的纬度/经度是"角度"，却直接喂给了吃"弧度"的 `sin`/`cos`**——4 个量全部要先 `* PI/180`。误差量级 **51.47%**。
> 相关：`反三角函数详解-asin-acos-atan-atan2`（本讲义第 5 节的精度隐患就是那篇里"acos 在 ±1 附近分辨率耗尽"的同一件事）。
> 演示程序：`test_\01_haversine_precision.cpp`；修正版：`test_\01_haversine_fixed.cpp`（**原文件 `test_\01.cpp` 保持原样未改动**）。

## 一、症状与定位

| | 值 |
|---|---|
| 样例输入 | `34.260958 108.942369` / `55.755825 37.617298`（西安 → 莫斯科） |
| 期望输出 | `5793.2236km` |
| 你的程序输出 | **`8775.0745km`** ❌ |
| 相对误差 | **51.47%** |

### ⭐ 第一条经验：**误差的量级本身就是诊断线索**

| 观察到的相对误差 | 大概率原因 |
|---|---|
| `1e-15` / `1e-16` 量级 | 浮点精度问题（换写法、加 eps） |
| `1e-6` ~ `1e-3` 量级 | 算法近似、`float`/`double` 混用、迭代次数不够 |
| **百分之几十 ~ 几倍** | **逻辑/单位错误**（角度弧度、公式抄错、下标错、分支错） |
| 结果完全离谱 / NaN / inf | 越界、未初始化、除零、定义域 |

**51% 不是精度问题，是逻辑问题。** 看到这种量级，直接去查"公式和单位"，不要去调 `eps`。

## 二、根因：角度 vs 弧度

Haversine 公式：

$$\text{hav}(\theta)=\sin^2\frac{\theta}{2}=\frac{1-\cos\theta}{2}$$

$$h=\text{hav}(\varphi_2-\varphi_1)+\cos\varphi_1\cos\varphi_2\,\text{hav}(\lambda_2-\lambda_1),\qquad d=R\cdot\theta,\quad \theta=2\arcsin\sqrt h$$

其中 $\varphi$ 是**纬度**、$\lambda$ 是**经度**——**这些角必须用弧度**。而题目输入是**角度**（度）。

你的代码：

```cpp
double temp = hav(a2 - a1) + cos(a1) * cos(a2) * hav(b2 - b1);
//                           ^^^^^^^^  a1 是 34.260958（度），但 cos 吃弧度
```

于是 `cos(34.260958)` 被当成 **34.26 弧度**（≈ 5.45 圈）来算：

| 量 | 直接当弧度用 | 正确（先转弧度） | 差 |
|---|---|---|---|
| `cos(lat1)`（34.260958） | **-0.9563470765** | `0.8264820958` | **-1.7828** |
| `cos(lon1)`（108.942369） | -0.5290005944 | -0.3246169394 | -0.2044 |
| `cos(lat2)`（55.755825） | 0.7018231072 | 0.5627208892 | +0.1391 |
| `cos(lon2)`（37.617298） | 0.9966551139 | 0.7921054001 | +0.2045 |

⚠️ 注意 `cos(lat1)` **连正负号都反了**（-0.956 → +0.826）。余弦本来值域就是 $[-1,1]$，所以错值"看起来完全合法"——这就是这类 bug 难查的原因。

### 为什么代码"看起来跑了"却没报错

`cos`/`sin` 对**任何实数**都有定义，不会像 `asin` 那样给 NaN。**它只是静默地算出一个完全合法的错数**。所以程序不崩、不警告、输出格式也对，只有答案错。

## 四、修正

### 最小修正（只加 4 行）

```cpp
const double PI = acos(-1.0);
a1 *= PI / 180.0;   // 纬度
b1 *= PI / 180.0;   // 经度
a2 *= PI / 180.0;
b2 *= PI / 180.0;
```

放在 `cin` 之后、公式之前。**只改这一处就能 AC**——实测两种精度写法在样例上都四舍五入到 `5793.2236`。

### 推荐修正版（完整文件）

`test_\01_haversine_fixed.cpp`：

```cpp
#include <bits/stdc++.h>
using namespace std;

const double PI = acos(-1.0);   // M_PI 在 -std=c++17 下未定义，用这个
const double R  = 6371.0;

double hav(double x) {          // hav(x) = sin^2(x/2) = (1-cos x)/2
    double s = sin(x / 2);
    return s * s;               // 用 sin^2 形式，小角度不丢精度
}

int main() {
    double lat1, lon1, lat2, lon2;
    cin >> lat1 >> lon1 >> lat2 >> lon2;

    lat1 *= PI / 180.0;         // ★ 原代码缺的就是这一步
    lon1 *= PI / 180.0;
    lat2 *= PI / 180.0;
    lon2 *= PI / 180.0;

    double h = hav(lat2 - lat1) + cos(lat1) * cos(lat2) * hav(lon2 - lon1);
    if (h > 1.0) h = 1.0;       // 兜底：浮点误差可能让 h 略微越过 1
    if (h < 0.0) h = 0.0;

    printf("%.4fkm\n", R * 2.0 * asin(sqrt(h)));
    return 0;
}
```

**实测验证**：

| 输入 | 输出 | 检查 |
|---|---|---|
| 样例（西安 → 莫斯科） | `5793.2236km` | ✅ 与期望一致 |
| 同一点 `30 120 / 30 120` | `0.0000km` | ✅ 距离为 0 |
| 对径点 `0 0 / 0 180` | `20015.0868km` | ✅ = $\pi R = 20015.0868$ |
| 南北极 `90 0 / -90 0` | `20015.0868km` | ✅ = $\pi R$ |

## 五、精度隐患：为什么建议连 `hav` 和反解一起换

**先说清楚：这不是你这次 WA 的原因。** 实测四种写法在样例上的结果：

```
原版组合 (1-cos)/2 + acos(1-2h) : 5793.2236449568 km
修正版组合 sin^2/2 + 2asin(sqrt): 5793.2236449568 km
→ 完全相同，都四舍五入到 5793.2236
```

但**当两点非常接近时会一起崩**。实测（赤道两点，经度差 $\theta$ 弧度，真值 $d=R\theta$）：

| θ | V1 `(1-cos)/2`+`acos` | V2 只换 hav | V3 只换反解 | V4 **修正版** |
|---|---|---|---|---|
| $10^{-1}$ | 5.53e-15 | 5.53e-15 | 5.53e-15 | **< 1e-17** |
| $10^{-4}$ | 2.62e-09 | 2.62e-09 | 2.62e-09 | **< 1e-17** |
| $10^{-6}$ | 4.44e-05 | 4.44e-05 | 4.44e-05 | **< 1e-17** |
| $10^{-7}$ | 4.00e-04 | 4.00e-04 | 4.00e-04 | **< 1e-17** |
| $10^{-8}$ | **1.00e+00** | **1.00e+00** | **1.00e+00** | **< 1e-17** |
| $10^{-12}$ | 1.00e+00 | 1.00e+00 | 1.00e+00 | **< 1e-17** |

**注意 V2、V3 都没救回来**——因为旧写法有**两处独立的相消**，必须同时修掉：

```
V1: (1-cos x)/2   ← x 很小时 cos(x) 舍入成 1.0，1-1 = 0，h 直接变 0
    acos(1-2h)    ← h 很小时 1-2h 舍入成 1.0，acos(1) = 0
```

$\theta=10^{-8}$ 时的实测（真值应为 `0.0000637100 km`）：

| 写法 | 输出 | 中间量 |
|---|---|---|
| V1 `(1-cos)/2` + `acos(1-2h)` | `0.0000000000` ❌ | `hav_A(1e-8) = 0`（真值 2.5e-17，被相消吃掉） |
| V2 `sin²/2` + `acos(1-2h)` | `0.0000000000` ❌ | `hav_B(1e-8) = 2.5000000000000003e-17` ✔ 但 `1-2h` 又舍入成 1 |
| V4 `sin²/2` + `2asin(√h)` | **`0.0000637100`** ✅ | 两处都避开 |

**原因（与 `反三角函数详解` 第五节完全同源）**：$\cos$ 在 $x\approx0$ 时值为 $\approx1$，而 double 在 1 附近的分辨率只有 $2.2\times10^{-16}$。$\theta=10^{-8}$ 时 $\cos\theta=1-5\times10^{-17}$，**这个差异小到 double 表示不出来**，$\cos$ 直接舍入成 1.0。$1-\cos\theta$ 于是变成 0——两个几乎相等的数相减，有效数字被吃光，这叫**灾难性相消（catastrophic cancellation）**。

而 $\sin^2(\theta/2)$ 里 $\sin(\theta/2)\approx\theta/2$ 是个小量本身，不涉及"大数减小数"，信息完整保留。

> 一句话记法：**凡是形如 `1 - cos(x)`、`1 - 2h`、`sqrt(1+x²) - x` 的"大数减小数"，小量情形都要换等价但无相消的写法。**

| # | 坑 | 后果 |

## 八、自查

1. 为什么角度没转弧度，程序**不报错也不崩溃**？这个 bug 最难查的地方在哪？
2. 相对误差 51.47% 这个数字，能排除哪几类原因？
3. `hav(x)` 写 `(1-cos(x))/2` 和 `sin(x/2)*sin(x/2)`，数学上相等吗？什么时候会差？
4. 为什么"只把 `acos` 换成 `asin`"（或只把 `(1-cos)` 换成 `sin²`）救不回小角度？
5. 这道题最好的三个本地自测输入是什么？期望值分别是多少？

**答案要点**
1. 因为 `cos`/`sin` 对任何实数都有定义，不会像 `asin(2)` 那样给 NaN——它静默返回一个**落在 $[-1,1]$ 内的完全合法的错值**，程序不崩、不警告、格式正确，只有答案错。难在"错得不显眼"。
2. 可以排除浮点精度问题（精度问题只有 1e-15~1e-16 量级）。51% 属于逻辑/单位错误量级，应去查角度弧度、公式、下标。
3. 数学上恒等。但 `(1-cos x)/2` 在 $x$ 很小时有**灾难性相消**：$\cos x$ 舍入成 1.0，$1-1=0$。实测 $x=10^{-8}$ 时前者给 0（真值 2.5e-17），后者给 2.5000000000000003e-17。
4. 因为旧写法有**两处独立的相消**：`(1-cos x)/2` 丢掉 h，`acos(1-2h)` 再丢一次 $\theta$。只修一处，另一处照样把结果归零（实测 V2、V3 在 $\theta\le10^{-8}$ 时都输出 0）。
5. 同一点 → `0.0000km`；对径点 `0 0` 与 `0 180` → `20015.0868km`（$=\pi R$）；南北极 `90 0` 与 `-90 0` → `20015.0868km`。分别检验零值、上界、边界。
