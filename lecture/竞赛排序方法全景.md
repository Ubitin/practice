# 竞赛排序方法全景 —— 怎么选、怎么写

> 一句话：竞赛 90% 的排序用 `sort()` 就够；剩下的场景（稳定、第 k 小、top-k、逆序对、值域小）
> 各有一个专门工具。本文是"选型图 + 常用写法"，配套各专题详解。

---

## 一、全景表（按用途选，不按名字背）

| 方法 | 复杂度 | 稳定 | 什么时候用 | 频率 |
|---|---|---|---|---|
| **`sort()`**（introsort：快排+堆排混合） | O(n log n)，最坏也保证 | ❌ | **默认首选，通用排序** | ⭐⭐⭐⭐⭐ |
| `stable_sort` | O(n log n) | ✅ | 同分要保留原相对顺序 | ⭐⭐ |
| **`nth_element`** | 平均 O(n) | ❌ | 只要第 k 小/中位数就位，不排全 | ⭐⭐⭐ |
| `partial_sort` / 堆 top-k | O(n log k) | ❌ | 只要前 k 个，且可以有序 | ⭐⭐⭐ |
| **归并排序**（手写） | O(n log n) | ✅ | 主要用途：**数逆序对** | ⭐⭐⭐⭐（考点在逆序对） |
| **计数排序**（手写） | O(n + 值域) | 可实现 | 值域小能开数组 | ⭐⭐⭐ |
| 快速排序（手写） | 平均 O(n log n)，最坏 O(n²) | ❌ | 理解分治 / 课程考试 | ⭐⭐ |
| 桶 / 基数排序 | O(n + 桶数) / O(d·n) | 可实现 | 进阶：哈希到桶 / 大整数按位 | ⭐ |
| 堆排序（手写） | O(n log n) | ❌ | 实战用 priority_queue 替代 | ⭐ |
| 冒泡 / 选择 / 插入 | O(n²) | 看写法 | 入门教学；n ≤ 1000 | ⭐（几乎不用） |

**数据量感觉**：n ≤ 1000 随便 O(n²)；n ≤ 10⁶ 用 `sort()` 毫无压力；
**手写快排才会退化 O(n²)，`sort()` 内部 introsort 保证 O(n log n)**。

## 二、决策树

```
要排序 → 先问"我要的到底是多少"
├─ 全部有序           → sort()
├─ 全部有序且要稳定     → stable_sort
├─ 只要第 k 小就位      → nth_element（平均 O(n)）
├─ 只要前 k 个（无序即可）→ nth_element / 堆
├─ 只要前 k 个且有序     → partial_sort
├─ 动态插入多次查 top-k → priority_queue
├─ 值域小能开数组       → 计数排序（O(n)）
├─ 顺带数逆序对         → 归并排序
└─ 理解原理/课程考试     → 手写快排、堆排
```

## 三、高频写法（机试直接抄）

```cpp
sort(a + 1, a + n + 1);                                 // 数组 1-based
sort(v.begin(), v.end(), greater<int>());               // 降序
sort(v.begin(), v.end(), [](const Stu& x, const Stu& y){ // 结构体多关键字
    if (x.score != y.score) return x.score > y.score;   // score 降序
    return x.id < y.id;                                 // 同分 id 升序
});
sort(p.begin(), p.end());                               // pair 自动先 first 后 second

sort(v.begin(), v.end());  v.erase(unique(v.begin(), v.end()), v.end());  // 去重三连
nth_element(v.begin(), v.begin() + k, v.end());         // 第 k+1 小就位（详见 nth_element详解）
partial_sort(v.begin(), v.begin() + k, v.end());        // 前 k 个有序

// 归并排序数逆序对：合并时"右半元素先落地"就累加左半剩余个数（详见对应专题）
// 计数排序：编号当下标，按桶序倒出来（详见 计数排序-为什么是O(m+n)）
```

## 四、竞赛里"排序"真正的考法

1. **写对 cmp / 结构体 / pair**——最容易失分的地方（多关键字顺序、`<` vs `>`）。
2. **排序是预处理**：去重、离散化（sort+unique+lower_bound）、二分查找的前提。
3. **排序 + 贪心/扫描**：活动安排、区间合并、按某关键字排序后 O(n) 扫。

## 五、自查

1. n = 10⁵，只求中位数，用什么？为什么不用 sort？
2. "前 3 名且按名次输出"用哪个？
3. 什么场景必须手写归并排序？

答案：1. `nth_element`，平均 O(n) vs sort 的 O(n log n)。2. `partial_sort`（或堆取 3 个再排）。3. 数逆序对时（sort 不告诉你逆序对个数）。
