# 洛谷 P3397 地毯 —— 二维差分排错实录

> 题目一句话：n×n 网格上铺 m 张地毯，每张覆盖闭区间矩形 (x1,y1)-(x2,y2)，问每个格子被盖了几层。
> 规模：n ≤ 1000，m ≤ 1000 → 每次铺 O(n²) 会超时，标准做法是**二维差分**（铺 O(1)，还原 O(n²)）。
> 本文记录一次"算法对、代码错"的完整排错：从症状 → 根因 → 修复 → 验证。

---

## 一、正确模型回顾：二维差分 = 四角标记 + 一次前缀和

1-based 闭区间矩形加 k，只需动 4 个角（都在差分数组 d 上）：

```cpp
d[x1][y1]     += k;
d[x2 + 1][y1] -= k;
d[x1][y2 + 1] -= k;
d[x2 + 1][y2 + 1] += k;
```

还原：在 d 上跑二维前缀和，得到每个格子的最终值。

```cpp
for (int i = 1; i <= n; ++i)
    for (int j = 1; j <= n; ++j)
        d[i][j] += d[i - 1][j] + d[i][j - 1] - d[i - 1][j - 1];   // 顺手输出即可
```

| 标记位置 | 含义 |
|---|---|
| `(x1,y1) +k` | 矩形**左上角**：从此处开始多 k |
| `(x2+1,y1) -k` | 矩形**下边界外一行**：盖住往下越界的部分 |
| `(x1,y2+1) -k` | 矩形**右边界外一列**：盖住往右越界的部分 |
| `(x2+1,y2+1) +k` | **右下角外面**：把被减了两次的右下区域加回来（容斥） |

> ⚠️ 注意四角里有**两个 +k**（左上、右下外），别看成"一加三减"。
> 还原时读 d 只用到下标 1..n，但**写**的时候 x2+1、y2+1 最大到 **n+1** —— 这就是本文的坑。

---

## 二、症状：小数据也对、一贴边就错、一大就崩

对出错代码 `int a[n+1][n+1]` + `int d[n+1][n+1]` 实测：

| 测试 | 期望 | 实际 | 结论 |
|---|---|---|---|
| n=3，盖 (1,1)-(3,3) 一张（**全图贴边**） | 3×3 全 1 | `1 2 2 / 0 1 1 / 0 1 1` | ❌ WA |
| n=5，盖 (2,2)-(4,4)（**不贴边**） | 中间 3×3 为 1，其余 0 | 完全正确 | ✅ 看起来对 |
| n=1000、m=1000 全图铺 1000 张 | 全 1000 | 进程退出码 `-1073741571` | ❌ RE（= `0xC00000FD` 栈溢出） |

**规律**：不贴边的用例全对 → 差分数学没问题；贴边用例错 → 问题出在数组边界。

---

## 三、根因（两个，都在"开数组"上）

### 根因 ①：差分数组少开 1 行/1 列 → 贴边时越界写

原代码开的是 `n+1`，有效下标 0..n。但四角标记会写到 `x2+1`、`y2+1`：
当地毯贴着右/下边界（x2 = n 或 y2 = n）时，要写的是 **d[n+1][...]** —— 下标 n+1 越界了。

越界写落在哪？在本机编译布局里恰好**腐蚀了紧随其后的 `a` 数组的第 0 行**，而前缀和 `a[i][j] = ... + a[i-1][j] ...` 把 a[0][*] 当"必须全 0 的哨兵行"读 —— 哨兵被改脏，全图输出全错。

> 越界写是**未定义行为**：不贴边时不越界，所以"小数据碰巧对"；一旦贴边、或换编译器/换机器，错误形式会变（WA / RE / 数据被改），是典型的"玄学 bug"。

### 根因 ②：用 VLA 装大数组 → 栈溢出

`int d[n+1][n+1]` 是**变长数组（VLA）**，n=1000 时每个约 `1001×1001×4B ≈ 4.0MB`，两个共约 **8MB 全压在函数栈上**，超出默认栈 → 直接崩（`0xC00000FD`）。

> C++ 标准**没有 VLA**（g++ 扩展，OJ 的 C++ 提交未必给开）。大数组要么 `vector`（堆上），要么全局静态数组。

---

## 四、修复与验证

```cpp
// ① 开 n+2（能容纳下标 n+1 的哨兵角）
// ② vector 放堆上，替代 VLA
vector<vector<int>> d(n + 2, vector<int>(n + 2, 0));

// ③ 前缀和还原可以原地做，a 数组直接省掉
for (int i = 1; i <= n; ++i)
    for (int j = 1; j <= n; ++j) {
        d[i][j] += d[i - 1][j] + d[i][j - 1] - d[i - 1][j - 1];
        cout << d[i][j] << (j == n ? '\n' : ' ');
    }
```

修正版验证结果：上表 3 组定向用例全过 + **300 组随机对拍**（坐标刻意让地毯常贴右/下边界，暴力 O(n²·m) 对拍）`bad = 0`。

---

## 五、同类坑自查清单（二维差分通用）

- [ ] 差分数组开 **(n+2)×(n+2)**（一维差分开 n+2 同理）——口诀：**"要写 +1 哨兵，就多开 1 格"**
- [ ] 大数组别用 VLA：`vector<vector<int>>` 或全局 `const int N` 静态数组
- [ ] 统一 1-based，第 0 行/列留作**必须全 0** 的哨兵（别在后面代码里动它）
- [ ] **贴边/全图用例必测**：最小反例就是盖一张 (1,1)-(n,n)
- [ ] 覆盖值可能大时前缀和用 `long long`（本题 k ≤ m = 1000，int 够）
- [ ] 玄学 WA 怀疑越界：把数组整体放大再跑一次，结果变了对就是越界

---

## 六、错码 vs 对码对照（改了三处）

| 位置 | 错 | 对 |
|---|---|---|
| 数组声明 | `int a[n+1][n+1]; int d[n+1][n+1];`（VLA） | `vector<vector<int>> d(n+2, vector<int>(n+2));` |
| 数组规模 | n+1（下标只到 n） | n+2（容纳 n+1 的哨兵角） |
| 还原 | 另开 a 数组存前缀和 | d 上原地前缀和，直接输出 |

四角标记、输入输出、复杂度均无需改动——**算法本来就是对的**。
