# 越界访问：读越界同样是 UB

> 问题：数组越界访问了，但因为不满足判定条件**没去修改它**，会报错吗？
> 结论：**越界读和越界写一样，都是未定义行为（UB）**。"没改它"并不能让访问变合法——
> 因为越界**读**发生在条件表达式求值的那一瞬间，UB 从那一刻就成立了。
> 本文全部观点都有 g++ 实测支撑。

---

## 一、C++ 的规则：只有 [0, size) 内的下标是有定义的

`a[i]` 当 `i` 不在 `[0, n)` 内时，标准**不保证任何行为**：

- 不保证崩溃；
- 不保证返回什么值；
- 不保证"看起来没影响"；
- 不保证下次运行、换个编译器、开个优化选项结果还一样。

所以"会不会报错"是个伪问题——正确的问题是：**这是 UB，任何结果（含碰巧正确）都不算数。**

---

## 二、为什么常常"不报错"（实测）

数组在栈上时，它旁边往往还排着别的变量/空闲空间。越界读只是**读到了邻居**，没碰到"未映射内存页"，就不会段错误，程序照常跑：

```
实测（-O0，读 a[5..7]，a 是 int a[5]={10,20,30,40,50}）：
a[5] = 0      ← 垃圾值
a[6] = 0      ← 垃圾值
a[7] = 7      ← 读到的竟是旁边的循环变量 i！（栈布局凑巧）
exit = 0      ← 程序没崩，"看起来"一切正常
```

**"没崩/没报错" ≠ "合法"**。它只是运气好没踩到保护区，不代表行为有定义。

---

## 三、越界读的三种下场（判题现场会遇到的）

| 场景 | 表现 | 难度 |
|---|---|---|
| 越界够深，跨到未映射页 | **RE**（段错误） | 好查：崩了 |
| 只读到邻居/垃圾 | 垃圾值参与 if 判断 → 结果随机对错 → **WA** | 最阴：本地可能碰巧 AC |
| 编译器利用 UB 做优化 | 把"永远不满足"的检查直接**删掉**、循环改写 | 更玄：代码行为随 -O 变化 |

第三种实测：`-O2` 编译时 g++ 直接警告：

```
warning: iteration 5 invokes undefined behavior [-Waggressive-loop-optimizations]
```

因为 a 的内容(10..50)永远不等于 999，编译器知道循环体"无意义"，加上越界是 UB，
它有权把整段检查优化消失——你的"防御代码"可能根本不存在于最终程序里。

---

## 四、你代码里的"判定条件"救不了你——顺序才关键

```cpp
if (a[i] == 999) { a[i] = -1; }   // ❌ i 越界时，a[i] 的【读】先发生，UB 已成立
                                  //    条件不满足只是"没写"，但已经读了越界
```

正确姿势是**短路**：让边界检查先执行、失败即停，不再求值后面的越界读：

```cpp
if (i >= 0 && i < n && a[i] == x)   // ✅ 边界 false → 短路，a[i] 根本不会被读
if (a[i] == x && i >= 0 && i < n)   // ❌ 顺序反了：先读 a[i] 才轮到边界判断
```

> 口诀：**边界条件永远放 `&&` 的最左边。**

---

## 五、防御与自查清单

- [ ] 循环统一 `for (i = 0; i < n; ++i)`，别用 `<=`/`i+1` 溢出边界
- [ ] 需要访问 `a[i-1]`、`a[i+1]` 时，单独判断 `i==0`/`i==n-1`
- [ ] 边界条件放 `&&` 最左（短路保护）
- [ ] 差分/前缀和类：**多开一格**（n+1/n+2 哨兵），让"越界角"有地方放（见 `洛谷P3397-地毯二维差分排错`）
- [ ] 本地怀疑越界：把 `[]` 临时换成 `.at()`（越界抛 `out_of_range` 精确定位）或开 `-fsanitize=address`
- [ ] **"AC 过"不代表安全**：数据一变（更大 n、贴边界）就可能炸——真正的安全是下标永不越界

---

## 六、一句话总结

**越界读 = 越界写 = UB，没有"只读不改就没事"这回事。**
没报错只是没触发崩溃；垃圾值、WA、编译器删代码都在等着你。
把"边界放最左短路 + 数组多开一格"练成肌肉记忆，这类 bug 才能绝迹。
