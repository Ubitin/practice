# nth_element 详解 —— 只排一个，平均 O(n)

> 一句话：`nth_element` 是**快排思想的"偷懒"版**——它只保证**一个元素**（排好序后该在第 k 位的那个）就位，
> 其余元素它懒得排。适用于"只要第 k 小 / 中位数 / 前 k 名（不要求有序）"的题。
> 配套：`快速排序-逐行精讲`（partition 原理）｜`算法讲义-02 §2.4`（小顶堆 top-k，动态查询用堆）。
> 本文所有输出均为 g++ 实测。

---

## 一、它到底做了什么

```cpp
nth_element(first, nth, last);          // 半开区间 [first, last)，nth 是"目标位置"的迭代器
```

调用后，保证三条：

1. 把区间里**排好序后本该出现在 `nth` 这个位置**的元素，放到 `nth` 上（即 0-based 下标 k = nth−first 处是**第 k+1 小**）；
2. **`nth` 左边所有元素 ≤ `nth` 上的元素**；
3. **`nth` 右边所有元素 ≥ `nth` 上的元素**。

⚠️ **关键**：左边、右边内部**不保证有序**（它们只是"一堆 ≤ 它"和"一堆 ≥ 它"乱序堆着）。

实测（对 `6 1 2 7 9 3 4 5 10 8`，k=4）：

```
调用后数组: 3 1 2 4 |5| 6 8 7 10 9
v[4] = 5（= 全排序后下标 4 的值，正确归位）
左边 3,1,2,4 全部 ≤ 5 ✅   右边 6,8,7,10,9 全部 ≥ 5 ✅
但左边内部 3,1,2,4 是乱序的 —— 它没帮你排完！
```

---

## 二、基本用法（记 4 个姿势就够）

```cpp
// ① vector：第 k+1 小（0-based 下标 k）
nth_element(v.begin(), v.begin() + k, v.end());
// v[k] 就位；k 从 0 数：k=0 是最小值，k=n/2 是中位数

// ② 数组：同样半开区间 [a, a+n)
nth_element(a, a + k, a + n);

// ③ 第 k+1 大：加 greater<int>()
nth_element(v.begin(), v.begin() + k, v.end(), greater<int>());

// ④ 中位数（n 个元素）
nth_element(v.begin(), v.begin() + n / 2, v.end());   // v[n/2] 即中位数
```

实测结果：第 2 大（k=1 + greater）→ 9 ✓；中位数（k=5）→ 6 ✓；第 1 小（k=0）→ 0 ✓。

> 需要 `<algorithm>`（`bits/stdc++.h` 已含）。它**原地重排**，没有返回值。

## 三、复杂度：为什么是"平均 O(n)"

| 做法 | 平均复杂度 | 干的事 |
|---|---|---|
| `sort` | O(n log n) | 全部排好 |
| `nth_element` | **O(n)** | 只让一个元素就位 |
| `partial_sort` | O(n log k) | 前 k 个有序（后 n−k 乱序） |
| 堆（priority_queue） | O(n log k) | 动态维护前 k 个 |

原理：nth_element = **快速选择（quickselect）**。它和快排共用同一个 partition（基准归位、左小右大），
但快排分完后**两边都递归**（所以 O(n log n)）；quickselect 只递归**包含 k 的那一半**：

```
T(n) = T(n/2) + O(n)  →  O(n)
```

（实现多为 introselect：快选 + 三数取中 + 堆兜底，实际非常稳。）
**空间 O(1)**（原地，迭代实现不用递归栈）。

## 四、和快排的关系（你已经会快排，这节 10 秒懂）

你写的挖坑 partition 返回基准下标 `i`。快排继续递归 `[l,i-1]` 和 `[i+1,r]` 两边；
nth_element 只做一件事：**看 k 落在哪边就只去那边**：

```cpp
// 手写 quickselect（找 0-based 第 k 小，5 行版思路）
int qselect(int a[], int l, int r, int k) {   // 在 a[l..r] 里找第 k 小
    while (l < r) {
        int i = partition(a, l, r);           // 复用快排的挖坑划分
        if (i == k) return a[i];              // 就位成功
        if (i < k) l = i + 1;                 // k 在右半 → 只去右边
        else       r = i - 1;                 // k 在左半 → 只去左边
    }
    return a[l];
}
```

对比一眼看懂复杂度差距：快排每条"分叉"都走完（树全部展开 = O(n log n)），
quickselect 每条只走**一条路**（树的深度 × 每层 O(n) = O(n)）。

## 五、常见题型

1. **中位数 / 分数线**：低于中位数的淘汰、第 k 名成绩……
   `nth_element(a, a + n/2, a + n)` 后直接读。
2. **名次/第 k 大**：第 k 大 → 降序 nth；或第 n−k 小。
3. **划分型**：把"前 k 个元素（无序即可）"挑出来做后续处理。
4. 需要**多次动态查询** top-k（不断插入新元素）→ 别用 nth_element（每次 O(n) 重排），用堆 `priority_queue`（见 `算法讲义-02` 第 k 大模板）。

## 六、坑清单

- [ ] **`nth` 必须在 [first, last) 内**：`v.begin()+k` 的 k 合法范围 0..n−1，传 n 是 UB
- [ ] **两半不排序**：想要"前 k 个有序输出" → `partial_sort`；整体有序 → `sort`
- [ ] **k 是 0-based**：找第 k+1 小写 `begin()+k`，别把"第 k 小"直接填 k 又不减
- [ ] 有**重复元素**时：nth 上放的是"随便哪个"相等的值，位置正确但值可能是任一重复项（不影响大小关系判断）
- [ ] 每次调用都会**打乱原数组**（原地重排），如果需要保留原顺序先复制一份
- [ ] 复杂度"平均 O(n)"：理论上最坏仍可能退化（实现已用 introselect 兜底，机试放心用）

## 七、自测

1. `nth_element(v.begin(), v.begin()+2, v.end())` 后，v[2] 是第几小的元素？v[0],v[1] 与 v[2] 有什么关系？
2. 找 n 个数的"前 3 大且按从大到小输出"，该用什么？（提示：不是 nth_element）
3. 为什么 nth_element 平均 O(n) 而快排 O(n log n)？

答案提示：1. 第 3 小（0-based 下标 2）；v[0],v[1] ≤ v[2] 但二者大小不定。2. `partial_sort`（或堆取 3 个再排），nth_element 只保证第 3 大就位、前三无序。3. 快排每层递归两半（展开成一棵树），quickselect 只递归含 k 的那一半（一条路径），每层 O(n) × 深度 log n → O(n)。
