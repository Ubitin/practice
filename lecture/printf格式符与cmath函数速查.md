## 一、printf / scanf 占位符（表 2-3 全表 + 实测）

| 占位符 | 说明 | 实测输出 |
|---|---|---|
| `%d` | 十进制整数（`int`），最常用 | `printf("%d", 42)` → `42` |
| `%nd` | 不足 n 位**前面补空格** | `%6d` → `␣␣␣␣42`（`[    42]`） |
| `%0nd` | 不足 n 位**前面补 0** | `%06d` → `[000042]` |
| `%-nd` | **左对齐**（补空格在右边） | `%-6d` → `[42    ]` |
| `%lld` | `long long`（**Linux / 洛谷等 OJ 用这个**） | `1234567890123` ✓ |
| `%I64d` | `long long` 的 **Windows** 写法 | `1234567890123` ✓ |
| `%f` | 输出 `float`/`double`（**默认 6 位小数**）；scanf 时读 `float` | `%f` → `3.141590` |
| `%lf` | **scanf 读 `double`** 用它（printf 里 `%f` 即可） | `scanf("%lf", &d)` ✓ |
| `%.nf` | 固定 n 位小数（四舍五入） | `%.3f` → `3.142` |
| `%n.mf` | 总宽 n、小数 m 位（空格补齐） | `%10.3f` → `[     3.142]` |
| `%c` | 单个字符 | `[A]` |
| `%s` | 字符串 | `[abc]`；`%5s` → `[  abc]`，`%-5s` → `[abc  ]` |

### ⚠️ 三个必须记住的差异 / 坑

1. **`long long` 的占位符跨平台不同**：Linux（几乎所有 OJ）用 `%lld`；Windows 老编译器（MSVC/老 MinGW）用 `%I64d`。
   > 教材表里写的 `%l64d` 是**笔误**——正确是 `%I64d`（大写字母 I 加 64）。
   > 本机实测：`%I64d` 与 `%lld` 都能正确输出（较新的 MinGW-w64 已支持 `%lld`）。
   > **结论**：交 OJ 一律 `%lld`，本地 Windows 调试若报错再换 `%I64d`。
2. **`%lf` 与 `%f` 的分工**：`scanf` 读 `double` 必须 `%lf`（`%f` 只读 `float`，会读成垃圾）；`printf` 输出 `double` 用 `%f` 就行（`%lf` 也可以，但没必要）。
3. **宽度/精度是"一次性"的**：`printf` 的 `%5d` 只作用于这一个参数；而 `cout` 的 `setw()` 也是一次性，但 `fixed/setprecision` 是持久的（见 §1.3）。

### 其它常用（手册已有，列在此处便于对照）

```cpp
printf("%zu\n", v.size());        // size_t（无符号长度）专用
printf("%05d\n", 7);              // 007
printf("%.2f%%\n", 87.5);         // 百分号要写 %% → 87.50%
```

## 二、`<cmath>` 数学函数（表 1-1 全表 + 实测）

| 函数原型 | 说明 | 实测（默认 6 位小数） |
|---|---|---|
| `double sin(double x)` / `cos` | 正弦/余弦，**x 是弧度** | `sin(3.14159/2)` → `1.000000`、`cos(0)` → `1.000000` |
| `double exp(double x)` | 返回 $e^x$ | `exp(1)` → `2.718282` |
| `double log(double x)` | 返回 **$x$ 的自然对数** $\ln x$ | `log(exp(1))` → `1.000000`；`log10(1000)` → `3.000000` |
| `double pow(double x, double y)` | 返回 $x^y$，也能算多次根 | `pow(3,2)` → `9.000000`、`pow(2,0.5)` → `1.414214` |
| `double sqrt(double x)` | 返回 $\sqrt{x}$ | `sqrt(9)` → `3.000000` |
| `double fabs(double x)` | 返回 $x$ 的**绝对值（浮点）** | `fabs(-10)` → `10.000000` |
| `double ceil(double x)` | **向上取整**：≥x 的最小整数 | `ceil(2.1)` → `3`、`ceil(-2.1)` → `-2` |
| `double floor(double x)` | **向下取整**：≤x 的最大整数 | `floor(2.9)` → `2`、`floor(-2.9)` → `-3` |

**共同点：参数和返回值都是 `double`**（`fabs` 不是 `abs`；`abs` 用于整数）。所以取整后要自己转类型：
`int k = (int)floor(a / (double)b);`

### ⚠️ 四个实测出来的坑

1. **整数幂千万别用 `pow`（精度不保证）**
   本机实测：2~10 的 1~30 次幂共 290 组，`(long long)pow(a,b)` 与整数乘法结果**有 61 组不一致**：
   ```
   pow(5,23): pow 给 11920928955078124，精确值 11920928955078125   ← 差 1
   pow(5,28): 转 long long 直接变成负数                            ← 灾难
   ```
   **要整数幂 → 循环乘 / 快速幂；只有浮点幂才用 `pow`**（并考虑 `round()` 修正）。

2. **浮点别用 `==` 比较**
   `0.1 + 0.2 = 0.30000000000000004`（≠ 0.3）；`sqrt(2)*sqrt(2) = 2.0000000000000004`。
   判等要写 `fabs(a - b) < 1e-9`（按题目精度选 eps）。

3. **整数除法陷阱**：`5/2 == 2`。想要浮点结果：`5/2.0` 或 `(double)5/2`；
   反过来，`ceil/floor` 用在整数除法上就等于没做（先把其中一个转 double）。

4. **三角函数吃弧度不吃角度**：30° 要写 `sin(30 * 3.14159265358979 / 180)`；Pi 可以直接写常量（`M_PI` 不是标准，`acos(-1.0)` 更稳）。

## 三、自查

1. `long long` 在 Windows 与 Linux 上分别用什么占位符？教材写的 `%l64d` 对吗？
2. `scanf` 读 `double` 用什么？`printf` 输出 `double` 用什么？
3. `ceil(-2.1)` 与 `floor(-2.9)` 分别是多少？
4. 为什么 `(long long)pow(5, 28)` 可能出负数？正确做法是什么？
5. `sqrt(2) * sqrt(2) == 2` 成立吗？该怎么比较浮点数？

答案：1. Windows 用 `%I64d`（教材的 `%l64d` 是笔误）、Linux/OJ 用 `%lld`。2. `scanf`→`%lf`，`printf`→`%f`。
3. `-2` 和 `-3`（ceil 向上、floor 向下，负数方向相反）。4. `pow` 返回 double，巨大整数超出 double 的精确整数范围（2⁵³），转换后得到错误值甚至负数；整数幂要用循环乘/快速幂。
5. 不成立（浮点误差）；用 `fabs(a-b) < 1e-9` 形式的相对/绝对误差判断。
