# 记忆化搜索 —— 递归 + 缓存（两个模板）

> 来源：教材"记忆化搜索"一节 + 例 11-5 Function（洛谷 [P1464](https://www.luogu.com.cn/problem/P1464)）。
> 一句话：**把递归算过的每个状态答案存进数组，第二次遇到直接查表** —— 用空间换时间。
> 两个模板已加进 `机试代码模板速查手册` §5.1，本文是原理 + 实测依据。

---

## 一、为什么需要它

教材的原话精神：递归实现本身没错，但"做了很多无用功"——
比如 `sol(2)` 可能被 `sol(4)` 调用、又被 `sol(8)` 调用，**而 sol(2) 的值是固定不变的**，
于是同一个子问题被反复重算 → 效率低下 → 超时。

解决办法：开一个数组 `f`，**`f[i]` 就是"规模为 i 时的答案"**。
先把数组初始化成"还没算过"的标记；递归进来**先查表**，算过就返回，没算过才继续递归，算完立刻存表。

一句话骨架：

```cpp
ans = 查表(状态);
if (没算过) { 递归算出来; 存表; }
return 表里的值;
```

## 二、模板 1：一维记忆化

```cpp
int n, f[1010];                          // f[i] = 规模 i 的答案；-1 表示"还没算过"
int sol(int x) {
    if (f[x] != -1) return f[x];         // ① 查表
    int ans = 1;
    for (int i = 1; i <= x / 2; i++) ans += sol(i);
    return f[x] = ans;                   // ② 存表
}
int main() {
    cin >> n;
    memset(f, -1, sizeof(f));            // ⚠️ 初值必须能与"合法答案"区分（答案恒 ≥1 → 用 -1）
    f[1] = 1;                            // 边界（递归出口）
    cout << sol(n) << endl;
}
```

**实测值**（本机 g++）：`n=1→1, 2→2, 4→4, 8→10, 10→14, 50→786, 100→9828, 1000→1981471878`

**实测加速比**（同样递归式，只差"有没有缓存"）：

| n | 朴素递归调用次数 | 记忆化调用次数 | 倍数 |
|---|---|---|---|
| 20 | 30 | 26 | 1.2× |
| 50 | 393 | 157 | 2.5× |
| 100 | 4 914 | 626 | 7.8× |
| 200 | 102 829 | 2 501 | 41× |
| 300 | 782 154 | 5 626 | **139×** |

> 结论：n 小的时候看不出差别，**n 一大朴素版本就指数式爆炸**，这正是教材说"超时"的原因。
> 记忆化后代价 ≈ 状态数 × 每个状态的转移量（本例 ≈ O(n²/4)）。

⚠️ `n=1000` 时答案 1 981 471 878 已逼近 `int` 上限（2 147 483 647）→ 规模再大要换 `long long`。

## 三、模板 2：多维记忆化（P1464 Function）

题意：递归函数 `w(a,b,c)`——
① 任一 ≤0 → 返回 1；② 任一 >20 → 返回 `w(20,20,20)`；
③ `a<b<c` → `w(a,b,c-1)+w(a,b-1,c-1)-w(a,b-1,c)`；
④ 否则 → `w(a-1,b,c)+w(a-1,b-1,c)+w(a-1,b,c-1)-w(a-1,b-1,c-1)`。
多组询问，`-1 -1 -1` 结束，输出格式 `w(a, b, c) = 结果`。

```cpp
long long f[25][25][25];                 // 全局数组自动清零 → 用 0 当"没算过"（答案恒 ≥1）
long long w(long long a, long long b, long long c) {
    if (a <= 0 || b <= 0 || c <= 0) return 1;              // 边界①：先判，负/零绝不能进数组下标
    if (a > 20 || b > 20 || c > 20) return w(20, 20, 20);  // 边界②：把大参数压回 20
    if (f[a][b][c] != 0) return f[a][b][c];                // 查表
    if (a < b && b < c)
        f[a][b][c] = w(a,b,c-1) + w(a,b-1,c-1) - w(a,b-1,c);
    else
        f[a][b][c] = w(a-1,b,c) + w(a-1,b-1,c) + w(a-1,b,c-1) - w(a-1,b-1,c-1);
    return f[a][b][c];                                     // 存表并返回
}
int main() {
    long long a, b, c;
    while (cin >> a >> b >> c) {
        if (a == -1 && b == -1 && c == -1) break;          // 终止条件在调用前判
        cout << "w(" << a << ", " << b << ", " << c << ") = " << w(a, b, c) << "\n";
    }
}
```

**实测**：

| 输入 | 输出 | 说明 |
|---|---|---|
| `1 1 1` | `w(1, 1, 1) = 2` | 官方样例 ✓ |
| `2 2 2` | `w(2, 2, 2) = 4` | 官方样例 ✓ |
| `10 4 6` | `w(10, 4, 6) = 523` | 官方样例 ✓ |
| `20 20 20` | `w(20, 20, 20) = 1048576` | 边界 |
| `25 25 25` | `w(25, 25, 25) = 1048576` | 被边界②压回 `w(20,20,20)`，结果相同 ✓ |
| `-5 3 7` | `w(-5, 3, 7) = 1` | 边界① |

状态总数只有 `20×20×20 = 8000`，每个状态 O(1) 转移 → 无论怎么问都瞬间出结果（**缓存跨多组询问共用**）。

## 四、记忆化搜索 vs 递推 DP

| | 记忆化搜索（递归+缓存） | 递推 DP（循环填表） |
|---|---|---|
| 写法 | 顺着题意写递归，加两行查表/存表 | 必须想清楚**遍历顺序**（谁能推出谁） |
| 复杂度 | 状态数 × 单状态转移（同递推） | 同 |
| 开销 | 递归栈 + 函数调用常数 | 常数更小 |
| 何时更难 | 边界/终止处理写清楚即可 | 转移顺序复杂时容易写错 |
| 典型场景 | 状态关系像"树/图"、天然递归（如本题） | 线性、区间、背包等有明确层序 |

> 一般建议：**先用记忆化把思路写对，再看是否值得改递推压常数**。

## 五、坑清单

- [ ] **未算标记要与合法答案区分**：答案恒 ≥1 可用 `0`；答案可能是 0 就必须用 `-1`（并 `memset(f,-1,sizeof(f))`）
- [ ] **先判边界，再用参数当下标**：`f[a][b][c]` 前必须保证 `0 < a,b,c ≤ 20`，否则越界（负下标是最常见崩法）
- [ ] **数组维度要开够**：`f[25][25][25]` 对应上界 20；开小了直接 RE
- [ ] **多组询问共享缓存**：数组别在每组数据前清空（清零就白记了）
- [ ] **数值范围**：先按题意估上界，不确定就上 `long long`（P1464 用 `long long` 稳）
- [ ] **输出格式**：P1464 要求 `w(a, b, c) = x`（逗号后有空格），格式错=WA
- [ ] 递归深度大时注意栈：状态数上万、递归深度上千要评估或改递推

## 六、自查

1. 记忆化搜索相比朴素递归，省掉的是什么？代价是什么？
2. 为什么 P1464 里必须先判 `a<=0` / `a>20`，再访问 `f[a][b][c]`？
3. 什么情况下不能用 `0` 当"未计算"标记？
4. 记忆化和递推 DP 的时间复杂度一样吗？

答案提示：1. 省掉同一子问题的重复求解；代价是 O(状态数) 的额外空间与查表开销。2. 否则下标越界（负数或超过 20）。3. 当"合法答案本身可能是 0"时，0 就无法区分"没算过"，要用 -1 之类标记。4. 一样（状态数 × 单状态转移），只是常数与实现难度不同。
