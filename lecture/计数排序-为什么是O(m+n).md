# 计数排序 —— 为什么复杂度是 O(m + n)

> 题目：洛谷 [P1271](https://www.luogu.com.cn/problem/P1271)。n 个候选人（编号 1..n），m 张选票，每张写一个候选人编号。
> 要求把这些选票按编号**从小到大**输出。本题用"计数排序"（桶思想）做到 O(m+n)。

## 一、代码（计数排序 = 两个循环）

```cpp
int a[1010] = {0}, n, m, tmp;
cin >> n >> m;
for (int i = 0; i < m; ++i) {      // ① 读 m 张票，按编号"进桶"
    cin >> tmp;
    a[tmp]++;                      // a[x] 记录编号 x 出现了几次
}
for (int i = 1; i <= n; ++i) {     // ② 按编号从小到大，把每个编号打印 a[i] 次
    for (int j = 0; j < a[i]; ++j)
        cout << i << ' ';
}
```

`a[x]` 是"编号 x 的票数"（桶）。因为编号范围就是 1..n，所以**编号本身就能当下标**——不用比较，直接桶装、按桶序倒出来就是有序的。

## 二、复杂度拆解：两段相加

| 段 | 循环 | 次数 | 合计 |
|---|---|---|---|
| ① | 读 m 张票 | **m** | O(m) |
| ② 外层 | 挨个检查 n 个编号 | **n** | O(n+m) |
| ② 内层 | 打印每桶的票 | **Σ a[i] = m** | （并入上式） |

**关键就在内层**：内层循环一共执行多少次？是 `Σ a[i]`（i=1..n）。
因为每张票都恰好落进某个桶，所以 **Σ a[i] = m**（所有桶的票数加起来 = 总票数 m）。
故第二段 = 外层 n 次 + 内层总共 m 次 = **O(n + m)**。

## 三、为什么不是 O(n × m)？

很多人一看到"双层循环"就条件反射 O(n×m)——**这里错了**。

内层循环的次数不是固定的 n，而是**那一桶的票数 a[i]**，它随 i 变化，而且**各自加起来恒等于 m**：

```
Σ a[i] = m      （票数守恒：票都投了，各桶之和不会超过 m）
```

所以不会出现"每桶都约 m 张"的情况（那需要 m 张票分给 n 个桶，总和还是 m，不可能每桶都是 m）。
**外层是"找桶"（n 次），内层是"倒票"（总共 m 次），二者是叠加关系，不是相乘关系。**

## 四、实测验证（n=5, m=10）

```
票 a[1]=2 a[2]=6 a[5]=2        ← 其余 0
外层循环次数 = n = 5
内层总执行次数 = Σa[i] = 10 = m
总代价 ≈ n + m = 15   → O(n + m)
```

换成 m 更大也成立：**内层次数永远锁死在 m**，与 n 无关。n 只决定外层"扫桶"的次数。

## 五、与比较排序对比 + 使用前提

| 排序 | 复杂度 | 适用 |
|---|---|---|
| sort / 快排 | O(m log m) | 通用 |
| **计数排序** | **O(m + 值域 n)** | 值域小、编号范围能开数组 |
| 桶/基数排序 | O(m + 值域) | 可扩展（本题下文提到） |

**注意**：O(m+n) 里的 n 是**编号范围（值域）**，不是输入量。所以：
- 编号只到 999（n ≤ 999）→ a[1010] 装得下，O(m+n) ≈ O(m)，很快；
- 若编号能到 10⁹ → **数组都开不出**（内存爆炸），计数排序失效，得换思路（这正是题目下方那个"警告"）。

## 六、自查

1. 内层循环总次数为什么恒等于 m？
2. 若 n=1000、m=2000000，总代价大约是多少次？
3. 为什么值域很大（如 10⁹）时不能用计数排序？

答案：1. 每张票进一个桶，各桶票数之和 = 总票数 m（票数守恒）。2. O(n+m) ≈ 200 万次（外层 1000 + 内层 200 万），几乎一次扫描。3. 需要开大小为值域的数组 a[10⁹]，内存爆掉；且扫桶也要 O(值域)。
