> 🎬 **配套动画**：`figures/图DFS深度优先搜索动画.html`（自包含，双击就能开）
> —— 左边是图，右边是**递归栈**、访问顺序、时间戳表、边分类统计；支持 播放/单步/后退/重置/调速、换起点、**无向图↔有向图**切换，还能用 `#f=帧号` 直接跳到某一帧。
>
> **一句话**：DFS 就是"**一条路走到黑，走不通了退回上一层换一条路**"。**看懂递归栈，就看懂了 DFS。**

---

## 一、先把模型说清

| 记号 | 含义 |
|---|---|
| **白点** | 还没访问过 |
| **橙点** | 正在访问（**它还在递归栈上**，它的邻居还没看完）|
| **绿点** | 已完成（它和它的所有后代都访问完了，**已经出栈**）|

DFS 的执行顺序只有三个动作，无限循环：

```
发现一个新点 → 染橙、压栈（往下钻）
   ↓
看它的第一个邻居：白的就钻进去；不是白的就跳过，看下一个邻居
   ↓
邻居全看完了 → 染绿、出栈（退回上一层，继续看上一层剩下的邻居）
```

---

## 二、动画里那条"递归栈"是灵魂

右上的**递归栈**面板画的是**真实调用栈**：底部是根，顶部是当前正在处理的点，括号里写着"**看到第几个邻居了**"。

关键感受（动画里一格一格看最清楚）：

| 现象 | 说明 |
|---|---|
| 栈只会**变高**（往下钻）或**变矮**（退回上一层）| 不会横着长——这正对应 DFS 的"深" |
| 栈里的点**永远构成一条链**（从根到当前点的路径）| 校验脚本专门验了这条：364 帧里全部成立 ✅ |
| 栈里每个点都记住了"我看到第几个邻居了" | 所以退回去以后能**接着往下看**，不会从头再来 |
| 当前点的邻居看完 → 出栈（染绿）| "一条路走到黑"走到头了，就该退了 |

**"为什么退回上一层还能继续搜？"** 因为栈帧里保留着上一层循环变量 `i` 的位置（也就是面板里那个"看到第 N 个邻居"）。

## 三、骨架代码（沿用你平时的写法：全局数组 + `void dfs(ll u)`）

```cpp
const ll maxn = 200005;
vector<ll> g[maxn];       // 邻接表（写在【全局】！见讲义「二维vector两种写法」）
bool vis[maxn];

void dfs(ll u) {
    vis[u] = true;                 // ① 进门就标记，防止绕回去
    for (ll v : g[u]) {            // ② 挨个看邻居
        if (vis[v]) continue;      //    访问过就跳过
        dfs(v);                    // ③ 白的就钻进去（这里就是"一条路走到黑"）
    }
}
// 调用：dfs(起点)   —— 或者外层 for 一遍，把所有连通块都走到（见第五节）
```

只有三行是核心：**标记、循环、递归**。

## 四、把"时间戳"加上：tin / tout

在动画里你会看到每个点被记了两个数：

| 名字 | 什么时候记 | 动画里的动作 |
|---|---|---|
| `tin[u]` | **发现** u 的时候（染色、压栈）| 「发现 1：tin[1]=2」|
| `tout[u]` | **离开** u 的时候（出栈）| 「1 的邻居全看完了：tout[1]=11」|

```cpp
ll timer_ = 0, tin[maxn], tout[maxn];
void dfs(ll u) {
    tin[u] = ++timer_;      // 进门
    for (ll v : g[u]) if (!vis[v]) { vis[v] = true; dfs(v); }
    tout[u] = ++timer_;     // 出门
}
```

**实测**：动画的无向图（8 个点、2 个连通块）跑完，时间戳一共用了 **16 = 2n** 个——**每个点进、出各一次**，所以 `tin/tout` 是 $1..2n$ 的一个排列（校验脚本验过：互不重复、最大值恰好 2n ✅）。

### 时间戳为什么有用：一眼判断祖宗关系

> **u 是 v 的祖先 ⟺ `tin[u] < tin[v] < tout[v] < tout[u]`**

也就是"**v 的整个活动区间被夹在 u 的区间里**"。
这正是上一题 **CF1006E** 那条结论的来源：**子树 = 时间戳上的一段连续区间**；那里我们只从根往下走（树），这里推广到任意图。

## 五、连通块：外层再套一个循环

一张图可能有几块互不相连的部分。DFS 只跑一个起点，只能走完**它所在的那一块**。所以外面再套一层：

```cpp
for (ll s = 1; s <= n; ++s)
    if (!vis[s]) { vis[s] = true; dfs(s); }     // 每进一次 if 就发现一个新连通块
```

**实测**：动画的无向图有 **2 个连通块**（`0 1 3 4 5 2` 和 `6 7`）——所以从 0 出发跑完第一块后，外层循环发现 6 还是白的，就从 6 又开了一棵 DFS 树 ✅。
（顺带一条恒等式：**树边数 = n − 连通块数**。实测无向图 6 = 8 − 2 ✅，有向图 4 = 5 − 1 ✅，校验脚本对 13 组全验过。）

## 六、边的分类：DFS 顺手就能给每条边"定性"

这是图 DFS 最有用的副产品。动画里边的颜色就是它：

| 类型 | 判定（考察 u→v 时 v 的状态）| 含义 |
|---|---|---|
| 🟢 **树边** | v 是**白**的 | 发现了新点，递归下去 → 这些边构成 **DFS 树** |
| 🔴 **回边** | v 是**橙**的（还在栈上）| 指向自己的**祖先** → **说明图里有环！** |
| 🔵 **前向边** | v 是**绿**的，且 v 是 u 的**后代**（有向图）| 通向自己子树里已完成的点 |
| 🟣 **横叉边** | v 是**绿**的，且 v **不是** u 的后代（有向图）| 通向别的分支 |
| ⚪ **回看的边** | 无向图里 v 是绿的 | 这条边**早就在对面被看过一次**了 |

**实测（动画的无向图，起点 0）**：树边 **6**、回边 **7**、回看的边 **1**，合计 **14 = 2×边数 7**——无向图每条边都会被看两次 ✅。

> ⚠️ **无向图里你永远看不到蓝色/紫色**（前向边、横叉边）：因为无向图的边是双向的，一旦 v 已经是绿的，说明 v 早在 u 之前就完成，那时它一定把 u 也带走了——矛盾。**所以无向图只有树边和回边**（动画里也有这一条校验，13 组全过 ✅）。
> **判环只用一句话**：DFS 过程中**出现过回边 ⟺ 图有环**。

**实测（动画的有向图，起点 0）**：树边 **4**、回边 **1**、前向边 **2**、横叉边 **1**——五种分类里四种齐全，正好用来认全这些名词 ✅

## 七、⚠️ 两个必须知道的坑

### 坑 ①：递归深度会爆栈（本地尤其明显）

图退化成一条链时（n 个点、n−1 层），递归就压 n 层。本机实测（Windows 默认 1MB 栈）：

| 递归深度 | 结果 |
|---|---|
| 20000 | 通过 |
| **25000** | **崩：0xC00000FD 栈溢出** |

而 $n$ 常见到 $2\times10^5$ ⇒ **本地会崩、评测机（Linux 栈大）却不崩**，特别容易白白怀疑自己。
对策：**写显式栈的迭代版**，或者本地编译加 `-Wl,--stack,268435456`（详见讲义「CF1006E…」§五）。

### 坑 ②：迭代版"入栈即标记"和递归**语义不同**（会被坑到）

很多人以为把递归改写成"自己开个栈"就等价了。**不等于**——最朴素的写法会给出**不同的访问顺序**：

```
朴素迭代：弹出 u，把 u 所有没访问的邻居【一次全压栈并立刻标记】
递归    ：只递归进【第一个】没访问的邻居，回来再处理下一个
```

**实测（同一张图，13 组里 3 组不同）**：

| 图 / 起点 | 递归版 | 朴素迭代版 |
|---|---|---|
| 无向图 起点1 | `1 0 2 5 4 3 6 7` | `1 0 2 5 3 4 6 7` |
| 有向图 起点0 | `0 1 2 4 3` | `0 1 4 2 3` |

（有向图那组的原因：从 0 出发时，2 被"顺路标记"成了 0 的孩子，后来 4 就抢在它前面了 → **DFS 树变了，顺序当然变**。）

**想要"和递归完全一致"的迭代版**，必须用**栈里存 (点, 看到第几个邻居)** 的写法（就是动画里递归栈面板画的东西）：

```cpp
vector<pair<ll,ll>> st;          // (点, 下一个要看的邻居下标)
st.push_back({s, 0}); vis[s] = true;
while (!st.empty()) {
    auto &fr = st.back();
    if (fr.second < (ll)g[fr.first].size()) {
        ll v = g[fr.first][fr.second++];
        if (!vis[v]) { vis[v] = true; st.push_back({v, 0}); }
    } else st.pop_back();        // 邻居看完了 → 出栈（= 递归里的 return）
}
```

> 记忆：**BFS 里"入队即标记"是标准做法；DFS 里"入栈即标记"却会改变树**——两者不能照搬。

## 十、自查（先做完再翻答案）

1. DFS 里"橙点"和"绿点"分别是什么意思？为什么橙点一定在递归栈上？
2. `tin/tout` 各在什么时候记录？为什么一共有 $2n$ 个？
3. 怎么用 `tin/tout` 判断 u 是不是 v 的祖先？
4. 考察边 u→v 时，v 是**橙色**说明什么？是绿色说明什么（有向图 / 无向图各怎么理解）？
5. 为什么无向图里不会出现前向边和横叉边？
6. 把递归 DFS 改写成"自己开栈"的迭代版时，最容易改变什么？正确的写法要往栈里存什么？

<details>
<summary>答案</summary>

1. 橙＝正在访问（它的邻居还没看完）；绿＝已完成（它和它所有后代都访问完了）。橙点必然是"从根一路钻下来、还没退回去"的点，所以正好构成递归栈里的那条链。
2. `tin` 在**发现**（染色压栈）时记，`tout` 在**离开**（出栈）时记。每个点恰好进、出各一次 ⇒ 共 $2n$ 个，且互不相同。
3. `tin[u] < tin[v] && tout[v] < tout[u]`（v 的整个区间被夹在 u 的区间里）。
4. v 是橙 ⇒ v 还在栈上 ⇒ v 是 u 的**祖先** ⇒ 这条边是**回边**，图里有环。v 是绿：有向图里再看 v 是不是 u 的后代——是则前向边，否则横叉边；无向图里只会是"这条边早就在对面被看过一次"（回看的边）。
5. 因为无向边是双向的：如果 v 已经完成（绿）而 u 此刻才考察这条边，说明 v 完成时 u 还是白的，那 v 早就该沿着这条边把 u 访问掉了 ⇒ 矛盾。
6. 最容易改变的是**访问顺序（以及 DFS 树本身）**——"弹出即把全部未访问邻居一次压栈并标记"会让某些点被"顺路"标记成别的点的孩子。正确写法：栈里存 **(点, 下一个要看的邻居下标)**，每次只处理一个邻居，看完了才出栈（＝模拟递归的 `return`）。
</details>
