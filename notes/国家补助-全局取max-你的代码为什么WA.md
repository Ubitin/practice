# 国家补助（全局取 max）· 你的代码为什么 WA

> **触发点**：你贴出题面（余额 + 两种操作：`1 p x` 单独改、`2 x` 把所有低于 x 的人抬到 x），问"看看我的代码为什么 WA"。
> **一句话结论（v1）**：**你的整体思路是对的**（记下"每个人最后一次被单独改的时刻"，再和补助时间线比较），**错在两处边界**：
> ① `t[i]` 没初始化，且最后的分支链缺 `else` ⇒ **有些公民完全不输出**；② 时间线的边界用 `t[i] > timer1` 太严 ⇒ **该被抬起来的人没被抬**。
> 实测：5000 组随机小数据对拍，**v1 错 4933 组**，修正版 **0 组**。
>
> **⭐ 后续（2026-09-26，你已重写为 v2）**：**v2 的逻辑已经完全正确**——`mon[]` 按时间点记补助值 + `max_element(mon.begin()+t[i], mon.end())` 正好就是"他最后一次被改之后的最大补助"，实测 **10000 组随机对拍 0 不一致 ✅**。
> **但 v2 会 TLE**：`max_element` 是 `O(q)`、每个人做一次 ⇒ **总 `O(n·q)`**，极限数据实测 **76875 ms（≈77 秒）**。改成"预处理后缀最大值"后 **192 ms**（快约 **400 倍**），详见 **§八**。

## 一、先把题意看穿（这题真正的钥匙）

> **`1 p x` 是"直接覆盖"——它把 p 之前受到的补助一笔抹掉。**

于是对每个人 p：

```text
最终余额 = max( 他最后一次被单独修改的值 a[p] ,
                【那次修改之后】出现过的所有 "2 x" 里最大的 x )
```

如果他**从来没被单独修改过**，那他能吃到**全局**所有补助里最大的那个。

⚠️ 划重点：**是"之后"**，不是"全局最大"。这一步想错就会得到完全错误的答案（我自己第一版就错在这里，下面有实证）。

## 二、你的原码（`test_\01.cpp`）

```cpp
ll res = 1e9, last = 0;
ll timer1 = 0, timer2 = 0;
ll a[maxn], t[maxn];                 // ★ t[] 从没被赋初值

int main(){
    cin>>n;
    for(ll i=1;i<=n;++i){ cin>>a[i]; t[i]=0; res = min(res, a[i]); }   // 注意：这里给 t[i]=0 了！
    cin>>q;
    for(ll i=1;i<=q;++i){
        cin>>k;
        if(k==1){ cin>>p>>x; a[p]=x; t[p]=i; }
        else if(k==2){
            cin>>x;
            if(x >= res) { res = x; timer1 = i; }   // 只有"刷新历史最大"才算进度条前进
            timer2 = i; last = x;
        }
    }
    for(ll i=1;i<=n;++i){
        if(t[i] < timer1)                        cout<<max(res , a[i])<<" ";
        else if(t[i] > timer1 && t[i] < timer2)  cout<<max(last, a[i])<<" ";
        else if(t[i] > timer2)                   cout<<a[i]<<" ";
    }   // ★ 没有 else：剩下的人（t[i] 落在空隙里）什么都不输出
}
```

**方向没错**：`t[i] < timer1` ⇒ 他被"历史最大补助"罩着；`t[i] > timer2` ⇒ 他最后一次修改在最晚的补助之后，是干净的。**问题出在这条分界线画歪了。**

## 三、两个真实 bug（都实测复现了）

### bug 1（最致命）：分支链缺 `else` ⇒ 有些公民一个字符都不输出

**最小反例**：

```text
输入:  3
       7 7 7
       1
       2 5
```

- 三个人初始都是 7；补助只给 `2 5`（5 比 7 小）⇒ `x >= res` 不成立 ⇒ **`timer1` 始终是 0**；
- 于是 `t[i] = 0`：`0 < 0` 假、`0 > 0 && 0 < 1` 假、`0 > 1` 假 ⇒ **三条分支全落空，什么都不打印**。

| | 暴力解 | **你的原码** | 修正版 |
|---|---|---|---|
| 输出 | `7 7 7` | **（空）** | `7 7 7` |

**同样的空洞还有 `q = 0`（没有任何事件）**：

```text
输入:  4
       9 6 0 6
       0
```
暴力 → `9 6 0 6`；**你的原码 → 空**（连一个数都不打印）。

⭐ 记住这个模式：**`if / else if / else if` 后面所有情况都没兜住 = 静默不输出**。这题判题只看输出，缺一个数就是 WA，而你在本地跑样例（两个样例都恰好落在已覆盖的分支里）**完全看不出来**。

### bug 2：`t[i] > timer1` 太严 ⇒ 该被抬起的人没被抬

**最小反例**：

```text
输入:  3
       11 0 13
       6
       2 15        ← 补助 15，所有人被抬到至少 15
       1 2 15      ← 第 2 个人被单独改成 15
       2 7
       1 2 9       ← 第 2 个人又被改成 9
       2 11        ← 补助 11（<15，不再刷新历史最大）
       2 8
```

- 第 2 个人最后一次被改是第 4 步（改成 9），之后还有补助 11 ⇒ 他应该是 **11**；
- 但你的判断是 `t[2]=4 > timer1=1` ⇒ 走"干净"分支输出 `a[2]=9` ⇒ **少抬了 2**。

| | 暴力解 | **你的原码** | 修正版 |
|---|---|---|---|
| 输出 | `15 11 15` | `15 **9** 15` | `15 11 15` |

## 四、修正版：倒着扫一遍，O(n + q)

与其正着维护"拐点"，不如**倒着扫**——因为每个人只关心"他最后一次修改**之后**的补助最大值"：

```cpp
vector<ll> sub(n + 1, 0);      // sub[p] = 最后一次改 p 之后的最大补助
vector<char> seen(n + 1, 0);   // p 是否被改过（倒扫第一次遇到＝时间上最后一次）
ll mx = 0;
for (ll i = q - 1; i >= 0; --i) {
    if (typ[i] == 2) {                     // ★ 先把"更靠后的补助"并进 mx
        mx = max(mx, opX[i]);
    } else if (!seen[opP[i]]) {            // ★ 再记录覆盖（倒扫第一次遇到才是最后一次）
        seen[opP[i]] = 1;
        sub[opP[i]] = mx;                  // 此刻 mx 恰好 = "这次覆盖之后"的最大补助
        a[opP[i]]   = opX[i];
    }
}
ll globalMax = mx;                          // 扫完后的 mx = 全部补助的最大值

for (ll i = 1; i <= n; ++i) {
    ll tag = seen[i] ? sub[i] : globalMax;  // ★ 从没被改过的人 ⇒ 吃全局最大补助
    cout << max(a[i], tag) << " \n"[i == n];
}
```

**三处"顺序/初值"是关键**（我自己写第一版时全踩了）：

| # | 要点 | 写错的后果 |
|---|---|---|
| 1 | 倒扫时**先** `mx = max(mx, x)`，**再**记录覆盖 | 顺序反了会把"这次覆盖**之前**"的补助也算进去（我用样例1 当场发现：正确 `3 2 3 4`，写成 `1 2 3 4`） |
| 2 | 每个 p **只认倒扫时第一次遇到**的那次覆盖 | 否则 `a[p]` 保留的是**最早**那次的值 |
| 3 | 从没被改过的人用 **`globalMax`**，不是 `0` | 否则 `max(a[i], 0)` 会把 `2 4` 这类补助漏掉（全是 0 的人应变成 4） |

## 六、⚠️ 关于"对拍工具本身"的三个坑（本轮我亲身踩了）

1. **对拍要用批量输入**：每个用例起一次进程太慢（Windows 上 `system()` 一次约 12 ms）。把 5000 个用例合成一个文件、让程序**读到 EOF 为止**，一次跑完。
   ⇒ 所以对拍专用的程序要写成 `while (cin >> n) { ... }`，而不是只读一次。
2. **`.exe` 可能是陈旧产物**：本轮我一度拿到"同一个程序 stderr 算出 3 2 3 4、stdout 却打印 1 2 3 4"这种自相矛盾的结果，删掉全部 `.exe` 重新编译后自相矛盾消失。
   ⇒ **看到"输出和推理对不上"时，第一件事是把可执行文件删掉重编**（这与题面里那条老经验同源：*先怀疑自己的工具*）。
3. 用 `system()` 调子进程时，**程序名要给绝对路径**：`system()` 的工作目录不保证是当前目录，用相对路径会"找不到程序"而静默不执行（本轮也踩了，表现为对拍报"不一致 0 个"其实根本没跑）。

## 七·五、⭐ v2 复核（2026-09-26）：逻辑对了，但会 TLE

你把代码重写成 v2：

```cpp
vector<ll> mon;                                  // mon[i] = 第 i 个事件若是 "2 x" 则记 x，否则 0
mon.resize(q + 1);  fill(mon.begin(), mon.end(), 0);
...                                              // 读事件时 mon[i] = x
for (ll i = 1; i <= n; ++i) {
    ll temp = *max_element(mon.begin() + t[i], mon.end());
    cout << max(a[i], temp) << " ";
}
```

### ✅ 逻辑完全正确

`max_element(mon.begin() + t[i], mon.end())` = **下标 `t[i]` 到末尾的最大值**，而 `mon[i]` 只有"第 i 个事件是 `2 x`"时才非零 ⇒ 这正好就是"**他最后一次被改之后**的最大补助"。
而且还顺手绕开了 v1 的两个坑：从没被改过的人 `t[i] = 0` ⇒ 从下标 0 开始取 ⇒ **自然就是全局最大补助**（不需要额外判 `else`）；`q = 0` 时 `mon` 只有 `mon[0] = 0` ⇒ 输出原值。

**实测**：**10000 组随机对拍（多种子）不一致 0 ✅**；官方样例 1/2 ✅；之前两个"空输出"反例（`3 / 7 7 7 / 1 / 2 5`、`q=0`）现在都正确 ✅。

### ❌ 但它是 `O(n·q)`，极限数据会 TLE

`max_element` 每次要扫 `O(q)` 个元素，你对 `n` 个人各做一次 ⇒ **总 `O(n·q)`**。
本题 `n ≤ 10^6`、`q ≤ 2×10^5` ⇒ 最坏约 **2×10^11** 次操作。

**实测（本机，`-O2`）**：

| 数据 | 你的 v2 | 后缀最大值版 | 倍数 |
|---|---|---|---|
| `n = q = 10000` | 84 ms | 32 ms | 2.6× |
| `n = q = 20000` | 183 ms | 33 ms | 5.5× |
| `n = q = 40000` | 530 ms | 39 ms | **13.6×** |
| **`n = 10^6, q = 2×10^5`** | **76875 ms（≈77 秒）** | **192 ms** | **≈400×** |

⭐ 看第 2→3 行：`n` 翻倍、耗时翻 **2.9 倍** ⇒ 这就是 `O(n·q)` 的平方级增长信号（对比后缀版几乎不变：32→39 ms）。

### ✅ 怎么改：把"每查一次算一次后缀"换成"预处理一遍后缀"

```cpp
vector<ll> mon(q + 2, 0);
// ... 读事件时照旧 mon[i] = x ...

vector<ll> suf(q + 2, 0);                        // suf[i] = max(mon[i..q])
for (ll i = q; i >= 0; --i) suf[i] = max(suf[i + 1], mon[i]);
//            ★ 必须一路扫到 i = 0！t[i] = 0 时查的就是 suf[0] = 全局最大补助

for (ll i = 1; i <= n; ++i) cout << max(a[i], suf[t[i]]) << " \n"[i == n];
```

- 预处理 `O(q)`，之后每人 `O(1)` ⇒ **总 `O(n + q)`**；
- 实测同一极限数据 **192 ms**，且与你的 v2 输出**内容完全一致**（SHA 不同只因为你的最后一项后面是空格、我的以换行结尾——判题无害）。

> ⚠️ 抄这个改法时**别漏掉 `i >= 0`**：我第一次写就只扫到 `i = 1`，结果 `suf[0] = 0`，导致"从没被改过的人"拿不到补助（样例 1 直接错成 `1 2 3 4`）。
> **你的 `max_element(begin() + 0, end())` 天然没有这个坑**——所以这一点上你的写法反而更不容易错。

## 八、自查

<details><summary>Q1：为什么这题不能直接对每个人模拟一遍所有操作？</summary>

因为单次模拟是 `O(q)`，`n` 个人就是 `O(n·q)`。本题 `n ≤ 10^6`、`q ≤ 2×10^5` ⇒ 最多 **2×10^11** 次操作，必 TLE。
正确做法是把"全局补助"信息**压缩成几个数**（每个人的 `sub[p]` + 全局最大值），预处理 `O(n+q)` 后每人是 `O(1)`。
（暴力解只在"小数据对拍"时用——那时 `n,q ≤ 10`，`O(n·q)` 完全无所谓。）

</details>

<details><summary>Q2：为什么"最后一次修改之后"是关键，而不是"所有补助里的最大"？</summary>

因为 `1 p x` 会**抹掉** p 之前受到的一切补助。举个反例：某人先被抬到 15，再被单独改成 9，之后只来了补助 11 ⇒ 他的答案是 **11**，不是 15。
（如果题目的 `1 p x` 是"加上 x"而不是"改成 x"，结论会完全不同——**操作语义决定算法**。）

</details>

<details><summary>Q3：为什么"从没被改过的人"要单独用全局最大补助？</summary>

因为倒扫时 `sub[p]` 只在遇到 `1 p x` 时才被赋值；从没被改过的人 `sub[p]` 保持 0。若直接 `max(a[p], 0)`，当补助全是正数时就会漏掉补助（`0 0 0` 三个人遇到 `2 4` 应该变成 `4 4 4`，写成 `max(a,0)` 会输出 `0 0 0`）。
所以要么**初始化为全局最大补助**，要么像修正版那样用 `seen[]` 区分。

</details>

<details><summary>Q4：`t[i] = 0` 而 `timer1` 也是 0，这算不算"初始化对了"？</summary>

不算——**两个都是 0 只是让第一组比较是"相等"，而后面的分支链没有兜住"相等"**。正确的做法是让分支**覆盖所有情况**（`if / else if / else`），或者干脆改结构（像修正版那样只用一个 `seen` 标记）。
⭐ 通用自查法：**写完 if-else 链后，把每个变量的每个取值区间枚举一遍，看有没有落空的**。本题落空的人就直接"消失"在输出里。

</details>

<details><summary>Q5：`res = 1e9` 这个初值有问题吗？</summary>

本题没问题（余额上限是 `10^9`，`1e9` 恰好是这个上界），但它是**脆的**：如果数据里余额能到 `10^9` 以上，`min` 就永远不会被刷新，`timer1` 永远不更新 ⇒ 又走回"空输出"。
更稳的写法是 `res = LLONG_MAX`（或干脆用 `seen` 标记，不依赖初值）。⚠️ 另外 `ll res = 1e9` 里 `1e9` 是 **double 字面量**，宜写 `1000000000LL`。

</details>

<details><summary>Q6：这题的答案会用超过 int 吗？</summary>

不会。`2 x` 是把小于 x 的人**赋值成 x**（不是加 x），所以任何余额都不会超过 `max(初始值, 所有补助值)`，本题上限 `10^9` —— `int` 装得下，但用 `long long` 更稳（你原本就用 `ll`，对的）。

</details>
