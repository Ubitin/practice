# 组合数 C(n,k) 有没有现成函数？（四套模板 + 该选哪套）

> **触发点**：你问"有没有能实现组合数计算的函数"。
> **一句话结论**：**C++ 标准库没有**（`std::` 里没有 `comb`/`binomial`）。而且**组合数是指数级增长的**——`C(67,33) = 14226520737620288370` 已经超过 `long long` 上限，所以"用哪种实现"**取决于你要精确值还是模意义下的值**。
> 四套模板按**数据范围**选：n 小（≤60）→ 杨辉三角或递推式；n 大 + 模数是质数 → 阶乘+逆元；要精确大值 → 质因数分解 + 大数。

---

## 一、先把"边界"钉死：组合数增长有多快

实测（`test_\comb_probe.cpp`，精确值用质因数分解法算，与 Python `math.comb` 一致）：

| n | `C(n, n/2)` | 能不能装进 `long long`（上限 9223372036854775807） |
|---|---|---|
| 60 | 118264581564861424 | ✅ |
| 64 | 1832624140942590534 | ✅ |
| **66** | **7219428434016265740** | ✅（最后一个勉强装下的偶数 n） |
| **67** | **14226520737620288370** | ✘ **溢出** |
| 68 | 28453041475240576740 | ✘ |

⭐ **记住 `n ≤ 66` 这条线**：精确值用 `long long` 最多撑到 `n = 66`（`C(66,33)`）。再大就必须换模数法或高精度。

---

## 二、四套模板（按范围选）

### 模板 ① 杨辉三角（精确值，n ≤ 60 左右）

```cpp
// dp[i][j] = C(i,j)：O(n²) 时间、O(n²) 空间；适合"要很多个 C 值"
vector<vector<ll>> C(nmax + 1, vector<ll>(nmax + 1, 0));
for (ll i = 0; i <= nmax; ++i) {
    C[i][0] = 1;
    for (ll j = 1; j <= i; ++j) C[i][j] = C[i-1][j-1] + C[i-1][j];
}
// ⚠️ 只能加到不会溢出的规模；n 大一点就爆 long long（见上表）
// 也可以只保存一行滚动：C[j] += C[j-1]（从右往左更新）
```

### 模板 ② 递推式（单个精确值，`n ≤ 66`）

```cpp
ll C_iter(ll n, ll k) {
    if (k < 0 || k > n) return 0;
    k = min(k, n - k);                       // 用对称性减少循环次数
    ll r = 1;
    for (ll i = 1; i <= k; ++i) r = r * (n - k + i) / i;
    return r;                                 // ★ 必须"先乘后除"，且中途值不能溢出
}
// 实测：C(20,10)=184756、C(30,15)=155117520、C(50,25)=126410606437752 全对 ✅
// ⚠️ 写成 r = r / i * (n-k+i) 会因整数除法截断而出错
// ⚠️ 中途值约为最终值的 O(n) 倍，所以能撑到的 n 比"最终值不溢出"更小一点（保守取 n ≤ 60）
```

### 模板 ③ 阶乘 + 逆元（**模质数**，n 可达 10⁶~10⁷）

这是竞赛里最常用的：预处理 `O(n)`，查询 `O(1)`。

```cpp
ll pw(ll a, ll b, ll m) { a %= m; ll r = 1 % m; while (b) { if (b&1) r = r*a%m; a = a*a%m; b >>= 1; } return r; }

vector<ll> f(nmax + 1), inv_f(nmax + 1);
f[0] = 1;
for (ll i = 1; i <= nmax; ++i) f[i] = f[i-1] * i % MOD;
inv_f[nmax] = pw(f[nmax], MOD - 2, MOD);                  // 费马小定理，要求 MOD 是质数
for (ll i = nmax; i >= 1; --i) inv_f[i-1] = inv_f[i] * i % MOD;

auto C = [&](ll a, ll b) -> ll {
    if (b < 0 || b > a || a < 0) return 0;
    return f[a] * inv_f[b] % MOD * inv_f[a-b] % MOD;      // C = a! / (b!(a-b)!)
};
```

**实测**：
- `C(100,50) mod 1e9+7 = 538992043` ✅（与 Python 一致）
- `C(200,100) mod 1e9+7 = 407336795` ✅
- 与模板 ② 的精确值取模对照（`n ≤ 40`）**全部一致** ✅
- 速度：**100 万次查询 2 ms** ✅

**⚠️⚠️ 三个必须知道的限制**：

| 限制 | 说明 | 违反的后果 |
|---|---|---|
| **MOD 必须是质数** | 逆元用费马小定理 `a^(p-2)` | **实测反例**：MOD 换成合数 `1000000006`，`C(100,50) mod m` 得 **850984348**，真值是 **515719098** ⇒ 静默错 |
| **必须 `n < MOD`** | 否则 `n!` 里含 MOD 的因子，`f[n] ≡ 0`，逆元不存在 | 结果错（此时要用 **Lucas 定理**） |
| **`n!` 别溢出** | 全程 `% MOD`，`f[i-1]*i` 要先升 `long long`/`__int128` 再取模 | 大模数下溢出 |

**MOD 是合数怎么办？** 两条路：
1. **用 Lucas 定理**（MOD 为小质数时把 n、k 写成 MOD 进制逐位相乘）；MOD 是质数幂则用 **扩展 Lucas**；
2. **质因数分解法**（模板 ④，天然不依赖质数）。

### 模板 ④ 质因数分解 + 大数（**精确值**，n 可到几千）

思路：`C(n,k) = n! / (k!(n-k)!)`，分母的质因数指数在分子里**一定够减**（组合数是整数）。
⇒ 把 `n!`、`k!`、`(n-k)!` 都分解成质因数，**指数相减**，再把 `质数^指数` 乘起来（大数用十进制数组）。

```cpp
// 指数部分（核心，很短）
map<ll,int> e;
auto add = [&](ll x, int sgn){ for (ll p=2; p*p<=x; ++p) while (x%p==0){ e[p]+=sgn; x/=p; } if (x>1) e[x]+=sgn; };
for (ll i=1;i<=n;++i)   add(i, +1);      // n!
for (ll i=1;i<=k;++i)   add(i, -1);      // k!
for (ll i=1;i<=n-k;++i) add(i, -1);      // (n-k)!
// 然后把每个质数的幂乘进一个大数（十进制数组乘法）即可
```

**实测**：`C(50,25) = 126410606437752`（与 `C_iter` 一致 ✅）、`C(100,50) = 100891344545564193334812497256`（与 Python `math.comb` 一致 ✅）。

⚠️ 复杂度约 `O(n log n + 结果位数²)`，n 到几千没问题；n 到 10⁶ 就该改用模板 ③。

## 三、选型表（拿着这张表照抄就行）

| 你的情况 | 用哪个 | 复杂度 |
|---|---|---|
| 要**很多个**精确 C 值，`n ≤ 50` | **① 杨辉三角** | `O(n²)` |
| 要**单个**精确 C 值，`n ≤ 66` | **② 递推式** | `O(k)` |
| `n` 大（10⁵~10⁷）**且模数是质数** | **③ 阶乘+逆元** | 预处理 `O(n)`，查询 `O(1)` |
| `n` 大但**模数是合数** | ③ 改造（Lucas / 扩展 Lucas）或 ④ | 视情况 |
| 要**精确大值**（`n ≥ 67`） | **④ 质因数分解 + 大数** | `O(n log n)` + 大数乘法 |
| 只要算**几个**小 C 值 | 直接 `②`，别搞复杂 | `O(k)` |

## 四、⚠️ 组合数最常见的 5 个坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | **整数除法截断** | `r = r * (n-k+i) / i` ✔；`r = r / i * (n-k+i)` ✘（先除会截断） |
| 2 | **溢出** | 精确值 `n ≥ 67` 就爆 `long long`；模意义下 `f[i-1]*i` 也可能爆（大模数要 `__int128`） |
| 3 | **逆元法用错模数** | MOD 必须是质数（实测合数模给出错误结果）；且 `n` 必须 `< MOD` |
| 4 | **边界没判** | `k < 0`、`k > n` 都应返回 0；`C(n,0)=C(n,n)=1`；`C(0,0)=1` |
| 5 | **负模 / 减法负数** | 容斥时 `(a - b) % MOD` 要写成 `((a-b)%MOD+MOD)%MOD` |

## 五、自查

<details><summary>Q1：C++ 真的完全没有现成组合数函数吗？</summary>

标准库没有。`<cmath>` 里没有，`<numeric>` 里也没有（只有 `gcd`、`lcm`、`accumulate`、`iota` 这些）。
C++17 之后有 `std::beta`（连带的贝塔函数），理论上 `C(n,k) = 1/((n+1)·B(n-k+1,k+1))`，但它是**浮点**的，大数必丢精度 ⇒ 竞赛里不能用。
**结论：老老实实自己写，四套模板挑一套。**

</details>

<details><summary>Q2：为什么"精确值"只能撑到 C(66,33)？</summary>

因为组合数增长是**指数级**的：`C(n,n/2) ≈ 2ⁿ/√(πn/2)`。
`n=66` 时 `C(66,33) = 7219428434016265740 < 9.22e18`（`long long` 上限）；`n=67` 时 `14226520737620288370 > 9.22e18` ⇒ 溢出。
⇒ 所以**要精确大值就必须上高精度**（模板 ④）。

</details>

<details><summary>Q3：为什么阶乘+逆元要求模数是质数？</summary>

因为 `inv_f[n] = f[n]^(MOD-2)` 用的是**费马小定理**，它只在 MOD 为质数时成立。
MOD 是合数时，`f[n]` 甚至可能与 MOD 不互素（逆元根本不存在），这时算出来的数是**错的但不是崩溃**——最难查的一类错。
**实测**：MOD = `1000000006`（合数）时，`C(100,50) mod m` 得 850984348，真值 515719098 ⇒ 静默错。

</details>

<details><summary>Q4：如果 MOD 是合数，但又是常见的那种"随手取的"怎么办？</summary>

两条路：
1. 把 MOD 分解成质数幂的乘积，对每个质数幂用 **扩展 Lucas** 求 `C(n,k) mod p^q`，再用 **CRT**（中国剩余定理）合并；
2. 如果 n 不大（≤ 几千），直接用**模板 ④（质因数分解 + 大数）**算出精确值，最后对 MOD 取模 —— 这是最省事的做法，且天然不依赖质数。
⇒ 选型判据：**n 小就 ④，n 大才上 Lucas/扩展 Lucas**。

</details>

<details><summary>Q5：为什么模板 ④ 里"分母的质因数指数一定够减"？</summary>

因为 `C(n,k)` 是整数：`n!/(k!(n-k)!)` 的结果是整数 ⇒ 分母的每个质因数在分子里的指数不少于分母。
所以相减之后**不会出现负指数**（如果出现负指数，说明分解范围搞错了，比如少算了某个数的因子）。
⭐ 这也是一个**自检手段**：如果算完发现某个质数的指数是负数，说明程序有 bug。

</details>

<details><summary>Q6：`C(n,k)` 要给"很多组查询"时，哪种最快？</summary>

模板 ③（阶乘+逆元）：预处理 `O(n)`，之后**每次查询 O(1)**（三次乘法两次取模）。
实测 **100 万次查询只要 2 ms**。
⚠️ 前提：MOD 是质数且 `n < MOD`。
如果想省内存（n 到 10⁷ 时两个 vector 各 80 MB），可以只存 `f[]`，查询时现算逆元 —— 但那就退化成 `O(log MOD)` 每次查询了。

</details>
