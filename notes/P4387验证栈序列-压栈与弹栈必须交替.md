# P4387 验证栈序列 —— 压栈和弹栈必须【交替】做

> **触发点**：2026-09-29，你贴 [P4387 验证栈序列](https://www.luogu.com.cn/problem/P4387) 问"我的代码问题出在哪里"。
> **判定**：❌ **算法结构错了**。一句话：**压栈和弹栈必须在同一个循环里交替做**——压一个、然后"能弹就弹"；不能先扫一遍只压、最后再扫一遍只弹。
> **证据**：官方样例 **两道全过**（`Yes`/`No`），但全排列穷举 n=1..6 共 **533,417 组 → 错 76,142 组**（n=4 错 29.2%、n=5 错 22.5%、n=6 错 14.0%）。最小反例：`入栈 1 2 / 出栈 1 2`（正确 Yes，你输出 No）。

## 一、题目（30 秒版）

有 `q` 个询问，每个询问给：

- 一行 `n`；
- **入栈序列**：`n` 个整数；
- **出栈序列**：`n` 个整数。

问：能否通过对入栈序列做**若干次压栈/弹栈**，恰好得到这个出栈序列？每个询问输出 `Yes` / `No`。

**官方样例**：

```
输入                  输出
2                     Yes
5                     No
1 2 3 4 5
5 4 3 2 1
4
1 2 3 4
2 4 1 3
```

## 二、你的代码错在哪（结构层，不是笔误）

你的写法是**两段式**：

| 段 | 代码 | 干了什么 |
|---|---|---|
| 第一段 | 第 22–25 行的 `for` | 扫 `pu`：遇到 `pu[i] == po[j]` 的**不压栈、只 `j++`**；其余压栈 |
| 第二段 | 第 26–33 行的 `while` | 再拿栈顶去对 `po[j]`，对得上就弹 |

这里面藏着一个**错误假设**：

> ❌ "只要 `pu[i] == po[j]`，就说明这个元素是**压进去后立刻弹出来**的。"

——**这只在"栈是空的时候"成立！** 如果此刻栈里还压着别人，这个元素应该**压在栈顶**，而且它可能要到更后面才被弹出来。

因为你在相等时**既不压、也不弹**（只 `j++`），这个元素就从栈里"凭空消失"了；再加上两段式结构，**真正的弹栈全发生在第二段，而第二段已经不压任何东西了** ⇒ 顺序与结构彻底对不上。

### 最小反例（n=2）

| 入栈 | 出栈 | 正确 | 你的 |
|---|---|---|---|
| `1 2` | `1 2` | **Yes** | **No** ❌ |

**手推你的代码**：

| 步骤 | 栈 | 发生了什么 |
|---|---|---|
| `s.push(pu[0])` | {1} | 预压 pu[0] |
| i=0：`pu[0]=1 == po[0]=1` | {1} | `j < n-1`（0<1）⇒ `j=1`，**没压也没弹** |
| i=1：`pu[1]=2 == po[1]=2` | {1} | `j < n-1` 是 1<1 = false ⇒ `j` 停在 1 |
| `while (j=1 < 2)` | {1} | 栈顶 1 vs `po[1]=2` ⇒ 不等 ⇒ **No** ❌ |

（正确过程：压 1 → 弹 1 → 压 2 → 弹 2 ⇒ **Yes**）

### 另外两个小毛病

| # | 问题 | 后果 |
|---|---|---|
| 1 | 第 21 行 `s.push(pu[0]);` 和第 22 行 `for (i = 0; ...)` **重复处理了 `pu[0]`** | 当 `pu[0] != po[0]` 时，`pu[0]` 被压进栈**两次** |
| 2 | 第 24 行 `j < n - 1` | 最后一个元素永远推不进 `j`，只能丢给第二段收尾，逻辑更绕且更容易错 |

## 三、正解：一个循环，压一个、能弹就弹

```cpp
ll j = 0;
stack<ll> s;
for (ll i = 0; i < n; ++i) {
    s.push(pu[i]);                               // ① 先把这个元素压进去
    while (!s.empty() && s.top() == po[j]) {     // ② 只要栈顶就是"下一个该出的"，就弹
        s.pop();
        ++j;
    }
}
cout << (j == n ? "Yes\n" : "No\n");             // ③ 全部弹出去了，才算 Yes
```

**为什么这样就对**（一句话直觉）：

> 出栈序列的**下一个元素**，要么**还没进过栈**（那就继续压），要么**就在栈顶**（那就弹掉）——**没有第三种可能**。

所以每压一个元素，就把它引发的"栈顶连续命中"全部弹干净。整个模拟是 `O(n)`。

🍜 **类比**：一个只能从顶端取东西的储物箱。给你一张"取出顺序清单"——你只能一直往里放，或者从顶上拿；**每放一件，就看看要不要顺手把顶上那件拿走**（可能一次拿走好几件）。

## 五、四个注意点

| # | 注意 | 说明 |
|---|---|---|
| 1 | 内层必须是 **`while`，不是 `if`** | 一次压栈可能引发**连续多次**弹栈（见自查 ③） |
| 2 | **`!s.empty()` 必须写在 `s.top()` 前面** | `&&` 从左往右短路；`s.top()` 在空栈上是 **UB**，可能直接崩 |
| 3 | 判据 `j == n` 和 `s.empty()` 等价 | 因为每个元素进出各一次，`j == n` ⇒ 栈必然已空 |
| 4 | `pu[]` 必须存下来 | 输入先给 `pu` 再给 `po`，而处理 `pu` 时就要用到 `po` ⇒ 至少要存一个序列；另外 `maxn` 要保证 `≥ n + 1` |

## 六、自查

<details>
<summary>① 入栈 `1 2 3`、出栈 `3 1 2` → Yes 还是 No？为什么？</summary>

**No**。压 1、压 2、压 3 ⇒ 栈顶 3 = `po[0]` ⇒ 弹掉 3（`j=1`）。此时栈里剩 `1 2`，栈顶是 2，而 `po[1] = 1` ⇒ 不等，且没有更多元素可压 ⇒ 失败。
**直观理由**：3 出栈时，栈里还压着 1 和 2 ⇒ 3 之后出来的只能是 2，不可能是 1（这就是"栈序"的约束）。
</details>

<details>
<summary>② 内层 `while` 改成 `if` 会怎样？给个反例。</summary>

**反例：入栈 `1 2 3`、出栈 `3 2 1` → 正确 Yes，改成 `if` 后判 No。**
压 3 之后栈里是 `1 2 3`，`po[0]=3` 命中了，但 `if` 只弹一次（弹出 3），接着循环结束（没有更多元素可压）⇒ `j=1 < 3` ⇒ No。
用 `while` 就会连着弹 3、2、1 ⇒ `j=3` ⇒ Yes。
</details>

<details>
<summary>③ 入栈 `1 2 3`、出栈 `3 2 1`，压完第 3 个元素后要连着弹几次？</summary>

**3 次**（依次弹出 3、2、1）——这就是"内层必须 `while`"的直接原因。
</details>

---

## 七、一句话带走

> **压一个，就看一眼栈顶——能弹就一路弹到不能弹为止。**
> 出栈序列的下一个数，只有两种可能：**还在外面（继续压）** 或 **就在栈顶（弹掉）**。
