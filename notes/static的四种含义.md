# static 的四种含义 —— 写在哪里，就是哪个意思

> 触发点：`test_\01_isbn_fixed.cpp` 里我写了 `static bool extract(...)`，这个 `static` 是什么意思？
> 结论：**`static` 的含义完全取决于它写在哪里**——它不是一个"功能"，而是复用了同一个关键字的四种不同语义。
> 本文全部结论都有 g++ 实测支撑。

---

## 〇、速查表：位置 → 含义

| 写在哪里 | 含义 | 典型用途 |
|---|---|---|
| **文件作用域的函数/全局变量前** | **内部链接**：只有本 `.cpp` 文件能看见 | 本文件私有的辅助函数（我代码里的用法）、避免多文件重名 |
| **函数内部的局部变量前** | **静态存储期**：只初始化一次，函数退出也不销毁 | 计数器、记忆化/缓存、单例 |
| **类的成员变量/成员函数前** | **属于类而不属于对象**：全类共享一份 | 全局配置、对象计数；`static` 成员函数没有 `this` |
| （C++17）类内 `static inline` 变量 | 允许直接在类内定义静态成员 | 省去类外定义 |

下面逐个说，重点是第一种（你问的那个）。

---

## 一、我代码里的用法：内部链接（本文件私有）

```cpp
static bool extract(const string& s, string& d){ ... }   // 只有这个 .cpp 能调用它
```

不加 `static` 的普通函数是**外部链接**：符号会进入链接表，别的 `.cpp` 也能通过声明调用它。
加了 `static` 就是**内部链接**：这个函数的符号对外不可见，**每个 .cpp 文件可以有同名函数而互不冲突**。

### 实测对比（g++）

**① 不加 static**：`a.cpp` 和 `b.cpp` 都定义 `int helper()` → 链接失败：

```
ld.exe: b.cpp:(.text+0x0): multiple definition of `helper()';
        a.cpp:(.text+0x0): first defined here
collect2.exe: error: ld returned 1 exit status
```

**② 都加 static**：同样两个同名函数 → **编译链接通过**，各用各的：

```
static 版本跑通: 1
（另附警告：warning: 'int helper()' defined but not used —— 因为它是本文件私有的，编译器知道外部用不到，甚至可直接丢弃）
```

### 那单文件 OJ 提交时写它有什么用？

单文件程序里**功能上没有区别**，它的价值是：

1. **防御性**：将来把多个 `.cpp` 一起编译（或把两份代码贴进同一个工程）不会撞名；
2. **表达意图**："这几个是本文件的内部辅助函数，不对外提供"；
3. **利于优化**：编译器知道它不被外部引用，可以更激进地内联/删除。

> 现代 C++ 更推荐用**匿名命名空间**达到同样效果（同样是内部链接）：
> ```cpp
> namespace {
>     bool extract(const string& s, string& d){ ... }
> }
> ```

## 二、static 局部变量：只初始化一次，退出不销毁

```cpp
void f(){ int c = 0; ++c; }              // 每次调用都是新的 c
void g(){ static int c = 0; ++c; }       // c 只初始化一次，值跨调用保留
```

**实测输出**（连续调用 3 次）：

```
无 static: 1        有 static: 1
无 static: 1        有 static: 2
无 static: 1        有 static: 3
```

要点：
- 初始化**只在第一次执行到这条语句时**发生（C++11 起还是线程安全的）；
- 生命周期是**整个程序**，存放在**全局/静态区**（不是栈）——所以函数返回后它依然活着；
- 常见用途：计数（`static int cnt`）、记忆化、单例的懒初始化；
- 坑：**多组测试数据时不会自动清零**（下一组用例会继承上一组的值）；递归里它是所有递归层**共享**的一份。

---

## 三、static 类成员：属于类，不属于对象

```cpp
struct Counter {
    static int total;              // 类内声明：所有对象共享同一份
    static int get(){ return total; }   // 静态成员函数：没有 this 指针
};
int Counter::total = 0;            // C++17 之前要在类外定义一次
```

- 所有对象共享一份，`Counter::total` 直接按类名访问；
- `static` 成员函数**没有 `this`**，因此不能访问非静态成员/非静态函数；
- C++17 起可写 `static inline int total = 0;` 直接在类内定义。

---

## 四、和相近概念对照

| 写法 | 链接性 | 可见范围 |
|---|---|---|
| `int f(){}`（函数默认） | 外部链接 | 全程序，可被别的 .cpp 调用 |
| `static int f(){}` | **内部链接** | 仅本 .cpp |
| `namespace { int f(){} }` | 内部链接 | 仅本 .cpp（C++ 推荐替代写法） |
| `extern int g;` | 外部链接声明 | 引用别处定义的变量 |
| 函数内 `static int c;` | 局部静态 | 只有该函数内部，但生命周期全程序 |
| 类内 `static int t;` | 类成员 | 通过 `类名::t` 全程序访问（视访问控制） |

## 五、自查

1. 两个 `.cpp` 各写一个同名普通函数会怎样？加 `static` 呢？
2. `static int c = 0;` 写在函数里，连续调用 3 次，输出是什么？为什么不重置？
3. 为什么静态成员函数里不能直接用非静态成员变量？
4. 单文件提交的 OJ 程序，给辅助函数加 `static` 有什么实际好处？

答案：1. 都会进全局符号表 → **链接错误 multiple definition**；加 `static` 后各自私有，不冲突。2. `1 2 3`；因为它只在第一次执行到时初始化，存储期是整个程序（全局/静态区），不会随函数退出销毁。3. 静态成员函数没有 `this` 指针，无法确定要访问哪个对象的那份成员。4. 功能上无差别，但表达"文件内部辅助函数"的意图，避免将来多文件/贴代码时撞名，并让编译器更容易优化。
