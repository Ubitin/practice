# 整数除零导致 RE —— P2440 木材加工排错

> 触发点：P2440 提交后 RE。代码在 `test_\01.cpp`。
> 一句话：**二分下界写成了 `l = 0`，搜索过程中 `mid` 会取到 0**，于是判定函数里执行 `len[i] / 0` → **整数除零 → 崩溃**。
> 实测：`n=1, k=2, len={3}`（答案应为 1）→ 退出码 **-1073741676 = 0xC0000094 = STATUS_INTEGER_DIVIDE_BY_ZERO**；而题面样例（答案 114）**不崩**。
> 演示程序：`test_\01_p2440_check.cpp`；修正版：`test_\01_p2440_fixed.cpp`（**原文件 `test_\01.cpp` 保持原样未改动**）。

---

## 一、症状：样例能过，"答案=1"的数据全崩

| 输入 | 期望 | 原码实测 |
|---|---|---|
| `3 7` / `232 124 456`（题面样例，答案 **114**） | 114 | `114` ✅ |
| `1 2` / `3`（答案 **1**） | 1 | **崩溃**，退出码 `-1073741676` |
| `2 3` / `5 1`（答案 **1**） | 1 | **崩溃**，退出码 `-1073741676` |
| `1 100` / `3`（无解） | 0 | `0` ✅ |
| `1 3` / `3`（sum==k） | 1 | `1` ✅ |

`-1073741676 = 0xC0000094` 正是 **STATUS_INTEGER_DIVIDE_BY_ZERO（整数除零）**。

> 规律：**答案 = 1 的数据几乎必然崩**，答案较大的数据反而正常。这一类"只在某个特定答案区间出问题"的 RE，最有价值的信息就是**退出码**——它直接告诉你崩溃类型。

## 二、完整崩溃轨迹（实测）

把原码的 `find()` 复刻出来并记录每一步：

```
搜索从 l=0, r=1e9 开始，共走了 29 步：
  ...（前面 23 步省略）
  第 24 步: l=0  r=117  mid=58   p=0
  第 25 步: l=0  r=57   mid=28   p=0
  第 26 步: l=0  r=27   mid=13   p=0
  第 27 步: l=0  r=12   mid=6    p=0
  第 28 步: l=0  r=5    mid=2    p=0      ← p(2) 为假（答案就是 1）
  第 29 步: l=0  r=1    mid=0    ← 即将执行 len[i] / 0 【崩溃】
```

**`l` 从头到尾都是 0**（因为 `p(mid)` 一路为假，走的全是 `r = mid - 1` 分支）。当 `r` 缩到 1 时，`mid = (0 + 1) >> 1 = 0`，下一步就是 `len[i] / 0`。

## 三、为什么"答案 = 1"必然踩到

`l` 恒为 0 时，`r` 每轮变成 `(r >> 1) - 1`，是**确定的序列**：

```
1e9 → 62499998 → 3906248 → 244138 → 15256 → 951 → 57 → 5 → 1
```

**只要 `p(mid)` 一路为假，`r` 必然经过 5 或 4 这一带。** 此时：

- `r = 5` → `mid = 2`。若 `p(2)` 为假（说明答案就是 1）→ `r = 1`
- `r = 4` → `mid = 2`。同上 → `r = 1`
- 下一轮 `l = 0, r = 1` → `mid = 0` → **崩溃**

**实测统计**：随机数据里"答案 = 1"的 9392 组，**mid 取到 0 的也是 9392 组（100%）**。

### 那为什么题面样例不崩？

样例答案是 114（不是 1）。搜索到 `l=0, r=117` 时 `mid=58`，此时 `p(58)` 为**真** → 走 `ans = 58; l = 59` 分支，`l` 不再是 0，后面 `mid` 永远 ≥ 59，自然不会碰到 0。

**所以这不是"偶发"，而是"取决于答案落在哪个区间"** ——答案小（=1）就必崩，答案大就正常。

## 四、修法（两条都要）

### ① 二分下界从 1 开始

```cpp
long long lo = 1, hi = mx;     // ★ 下界是 1，绝不可能取到 0
```

**为什么能这么改**：题目要切的是"小段长度"，长度 0 没有意义；而且 `p(1) = Σlen[i]`，只要总长度够就能成立。答案要么 ≥ 1，要么就是 0（切不出来）——而"0"由 `ans` 的初值兜底，**不需要让 `mid` 去试 0**。

### ② `p()` 里对 `x <= 0` 兜底（双保险）

```cpp
bool ok(ll x) {
    if (x <= 0) return false;   // ★ x == 0 会整数除零
    ll res = 0;
    for (ll i = 0; i < n; ++i) {
        res += len[i] / x;
        if (res >= k) return true;   // 提前返回：省时间也防 res 溢出
    }
    return res >= k;
}
```

**① 是从根上避免，② 是防止以后改代码又踩回来。** 两条一起写才稳。

### 顺手把上界收紧

```cpp
ll hi = mx;                     // mx = max_element(len)，比 1e9 少跑几轮
```

## 七、通用经验：整数除法和取模前必须防 0

### 规则一：`/` 和 `%` 的右操作数，一律先判 0

```cpp
if (x == 0) return false;        // 或 return 0 / continue，按语义选
res += len[i] / x;
```

**整数除零不是"得到 inf"或"得到 0"，而是直接把进程干掉**（Windows `0xC0000094`，Linux `SIGFPE` / 退出码 136）。浮点除零才是 `inf`——**两者行为完全不同**：

| 运算 | 除以 0 的后果 |
|---|---|
| `整数 / 0` | **崩溃**（0xC0000094 / SIGFPE） |
| `浮点 / 0.0` | `inf` 或 `nan`，程序继续跑 |

### 规则二：二分答案的下界要按"答案的合法范围"设

下界写 0 只在"0 是合法的答案取值"时才合理。**如果 `check(0)` 本身没有意义（除以 0、取模 0、下标 0），就绝不能把 0 放进二分区间。**

> 更一般地说：**写二分之前先想清楚"`check` 在所有可能的 `mid` 上都定义良好吗"**。答案范围、边界语义、`check` 的定义域，这三件事必须对齐。

### 规则三：看到 RE 先看退出码

| 退出码 | 含义 | 常见原因 |
|---|---|---|
| `-1073741676` `0xC0000094` | **整数除零** | `/0`、`%0` ← 本次 |
| `-1073741819` `0xC0000005` | 访问违规 | 空指针、越界读写 |
| `-1073741571` `0xC00000FD` | 栈溢出 | 递归太深、函数内开大数组 |
| Linux `136` | SIGFPE | 整数除零 |
| Linux `139` / `134` | SIGSEGV / SIGABRT | 段错误 / `assert` 失败 |

## 八、自查

1. 原码的 `mid` 为什么能取到 0？把 `l` 一路为假的收缩过程写出来。
2. 为什么"答案 = 1"的数据几乎必然崩，而答案 114 的样例不崩？
3. `整数 / 0` 和 `浮点 / 0.0` 的结果分别是什么？
4. 修法为什么用 `lo = 1` 是安全的？答案 0 由谁兜底？
5. 写二分答案前，关于 `check` 函数应该先想清楚哪件事？

**答案要点**
1. 因为 `l` 初始为 0，而 `p(mid)` 一路为假时走的都是 `r = mid - 1`，`l` 始终不变。`r` 按 `(r>>1)-1` 收缩到 5 或 4 时 `mid=2`，若仍为假则 `r=1`，下一轮 `mid = (0+1)>>1 = 0`。
2. 答案 = 1 意味着 `p(2)` 为假，搜索路径必然让 `r` 缩到 1 → `mid=0`（实测 9392/9392 = 100%）。而样例答案 114 时，早早就出现 `p(mid)` 为真、`l = mid+1` 离开 0，后面 `mid` 再也回不到 0。
3. 整数除零直接**崩溃**（Windows `0xC0000094`，Linux `SIGFPE`）；浮点除零得到 `inf` 或 `nan`，程序继续执行。
4. 因为题目要切"小段长度"，长度为 0 无意义，而 `p(1) = Σlen[i]`；答案要么 ≥1，要么就是"切不出来"这一种情况。后者由 `ans` 的初值 0 兜底，不需要让 `mid` 去试 0。
5. 要想清楚 **`check(mid)` 在二分区间内所有可能的 `mid` 上都定义良好吗**——尤其是有没有除零、取模、数组下标为 0 之类的边界。答案范围、边界语义、`check` 的定义域三者必须对齐。
