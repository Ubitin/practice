# P2895 流星雨 · 为什么"思路一致"却是 WA：memset 按字节填 + 答案初值给反

> **触发点**：你说"思路基本一致，但是问题出在哪里"。我把 `test_\01.cpp` 和教材代码逐行比过——**思路确实一模一样**：BFS 骨架、方向数组、`t+1 >= b[nx][ny]` 的严格判据、入队即标记，**全对**。问题只出在两行"初始化"上。
> **一句话结论**：`memset` 是按**字节**填同一个值，用它给 `long long` 赋 1002 得到 `0xEAEAEAEAEAEAEAEA` = **-1519143629599610134**（负数！），于是"还没被砸的格子"变成"负数时刻就该被砸"，**BFS 连一步都走不出去**；而 `ll ans = 0` 求最小值，`min(0, 任何非负数)` 恒为 0，判无解又拿 `ans == 1002` 去比。两处合力 ⇒ **你的程序对任何输入都输出 0**。

## 三、Bug 1：`memset` 是按字节填，不是按元素填

```cpp
memset(ti, -1, sizeof(ti));     // ✔ 对的
memset(b, 1002, sizeof(b));     // ✘ 这一行是元凶（b 是 long long[310][310]）
```

`memset(p, v, n)` 的语义是：**把从 p 开始的 n 个字节，每个字节都写成 `(unsigned char)v`**。它不认识你的元素类型。

| 调用 | 每字节被填成 | 8 个字节拼起来（long long） | 结果 |
|---|---|---|---|
| `memset(p, 0, n)` | `0x00` | `0x0000000000000000` | 0 ✔ |
| `memset(p, -1, n)` | `0xFF` | `0xFFFFFFFFFFFFFFFF` | -1 ✔（所以 `ti` 没事）|
| `memset(p, 0x3f, n)` | `0x3F` | `0x3F3F3F3F3F3F3F3F` | 4557430888798830399 ✔（可当 INF）|
| `memset(p, 1002, n)` | **`0xEA`** = 1002&0xFF | `0xEAEAEAEAEAEAEAEA` | **-1519143629599610134** ✘ |

`test_\memset_ll_demo.cpp` 的真实输出：

```
long long b[0][0] = -1519143629599610134
  b[0][0] == 1002 ? 否
  b[0][0] > 0      ? 否
  min(5, b[0][0])  = -1519143629599610134  <- 我想记录陨石时刻 5
  (0+1) >= b[0][1] ? 是  <- 会被当成"已经炸了"
int       c[0][0] = -353703190
  c[0][0] == 1002 ? 否
memset(d,-1) -> d[0][0] = -1  (正确)
```

**三重连锁反应**（这才是为什么"看着像算法全错"）：

1. `b[x][y] = min(t, b[x][y])` = `min(2, -1.5e18)` = **-1.5e18** ⇒ **陨石时刻根本没记进去**，`b` 里全是负数。
2. BFS 判据 `(t+1) >= b[nx][ny]` ⇒ `1 >= -1.5e18` **恒真** ⇒ 每个方向都 `continue` ⇒ **一步走不出去**。
3. 收尾判据 `b[i][j] == 1002` ⇒ **永假** ⇒ 一个安全格都统计不到。

正确写法（四选一）：

```cpp
const ll INF = (ll)1e18;

// ① 双循环：最直白
for (ll i = 0; i < 310; ++i)
    for (ll j = 0; j < 310; ++j) b[i][j] = INF;

// ② fill 摊平：二维数组内存连续，可以当一维用
fill(&b[0][0], &b[0][0] + 310 * 310, INF);

// ③ 把 b 定义成 int，就可以用 memset 0x3f（每个 int 正好 4 个字节，整字节重复）
int b[310][310];
memset(b, 0x3f, sizeof(b));      // 0x3f3f3f3f = 1061109567，远大于 t ≤ 1000

// ④ 用"题面上限 + 1"当哨兵（本题 t ≤ 1000，所以 1001/1002 够用）——同样要循环赋值
```

> ⚠️ **口诀：只有 0、-1、0x3f、0x7f 这种"每个字节都一样"的值能用 memset 填；其它数值一律循环或 fill。**
> ⚠️ "没被砸"的判据请写**区间** `b[i][j] > 1000`，不要写 `b[i][j] == 1002`——哨兵值哪天改成 1e9 或 INT_MAX，等号判断就又断了（教材写的就是 `death[i][j] > 1000`）。
> ⚠️ 元素是 `string`/`vector` 时绝不 memset（会破坏内部指针）。
> 手册已同步：**§2.6** 新增"第二个翻车点"实测段。

## 四、Bug 2：求最小值，`ans` 却从 0 开始

```cpp
ll ans = 0;                       // ← 求 min 却给了"最小可能值"
for (...) if (b[i][j] == 1002 && ti[i][j] != -1)
        ans = min(ans, ti[i][j]); // ti ≥ 0 ⇒ min(0, x) 永远是 0
if (ans == 1002) cout << -1;      // ← 判无解的哨兵和初值对不上，永不成立
else cout << ans;
```

实测：300 组随机数据里 **输出 0 的有 300 组（100%）**；样本期望 5、它输出 0。第 3 个 bug 是前两个的"合谋"：`ans` 恒为 0，`-1` 分支永远走不到。

**"最值三件套"必须成对**（初值 / 更新 / 判无解）：

| 目标 | 初值 | 更新 | 判"没更新过/无解" |
|---|---|---|---|
| 最小值 | `INF`（很大）| `ans = min(ans, x)` | `ans == INF` |
| 最大值 | `-INF`（很小）| `ans = max(ans, x)` | `ans == -INF` |
| 计数 | 0 | `++ans` | —— |

这与之前 `P1873` 那道题的 `int ans, mid` **未初始化**是同一族病：一个是**没给初值**、一个是**给反了初值**，共同点都是"样例能过（或恰好输出 0 看着不刺眼）、评测全错"。
手册已同步：**§6.6** 新增 ④ 三件套。

## 五、三处"看着像 bug、其实你写对了"

| 位置 | 你的写法 | 判定 |
|---|---|---|
| 能否站上去 | `(t+1) >= b[nx][ny]` → continue | ✔ 必须**严格早于**摧毁时刻。写成 `>` 就允许 `t+1 == b` —— "站在正在被砸的格子上" |
| 是否来过 | `ti[nx][ny] != -1`，在**入队时**判 | ✔ 入队即标记，队列不会暴涨（BFS 头号 bug 你没犯）|
| 陨石落点判负 | 落点没判负、邻居判了 | ✔ 题面保证 0 ≤ Xi,Yi ≤ 300，落点不必判；邻居**必须**判（教材的 `MIN` 宏就是干这个）|
| 数组上界 | 只判 `nx < 0 \|\| ny < 0` | ⚠️ 隐患：BFS 能一路铺到 x=309，下一次就会去读写 `b[310][ny]`（越界）。教材同样漏了。建议补 `nx >= 310 \|\| ny >= 310` |
| 安全格判据 | `b[i][j] == 1002` | ⚠️ 改成 `> 1000`（见 §三）|
| 循环变量 | 外层 `for(ll i…)` 里又嵌 `for(ll i…)` | ⚠️ `-Wshadow` 会点出来（实测原文 `declaration of 'i' shadows a previous local`）。本题**无害**（内层作用域独立、外层 `i` 不受影响），但 **P1824 那次 RE 就是变量遮蔽造成的**，别养成习惯 |

> **编译器不会救这两处**（实测）：`-Wall -Wextra` 对 `memset` 填错值和 `ans` 初值给反**一声不吭**（你的原码零警告）；加上 `-Wshadow` 也只抓到那个**无害**的 `i` 遮蔽。换句话说——**这类 bug 编译器、样例、肉眼全都放行，只有"自己对一遍初始化"和"对拍"能抓**。

### 教材也没管的一处边界：起点在 0 时刻就被砸

```
2
1 0 0      ← 陨石 0 时刻砸 (1,0)，顺手把 (0,0) 也摧毁了
5 5 100
```

| 程序 | 输出 |
|---|---|
| 教材原码 | 1 |
| 修正版（默认跟教材一致）| 1 |
| 独立参考解（教材口径：无条件从起点出发）| 1 |
| 独立参考解（严格口径：起点 t=0 就被砸 = 人还没迈步就没了）| **-1** |

**这是一个真实的模型分歧，不是代码笔误**：严格说，人 0 时刻站位的那格 0 时刻被摧毁 ⇒ 直接 -1；教材口径会让她 1 时刻走到旁边那格得 1。
我把严格判据做成了开关（`#define STRICT_START 0/1`），**默认关**——因为教材代码是能在评测上 AC 的，判题口径按教材走最稳。

## 七、修正版代码（`test_\01_p2895_fixed.cpp`，结构与你原码一致）

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

const ll INF = (ll)1e18;         // ★1 真正的"无穷大"

ll m = 0;
ll rm[4][2] = {{1,0},{0,1},{-1,0},{0,-1}};
ll b[310][310];      // 每个格子被摧毁的时间
ll ti[310][310];     // 走到每个格子的最早时间，-1 = 不可达

struct dot { ll x, y; };

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    memset(ti, -1, sizeof(ti));          // -1 整字节重复，合法
    for (ll i = 0; i < 310; ++i)         // ★2 不能用 memset(b,1002,sizeof(b))
        for (ll j = 0; j < 310; ++j) b[i][j] = INF;

    cin >> m;
    for (ll k = 0; k < m; ++k) {
        ll x, y, t; cin >> x >> y >> t;
        if (x >= 0 && y >= 0) b[x][y] = min(t, b[x][y]);   // ★3 落点也判负（防御式）
        for (ll d = 0; d < 4; ++d) {
            ll xt = x + rm[d][0], yt = y + rm[d][1];
            if (xt >= 0 && yt >= 0) b[xt][yt] = min(t, b[xt][yt]);
        }
    }

#define STRICT_START 0    // ★4 想严格处理"起点 0 时刻被砸"就改成 1（见 §五）
#if STRICT_START
    if (b[0][0] == 0) { cout << -1; return 0; }
#endif

    queue<dot> q;
    q.push({0, 0});
    ti[0][0] = 0;
    while (!q.empty()) {
        dot u = q.front(); q.pop();
        ll ux = u.x, uy = u.y, t = ti[ux][uy];
        for (ll d = 0; d < 4; ++d) {
            ll nx = ux + rm[d][0], ny = uy + rm[d][1];
            if (nx < 0 || ny < 0 || nx >= 310 || ny >= 310) continue;  // ★5 上下界都判
            if (ti[nx][ny] != -1) continue;                            // 入队即标记
            if (t + 1 >= b[nx][ny]) continue;   // 严格早于摧毁时刻
            ti[nx][ny] = t + 1;
            q.push({nx, ny});
        }
    }

    ll ans = INF;                                   // ★6 求 min 的初值
    for (ll i = 0; i < 310; ++i)
        for (ll j = 0; j < 310; ++j)
            if (b[i][j] > 1000 && ti[i][j] != -1)   // ★7 区间判据
                ans = min(ans, ti[i][j]);

    if (ans == INF) cout << -1;                     // ★8 与初值成对
    else cout << ans;
    return 0;
}
```

<summary>答案</summary>

1. `16843009`（= `0x01010101`），不是 1。每个字节被填成 `0x01`。
2. `4557430888798830399`（= `0x3F3F3F3F3F3F3F3F`），可以当 INF：远大于题目时间上限，且"INF + 有限值"不会溢出 long long。
