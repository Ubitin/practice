# 后缀表达式求值 · 为什么"一行输出都没有"（退出码 0xC000001D）

> **触发点**：你问"`01.cpp` 为何没有输出"。
> **一句话结论**：**程序根本没跑到输出那一步 —— 它在处理第一个 `.` 时就崩了**（退出码 **`0xC000001D`**）。
> 根因是 **`string temp;` 写在 `for` 循环里面**：每轮循环都重新建一个空串，所以遇到 `.` 时 `temp` 是**空串**，
> `stoll(temp)` 抛 `std::invalid_argument` ⇒ **代码里没有 `try/catch`** ⇒ `std::terminate` ⇒ `abort` ⇒ **一行输出都没有**。

## 二、根因逐行拆解

```cpp
for(ll i = 0;i<lenth;++i){
    char c ; c = num[i];
    string temp;                                  // ★★★ 罪魁：每轮都新建 → 每轮都是空串
    if(c >= '0' && c <= '9') temp += c;           // 只把【当前这一个字符】加进去
    else if(c == '.') {
        s.push(stoll(temp));                      // 到这里 temp 是空的 → 抛异常 → 崩
        temp.clear();
    }
```

### 为什么 `temp` 一定是空的？

按你的语法（数字以 `.` 结尾），输入 `12.@` 的处理过程是：

| i | c | 动作 | 此刻 temp |
|---|---|---|---|
| 0 | `'1'` | `temp += '1'` → `"1"` | `"1"` |
| 1 | `'2'` | **`temp` 被重新构造为空串**，再加 `'2'` → `"2"` | `"2"` |
| 2 | `'.'` | **`temp` 又被重新构造为空串** ⇒ `stoll("")` | `""` ← **崩在这里** |

⇒ 两个后果：
1. **多位数必然出错**：即使不崩，`12.` 也只会得到 `2`（只有最后一位）而不是 `12`；
2. **`.` 处必然空串** ⇒ `stoll("")` 抛 `std::invalid_argument`。

### 为什么"没有输出"而不是打印错误？

`stoll` 遇到**无法转换**的串（空串、或全非数字）会**抛异常**。你的代码里**没有 try/catch**，
未捕获的异常 ⇒ `std::terminate()` ⇒ `abort()` ⇒ 进程直接死掉，**缓冲区里的输出也一起丢了**（屏幕上一片空白）。

⭐ 顺带解释：**"崩溃时输出丢失"**还和 `cout` 缓冲有关——如果崩之前有 `cout`，内容可能还在缓冲区里没刷出来。
⇒ 排查时**别只看有没有输出**，一定看**退出码**。

## 三、修正版（`test_\01_calc_fixed.cpp`，**你的 `01.cpp` 我没动**）

```cpp
stack<ll> s;
string temp;                     // ★ 关键 1：声明在循环【外面】，数字才能跨字符累加
for (size_t i = 0; i < num.size(); ++i) {
    char c = num[i];
    if (c >= '0' && c <= '9') {
        temp += c;
    } else if (c == '.') {
        if (!temp.empty()) {     // ★ 关键 2：防御，空串不进 stoll
            s.push(stoll(temp));
            temp.clear();
        }
    } else if (c=='+'||c=='-'||c=='*'||c=='/') {
        ll x = s.top(); s.pop(); // 先弹出的是【右】操作数
        ll y = s.top(); s.pop(); // 后弹出的是【左】操作数
        ll res = (c=='+') ? y+x : (c=='-') ? y-x : (c=='*') ? y*x : y/x;
        s.push(res);             // ★ 关键 3：减法/除法必须是 y ○ x，不是 x ○ y
    } else if (c == '@') {
        cout << s.top() << "\n"; // ★ 关键 4：加换行；输出后不退栈
    }
}
```

### 另外两处也一并改了

| # | 原写法 | 问题 |
|---|---|---|
| 1 | `s.push(0);` 在第 11 行 | **表达式求值不该预置 0**：它会让"操作数不够"的表达式静默算出错答案，而不是报错 |
| 2 | `cout<<s.top();`（没有换行） | 多半不影响判题，但输出多组时全粘在一起 ⇒ 加 `"\n"` |

| # | 经验 | 具体做法 |
|---|---|---|
| 1 | **"没有输出" 先看退出码，不要先怀疑逻辑** | `0xC000001D`（非法指令/fail-fast）、`0xC0000005`（访问违规）、`0xC00000FD`（栈溢出）、`0xC0000094`（整数除零）—— **每种都对应一类 bug**。判题机显示 RE 时同理 |
| 2 | **循环内定义的变量 = 每轮重置** | 需要"跨轮累积"的状态（数字串、计数、标记）**必须声明在循环外**。这是初学阶段最常见的一类 bug |

## 六、自查

<details><summary>Q1：为什么 `temp` 写在循环里会导致 `.` 处拿到空串？</summary>

C++ 里**块作用域变量的生命周期只限它所在的那一对大括号**。`for(...){ string temp; ... }` 每执行一轮循环体，
`temp` 都被**销毁再重新构造**（默认构造 = 空串）。
⇒ 输入 `12.@` 时：第 0 轮 temp="1"（轮末销毁）→ 第 1 轮 temp="" 再加 '2' 得 "2"（轮末销毁）→ 第 2 轮 temp="" 就遇到 '.'。
**修法**：把 `temp` 移到 `for` 外面，它就能跨轮活着。

</details>

<details><summary>Q2：退出码 `0xC000001D` 是什么？为什么不是常见的 `0xC0000005`？</summary>

`0xC000001D` 是 Windows 的 **STATUS_ILLEGAL_INSTRUCTION**（非法指令）。
它出现在**未捕获 C++ 异常触发 fail-fast** 时——运行库为了让进程"确定性地死掉"，会执行一条非法指令而不是普通崩溃。
⚠️ 所以**别把"没见过的退出码"当成没事**：`0xC0000005`（访问违规）、`0xC00000FD`（栈溢出）、`0xC0000094`（整数除零）、
`0xC000001D`（异常 fail-fast）、`0xC0000374`（堆损坏）都应该记进你的报错速查表。

</details>

<details><summary>Q3：为什么"崩之前的输出也会消失"？</summary>

`cout` 是**带缓冲**的：`cout << "x"` 通常只写进内存缓冲区，真正落到终端是在**换行、缓冲区满、或程序正常退出**时。
进程被 `abort()` 杀掉时，缓冲区**不会刷**⇒ 你之前打印的内容就丢了。
⇒ 两个对策：① 调试时用 `cerr`（无缓冲，立即输出）；② 在关键位置加 `cout << flush`，或干脆用 `printf`（行缓冲）。
（这也是为什么"崩溃排查"时**能打印出东西反而说明崩得更晚**。）

</details>

<details><summary>Q4：`s.push(0)` 这行到底有什么害处？</summary>

它让栈里**预先有一个 0**。后果是：当表达式里的操作数不够时（例如输入以运算符开头），程序**不会报错**，而是拿这个 0 参与运算
⇒ **静默算出错误答案**。例如输入 `.` 开头的表达式，会莫名其妙输出 0 而不提示格式错误。
⇒ 表达式求值的标准做法是**空栈开始**；如果你想要"健壮性"，应该在取 `top()` 前判 `s.size() >= 2`，而不是预置一个 0。

</details>

<details><summary>Q5：怎么快速定位"崩在哪一行"？</summary>

三个层次：
1. **看退出码**（最快）→ 判断是哪类崩溃；
2. **加打点**：在可疑位置 `cerr << "at i=" << i << endl;`（`cerr` 无缓冲，崩溃前的都能看到）；
3. **上调试器**：`g++ -g` 编译后用 `gdb` 跑，`bt` 看栈回溯（本机 w64devkit 带 gdb）。
⭐ 对本例，第 2 步马上就能看到"打点在 `stoll` 前停下、且 temp 是空"⇒ 一眼定位。
</details>

## 七、补记：你改成 `getchar + do/while` 之后"依旧没有输出"

> **触发点**：你重写为 `getchar()` + `do{...}while(c != '@')` 的版本，说"依旧没有输出"。
> **一句话结论**：**这次不是崩溃，是三个不同的 bug 叠在一起**——① `temp` 仍在循环里（数字全变 0）；② **没判 EOF ⇒ 死循环/崩**；③ 非法字符分支里**在 `switch` 外面弹栈**。

### 7.1 实测：三种失败模式（同一份代码）

| 输入 | 你的输出 | 退出码 | 病因 |
|---|---|---|---|
| `9.@` | **0**（应 9） | 0 | `temp` 循环内归零 ⇒ 只压入个位 |
| `12.@` | 0（应 12） | 0 | 同上（`'1'` 被下一轮的归零丢掉） |
| `5.3.+@` | 0（应 8） | 0 | 同上 |
| `5.3.-@` | 0（应 2） | 0 | 同上 |
| **`6.2./@`** | **空** | **0xC0000094 整数除零** | 压进去的全是 0 ⇒ `y / 0` |
| **输入结束（EOF）** | **空** | 0xC0000005 | **死循环 + 弹空栈** |
| `9.@` **带换行** | 0 | 0 | `'\n'` 掉进非法分支弹栈 |

⭐ 注意第一行：**`9.@` 其实输出的是 `0`，不是"没有输出"** ⇒ **"没有输出"只出现在 EOF / 除零两种情况**。这也说明"没有输出"这类描述**必须靠退出码和具体输入来定位**。

### 7.2 bug 1：`temp` 仍在循环**里面**

```cpp
do{
    c = getchar();
    ll temp = 0;                                    // ★ 每轮归零
    if(c >= '0' && c <= '9') temp = temp * 10 + c - '0';   // 只能装当前一个字符
    else if(c == '.') { s.push(temp); temp = 0; }          // 压进去的是 0
```
`12.@` 的过程：`'1'`→temp=1（轮末销毁）→ `'2'`→归零后=2 → `'.'`→归零后=**0**。
⇒ **修法：`ll temp = 0;` 移到 `do` 外面**（和上一版同一个错误，只是从 `string` 变成了 `ll`）。

### 7.3 bug 2（**这是"没有输出"的主因**）：没判 EOF，循环永不退出

```cpp
}while(c != '@');          // ★ 输入流结束时 getchar() 返回 EOF(-1)，永远不等于 '@'
```

- 从**管道/文件**读输入时，读完就返回 `EOF`；`EOF != '@'` ⇒ **继续循环**；
- 每轮 `c = EOF` 掉进 `else if(c != '@')` 分支（**EOF ≠ '@' 成立**）；
- 于是**永远循环**：要么死循环空转，要么把栈弹空后 `s.top()` 崩掉（实测 `0xC0000005`）。

⇒ **修法**：`while ((c = getchar()) != EOF && c != '@')`。

⚠️ **同族的坑**：判题机的输入**末尾可能有换行/空格**，`getchar` 会读到 `'\n'`，
若你的分支把所有"非数字非运算符"都当运算符处理，就会误动作。**必须显式忽略空白字符**。

### 7.4 bug 3：非法字符分支里，**弹栈写在 `switch` 外面**

```cpp
else if(c != '@') {
    ll x = s.top(); s.pop();        // ★ 这两行不在 switch 里面！
    ll y = s.top(); s.pop();
    switch (c) {
        case '+' : ...; break;
        case '-' : ...; break;
        ...
        default : break;            // 非法字符：什么都不做，但栈已经被弹了两次
    }
}
```
⇒ 读到任何**非运算符字符**（空格、换行、EOF、字母）都会**白弹两次栈** ⇒
栈弹空后 `s.top()` 对空栈 ⇒ `0xC0000005`。
**修法**：把 pop 放进 `switch` 内部，或先判断 `c` 是不是运算符再 pop。

### 7.5 另外：除法没判零 ⇒ `0xC0000094`

`case '/' : s.push(y / x);` 当 `x == 0` 时**整数除零 ⇒ 崩溃**（实测评测机显示 RE）。
⇒ 加一句 `if (x == 0) ...` 或用 `if (s.size() < 2) continue;` 之类的前置防御。

### 7.7 三条通用经验（这次比上次更值钱）

| # | 经验 |
|---|---|
| 1 | **"移到循环外"要检查每一处同类变量**：这次你把 `string temp` 改成了 `ll temp`，但**位置没动** ⇒ 同一个 bug 换了个类型又来一次。改 bug 时问一句「**这个变量需要跨轮活着吗？**」 |
| 2 | **读输入必须处理 EOF**：`getchar()/scanf()/cin` 都要判结束。`while(c != '@')` 这种"靠哨兵字符退出"的写法**必须加上 EOF 判断**，否则输入一结束就死循环 |
| 3 | **`switch` 之外的公共代码会对所有分支生效**：把 `pop` 写在 `switch` 前，意味着"非法字符"也会弹栈 ⇒ 必须在**进入分支前就校验字符**，或者把公共操作放进需要它的分支里 |
