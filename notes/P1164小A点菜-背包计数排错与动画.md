## 0. 一句话本质

**"恰好凑出 m 元的方案数"= 计数型 0/1 背包**：

```
dp[j] = 用"已经考虑过的那些菜"、恰好凑出 j 元的方案数
dp[0] = 1                                  // 什么都不点
每加一道价格 x 的菜: for (j = m; j >= x; --j) dp[j] += dp[j - x];
答案 = dp[m]
```

与手册 §5 的"求最大价值背包"只差三处：**初始化为 1（不是 0）、累加（不是取 max）、j 仍然倒序**。

## 1. 题面与样例

> n 道菜，第 i 道价格 a_i；口袋里有 m 元；**每道菜最多点一次**，求**恰好花完 m 元**的点法数。

```
输入            输出
4 4             3
1 1 2 2
```
3 种点法：`{1, 1, 2(第3道)}`、`{1, 1, 2(第4道)}`、`{2(第3道), 2(第4道)}`。

## 2. 原始代码的两处致命错误（实测：**样例都跑不完**）

```cpp
void fit(vector<int>a,int M){
    for(size_t i = a.size() - 1;i>=0;--i){        // ← ①
        if(a[i] <= M) a.erase(a.begin() + i,a.end());
    }
}
int count(vector<int>a,int M){
    if(M == 0) return 1;
    if(M < 0) return 0;
    if(a.size() == 0 || M > 0) return 0;          // ← ②
    ...
}
```

### 🔴 ① `size_t i >= 0` 恒为真 → 死循环

`size_t` 是**无符号**类型，`i >= 0` 永远成立：`i` 减到 0 后再 `--i` 会回绕成 `SIZE_MAX`（约 1.8×10¹⁹），循环永不退出，还会拿这个巨大下标访问 `a[i]`（越界 UB）。

**实测**：样例输入跑 5 秒仍未结束 ❌。GCC 其实会直接警告：

```
test_\01.cpp:5:34: warning: comparison of unsigned expression in '>= 0' is always true [-Wtype-limits]
test_\01.cpp:18:35: warning: comparison of unsigned expression in '>= 0' is always true [-Wtype-limits]
```

**修法**：逆序遍历用有符号下标 —— `for (int i = (int)a.size() - 1; i >= 0; --i)`（或改用迭代器/`std::reverse` 思路）。

> 顺带的经验：**编译时加 `-Wall -Wextra`**，这类"无符号恒真"会被当场点名；把警告当错误看，能省掉大量调试时间。

### 🔴 ② 第 13 行让整个递归变成死代码

```cpp
if(M == 0) return 1;                      // 已处理 M == 0
if(M < 0) return 0;                       // 已处理 M < 0
if(a.size() == 0 || M > 0) return 0;      // 走到这里 M 必然 > 0 → 无条件返回 0
```

前两行已经把 `M == 0`、`M < 0` 排除，所以第三行的 `M > 0` **恒成立** → 函数永远在这里返回 0，**下面枚举子集的循环一次都执行不到**。

**隔离实测**：只把两处 `size_t` 循环改成 `int`（其余原样），样例输出 **0**（期望 3）——说明这是与 ① **相互独立**的第二个 bug，光修死循环依然错。

## 3. 另外 4 个问题

| # | 问题 | 说明 |
|---|---|---|
| ③ | `fit(vector<int> a, ...)` **按值传参** | 函数内怎么改都影响不到 `main` 的 `a`，整个函数是**空操作**；而且 `erase(begin()+i, end())` 删的是"从 i 到末尾一整段"，不是单个元素（删一个应传 `begin()+i`） |
| ④ | **算法是指数级** | 枚举所有子集 + 每层拷贝 `vector` ≈ O(2ⁿ·n)；n ≤ 100 时 2¹⁰⁰ 绝无可能，逻辑全修对也必然 **TLE** |
| ⑤ | `count` 与 `std::count` **重名** | `using namespace std;` 下自找麻烦，改名如 `countWays` 更安全 |
| ⑥ | 输出没有换行 | `cout<<ans;` → 建议 `cout<<ans<<"\n";`（一般不影响判题，但更规范） |

## 4. 正解

```cpp
#include<bits/stdc++.h>
using namespace std;
int main(){
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m; cin >> n >> m;
    vector<int> dp(m + 1, 0);
    dp[0] = 1;                                  // 凑 0 元：什么都不点，1 种方案

    for (int i = 0; i < n; ++i) {
        int x; cin >> x;
        for (int j = m; j >= x; --j)            // ← 必须倒序
            dp[j] += dp[j - x];
    }
    cout << dp[m] << "\n";
}
```

**① `dp[0] = 1`**：凑 0 元只有"什么都不点"一种办法。若写 0，后面全部乘 0，整个 DP 报废。

**② `dp[j] += dp[j-x]`**：新增的方案 = "不点这道菜时能凑出 `j-x` 元"的那些方案，再点上这道菜。

**③ 必须倒序**（本题最容易错的一点）：倒序时 `dp[j-x]` **还没被本轮更新**，代表"没点这道菜"的世界；正序时它已被本轮改过，等于允许"同一道菜点两次、三次……"，退化成**完全背包**。

**实测对照**（样例 `4 4 / 1 1 2 2`）：

| 遍历顺序 | dp[4] | 结论 |
|---|---|---|
| `for (j = m; j >= x; --j)` 倒序 | **3** ✅ | 与枚举的 3 种点法一致 |
| `for (j = x; j <= m; ++j)` 正序 | **14** ❌ | 同一道菜被重复点出"假方案" |

**④ 买不起的菜要跳过**：若 `x > m`，内层循环 `j` 从 m 到 x 根本不执行（`m < x`），天然被跳过；写动画/模拟代码时别把这种情况的方向写反（我在 `figures/P1164-背包计数动画.html` 里就踩了一次，被随机对拍抓出来）。

**⑤ 复杂度**：O(n·m) ≤ 100 × 10000 = 10⁶，实测 **0.03 s**。

## 7. 常见追问

- **答案会不会溢出？** 这道题的判题数据里答案不会超过 `int`（主流 AC 写法就是 `int dp[10005]`），写 `int` 即可、`long long` 更保险。但如果自造"价格全是 1、m 取中等"的数据，方案数可以大到**连 `long long` 都爆**（我随机造数据时实测出现过负数 `-2170001219427477563`）——那是数据超出本题保证范围，不是代码问题。
- **完全背包（每种菜可点无限次）怎么写？** 把内层 `j` 改成**正序** `j = x → m`——正是上面那个"错误写法"，场景不同，正误互换。
- **求最大价值怎么改？** 初始化 `dp` 为 0（或 −∞）、转移改 `dp[j] = max(dp[j], dp[j-x] + v[i])`（手册 §5）。
- **能不能枚举子集 / 记忆化？** n ≤ 100 时枚举子集是 2¹⁰⁰；记忆化搜索可以（`dfs(i, rest)`），但递推版更短更快。

---

**一句话总结**：**`dp[0] = 1` + 每道菜倒序 `dp[j] += dp[j-x]`** 就是"恰好凑出 m 元的方案数"的全部；这道题的两个致命伤与 DP 无关——一个是 `size_t` 无符号回绕造成的死循环，一个是"提前 `return` 把后面的代码变成死代码"，**开 `-Wall -Wextra` 编译能当场抓到第一个**。
