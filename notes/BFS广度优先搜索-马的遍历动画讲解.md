## 一、BFS 和 DFS 的分工

| | DFS（深度优先） | **BFS（广度优先）** |
|---|---|---|
| 数据结构 | 栈（递归） | **队列（先入先出）** |
| 扩展顺序 | 一条路走到底，走不动才回头 | **先处理离起点近的，再处理远的** |
| 形象说法 | 一根筋往下钻 | **一圈一圈往外扩** |
| 擅长 | 求**所有方案**、判断连通性 | 求**最短步数 / 最少操作数** |
| 缺点 | 容易陷入"过深"的情况，半天找不到解 | 状态多时队列会很大，费空间 |

> ⚠️ **求最短路必须用 BFS**。DFS 先到达某个点，不代表走的是最短路——它可能绕了一大圈才第一次碰到目标。

## 二、BFS 的一般形式（教材原版）

```
Q.push(初始状态);              // 起点入队
while (!Q.empty()) {           // 队列不空
    State u = Q.front();       // 取出队首
    Q.pop();                   // 出队
    for (枚举 u 的所有可能状态 v) {   // 找到 u 的所有可达状态
        if (是合法的) {        // 需满足条件（未访问过、不在队列内…）
            Q.push(v);         // 入队（同时可能需要维护必要信息）
        }
    }
}
```

**三个动作**：**入队 → 取队首 → 枚举它能到的点**，循环到队列空为止。

## 三、例 14-4 的代码（教材原版 + 注释）

```cpp
int ans[maxn][maxn];                       // 记录答案，-1 = 未访问
int walk[8][2] = {{2,1},{1,2},{-1,2},{-2,1},
                  {-2,-1},{-1,-2},{1,-2},{2,-1}};   // 马的 8 个方向

ans[sx][sy] = 0;                           // 起点到自己是 0 步
coord s {sx, sy};  Q.push(s);              // 起点入队

while (!Q.empty()) {
    coord u = Q.front();  Q.pop();         // 取队首并出队
    for (int k = 0; k < 8; ++k) {
        int nx = u.x + walk[k][0], ny = u.y + walk[k][1];
        if (nx < 1 || nx > n || ny < 1 || ny > m) continue;   // 越界
        if (ans[nx][ny] != -1) continue;                      // 已访问（★ 关键）
        ans[nx][ny] = ans[u.x][u.y] + 1;                      // 首次访问 → 记步数
        coord t {nx, ny};  Q.push(t);                         // 入队
    }
}
```

`walk[8][2]` 这 8 组偏移**与教材完全一致**（校验脚本逐组核对过 ✓）。

## 四、⭐ 为什么"第一次到达"就是最短

这是 BFS 的灵魂，值得说透：

**队列是先入先出（FIFO）的。** 起点在队里时 `d = 0`；把它的邻居入队，它们的 `d = 1`；等所有 `d = 0` 和 `d = 1` 的都出队了，才轮到 `d = 2`……

于是**出队的顺序必然按 `d` 从小到大**（同层内部随意）。所以当某个点第一次被扩展到、被标记 `ans = d+1` 时：

> 前面所有 `d, d+1, ..., d` 层都已经处理完毕了。如果存在一条更短的路（步数 `< d+1`），那条路上的点会**更早**被处理，早就该碰到它了 —— 矛盾。
> **所以 `d+1` 一定是最短步数。**

**实测验证**（校验脚本）：在 50 组配置（5 种棋盘 × 2 种走法 × 5 个起点）上，**"出队顺序恒按 d 非降"**这个不变式全部成立，且每个点入队时记下的步数与独立算法算出的最短距离**逐格一致**。

### 而 DFS 没有这个性质

DFS 可能第一次走到目标时是用了一条很长的绕路。例如 4×4 棋盘上从 (1,1) 找 (1,2)：DFS 可能会先钻到 (2,3) → (4,4) → (4,2) → …，最后才第一次碰到 (1,2)，而实际最短只要 3 步。

## 五、队列里到底装什么

装的是「**已经发现了、但还没被扩展**」的点。

> **每个点只会入队一次**：入队的那一刻就立刻把 `ans[nx][ny]` 标成步数，后面再遇到它就被 `ans != -1` 挡住。

这一条很重要——**"入队即标记"**，而不是"出队时才标记"。如果等到出队才标记，同一个点可能被多个邻居重复入队，队列会爆炸（同一层里会重复一堆）。

| 配置 | 搜索帧数 | 入队点数 | 最远步数 | 各层点数 |
|---|---|---|---|---|
| **4×4 马（教材例14-4）** | **162** | 16 / 16 | 5 | 1, 2, 5, 4, 2, 2 |
| 6×6 马 | 362 | 36 / 36 | 4 | 1, 2, 9, 16, 8 |
| 8×8 马 | 642 | 64 / 64 | 6 | 1, 2, 9, 20, 21, 10, 1 |

**4×4 起点 (1,1) 的骑士距离表**（动画最终帧实测）：

```
0  3  2  5
3  4  1  2
2  1  4  3
5  2  3  2
```

> **BFS 的搜索动作数与「点个数的 × 方向数」同阶**——每个点只出队一次、只枚举一遍方向。这就是 BFS 复杂度 `O(n·m)` 的来源。
> 对比 DFS 的八皇后式搜索会指数爆炸；BFS 因为"每个点只处理一次"，复杂度是**线性的**。

## 九、坑清单

| # | 坑 | 后果 |
|---|---|---|
| 1 | **出队时才标记已访问** | 同一层里同一个点被多个邻居重复入队 → 队列暴涨（应"**入队即标记**"） |
| 2 | 忘了判边界 | 数组越界 → RE（实测退出码 `0xC0000005`） |
| 3 | 忘了判 `ans != -1` | 死循环（互相把对方反复入队） |
| 4 | 用 DFS 求最短路 | **答案偏大**——DFS 先到的不一定最短 |
| 5 | `ans` 初值用 0 而不是 -1 | 分不清"未访问"和"步数 0"（起点就是 0 步） |
| 6 | 起点没有设 `ans=0` 就入队 | 起点的步数变成未知值 |
| 7 | 队列用 `stack` 或 `vector` 当栈用 | 变成 DFS 了，正确性全丢 |
| 8 | 多组数据忘了清空队列与 `ans` | 上一组的数据污染下一组 |
| 9 | 以为 BFS 一定能求出"所有路径数" | BFS 求的是**最短距离**；求路径条数要在 BFS 时额外累加（且要注意同层计数顺序） |

> **第 1 条是 BFS 的头号 bug**，而且症状很隐蔽：程序不崩、小数据也对，只是在某些图上队列长度爆炸 → TLE 或 MLE。记住：**`ans` 赋值和 `Q.push` 必须紧挨着写**。

## 十、自查

1. DFS 和 BFS 分别用什么数据结构？各自擅长解决什么问题？
2. 为什么 BFS 保证"第一次到达某点时的步数就是最短步数"？请用队列的先入先出性质说明。
3. "入队即标记"和"出队才标记"有什么区别？后者会导致什么？
4. `ans` 为什么要初始化成 `-1` 而不是 `0`？
5. BFS 的复杂度为什么是 `O(n·m)`（点数 × 方向数）而不是指数级？
6. 教材图 14-8(a) 是 4 向扩散还是马的 8 向？和例 14-4 的代码一致吗？

**答案要点**
1. DFS 用**栈**（递归），擅长求**所有方案**、判断连通性、回溯搜索；BFS 用**队列**，擅长求**最短步数 / 最少操作数**。
2. 队列先入先出 ⇒ 出队顺序一定按步数 `d` 从小到大。所以某个点第一次被扩展到时，所有步数更小的层都已处理完毕，**不可能还有更短的路没走到它**，故 `d+1` 就是最短。
3. "入队即标记"是在 `Q.push` 的同时就设 `ans`；"出队才标记"会让同一层的多个邻居都把同一个点重新入队 → 队列里出现大量重复 → 时间/空间爆炸。必须入队即标记。
4. 因为 `-1` 表示"未访问"，而 `0` 是起点自己的步数。若用 `0` 当初值，就无法把"没访问过"和"步数为 0"区分开，起点会被反复入队。
5. 因为**每个点只会出队一次、只枚举一遍它的方向**，总操作数 = 点数 × 方向数 = `O(n·m)`。BFS 不像 DFS 那样会反复重走同一条路，所以不是指数级。
6. 是**4 向扩散**（曼哈顿距离 `0 1 2 3 / 1 2 3 4 / …`），与例 14-4 代码里的**马 8 向**不一致；两者共用同一套 BFS 骨架，只有"枚举可达点"那一步不同。

## 附录：动画的核心逻辑（与网页内嵌的完全一致）

```js
const WALK8 = [[2,1],[1,2],[-1,2],[-2,1],[-2,-1],[-1,-2],[1,-2],[2,-1]];  // 教材原版
const WALK4 = [[-1,0],[1,0],[0,-1],[0,1]];                                 // 4 向

function buildTrace(N, M, sx, sy, mode) {
  const WALK = mode === 4 ? WALK4 : WALK8;
  const dist = Array.from({length:N+1}, () => new Array(M+1).fill(-1));
  const queue = [];
  dist[sx][sy] = 0;                          // ★ 起点步数 0
  queue.push({x:sx, y:sy, d:0});
  for (let head = 0; head < queue.length; ++head) {
    const u = queue[head];                   // 取队首（head 往后走 = 出队）
    for (const [dx, dy] of WALK) {
      const nx = u.x + dx, ny = u.y + dy;
      if (nx < 1 || nx > N || ny < 1 || ny > M) continue;   // 越界
      if (dist[nx][ny] !== -1) continue;                     // 已访问
      dist[nx][ny] = u.d + 1;                                // ★ 入队即标记
      queue.push({x:nx, y:ny, d:u.d + 1});
    }
  }
  return { dist, enqueued: queue.length };
}
```
