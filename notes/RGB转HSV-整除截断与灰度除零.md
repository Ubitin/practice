# RGB → HSV：公式抄对了，但**三处实现 bug**（含一例 RE）

> **触发点**：你贴了这道 RGB→HSV 的题（样例 `0 215 0 → 120.0000,100.0000%,84.3137%`），让看代码。
> **一句话结论**：**思路和公式都抄对了**（max/min、S 的公式、H 的三档分岔、`H<0` 加 360 全在），但有三处实现 bug：
> ① **没归一化**——V 直接打印成 `21500.0000` 而不是 `84.3137%`；
> ② **两处整除截断**——`d`、`M` 是 `int`，`/` 全变成了整数除法；
> ③ **灰度时整数除零 → RE**——输入 `100 100 100` 直接崩（退出码 `0xC0000094`）。
> **实测对照**：你的原版 vs Python 标准库 `colorsys`：**322/322 全错**（含崩溃）；**修正版 3022/3022 全对** ✅。

---

## 一、题目模型（照题面抄三行）

1. 输入 **R、G、B 的字节值**（0~255）⇒ 先归一化到 $[0,1]$：`r /= 255.0`
2. `V = max`；`S = (max−min)/max`（**V=0 时 S=0**）；
   `H = 60 × { 0+(G−B)/d | 2+(B−R)/d | 4+(R−G)/d }`（**按 max 是 R / G / B 分三档**，`d = max−min`）；**`H<0` 则 `H += 360`**
3. 输出 `H,S%,V%`：**逗号间隔、保留 4 位小数**，其中 **H 不带百分号，S 和 V 带百分号**

---

## 二、逐处诊断（4 个问题，全部实测）

| # | 你写的 | 问题 | 实测证据 |
|---|---|---|---|
| ① | `v = M;`（M 是 int，0~255）| **漏了除以 255** | 样例 V 打印 **21500.0000**，应 **84.3137%** |
| ② | `int d = M - m;` 之后写 `s = d / M`、`(g-b)/d` | **整数除法截断** | `100 200 150` → S = **0%**（应 50%）、H = **120**（应 150）；`0 215 100` → H = **120**（应 **147.9070**）|
| ③ | H 分档里除以 `d`，但**没判 `d == 0`** | **整数除零 → RE** | 灰色 `100 100 100` → **退出码 -1073741676 = 0xC0000094**；`0 0 0`、`255 255 255` 同样崩 |
| ④ | `printf("...\%,...\%")` | `\%` **不是合法转义** | GCC 实测警告 `unknown conversion type character ','`、`spurious trailing '%'` ⇒ **V 后面那个 % 根本没打出来** |

## 三、修正版：就六处（`test_\hsv_fixed.cpp`）

```cpp
double r, g, b;
cin >> r >> g >> b;
r /= 255.0; g /= 255.0; b /= 255.0;          // ★1 归一化：除以 255（不是 256），且用 double 除

double M = max(max(r, g), max(g, b));
double m = min(min(r, g), min(g, b));
double d = M - m;                            // ★2 d 必须是 double！用 int 会让后面全变整除

double V = M;
double S = (M == 0.0) ? 0.0 : d / M;         // 题面：V=0 时 S=0（避免 0/0）
double H = 0.0;                              // ★3 灰度（d==0）时 H 无定义，约定取 0（与 colorsys 一致）

if (d != 0.0) {                              // ★4 不判就会整数除零 → RE
    if (M == r)      H = 60.0 * (0.0 + (g - b) / d);
    else if (M == g) H = 60.0 * (2.0 + (b - r) / d);
    else             H = 60.0 * (4.0 + (r - g) / d);   // M == B
    if (H < 0.0) H += 360.0;                 // ★5 题面明确要求
}
printf("%.4f,%.4f%%,%.4f%%\n", H, S * 100.0, V * 100.0);   // ★6 百分号写 %%；H 不带 %
```

## 五、值得记住的五点

| 点 | 说明 |
|---|---|
| **归一化用 255** | 215/255 = 0.843137… ⇒ **84.3137%** ✓ 与样例完全吻合，反推确认除数就是 **255**（用 256 会得 83.98% ✗）|
| **整数除法陷阱** | `int d = M - m;` 一旦 `d` 是 int，后面所有 `/d`、`d/M` 全变整除（小数部分直接丢掉）。**凡是参与浮点计算的量一律用 `double`**——这与讲义「四舍五入…负数会错一半」里 `long long u = x;` 是同一族病 |
| **灰度（d == 0）** | 题面没写，但**必须处理**：S = 0、H 约定取 **0**（`colorsys` 也返回 0）。不判 `d==0` 就是整数除零 RE |
| **输出格式** | 打印一个百分号要写 **`%%`**；`\%` 不是合法转义（GCC 会警告，且**会把后面的转换符吃掉**）。另外 **H 不带 %** |
| **输入截断** | 你写了 `r = lowByte(r);`——题目保证 0~255 所以无害；但若输入可能超范围，这种"悄悄截断"会让结果看起来对却错，不如显式判断范围 |

## 六、自查（先做完再翻答案）

1. V 为什么要除以 255 而不是 256？用样例反推说明。
2. `int d = M - m;` 会引起哪**两个**后果？各举一个实测反例。
3. 输入 `100 100 100` 为什么崩？退出码是多少？
4. 想在 `printf` 里打印一个百分号，要写什么？写 `\%` 会怎样？
5. 灰度输入（R=G=B≠0）时，S、H、V 分别该输出什么？

<details>
<summary>答案</summary>

1. 因为输入是**字节值**（0~255），归一化要除 255：215/255 = 0.843137… → **84.3137%**，与样例给的 `84.3137%` 完全吻合；若除 256 得 83.9843% ✗。
2. ① **S 被截成 0 或 1**：`100 200 150` 时 `d/M = 100/200 = 0` ⇒ S 输出 0%（应 50%）；② **H 的分式项被截成 0**：`0 215 100` 时 `(b−r)/d = 100/215 = 0` ⇒ H 输出 120（应 147.9070）。另外这还埋了 ③ 的除零雷。
3. 因为灰色时 `d = M − m = 0`，而 H 分档里有 `(g−b)/d` ⇒ **整数除零**，Windows 退出码 **-1073741676 = 0xC0000094**（Linux 是 SIGFPE 136）。
4. 写 **`%%`**。写 `\%` 不是合法转义：GCC 会警告 `unknown conversion type character`，实测**连后面那个转换符一起吃掉**，结果 V 后面的 `%` 没打印出来。
5. S = **0.0000%**，H = **0.0000**（题面未定义，约定取 0，与 Python `colorsys` 一致），V = M/255×100%（如 `100 100 100` → **39.2157%**）。
</details>
