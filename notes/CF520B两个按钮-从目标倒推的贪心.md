## 二、为什么"正着想"想不清楚（你的思路断在哪）

正向站在 `n` 上，每一步有两个选择：**×2** 还是 **−1**。

## 三、正解：把箭头反过来（这题的全部思想）

### 3.1 倒着走，规则自动出现

正向有两条路：`x → 2x`、`x → x−1`。
**把它反过来读**，就是"我现在在 m，上一步是从哪来的"：

| 正向（从 n 出发） | 倒推（从 m 回退） |
|---|---|
| `x → 2x` | `m → m / 2`（**仅当 m 是偶数**） |
| `x → x−1` | `m → m + 1`（永远可以） |

于是倒推的规则只有两条，**没有选择困难**：

| m 的情况 | 该做什么 | 代价 |
|---|---|---|
| **偶数** | **÷2** | 1 |
| **奇数** | **+1**（奇数除不了 2） | 1 |
| `m ≤ n` | **停**，剩下只能一路减：代价 `n − m` | `n − m` |

### 3.2 💭 为什么"偶数就一定 ÷2"（两步对比，够用了）

假设 `m` 是偶数，你偏不除，只能先 +1：

| 走法 | 过程 | 用了几步才到 `m/2` 附近 |
|---|---|---|
| **直接 ÷2** | `m → m/2` | **1 步** |
| 绕路 | `m → m+1`（变奇数！不能再除）→ 再 `+1` → `m+2` → `÷2` = `m/2 + 1` | **3 步** |

而"直接 ÷2 到 `m/2`，再 `+1` 到 `m/2+1`"只要 **2 步**。
⇒ 绕路永远更贵，**偶数时必须 ÷2**。

### 3.3 💭 为什么"奇数就一定 +1"

正向的 **×2 只能产出偶数**。所以任何时刻你要到达一个**奇数 m**，最后一步**不可能是 ×2**，只能是"从 `m+1` 减下来"。
倒推时这个"减一"就变成"加一"，**那 1 步代价省不掉**。

> 🍜 **生活化类比**：正向的"−1"一次只能挪一格，是**最贵的操作**；倒推时的"+1"代表的就是它。
> 所以倒推过程的目标是 —— **尽量少加 1，尽快用 ÷2 把数字收缩下去**。

## 五、骨架（只给关键几行，完整代码你自己敲）

```cpp
ll ans = 0;
if (m <= n) {
    ans = n - m;              // 只能一路减 1
} else {
    while (m > n) {
        if (m % 2) m++;       // 奇数 → +1 凑偶
        else       m /= 2;    // 偶数 → ÷2
        ans++;
    }
    ans += n - m;             // 退到 <= n 之后，剩下的全靠减 1

cout << ans << '\n';         // 别忘了换行
```

⚠️ **三个最容易写错的位置**：

| # | 位置 | 错了会怎样 |
|---|---|---|
| 1 | 必须先判 `m <= n` | 否则 `while (m > n)` 一次都不进，`ans += n − m` 变成**负数** |

| 3 | 循环**结束后**的 `ans += n - m` | 漏掉它，`m` 退到比 `n` 小的那些步数全丢了 |

### 9.1 正向 BFS 解法（保底解法，完整讲一遍）

**为什么 BFS 一定对**：BFS 就是"按步数从小到大一层层扩散"——第 0 层是 `n` 自己、第 1 层是"按 1 次能到的所有数"、第 2 层是"按 2 次能到的"……**第一次踩到 `m` 时，它所在的层号就是答案**。这和你做 P1443 马的遍历、CF377A 时用的是同一个道理：**边权都是 1 的最少步数问题，BFS 天生就对**，不需要额外证明。

**三句话把模型写出来**：

| 问题 | 答案 |
|---|---|
| 状态是什么？ | **当前的数字**（一个数就是一个点） |
| 边是什么？ | 按红键 → `u*2`；按蓝键 → `u−1`（每条边都算 1 步） |
| 起点 / 终点？ | 起点 `n`，终点 `m` |

**⭐ 唯一的坑：数组要开到 `2m`，不是 `m`**（正对应你第 ① 类坑"数组开小，而且不崩"）

因为 BFS 会走到**比 m 大的数**（例如 `1 → 10000` 的搜索过程中就会经过 10000 右边的一些数）。到底开多大才够？

> 💭 **证明"最优路上不会出现超过 2m 的数"**：
> 设某条最优路里出现过的最大数是 `V`，且 `V > 2m`。让它"变成 V"的最后一步是某次**乘法**（在 `w = V/2` 处按红键）；因为 `V` 已是最大值，**这之后它再也没乘过**，只能一路减到 `m`，代价 `V − m`。
> 但若**不按那次乘法**，直接从 `w` 一路减到 `m`，代价是 `w − m`，还**省掉了乘法那 1 步** —— 新路更短，与"最优"矛盾。
> ⇒ 最优路上必有 `V ≤ 2m`，**数组开到 `2m + 5` 一定够**（保险写法：`2*max(n,m)+5`）。

**骨架（关键 4 段）**：

```cpp
if (n >= m) { cout << n - m << '\n'; return 0; }   // 起点在右边：只能一路减
int LIM = 2 * m + 5;
vector<int> dist(LIM + 1, -1), q(LIM + 1);         // q 当手写队列用
int head = 0, tail = 0;
dist[n] = 0; q[tail++] = n;
while (head < tail) {
    int u = q[head++];
    if (u == m) break;                             // ★ 第一次到达就是最短
    int v[2] = {u * 2, u - 1};
    for (int k = 0; k < 2; ++k) {
        if (v[k] < 1 || v[k] > LIM || dist[v[k]] != -1) continue;
        dist[v[k]] = dist[u] + 1;                  // ★ 入队即标记
        q[tail++] = v[k];
    }
}
cout << dist[m] << '\n';
```

⚠️ 两个老坑（你在 P1443 / CF377A 已经踩过，这里再点一遍）：
1. **入队时就标记**，别等出队才标 —— 否则同一个数会被反复塞进队列，队列暴涨。
2. `v[k] < 1` 也要判（减到 `0` 或负数没有意义，等于走进了死路）。

**实测（✅ 可自己复现）**：

| 检查 | 结果 |
|---|---|
| BFS(`2m+5`) vs BFS(`4max+16`) vs 倒推贪心，`[1,300]²` 共 **90000** 组 | **不一致 0** ✅（同时说明"开到 2m 就够"不是猜的） |
| 随机 **20000** 组（`n,m ≤ 10⁴`） | **不一致 0** ✅ |
| 单次耗时（`n=1, m=10000`） | BFS **18.2 µs** vs 倒推贪心 **0.004 µs**（约 **4000 倍**；BFS 每次还要新建两个数组） |
| 数组内存 | `dist` + `q` ≈ **156 KB**（`2 × 20006 × 4` 字节） |
| BFS 访问规模（`1 → 10000`） | 访问 **13209** 个状态、队列峰值 **2819**、答案 20 步 |

⭐ **注意最后一行**：BFS 访问了 **13209** 个数，**比 m = 10000 还多** —— 因为它把"20 步以内能到的**所有**数"都翻了一遍（包含 m 右边的数）。这正好印证你 `DFS与BFS的常见误解辨析` 里那条结论：**BFS 也是穷举，只是按距离从小到大的顺序穷举**；"第一次到达即最短"省掉的只是"目标之后的层"，前面每一层一格都没少搜。

💭 **什么时候用 BFS，什么时候用倒推**：

| 情形 | 选择 |
|---|---|
| 你能给出倒推的证明（这题给得出） | **倒推贪心**：4 行、O(log m)、几乎不占内存 |
| 想不出贪心证明 / "上一步"不唯一 | **BFS 保底**：不需要任何聪明想法，只要能说出"状态 + 操作" |
| 操作换了（如按钮变成 `×3` 和 `−1`） | BFS 代码一个字不用改；倒推规则得重新推、重新证明 |
| `m` 很大（如 10⁹） | 只能倒推（BFS 要 O(m) 时间和内存） |

（以后再说、现在别碰）如果两个按钮**代价不一样**（比如红键 2 秒、蓝键 1 秒），BFS 就不够用了，那时要换成"带权最短路"。

</details>

<details>
<summary>④ 为什么 `m <= n` 时答案一定是 `n − m`？</summary>

因为**只有 −1 能让数字变小**，×2 只会更大。所以从 `n` 到更小的 `m`，只能老老实实减 `n − m` 次（×2 只会浪费步数）。
</details>

<details>
<summary>⑤ 能不能"一路除到 m == n"？为什么必须在第一次 `m ≤ n` 时停手？</summary>

不能。除到 `m < n` 之后，你唯一能做的只有 +1（正向的 −1），**越除离 n 越远**。
所以正确做法是：**第一次出现 `m ≤ n` 就停**，把还差的 `n − m` 用减法一次补齐。
（这也是为什么 `while (m > n)` 之后必须跟一句 `ans += n - m`。）
</details>

## 十一、一句话带走

> 正向是"**×2 和 −1**"，倒推就是"**÷2 和 +1**"；
> **偶数必 ÷2，奇数必 +1，退到 ≤ n 再加差**。
> 想不清楚的时候，**把箭头反过来**。
