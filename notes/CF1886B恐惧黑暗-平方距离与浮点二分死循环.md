# CF1886B Fear of the Dark · 你的程序「卡死」是死循环：平方距离 + 浮点二分的舍入陷阱

> **触发点**：你让我看 `test_\01.cpp` 哪里出问题。
> **结论**：**思路（二分答案 + 三段判定）完全正确，但有三处实现 bug**——其中一处会让程序**死循环**（在测评机上就是 **TLE**）：
> ① **第 14 行把「平方距离」拿去和 `w` 比**（量纲不一致）→ 答案被放大成平方量级；
> ② **第 26 行 `while(l <= r - del)` 用浮点减法判终止** → 阈值一大就**永远退不出循环**；
> ③ **第 42 行下界 `l = 0.1`** → 答案为 0 时永远找不到。
> 而且 ① 会把"二分的阈值"顶到几十万，恰好落进 ② 的雷区 —— **两个 bug 是互相咬合的**。

## 一、你的判定逻辑本身是对的

题目模型：$O=(0,0)$、起点 $P$、两盏灯在 $A,B$，照明半径 $w$。要求 $w$ 最小，使得 $O$ 与 $P$ 落在两个半径 $w$ 的**圆盘并集的同一个连通块**里。只有四种可能：

| 情况 | 需要的 $w$ |
|---|---|
| ① 一盏 A 同时罩住 $O$ 和 $P$ | $\max(|OA|,\ |PA|)$ |
| ② 一盏 B 同时罩住 $O$ 和 $P$ | $\max(|OB|,\ |PB|)$ |
| ③ $O$ 靠 A、$P$ 靠 B，两圆要相交 | $\max(|AB|/2,\ |OA|,\ |PB|)$ |
| ④ $O$ 靠 B、$P$ 靠 A | $\max(|AB|/2,\ |OB|,\ |PA|)$ |

你的 `p(w)` 三条判定（**至少一盏照到 O** ／ **至少一盏照到 P** ／ **不然两圆必须相交**）**正好覆盖这四种情况**，方向完全正确 ✔。问题全在实现细节。

## 二、Bug ①（答案错）：平方距离被当成距离用

```cpp
if((ax * ax + ay * ay) > (w + del) && (bx * bx + by * by) > (w + del)) return false;
//   ↑ 这是 |OA|²（平方距离），却拿它和半径 w 比 —— 量纲不一致
```

`ax*ax + ay*ay` 是**平方**。同一条判定里第 16 行用的是 `dis(...)`（真距离），**两行量纲打架**。

**实测**（输入 `1 / k 0 k 0 -k 0`，即 $P=A=(k,0)$、$B=(-k,0)$，正确答案就是 $k$）：

| k | $|OA|^2=k^2$ | 你的输出 | 正确答案 |
|---|---|---|---|
| 100 | 10000 | **10000** | 100 |
| 150 | 22500 | **22500** | 150 |
| 181 | 32761 | **32761** | 181 |
| 182 | 33124 | **卡死** | 182 |

> 答案直接被放大成 $k^2$ —— 例如 $k=100$ 时报 10000，误差 **100 倍**。

**修法**：统一用长度比较（或两边都平方）：

```cpp
if (dis(0,0,ax,ay) > (w + del) && dis(0,0,bx,by) > (w + del)) return false;
```

## 三、Bug ②（死循环 → TLE）：`while(l <= r - del)` 的浮点舍入陷阱

```cpp
while(l <= (r - del)){          // del = 1e-11
    if(p(mid = (l + r) / 2)){ ans = mid; r = mid; }
    else l = mid;
}
```

这个终止条件要求浮点减法 `r - del` **真的**比 `r` 小 `del`。可是在 double 里，一个数能分辨的最小间隔是 **ULP**（单位末位），量级越大 ULP 越大：

| 阈值量级 $x$ | 1 个 ULP | `del/ULP` | `x - del` 实际减掉 | 结果 |
|---|---|---|---|---|
| 22500 | 3.638e-12 | 2.75 | ≈3 ULP | ✅ 正常退出 |
| 32761 | 3.638e-12 | 2.75 | ≈3 ULP | ✅ 正常退出 |
| **33124** | **7.276e-12** | **1.37** | **只减掉 1 ULP** | ❌ **卡死** |
| 40000 | 7.276e-12 | 1.37 | 只减掉 1 ULP | ❌ 卡死 |
| 90000 | 1.455e-11 | 0.69 | 只减掉 1 ULP | ❌ 卡死 |

**死循环是怎么发生的**：当 `del` 只有 1 个 ULP 时，`r - del` 被舍入成 `r - 1ULP`，条件退化成"`l` 和 `r` 是否相邻"；而 `l`、`r` 相邻时 `mid = (l+r)/2` **只能舍入成 `l` 或 `r`** —— 若舍成 `l` 且 `p(l)` 为假，就执行 `l = mid = l`，**`l` 一步都不前进 → 无限循环**。

**实测边界极其干净**（输入 `1 / k 0 k 0 -k 0`）：

| k | $k^2$ | 与 $2^{15}=32768$ | 结果 |
|---|---|---|---|
| 181 | 32761 | 刚好在下面 | ✅ 输出 32761（错但能出来）|
| **182** | **33124** | 刚跨过去 | ❌ **卡死** |

**为什么正好卡在 32768**：$2^{15}$ 处 ULP 从 $3.64\times10^{-12}$ **翻倍**到 $7.28\times10^{-12}$，`del=1e-11` 与它的比值从 2.75 掉到 1.37 → 越过"能不能真的减掉 del"的临界点。

> ⚠️ 而 **Bug ① 把阈值顶到了 $k^2$ 这个量级**（最多约 $2\times10^6$），所以大量数据都会落进这条路 → **在测评机上就是成片的 TLE**。
> 用你的原版跑 5000 组随机数据：**20 秒都没跑完（卡死）**；修正版跑完只要不到 1 秒。

**修法**：浮点二分一律写**固定次数**：

```cpp
double find(double l, double r){
    double ans = r;
    for (int it = 0; it < 100; ++it) {      // 100 次足够把区间压到 1e-24，永不死循环
        double mid = (l + r) / 2;
        if (p(mid)) { ans = mid; r = mid; }
        else l = mid;
    }
    return ans;
}
```

## 四、Bug ③（小答案错）：下界给成了 0.1


答案**可以是 0**（灯就在起点和终点上时 $w=0$ 就够）。下界给 0.1，就永远搜不到 0.1 以下。

## 七、自查（3 题）

1. 为什么 `ax*ax + ay*ay` 不能直接和 `w` 比？
2. `while (l <= r - 1e-11)` 在什么情况下会变成死循环？为什么阈值正好在 32768 附近开始出事？
3. 浮点二分为什么推荐"固定次数"而不是"区间小于 eps"？

<details>
<summary>答案</summary>

1. 它是**平方距离**（$|OA|^2$），量纲和半径 $w$ 不同。要和 $w$ 比就得先开方，或者两边都平方（$|OA|^2$ 与 $w^2$ 比）。
2. 当阈值量级使得 `1e-11` 不足 2 个 ULP 时，`r - 1e-11` 被舍入成 `r - 1ULP`，终止条件退化成"`l`、`r` 相邻"。相邻时 `mid=(l+r)/2` 只能舍入成 `l` 或 `r`，若舍成 `l` 且 `p(l)` 为假，`l` 就不前进 → 死循环。$2^{15}=32768$ 处 ULP 翻倍（$3.64\times10^{-12}\to7.28\times10^{-12}$），`del/ULP` 从 2.75 掉到 1.37，正好越过临界 ⇒ 实测 32761 正常、33124 卡死。
3. 因为"区间小于 eps"这个判断本身也依赖浮点减法（`r - l <= eps`）与 `mid` 的舍入：`eps` 小于 ULP 时判断失效、`mid` 可能等于端点，都可能让区间不再收缩。**固定次数**把收敛交给算法（每次区间减半），100 次后精度远超题目要求，且绝不依赖浮点比较。
</details>
