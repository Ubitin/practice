# CF377A Maze · 通俗版思路：**反着删格子**

> **触发点**：你说很少做图相关的题，要一个通俗的思路，代码自己敲。
> **一句话思路**：**不要去想"怎么挑 k 个格子堵"——反过来想"哪 k 个格子最该堵"**：从任意一个空格出发做一次"一条路走到黑"的搜索（DFS），**每次从一个格子退回来的时候，就把它记到一张名单上**；最后**把名单最前面的 k 个格子堵上**，剩下的必然还是连通的。
> 名字听着玄，其实就一句话：**把最角落的死胡同整条剪掉，主干当然毫发无伤。**

---

## 一、先把题看懂（三句话）

1. 一个 $n\times m$ 的迷宫，`#` 是墙、`.` 是空地。
2. 你要把**恰好 k 个** `.` 改成 `X`（变成墙）。
3. 要求：改完之后，**剩下的 `.` 还必须是一个连通块**（上下左右能互相走到）。
4. 答案不唯一 —— **任何**满足条件的改法都算对。

---

## 二、拿一个 4×5 的小迷宫走一遍（题眼都在这）

```
.....
.###.
.#...
.....          k = 4（要塞 4 个格子）
```
一共 16 个空格。从左上角 `(0,0)` 开始"一条路走到黑"：

- 一直往右走到头：`(0,0)→(0,1)→(0,2)→(0,3)→(0,4)`
- 右边没路了就往下：`→(1,4)→(2,4)→(3,4)`
- 再往左：`→(3,3)→(2,3)→(2,2)`
- ……最后绕回起点 `(0,0)`

**关键动作**：每从一个格子退回来（四个方向都试过了），就在名单上记下它。走完得到的名单（实测）：

| 名单位置 | 格子 | | 名单位置 | 格子 |
|---|---|---|---|---|
| **[0]** | **(0,1)** ← 变墙 | | [8] | (2,3) |
| **[1]** | **(0,2)** ← 变墙 | | [9] | (2,2) |
| **[2]** | **(0,3)** ← 变墙 | | [10] | (3,2) |
| **[3]** | **(0,4)** ← 变墙 | | [11] | (3,1) |
| [4] | (1,4) | | [12] | (3,0) |
| [5] | (2,4) | | [13] | (2,0) |
| [6] | (3,4) | | [14] | (1,0) |
| [7] | (3,3) | | [15] | **(0,0) ← 起点，永远留到最后** |

把名单**最前面 4 个**堵上，答案就是：

```
.XXXX
.###.
.#...
.....
```
剩下 12 个空格仍然连通 ✅（校验器实测：`恰好 4 个变墙、墙没被改、12 个空格连通`）

---

## 三、为什么这样一定连通？（一句话版的证明）

**名单是"后序"的：一个格子一定在它的所有"子孙"之后才被记上。**

所以"名单最前面的 k 个"有一个很好的性质：**如果一个格子被堵了，那么它后面钻进去的所有格子也一定已经被堵了**（因为子孙都排在它前面）。

⇒ 我们堵掉的其实是**几棵完整的小树枝**（连根剪掉），而起点所在的主干一个都没动
⇒ 剩下的格子都还能顺着原路走回起点 ⇒ **必然连通** ✅

> 换个说法：你删的是"离起点最远的那些末端"，不是"路中间的关节"。

## 四、代码骨架（你照着敲就行）

```cpp
int n, m, k;
vector<string> g;                  // 迷宫
vector<pair<int,int>> ord;         // 后序名单
int dx[4] = {1,-1,0,0}, dy[4] = {0,0,1,-1};

// ① 找第一个空格当起点
// ② 从它开始做 DFS：
//    - 进格子：标记"已访问"
//    - 四个邻居里凡是"是空格且没访问过"的，就钻进去
//    - 四个邻居都看完 → 把当前格子 push 进 ord（这就是"记名单"的时刻）
// ③ 把 ord[0] ~ ord[k-1] 改成 'X'
// ④ 逐行输出 g
```

**推荐写成"自己开栈"的迭代版**（原因见下一节），核心就是把递归换成：

```
栈里存 (格子x, 格子y, 下一个要看第几个方向)
循环：看栈顶格子还没看的方向 → 那边是没访问过的空格就压进去（= 递归）
      四个方向都看完了 → 记名单 + 弹出（= return）
```
这套"栈里存 (点, 下标)"的写法就是讲义「CF1006E…」里那个**能与递归完全等价**的迭代 DFS，一个模板两题通用。

## 五、⚠️ 这道题最容易翻车的地方：**递归深度**

$n,m\le 500$ ⇒ 空格最多 **250000** 个，而它们可能连成**一条长蛇**（迷宫嘛，蛇形走廊太常见了）。
DFS 的深度就等于这条蛇的长度。

**实测**（我造了一个 500×500 的蛇形走廊，**12.5 万个空格**连成一条线）：

| 写法 | 结果 |
|---|---|
| **递归 DFS**（本机默认 1MB 栈）| **退出码 -1073741571 = `0xC00000FD` 栈溢出，一行都没输出** ✗ |
| 递归 DFS + 编译加 `-Wl,--stack,268435456` | 通过（500 行输出）✅ |
| **迭代 DFS（自己开栈）** | 通过 ✅ |

> ⚠️ 和 CF1006E 那次一模一样：**本机崩、评测机（Linux 栈大）可能不崩**。别因此怀疑自己的思路。
> 本地测试建议：要么写迭代版，要么编译时加 `-Wl,--stack,268435456`。

## 六、另外四个小坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | **答案不唯一** | 所以**不能**拿一份"标准输出"去比对！要写/用一个 **checker**（判断"恰好 k 个新墙 + 墙没动 + 剩下连通"）。我给了现成的 `cf377a_check.py` |
| 2 | **恰好 k 个** | 多堵/少堵都不行。注意 `k = 0` 时什么都不用改 |
| 3 | **读入网格** | 每行是一个不含空格的字符串，直接 `cin >> g[i]` 最省事（别用 `getline` 踩换行符的坑）|
| 4 | **输出就是网格本身** | $n$ 行、每行 $m$ 个字符，别多加空格或空行 |

> 进阶（本题数据用不到）：如果把空格分成好几块，只从第一块搜一次就不够了——那时候要"保留哪一块、其余整块删掉"分别处理。**本题保证有解**，从第一个空格搜一次就够。

## 七、两种都对的删法（我各跑了 20000 组随机迷宫）

| 删法 | 做法 | 实测 |
|---|---|---|
| **A（推荐，标准）** | DFS **后序**名单，删**最前面** k 个 | 20000 组 **0 失败** ✅ |
| B（等价） | BFS 按层序访问，删**最后面** k 个（离起点最远的那批）| 20000 组 **0 失败** ✅ |

B 也对的原因：BFS 的顺序是"按离起点远近排的"，删掉最远的一批之后，**每个留下来的格子，它在 BFS 树上的父亲也一定留着**（父亲更近）⇒ 顺着父亲一路能走回起点 ⇒ 连通 ✅

> 你只需要记一种。**推荐 A（后序 + 删前缀）**：它是题解通用做法，遇到"删点保连通"的其他题也能套。

## 九、自查（先做完再翻答案）

1. 为什么"后序名单最前面的 k 个"堵掉之后，剩下的还连通？
2. 名单的**最后**一个是谁？为什么它永远不会被堵？
3. 递归版在什么数据上会崩？崩的退出码是什么？两种解决办法分别是什么？
4. 为什么这题不能像别的题那样"拿标准输出对拍"？正确做法是什么？
5. 用 BFS 层序倒着删最后 k 个，为什么也对？

<details>
<summary>答案</summary>

1. 因为后序名单里**子孙排在祖先前面**，"堵掉前缀"等价于**连根剪掉几棵完整的子树**；起点所在的主干没被动过，所以剩下的格子都能顺原路走回起点 ⇒ 连通。
2. 是**搜索起点**（它是最后才"退回来"的那个，所以排在名单最后）。删的永远是最前面 k 个，所以起点不可能被堵。
3. 空格连成一条长链时（如 500×500 蛇形走廊，实测 **125250 个空格**）会栈溢出，退出码 **-1073741571 = 0xC00000FD**。办法：① 写**迭代 DFS**（自己开栈）；② 本地编译加 `-Wl,--stack,268435456`。
4. 因为这题**答案不唯一**，任何合法改法都算对；和一份固定输出逐字符比对必然误判。正确做法是写 **checker**：验证"恰好 k 个新墙、原墙没被改、剩下的空格连通、空格数 = 原数 − k"。
5. 因为 BFS 顺序按"离起点远近"排，删掉最远的一批后，**留下来的每个格子的 BFS 父亲也留着**（父亲更近），顺着一层层能回到起点 ⇒ 连通。
