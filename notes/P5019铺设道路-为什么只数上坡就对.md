# P5019 铺设道路 · 为什么"只数上升的高度"就是对的

> **触发点**：你贴出这份 20 行的题解（`test_\p5019.cpp`），问"为什么这么写是对的"。
> **一句话结论**：**这题看着像"区间加"（要模拟每一次铺路），其实一次模拟都不用做——答案只由相邻两段的"高度差"决定：`ans = a[0] + Σ max(0, a[i] − a[i−1])`。** 因为**每出现一个"上坡"，就必然有那一段土是"别人帮不上忙、只能自己单独铺"的**，而上坡的总量恰好构成下界，又恰好能被一种贪心构造达到。

---

## 一、先把题贴明白（这题到底在问什么）

- 有 `n` 段路，第 `i` 段需要填 `a[i]` 单位土；
- **一次操作**：选一段**连续区间** `[l, r]`，把区间里每段**各填 1 单位**（注意：只能各填 1，不能填 2；也不能让任何一段超过它需要的量）；
- 问：填满所有段**最少**要几次操作。

你的代码求的就是这个最小次数：

```cpp
long long ans = 0;
for (long long i = 0; i < n; ++i) cin >> a[i];
for (long long i = 1; i < n; ++i)
    if (a[i] > a[i - 1]) ans += (a[i] - a[i - 1]);
cout << ans + a[0];
```

**它的本质是**：`ans = a[0] + Σ_{i=1}^{n-1} max(0, a[i] − a[i−1])`。
（代码里没写 `max`，而是用 `if (a[i] > a[i-1])` 实现了同样的事：只有上坡才算，下坡不算。）

---

## 二、为什么这题**不能**用"思考怎么铺"的办法想

看一眼题面，人的第一反应是"我每天铺一段，怎么铺最省？"——**这个方向会把你带进坑里**，因为你没法一眼看出"哪种铺法最优"，而且数据到了 `n = 10^5` 就彻底没法搜索了。

正解的视角完全不同：**别管怎么铺，先问"最少多少次"这个数被什么卡住了**。答案是——**被"上坡"卡住了**。

---

## 三、核心直觉：**上坡 = 别人帮不上忙的土**

先记住一条铁律（它是本题全部推理的基石）：

> **一次操作铺的是一个连续区间，而且是"整段各 +1"。**
> 所以如果第 `i` 段比第 `i−1` 段**高出 d**，那么第 `i` 段最上面那 `d` 层土，**左边那一列根本没有**——
> 任何**同时**铺到第 `i−1` 段和第 `i` 段的操作，都**不可能**去填这 `d` 层（否则第 `i−1` 段就超填了）。
> ⇒ **这 d 层只能靠"只铺到第 i 段为止（或从第 i 段开始）"的操作来填，无法与左边共享。**

换句话说：**每一处"上坡"，都是一笔无法省掉的开销。** 于是

```text
最少操作数 ≥ a[0]（第一段自己就得铺 a[0] 次）
          + Σ 每一处上坡的高度（这些土谁也不能替它铺）
```

这就解释了**为什么下坡完全不算**：第 `i` 段比第 `i−1` 段矮的时候，第 `i` 段的土是**可以和第 `i−1` 段一起铺的**（区间从左边延伸过来就把矮的那段盖住了），不需要额外开销。

## 四、把"是"变成"恰好"：一个 6 段小例子

取 `a = [4, 3, 2, 5, 3, 5]`（这是题目官方样例 2 的形状）。按公式：

| 位置 | 值 | 与左边比 | 计入 |
|---|---|---|---|
| 1 | 4 | ——（最左端） | **+4** |
| 2 | 3 | 下降 1 | 0（下坡不算） |
| 3 | 2 | 下降 1 | 0（下坡不算） |
| 4 | 5 | **上升 3** | **+3** |
| 5 | 3 | 下降 2 | 0 |
| 6 | 5 | **上升 2** | **+2** |

`答案 = 4 + 0 + 0 + 3 + 0 + 2 = 9`。

**而现在——真的拿 9 次铺出来给你看**（用 `test_\p5019_construct.cpp` 生成并逐格核对过）：

| 次数 | 铺哪一段（区间） |
|---|---|
| 1 | [1, 6] |
| 2 | [1, 6] |
| 3 | [1, 2] |
| 4 | [1, 1] |
| 5 | [4, 6] |
| 6 | [4, 4] |
| 7 | [4, 4] |
| 8 | [6, 6] |
| 9 | [6, 6] |

核对结果（程序自动验的）：**每段被填总数恰好等于 a[i] ✅、9 次操作每次都是合法连续区间且从不超填 ✅、最终刚好填满 ✅**。

数一遍背后发生了什么，正好是三笔"开销"：

- 前 4 次操作构成"左坡"：第 4 次只铺第 1 段（因为第 2 段只需要 3 层，第 4 层它不要了）⇒ **这一段开销 4 = a[0]**；
- 第 5~7 次构成"第 4 段的高台"：两次铺 [4,6]、一次只铺 [4,4] ⇒ **开销 3 = a[4]−a[3]**（第 4 段比第 3 段高 3）；
- 第 8~9 次构成"第 6 段的高台"：两次只铺 [6,6] ⇒ **开销 2 = a[6]−a[5]**（第 6 段比第 5 段高 2）。

**下坡的地方一次额外开销都没有**——第 2、3、5 段全都是"顺路被盖住"的。

## 五、完整证明（两句话版本）

**① 下界（至少要这么多次）**
把"高度"竖着切成一格一格。对每个 `i ≥ 2`，第 `i` 段中高度落在 `(a[i−1], a[i]]` 这 `max(0, a[i]−a[i−1])` 层土，**不可能被任何"同时覆盖 i−1 和 i"的操作填到**（那会把第 `i−1` 段顶超）。又因为操作必须连续，**任何**填到第 `i` 段这一层的操作，要么延伸到 `i−1`（不行），要么只从 `i` 或更右开始 —— 总之它**填不到第 `i−1` 段**，所以每一个这样的操作都"只服务右边这一块"。层与层之间也不能合并（一次只 +1），所以**至少需要 max(0, a[i]−a[i−1]) 次操作**来填这一层。再加上最左段那 `a[0]` 次（最左端左边没有任何东西可以共享），得到
`答案 ≥ a[0] + Σ_{i≥2} max(0, a[i]−a[i−1])`。

**② 可达性（这个次数真的够）**
用朴素贪心构造：从左往右扫，**每当 `a[i] > a[i−1]`，就新开 `a[i]−a[i−1]` 次操作，每次都从第 `i` 段开始、尽量向右延伸**（延伸到右边那段"已经不需要了"为止）。
可以验证：每段 `i` 被填的次数恰好是
`max(0, a[i]−a[i−1])`（它自己开的那一批）+ `max(0, a[i+1]−a[i])`… 这类"从左边延伸过来的"部分 —— 合起来正好等于 `a[i]`；且**永不超填**（延伸时会检查右边是否还被需要）。
（这一步不是"想当然"：见第六节的实测，程序把每次操作都记下来逐格验证了。）

**下界 = 可达到 ⇒ 公式就是最小值。**

## 七、这份代码逐行读

```cpp
long long ans = 0;                                    // ① 只累计"上升量"
for (long long i = 0; i < n; ++i) cin >> a[i];
for (long long i = 1; i < n; ++i)                     // ② 从第 2 段开始比
    if (a[i] > a[i - 1])                              // ③ 只处理"上坡"，下坡直接跳过
        ans += (a[i] - a[i - 1]);                     // ④ 加上这一截的高度
cout << ans + a[0];                                   // ⑤ 别忘了最左段的 a[0]
```

**四个容易写错的地方，你都写对了：**

| 点 | 写错的后果 |
|---|---|
| ⑤ `ans + a[0]` 这一项 | 忘了它，`[4,3,2,5,3,5]` 会输出 5 而不是 9 |
| ③ 判据必须是**严格** `a[i] > a[i-1]` | 写成 `>=` 时平的段落会加 0，其实**结果一样**（`max(0,0)=0`），但写成 `a[i] < a[i-1]`（判下坡）就完全错了 |
| ④ 累加的是 `a[i] - a[i-1]` 而不是 `a[i]` | 直接加 `a[i]` 会变成"每段都单独铺"，答案偏大 |
| 循环从 `i = 1` 开始 | 从 `i = 0` 开始会访问 `a[-1]`，越界读 |

**复杂性**：`O(n)` 时间、`O(n)` 空间（只要存数组；其实还可以边读边算，连数组都不用）。

## 八、⚠️ 你代码里唯一值得改的地方（本题数据碰不到）

`test_\p5019.cpp` 第 18 行是 `cout << ans + a[0];`——**如果 `n = 0`，`a` 是空 vector，`a[0]` 就是越界读（UB）**。
洛谷这题 `n ≥ 1` 所以**碰不到**，但这是个习惯问题。两个改法（**我没有改动你的原文件**）：

```cpp
// 改法 A：加一句保护
if (n == 0) { cout << 0 << "\n"; return 0; }

// 改法 B（推荐）：边读边算，根本不需要数组，也就不存在 a[0] 越界
long long ans = 0, prev = 0, x;
for (long long i = 0; i < n; ++i) {
    cin >> x;
    if (x > prev) ans += x - prev;   // 第一段时 prev=0，等价于 ans += a[0] ✔
    prev = x;
}
cout << ans << "\n";
```

**改法 B 有个额外好处**：它把公式 `a[0] + Σ max(0, a[i]−a[i−1])` 统一成了 **`Σ max(0, a[i]−a[i−1])`（令 `a[0] 的前一项 = 0`）**——因为"最左端"和"上坡"在数学上是**同一件事：从 0 升到 a[0] 也是一次上升**。想通这一点，公式和代码就都变成一句话了。

## 九、一句话把这类题串起来

| 题型 | 表面 | 正解视角 |
|---|---|---|
| **P5019 铺路** | 区间 +1，最少几次 | **数上升量**（差分正部之和） |
| P1969 积木大赛 | 和本题几乎一样的"区间 −1" | 同上，一个公式 |
| 差分数组 | 区间加 d 怎么快速做 | 差分 = **相邻差**，本题的公式就是"差分正部和" |
| CF1840D / P1182 | "最少分几组 / 最小化最大值" | 二分答案 + 贪心判定 |

⭐ **共性**：**当题目问"最少几次区间操作"时，先别急着模拟，去看看"哪些工作是无法共享的"——这类题的下界往往就是答案。**
本题里那个"无法共享的工作"就是**上坡**。

## 十、自查

<details><summary>Q1：为什么下坡（a[i] &lt; a[i−1]）完全不计入答案？</summary>

因为第 `i` 段的土**可以和第 `i−1` 段一起铺**（区间从左边延伸过来就把它盖住了），不产生"无法共享"的开销。
反例检验：`[6,5,4,3,2,1]` 全部是下坡，答案是 `a[0] = 6` —— 6 次 `[1,6]` 就铺完了。

</details>

<details><summary>Q2：[4,3,2,5,3,5] 为什么不是 4+3+5=12 或 4+5=9 之外的别的数？</summary>

因为第 4 段的 5 层里，有 `a[3] = 2` 层是**和第 3 段共享**的（前两次 `[1,6]` 已经把它盖到 2 层），只有高出第 3 段的那 `5−2 = 3` 层才需要单独开销。
所以是 `4 + 3 + 2 = 9`：`4`（左坡）+ `3`（第 4 段比第 3 段高）+ `2`（第 6 段比第 5 段高）。

</details>

<details><summary>Q3：怎么把"上坡不可共享"这句话变成严格的数学论证？</summary>

看第 `i` 段中高度在 `(a[i−1], a[i]]` 的那些格子。任何填到这些格子的操作，如果它同时覆盖了第 `i−1` 段，就会让第 `i−1` 段被填到超过 `a[i−1]`（超填，非法）；所以这类操作**必须从第 `i` 段或更右开始**，也就是说它们**永远服务不到第 `i−1` 段**。而一次操作只能 +1 一层，所以这一层至少要 `max(0, a[i]−a[i−1])` 次操作。对所有 `i` 求和即得下界。

</details>

<details><summary>Q4：为什么"上界能取到"不是显然的？</summary>

下界只证明了"至少要这么多"。要成为答案，还得证明"真的能只用这么多次铺完"。
证据有两类：① 贪心构造（`test_\p5019_construct.cpp`）把 9 次操作真的列出来并逐格核对通过；② 分治参考解（完全另一套推理）对 3000 轮随机数据给出同样的数。**下界 + 能构造出达到下界的方案 = 它就是最小值**，这就是贪心题的标准证明格式。

</details>

<details><summary>Q5：如果题目改成"每次可以选一个区间各填 2 单位"，公式还成立吗？</summary>

**不再成立**——因为"填一层要一次操作"这个前提被打破了（一次能填 2 层，层与层可以合并，下界立刻变松）。
这类题必须重新推。**教训**：贪心公式永远是"绑定在具体操作定义上"的，换了操作规则就要重新论证，不能照搬。

</details>

<details><summary>Q6：为什么这题的数据范围里答案不会溢出？</summary>

`a[i] ≤ 10000`、`n ≤ 100000`，最坏情况答案是"每段都比左边高" ⇒ 总和 ≤ `10000 × 100000 = 1e9`，**`int` 其实勉强够**（`INT_MAX ≈ 2.1e9`），但用 `long long` 更稳。
你的代码全程 `long long`，安全 ✅。

</details>
