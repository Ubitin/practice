# P2234 营业额统计 —— 你的思路是对的，错在**哨兵**和**比较函数**

> **触发点**：2026-09-29，你说"我觉得自己的思路没有问题，为什么错了"。
> **判定（分开说）**：
> ✅ **思路没问题**——"排序 + 从后往前删 + 双向链表找前驱后继"就是这题的标准离线解法。
> ❌ **实现有两个 bug**：① **哨兵的值写成 `0`**（想顺便把第一天的贡献凑出来）② **`cmp` 用了 `<=`**（非严格弱序 → `std::sort` 的 UB）。
> **最直接的证据**：官方样例 `6 / 5 1 2 5 4 6` 应输出 **12**，你输出 **9**。

---

## 一、题目（30 秒版）

`n` 天的营业额 `a_i`。

- 第 `i` 天的**最小波动值** = `min{ |a_i − a_j| : j < i }`；
- **第一天的波动值 = 它自己的营业额**。

求所有天的最小波动值之和。

**样例**（题面原话）：

```
输入          输出        结果说明
6             12          5 + |1-5| + |2-1| + |5-5| + |4-5| + |6-5|
5                                    = 5 + 4 + 1 + 0 + 1 + 1 = 12
1
2
5
4
6
```

## 二、先肯定：你的思路确实是**正解**

你的做法：

1. 把 `(营业额, 第几天)` 按营业额**排序**；
2. 排序后把相邻元素串成**双向链表**（`l` / `r`）；
3. **从第 n 天倒着处理**：第 j 天的元素在链表里的**前驱和后继**，就是"值最接近的两个候选"，取差值的最小值，累加；
4. 处理完把它**从链表里删掉**（`v[l].r = r; v[r].l = l;`）。

**为什么对**：

- 处理第 `j` 天时，链表里恰好只剩**第 1..j 天**的元素（第 j+1..n 天在前面几步已经被删掉了）；
- 而"值离 `a_j` 最近的那个"**必然**是排序后的**直接前驱或直接后继**（任何更远的元素差值只会更大）⇒ 取两者最小即可；
- 删掉之后链表里只剩 `1..j−1` 天，正好对上第 `j−1` 天的需求。

这跟题解的原话完全一致：*"两侧的话因为要进行删除操作（防止后面的天对前面产生影响，我们从 n 倒序遍历）所以考虑容易进行删除的链表"*。

🍜 **类比**：把所有人按身高排好队、手拉手。从**最后一个来的人**开始往回问："比你高的那个和比你矮的那个，谁跟你更接近？"问完就让这个人**离队**（把手松开），下一个人再问时，队里剩下的就都是"比他先来的人"。

## 三、Bug 1（主因）：**哨兵的值不能乱写**

你的代码：

```cpp
v[0] = {n + 1, 1, 0, 0};   v[n + 1] = {n, 0, 0, n + 1};
//                      ^ sa = 0                    ^ sa = 0
```

而取答案时是：

```cpp
res = min(abs(v[id].sa - v[v[id].l].sa), abs(v[id].sa - v[v[id].r].sa));
//                       ^^^^^^^^^^^^^^ 哨兵的 sa 会参与比较！
```

### 你（大概）的本意 & 它为什么危险

我猜你的想法是：**最后处理第 1 天时**，链表里只剩它一个，左右都是哨兵 ⇒ `min(|a1−0|, |a1−0|) = a1`，正好等于题目要求的第一天波动值。**这个"顺便"很聪明——但它污染了别的极端情况。**

**后果**：只要某个元素是"**当前剩余元素里的最小值**"，它的左邻居就是哨兵 `0`；一旦

```
a_i  <  |a_i − 右邻居|
```

`min` 就会**选中哨兵**，答案偏小。

### 样例就是这么错的（差 3，全在第 2 天）

| 天 | 营业额 | 你的贡献 | 正确贡献 | 说明 |
|---|---|---|---|---|
| 1 | 5 | 5 | 5 | 最后处理，左右都是哨兵 ⇒ 5（**凑对了**）|
| 2 | **1** | **1** | **4** | 它是剩余里的最小值 ⇒ 左邻居是哨兵 0 ⇒ `min(\|1−0\|, \|1−5\|) = min(1,4) = ` **1** ✗ |
| 3 | 2 | 1 | 1 | |
| 4 | 5 | 0 | 0 | |
| 5 | 4 | 1 | 1 | |
| 6 | 6 | 1 | 1 | |
| **合计** | | **9** | **12** | |

### 更小的反例

| n | 序列 | 你的输出 | 正确 | 为什么 |
|---|---|---|---|---|
| 2 | `1000 5` | **1005** | **1995** | 第 2 天=5 是剩余最小值 ⇒ 哨兵给 5，正确是 \|5−1000\|=995 |
| 2 | `100 1` | **101** | **199** | 同上 |
| 2 | `1 100` | 100 | 100 | ✅ 这里哨兵距离 100 大于真实差值 99 ⇒ **侥幸对** |

### 修法（两种都行）

**(a) 哨兵用 ±INF + 第 1 天单独加**（推荐，最贴近题解）
```cpp
const ll INF = (ll)1e18;
v[0] = {n + 1, 1, -INF, 0}; v[n + 1] = {n, 0, INF, n + 1};
for (ll j = n; j >= 2; --j) { ... }     // ★ 第 1 天不进循环
ans += a[1];                            // ★ 第一项单独加
```
> 题解里那句 **"P.S. 最后别忘了加上第一项"** 说的就是这件事。

**(b) 干脆不读哨兵的值**
```cpp
ll res = LLONG_MAX;
if (v[id].l != 0)     res = min(res, llabs(v[id].sa - v[v[id].l].sa));   // 左邻居不是哨兵才算
if (v[id].r != n + 1) res = min(res, llabs(v[id].sa - v[v[id].r].sa));
ans += a[1];
```

## 四、Bug 2：`cmp` 必须是**严格弱序**——写 `<`，不能写 `<=`

你的代码：

```cpp
bool cmp(a x, a y){ return x.sa <= y.sa; }   // ❌
```

`std::sort` 要求比较函数满足**严格弱序（strict weak ordering）**，其中一条是"`cmp(x, x)` 必须为 **假**"（不允许自反）。`<=` 违反这一条 ⇒ **未定义行为**：排序过程中可能**读/写到数组边界之外**，轻则顺序错乱，重则崩溃。

**实测（用你的真实源码编译运行）**：

| 数据 | 你的程序 |
|---|---|
| n=32767、值域 10⁶（重复很少） | exit 0，输出 5337741（**答案仍错**，那是 Bug 1 的锅）|
| n=32767、**值域只有 5 个值**（大量重复） | **exit = −1073741819 = `0xC0000005` 崩溃，输出为空** ❌ |
| 隔离实验：`sort` 用 `<=`，n=400 | **exit = −1073740940 = `0xC0000374` 堆损坏**（走到程序退出时才报）|
| 隔离实验：同样数据改成 `<`，n=5000 | exit 0，排序正确 ✅ |

⇒ 在评测机上这就是 **RE**。**改成 `return x.sa < y.sa;` 即可**（或者把两个字段塞进 `pair<ll,ll>`，直接用默认的 `<` 排）。

## 七、自查

<details>
<summary>① 为什么只看"前驱和后继"就够了，不用看所有剩余元素？</summary>

因为数列已经**排序**：设 `a_j` 落在排序后的位置 `p`，那么任何比前驱还小的元素，与 `a_j` 的差值都 ≥ 前驱的差值；任何比后继还大的元素同理。所以**离它最近的值只可能是直接前驱或直接后继**。
</details>

<details>
<summary>② 哨兵改成 ±INF 之后，为什么第 1 天必须单独处理？</summary>

处理第 1 天时，链表里只剩它自己，左邻右舍都是哨兵。若哨兵是 ±INF，`min(|a1−(−INF)|, |a1−INF|)` 会算出 ≈ INF（错的）。
所以按题目定义"第一天的波动值 = 它自己的营业额"，直接 `ans += a[1]`。
</details>

<details>
<summary>③ `cmp` 写成 `<=` 会怎样？为什么？</summary>

**未定义行为**，实测可能**崩溃**（`0xC0000005` 访问违规 / `0xC0000374` 堆损坏）、也可能给出错乱的顺序。
原因：`std::sort` 要求严格弱序，其中 `cmp(x,x)` 必须为假；`<=` 让它为真，破坏了算法对"元素集合"的基本假设，内部循环可能一路扫出数组边界。
</details>

<details>
<summary>④ 如果用 `multiset` 写，`lower_bound` 之后要检查哪两件事？</summary>

```cpp
auto it = s.lower_bound(x);
ll best = LLONG_MAX;
if (it != s.end())  best = min(best, *it - x);          // ① 有没有"后继"
if (it != s.begin()) best = min(best, x - *prev(it));   // ② 有没有"前驱"（begin() 不能再 prev）
```
另外：如果 `*it == x`（存在相同营业额），`best` 自然就是 0 —— 这也正是"重复值必须输出 0"的处理方式。
</details>

## 八、一句话带走

> **思路对不等于能过**：这题的两个杀手是"**哨兵的值**"和"**比较函数的严格性**"。
> **哨兵只该代表"没有这个邻居"，所以要么用 ±INF、要么显式判"是不是哨兵"——绝不能用一个真实的数字去假装它。**
