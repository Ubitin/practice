# P1024 一元三次方程求解 —— 漏根排错

> 触发点：P1024 提交后**有时漏根**（输出的根少于 3 个）。代码在 `test_\01.cpp`。
> 一句话：**二分分支把根算出来了，却压根没有输出。** 程序只输出那些"恰好落在整数点上"的根，所以题面样例（三个根都是整数）能过，换个数据就漏。
> 实测：随机 1000 组三实根方程，原码**漏根 1000/1000 组（100%）**；只在二分分支后补一句 `printf`，立刻降到 **0/1000**。
> 演示程序：`test_\01_p1024_check.cpp`；修正版：`test_\01_p1024_fixed.cpp`（**原文件 `test_\01.cpp` 保持原样未改动**）。

---

## 一、症状：样例能过，别的数据漏根

| 输入 | 期望 | 原码实测 |
|---|---|---|
| `1 -5 -4 20`（题面样例，根 −2/2/5 **全是整数**） | `-2.00 2.00 5.00` | `-2.00 2.00 5.00` ✅ **通过** |
| `1 -6 11 -6`（根 1/2/3 全是整数） | `1.00 2.00 3.00` | `1.00 2.00 3.00` ✅ 通过 |
| `1 0 -2 0`（根 −1.41 / 0 / 1.41） | `-1.41 0.00 1.41` | **`0.00`** ❌ 少 2 个 |
| `1 0 -3 2`（根 −2 / 1 / 1） | `-2.00 1.00` | `-2.00 1.00` |

**规律很明显：只有整数根才被输出。** 这不是"有时"漏，而是"**非整数根一律漏**"——你在样例上验证过、又碰巧用整数根试过，所以感觉是"有时"。

## 二、主因：二分算出根，却没有输出

你的代码：

```cpp
for(int i = -100; i <= 100; ++i){
    double l = i, r = i + 1;
    if(fabs(f(l)) < eps)        printf("%.2lf ", l);   // ← 只有这里输出
    else if(fabs(f(r)) < eps)   continue;
    else if(f(l) * f(r) < 0){
        while(abs(l - r) > eps){
            double mid = (l + r) / 2;
            if(f(mid) * f(r) > 0) r = mid;
            else l = mid;
        }
        // ←←← 这里缺了一句 printf！二分辛辛苦苦收敛出的根，算完就丢掉了
    }
}
```

**`printf` 只写在了第一个分支里。** 第二个分支把 `l`/`r` 收敛到了 1e-4 精度，然后……什么都没做。

**实测对比**：

```
原码（二分分支不输出）：漏根 1000 / 1000 组，结果不符 1000 组
补上 printf 之后      ：漏根    0 / 1000 组，结果不符    0 组
```

**这一句 `printf` 就是漏根的全部主因。**

> ⚠️ 注意这里有个思维陷阱：二分那段**写得很像对的**（循环、mid、收敛条件都在），读代码时很容易"看着看着就点头"。**写完任何二分，都要回头确认"结果去哪了"**——收敛出来的 `l`/`r` 最后有没有被使用。

## 三、修法

```cpp
if (fl == 0.0) {                 // ① 端点恰好是根
    emit(l);
    continue;
}
if (fl * fr < 0) {               // ② 区间内变号 → 有根
    for (int k = 0; k < 100; ++k) {
        double mid = (l + r) / 2;
        if (f(mid) * fr > 0) r = mid;
        else                 l = mid;
    }
    emit((l + r) / 2);           // ★ 原码缺的就是这一句
}
```

## 四、顺带查出的两个隐患

### 隐患① `fabs(f(l)) < eps` 判的不是"是不是根"

这是**函数值**的绝对大小，不是**到根的距离**。判据是否成立完全取决于系数的大小：

- 系数整体放大 → `f(l)` 处处很大 → 该分支永不触发（真根被漏）
- 系数整体缩小 → `f(l)` 处处很小 → **一堆整数点被误判成根**

**实测**：`a=1e-8, b=0, c=-2e-8, d=0`（真根 −1.41 / 0 / 1.41）

```
输出共 43 个：-21.00 -20.00 -19.00 -18.00 ... 
```

**输出 43 个"根"，全是假的。**

系数缩放测试（根恒为 −2 / 2 / 5，只把系数乘 `k`）：

| k | 原码输出个数 | 修正版 |
|---|---|---|
| 1e-8 | **44 个** ❌ | 3 个 ✔ |
| 1e-3 | 3 个 | 3 个 ✔ |
| 1 | 3 个 | 3 个 ✔ |
| 1e6 | 3 个 | 3 个 ✔ |
| 1e9 | 3 个 | 3 个 ✔ |

**修正版改用 `f(l) == 0.0` 做精确整数根判定**，其余全部交给"区间变号"判据——变号与否**与系数的整体尺度无关**，所以稳。

### 隐患② `while(abs(l - r) > eps)` 用区间宽度当终止条件

步长是 1，`eps = 1e-4`，约 13 轮就停，精度刚好 1e-4。对 2 位小数够用但余量很小。

**改成固定迭代次数更稳**：

```cpp
for (int k = 0; k < 100; ++k) { ... }   // 100 次 = 精度 1e-30，远超需要
```

> 浮点二分**尽量不要用"区间宽度 < eps"当终止条件**：轮数依赖初值区间宽度，换个范围（比如 [0, 1e9]）轮数就要重算。固定次数简单且可控。

## 五、特别说明：`abs(l - r)` 是**对的**，不是 bug

我一开始怀疑这里用了整数版 `abs`（那会把 `double` 截断成 `int`，精度全毁）。**实测核实：没冤枉它。**

```
abs(0.4) = 0.4
sizeof(abs(0.4)) 的结果类型：double（正确）
```

C++ 的 `<cmath>` 提供了 `std::abs(double)` 重载，配合 `using namespace std;` 会正确选中浮点版。

> 对比：**C 语言**里 `abs` 只有整数版，浮点要用 `fabs` —— 所以在 C 里这么写就是 bug。C++ 不是。**这个区别值得记住。**

## 七、修正版的三个关键点（浮点二分求根通用）

### ① 端点恰好是根，要单独判

题目保证"两两间距 ≥ 1"，所以以 1 为步长扫描时**每个区间最多一个根**。但如果根**正好落在整数点** `i` 上：

```
f(i) = 0  ⇒  区间 [i-1, i] 的 f(i-1) * f(i) = 0
              区间 [i, i+1] 的 f(i) * f(i+1) = 0
```

**两个区间的乘积都是 0，都不满足 `< 0`** → 只看变号会**整个漏掉它**。所以必须先判 `f(i) == 0`。

> 补充：如果 `f(i)` 因浮点误差算成了 ±1e-17（不是精确 0），那么它与左右邻点之一必然异号，变号判据会在相邻区间把它抓到（收敛到 i）。所以 **`f(i)==0` 精确判定 + 变号判据** 两条一起用就完备了。

### ② 输出前做去重

```cpp
if (x - last >= 0.5) { printf("%.2f ", x); last = x; }
```
防止"整数根"被端点判定和变号判定同时抓到、输出两遍。

### ③ 边界端点要单独补

循环 `i` 从 −100 到 99 覆盖了区间 [−100, 100]，但 **`x = 100` 这个点本身**要单独判一次 `f(100.0) == 0`。

## 八、坑清单

| # | 坑 | 症状 |
|---|---|---|
| 1 | **二分算完没有输出** | 非整数根全部漏掉（本次主因，实测 100% 漏根） |
| 2 | 用 `fabs(f(x)) < eps` 判"是不是根" | 与系数尺度绑定：系数小 → 假根刷屏；系数大 → 真根漏掉 |
| 3 | 只用 `f(l) * f(r) < 0` 判区间有根 | 根恰好落在整数点上时两端乘积都是 0 → 漏根 |
| 4 | 浮点二分用"区间宽度 < eps"终止 | 精度余量小；换区间范围要重算轮数。固定 100 次更稳 |
| 5 | 忘了补右端点 `x = 100` | 根在 100 时漏掉 |
| 6 | 端点根与区间根都命中，输出两遍 | 需要去重 |
| 7 | 以为 `abs(double)` 会截断 | **C++ 里不会**（`<cmath>` 有 `double` 重载）；**C 里会**（只有整数版，要写 `fabs`） |

## 九、自查

1. 原码为什么"题面样例能过，别的数据漏根"？漏的是哪一类根？
2. `fabs(f(l)) < 1e-4` 为什么不能用来判断"l 是不是根"？系数乘 1e-8 会怎样？
3. 根恰好等于某个整数 `i` 时，为什么只靠 `f(l) * f(r) < 0` 会漏掉它？
4. `abs(l - r)` 在 C++ 里会不会把 `double` 截断成 `int`？在 C 里呢？
5. 浮点二分为什么更适合"固定迭代 100 次"而不是"区间宽度 < eps"？

**答案要点**
1. 因为输出只写在 `fabs(f(l)) < eps` 那个分支里；二分分支算出根后没有 `printf`。漏掉的是**所有非整数根**——题面样例的三个根恰好都是整数，所以看起来"能过"。
2. 它衡量的是**函数值**的绝对大小，不是**到根的距离**，是否成立完全取决于系数的整体尺度。系数乘 1e-8 后大量整数点的函数值都 < 1e-4，实测输出了 43 个假根。
3. 因为 `f(i) = 0` 会让 `f(i-1)*f(i)` 和 `f(i)*f(i+1)` **都等于 0**，而判据要求 `< 0`，两个区间都被跳过。必须先单独判 `f(i) == 0`。
4. **C++ 里不会**——`<cmath>` 提供了 `std::abs(double)` 重载（实测 `abs(0.4) = 0.4`，返回类型 `double`）。**C 里会**——C 的 `abs` 只有整数版，浮点必须用 `fabs`。
5. 因为"区间宽度 < eps"的迭代轮数取决于初值区间宽度，换一个范围就要重算；固定 100 次则精度恒为 `(r-l)/2^100`，简单、可控、不需要调参。
