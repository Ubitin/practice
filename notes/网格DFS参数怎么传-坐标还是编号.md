# 网格 DFS 的参数怎么传：坐标还是编号？

> **触发点**：你在写 CF377A，`void dfs(ll u){ }` 敲出来了，但不知道 `u` 里该放什么。
> **一句话结论**：**网格题的 DFS 传「当前格子的坐标」→ `dfs(x, y)`**。想保留你习惯的"只有一个参数 `u`"也行——把格子编号成 `u = x*m + y`，进函数第一行还原回坐标。**两种写法结果完全一样**（实测输出逐字节相同，SHA256 一致）。

---

## 一、为什么"传一个 u"在网格题里会卡住

| | 树 / 图（你熟悉的场景） | 网格（CF377A 这种） |
|---|---|---|
| 一个点怎么称呼 | **天生有编号**，题目直接给 `1..n` | 天然就是二维的 `(x, y)`，**没有编号** |
| 邻居怎么拿到 | 早就存好了：`for (auto v : ch[u])` | 现场算：`(x±1, y)`、`(x, y±1)` |
| dfs 参数自然长什么样 | `void dfs(ll u)` ✔ | 要么 `void dfs(ll x, ll y)` ✔，要么**自己造编号** |

一句话：树上那个 `u` 是**题目发给你的**；网格上**没有 `u`**，得你自己决定"用坐标，还是自己编个号"。

---

## 二、写法 A：传坐标（推荐）

下面这份骨架**直接沿用你 `01.cpp` 里的变量名**（`wall` / `blank` / `cnt` / `timer`），只有三处需要按注释改：

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
const ll maxn = 505;          // ← 你原来写的 502，改成 505 更保险
const ll maxe = 250005;       // ← ★ 后序名单最多要装 n*m = 250000 个空格！

ll n, m, k;
char g[maxn][maxn];           // ★ 建议把 bool wall 换成 char g：因为输出要区分 '#' 和 'X'
bool blank[maxn][maxn];       // 记录该空地是否被访问过（恒为 false 更好；用 true 也行）
struct dot { ll x, y; };
dot cnt[maxe];                // ★ 你原来写的是 cnt[maxn]（只有 502 个），会越界！
ll timer = 0;

ll dx[4] = {1, -1, 0, 0};
ll dy[4] = {0, 0, 1, -1};

// ↓↓↓ 参数就是这两个：当前格子的坐标（1-based）↓↓↓
void dfs(ll x, ll y) {
    blank[x][y] = true;                       // ① 进门先盖章，防止走回头路
    for (ll d = 0; d < 4; ++d) {              // ② 四个方向挨个看
        ll nx = x + dx[d], ny = y + dy[d];
        if (nx < 1 || nx > n || ny < 1 || ny > m) continue;  // ③ 出界就跳过
        if (g[nx][ny] != '.' || blank[nx][ny]) continue;     // ④ 是墙 / 走过就跳过
        dfs(nx, ny);                          // ⑤ 递归时传【新格子】的坐标
    }
    cnt[++timer] = {x, y};                    // ⑥ 四方向全看完才记账 = 后序
}

int main() {
    cin >> n >> m >> k;
    ll sx = 1, sy = 1;
    for (ll i = 1; i <= n; ++i) {
        static char s[maxn];
        scanf("%s", s + 1);                   // 每一行是连续字符串，别用 getline
        for (ll j = 1; j <= m; ++j) {
            g[i][j] = s[j];
            if (s[j] == '.') { sx = i; sy = j; }   // 随便记住一个空格当起点
        }
    }
    dfs(sx, sy);                              // 从第一个空格出发

    for (ll i = 1; i <= k; ++i)
        g[cnt[i].x][cnt[i].y] = 'X';           // ★ 把名单最前面 k 个变成墙

    for (ll i = 1; i <= n; ++i) {
        for (ll j = 1; j <= m; ++j) putchar(g[i][j]);
        putchar('\n');
    }
    return 0;
}
```

逐行读一遍 `dfs` 里那 6 步（这就是递归的全部内容）：

| 步骤 | 代码 | 干什么 |
|---|---|---|
| ① | `blank[x][y] = true;` | **进门盖章**。盖章的时机很重要：一进门就盖，不然会绕回来死循环 |
| ② | `for (ll d = 0; d < 4; ++d)` | 把上下左右四个方向挨个试一遍 |
| ③ | `if (nx < 1 \|\| nx > n \|\| ...) continue;` | **出界**就跳过（你上一题 P2895 漏了上界，实测越界 620 次） |
| ④ | `if (g[nx][ny] != '.' \|\| blank[nx][ny]) continue;` | **是墙**或**走过**就跳过 |
| ⑤ | `dfs(nx, ny);` | **递归**：参数换成新格子的坐标 |
| ⑥ | `cnt[++timer] = {x, y};` | **出门记账**：四个方向都看完了才记 —— 这就是"后序" |

> **记不住写法的口诀**：dfs 一进门只干三件事 —— **盖章、看四个方向、出门记账**。第 ⑥ 步写在 for 的**外面**（后序），写在 for 的**前面**就是先序。

## 三、写法 B：传编号 `u = x*m + y`（保留你的老风格）

如果你就是喜欢 `void dfs(ll u)` 这种一个参数的形式，完全可以——**自己给格子编号**：

```cpp
const ll maxn = 505;   const ll maxe = 250005;
ll n, m, k;
char g[maxn][maxn];
bool blank[maxn][maxn];
struct dot { ll x, y; };
dot cnt[maxe];
ll timer = 0;

void dfs(ll u) {                       // ← 只有一个参数：格子编号
    ll x = u / m, y = u % m;           // ★ 第一行：把编号还原成坐标（0-based）
    blank[x][y] = true;
    const ll dx[4] = {1, -1, 0, 0}, dy[4] = {0, 0, 1, -1};
    for (ll d = 0; d < 4; ++d) {
        ll nx = x + dx[d], ny = y + dy[d];
        if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;   // 0-based：上界是 >= n
        if (g[nx][ny] != '.' || blank[nx][ny]) continue;
        dfs(nx * m + ny);              // ★ 邻居也要【先编号】再递归
    }
    cnt[++timer] = {x, y};
}

int main() {
    // 读入略（0-based）
    // 起点编号 = sx * m + sy
    dfs(sx * m + sy);
    // 之后一样：cnt[1..k] 变 'X'
}
```

**编号 ↔ 坐标**：

```
编号 u = x * m + y     （把二维压成一维，x 是行号、y 是列号，都从 0 开始）
坐标 x = u / m         （整数除法，正好是行号）
坐标 y = u % m         （取余，正好是列号）
```

⚠️ **两个必须注意的地方**：
1. **行号 x、列号 y 必须都从 0 开始**，公式才成立。不巧的是 `u = x*m+y` 用的是**列数 m**，别写成 n（写成 n 的话编号会重复、不同的格子撞到一起）。
2. **每次递归都要重新编号**：`dfs(nx * m + ny)`，不能写 `dfs(nx)` 也不能写 `dfs(u + 1)`。

## 四、哪些东西**不需要**传

新手最容易把一堆东西全塞进参数里，下面这些**都不用传**：

| 想传的东西 | 为什么不用传 |
|---|---|
| **上一个格子（父亲）** | `blank[nx][ny]` 已经挡住了回头路，"走过来的那一格"必然是 `true`，自动被跳过 |
| **步数 / 深度 / 层数** | 本题只关心"连不连通"，跟远近无关（要远近就用 BFS） |
| **k、答案、计数器** | 用**全局变量**（`k`、`timer`、`cnt`），函数里直接改就行 |
| **n、m、网格** | 同上，全部放全局 |
| **`vector` 之类的容器** | 全局数组最省事，也不会爆栈 |

> **判断标准**：这个值**每一层递归都不同**吗？不同才传（比如坐标 `x, y`）；所有层共用同一个 → 放全局。

**唯一值得考虑的"多传一个"**：如果要记录**路径**，可以传深度 `dfs(x, y, step)`；如果要判**二分图染色**，可以传颜色 `dfs(x, y, c)`。CF377A 两个都不需要。

## 五、⚠️ 最容易翻车的坑：后序名单**开小了**

你原来写的是：

```cpp
const ll maxn = 502;
dot cnt[maxn];        // ← 只有 502 个位置
```

**但网格最大 500×500，空格最多 250000 个**，后序名单的长度 = **空格个数**，所以 `cnt` 至少要开 `250005`。

**实测对比**（我用你的变量名写了两个只差这一行的版本，跑同一个 **500×500 蛇形走廊**，空格 125250 个）：

| 版本 | 后序名单大小 | `timer` 结果 | 退出码 | 结论 |
|---|---|---|---|---|
| 正确版 | `dot cnt[250005]` | **125250** ✔ | 0 | 正确，用时 43ms |
| 错误版 | `dot cnt[502]` | **243** ✘（应为 125250） | **0** | **不崩溃、静默算错！** |

落后那个结果最吓人：**它没有报错、没有崩溃、退出码还是 0**，只是越界写把旁边的全局变量（`timer` 自己）踩坏了，于是 `timer` 停在 243，答案悄悄错掉。

> **教训**：数组越界不一定崩，**"不崩"不等于"对"**。名单类数组一律按 `n*m` 开。
> （顺带一提：本机 w64devkit 没有 ASan，`-fsanitize=address` 报 `cannot find -lasan`，抓越界只能靠 `const int maxe = 250005;` 这种自觉。）

## 八、自查

<details><summary>Q1：为什么 `dfs` 不用传"父亲格子"？</summary>

因为 `used`/`blank` 盖章挡住了回头路：你从父亲走过来的那一格必然是 `true`，`if (blank[nx][ny]) continue;` 会直接跳过它。传父亲只是"少一次数组读"的优化，写不写都对。
（⚠️ 例外：如果题目**允许重复访问**（比如统计路径条数），那才必须传父亲或用别的判重方式。）

</details>

<details><summary>Q2：为什么 `cnt[++timer] = {x,y}` 写在 for 外面？</summary>

写在 for **外面** = 四个方向全走完、准备"出门"时才记 → **后序**（儿子排在父亲前面）；
写在 for **前面** = 一进门就记 → **先序**（父亲排在儿子前面）。
CF377A 必须用**后序**：只有"儿子在前"才能保证"删最前面 k 个 = 连根剪掉几棵完整子树"，剩下的才连通。

</details>

<details><summary>Q3：写法 B 里为什么是 `dfs(nx * m + ny)` 而不是 `dfs(nx)`？</summary>

因为参数是**格子编号**，编号的公式是 `u = x*m + y`，所以传进去之前必须把新坐标**先算成编号**。`dfs(nx)` 传的是行号，`u/m` 出来的 x 就完全不对了。

</details>

<details><summary>Q4：`u = x*m + y` 里的 m 能不能换成 n？</summary>

不能。编号必须**一一对应**：用 m（列数）才能保证"每行占 m 个编号、不重不漏"。换成 n 之后不同格子会算出同一个编号，DFS 会把两个格子当成一个，答案就乱了。

</details>

<details><summary>Q5：后序名单一定要开 `n*m` 吗？我开 5 万行不行？</summary>

- 如果开**小了**：小数据全对、大数据**不崩溃但算错**（实测 `timer` 243 而不是 125250）。
- 开 `250005` 只占 250005 × 16 字节 ≈ **4MB** 全局内存，完全无所谓（CF 内存限制一般 256MB）。
⇒ **一律开 `n*m + 5`**，别省。

</details>

<details><summary>Q6：为什么本地编译要加 `-Wl,--stack,268435456`？</summary>

本机 Windows 默认栈只有 1MB，递归深度上万就爆（实测链形/蛇形 25000 层 → 退出码 `0xC00000FD`）。加上这个参数把栈开到 256MB 就能跑。**注意这是本地调试用的**，评测机（Linux 栈通常 8MB+）不需要——但更稳的做法是直接用**迭代 DFS**，两边都不用管。

</details>
