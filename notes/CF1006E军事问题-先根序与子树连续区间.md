# CF1006E · 把全军排成一张名单，之后每次提问都只是"数格子"

> **一句话**：先排出一张**"谁第几个收到命令"的名单**，之后所有查询都只是在名单上数格子。
> 下面全部用 5 个人的小例子讲，不用任何术语。

---

## 一、先拿 5 个人试一遍（这是全题的钥匙）

组织结构（2、3 归 1 管；4、5 归 2 管）：

```
        1
       / \
      2   3
     / \
    4   5
```

现在 1 下命令，看谁第几个收到：

| 第几个收到 | 是谁 | 为什么 |
|---|---|---|
| 第 1 个 | 1 | 自己先收到 |
| 第 2 个 | 2 | 1 传给第一个手下 2 |
| 第 3 个 | 4 | 2 传给自己的第一个手下 4 |
| 第 4 个 | 5 | 2 再传给第二个手下 5 |
| 第 5 个 | 3 | 2 那边全传完了，1 才轮到第二个手下 3 |

**名单 = `1 2 4 5 3`**

---

## 二、看出来了吗：每个人的手下都"挤在一起"

| 谁 | 他的手下（含他自己）| 在名单上是第几格 |
|---|---|---|
| 1 | `1 2 4 5` 3 | 第 **1~5** 格（就是全部）|
| 2 | `2 4 5` | 第 **2~4** 格（**连着**）|
| 3 | `3` | 第 **5** 格 |
| 4 | `4` | 第 **3** 格 |

**为什么连着？** 因为传命令是**一条道走到黑**：1 一旦开始让 2 传，就得等 2 和他所有手下全部传完，才轮到 3。中间插不进任何人。

所以：**每个人的手下，在名单上是从"他那一格"开始的一段连续格子。**

---

## 三、所以查询就是数格子

问 **(2, 2)**：2 的手下里第 2 个是谁？
- 2 在第 **2** 格 → 往后数第 2 个 = 第 `2 + 2 - 1 = 3` 格
- 名单第 3 格写的是 **4** ✔（2 的手下顺序是 2,4,5，第 2 个正是 4）

问 **(1, 4)**：1 在第 1 格 → 第 `1 + 4 - 1 = 4` 格 = **5** ✔

所以你只需要两个数：

| 名字 | 意思 |
|---|---|
| `pos[u]` | u 在名单上的**第几格** |
| `cnt[u]` | u 手下**有多少人**（含自己）|

**答案 = `ord[ pos[u] + k - 1 ]`**；如果 `k > cnt[u]`（手下不够 k 个）→ 输出 **-1**。

---

## 四、名单和人数怎么算：**一段 dfs 全搞定**（按你平时的写法）

你平时写 dfs 是「**全局数组 + `void dfs(ll k)` + 全局答案变量 + 1-based**」，这题完全沿用：

```cpp
ll n, q;
ll par_[maxn];
vector<ll> ch[maxn];        // ch[u] = u 的直接手下，按名单顺序

ll pos_[maxn];              // 我第几个收到（我在名单上的第几格）
ll cnt[maxn];               // 我的手下人数（含自己）
ll ord_[maxn];              // 名单上第 i 格是谁
ll timer_ = 0;

void dfs(ll u) {
    // ★ 和你写数组 dfs 的唯一区别：这里【不用写"到边界就 return"】
    //   叶子没有手下，下面的 for 自然空转一圈就回来了
    pos_[u] = ++timer_;     // 我是第 timer_ 个收到的
    ord_[timer_] = u;       // 名单第 timer_ 格写上我
    cnt[u] = 1;             // 手下人数：先算我自己
    for (ll v : ch[u]) {    // 按名单顺序，挨个把手下的活派下去
        dfs(v);
        cnt[u] += cnt[v];   // 手下 v 传完回来，把他那边的总人数加进来
    }
}
```

只要这一遍，`pos_`、`ord_`、`cnt` 全都出来了 —— 和你的 P2392 那种"进去改、出来累加"的节奏一模一样。

主程序也很短：

```cpp
cin >> n >> q;
for (ll i = 2; i <= n; ++i) {       // 1-based
    cin >> par_[i];
    ch[par_[i]].push_back(i);       // i 从小到大读入 ⇒ 天然就是名单顺序，不用排序
}
dfs(1);
while (q--) {
    ll u, k; cin >> u >> k;
    if (k > cnt[u]) cout << -1 << '\n';          // 手下不够 k 个
    else cout << ord_[pos_[u] + k - 1] << '\n';  // 从他那一格往后数
}
```

> 附注（不想用递归时才需要）：`cnt` 也可以完全不用 dfs —— 题目保证 $p_i<i$，那就 `for (i = n; i >= 2; --i) cnt[父亲[i]] += cnt[i];`（倒着扫一遍）。实测 20000 棵随机树与真 DFS **逐点一致 ✅**。但既然你习惯递归 dfs，用上面的写法就够了。

## 五、⚠️ 但这段 dfs 本地跑极限数据会崩（实测，务必看）

如果树退化成一条直线 `1-2-3-…-200000`，你的 `dfs(1)` 会递归 20 万层。本机实测（Windows，默认栈只有 1MB）：

| 节点数（一条链）| 结果 |
|---|---|
| 20000 | 通过 |
| **25000** | **崩，退出码 -1073741571（0xC00000FD 栈溢出）** |
| 200000 | 崩 |

我用**你这版风格的同一个文件**编译了两次，跑 `cf1006e_big_chain.txt`（20 万节点的链）：

| 编译命令 | 结果 |
|---|---|
| `g++ -O2 -std=c++17 -o a.exe ...`（你平时那样）| **崩，退出码 -1073741571** |
| `g++ -O2 -std=c++17 -Wl,--stack,268435456 -o a.exe ...` | **通过，104ms，答案全对 ✅** |

> ⚠️ **评测机（Linux）的栈大得多，递归多半不会崩 —— 所以你会看到"本机崩、交上去却过"，很容易白白怀疑自己的代码。**
> **两个办法，任选：**
> **① 编译时加参数**（改动最小，继续用你习惯的递归写法）：本地编译命令加一句 `-Wl,--stack,268435456`；
> **② 改成"自己开栈"的写法**（本机线上都安全）：把 `dfs` 换成一个 `vector<int> st`，弹出栈顶就记进名单，儿子**倒着压**进去（这样弹出来才是正顺序）。

## 六、三个小地方别写错

| # | 注意 |
|---|---|
| 1 | **k 从 1 开始数**（自己是第 1 个）→ 要用 `k - 1`，写成 `k` 整体错一位 |
| 2 | **k 比手下人数大 → 输出 -1**（题目里有这种查询）|
| 3 | **查询最多 20 万条** → 不能每问一次就重跑一遍遍历（那是 O(n·q)，必超时）；必须预处理成 **O(1)** 回答 |

## 八、自查（3 题）

1. 第一节那棵树，问 **(1, 3)** 答案是多少？（提示：数格子）
2. 为什么 2 的手下在名单上一定是**连着**的？
3. 为什么算"手下人数"时可以**倒着按编号扫**？

<details>
<summary>答案</summary>

1. `ord[1 + 3 - 1] = ord[3] = 4`。（名单 `1 2 4 5 3` 的第 3 格是 4）
2. 因为传命令是"一条道走到黑"：必须把一个人的整棵子树全部传完才会离开他，所以他的手下之间插不进外人。
3. 因为 $p_i < i$ ⇒ i 的所有儿子编号都比 i 大 ⇒ 从 n 倒着扫时，儿子们的大小已经加到 i 头上了。
</details>
