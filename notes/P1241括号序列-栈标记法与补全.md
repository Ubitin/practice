# P1241 括号序列 —— 用栈"标记"出能配对的，剩下的一人补一个

> **触发点**：2026-09-29，你在做 [P1241 括号序列](https://www.luogu.com.cn/problem/P1241)，原话是"**我没有思路**"。
> **一句话结论**：**先用栈把"能配成对"的括号两两打上标记（不是真删！），然后从左到右输出——没标记的右括号在它【前面】补一个左括号，没标记的左括号在它【后面】补一个右括号。**
> **判据**：官方样例 `([()` → `()[]()` ✅、`([)` → `()[]()` ✅；穷举长度 ≤ 8 的全部 **87380** 个串，输出**全部**是合法规则序列、且**全部**包含原串为子序列 ✅。

---

## 一、题目（30 秒版）

**规则序列**的定义：

1. 空序列是规则序列；
2. 如果 `S` 是规则序列，那么 `(S)` 和 `[S]` 也是；
3. 如果 `A`、`B` 都是规则序列，那么 `AB` 也是。

给你一行只由 `( ) [ ]` 组成的串（**长度 ≤ 100**），**添加尽量少的括号**让它变成规则序列，输出补好的串。
（形式化的说法：**把原串当成子序列塞进输出里**，输出必须是规则序列。）

| 输入 | 输出 |
|---|---|
| `([()` | `()[]()` |
| `([)` | `()[]()` |

---

## 二、思路：**分两步，别想着一口气把答案拼出来**

很多人卡住是因为想"边扫边决定插什么"——那样每一步都不知道该插谁。**拆成两步就不难了**。

### 第 1 步：用栈找出"哪些括号能配成一对"

从左往右扫：

| 遇到 | 怎么做 |
|---|---|
| 左括号 `(` `[` | **入栈**（它举着手，等着被配对） |
| 右括号 `)` `]` | 看**栈顶**（= 它左边最近的那个还没配对的左括号）：<br>· 类型**对得上** ⇒ 这两个**配成一对**，各打一个**标记**，栈顶弹出<br>· 类型**对不上** ⇒ **什么都不做**（⚠️ **千万别弹栈**，见第四节） |

扫完后：**打了标记的 = 已经成对，不用补**；**没打标记的 = 落单，必须补**。

### 第 2 步：从左到右输出，落单的"一人补一个"

| 字符 | 有标记？ | 输出 |
|---|---|---|
| `)` | 有 | 直接输出 `)` |
| `)` | **没有** | 先补 `(`，再输出 `)` ← 补在它**前面** |
| `]` | **没有** | 先补 `[`，再输出 `]` |
| `(` | 有 | 直接输出 `(` |
| `(` | **没有** | 输出 `(`，再补 `)` ← 补在它**后面** |
| `[` | **没有** | 输出 `[`，再补 `]` |

🍜 **生活化类比**：一屋子人在**握手配对**（左手拉右手）。
栈记的就是"**谁还举着手在等**"。配对成功的两人各自打个勾；散场时——**还在举手的**给他补一只右手，**没手可拉的**给他补一只左手。

## 三、手推一遍（样例 1：`([()`）

**第 1 步（配对）**：

| 步 | 字符 | 栈（存下标） | 动作 | 标记 |
|---|---|---|---|---|
| 1 | `(`(0) | {0} | 入栈 | — |
| 2 | `[`(1) | {0,1} | 入栈 | — |
| 3 | `(`(2) | {0,1,2} | 入栈 | — |
| 4 | `)`(3) | {0,1} | 栈顶是下标 2 的 `(` ⇒ **配对**，标记 2、3，弹出 2 | m[2]=m[3]=✓ |

**第 2 步（输出）**：

| 下标 | 字符 | 有标记？ | 输出片段 |
|---|---|---|---|
| 0 | `(` | 没有 | `(` + 补`)` = `()` |
| 1 | `[` | 没有 | `[` + 补`]` = `[]` |
| 2 | `(` | 有 | `(` |
| 3 | `)` | 有 | `)` |

⇒ `()` + `[]` + `()` = **`()[]()`** ✅

**样例 2（`([)`）**：第 3 个字符 `)` 看栈顶是 `[`，**类型对不上** ⇒ 什么都不动；三个字符**全部落单** ⇒ `()` `[]` `()` ⇒ **`()[]()`** ✅

## 四、⚠️ 最关键的一个坑：类型对不上时【不要弹栈】

**为什么不能弹？** 因为栈顶那个左括号**并没有被用掉**，它只是"暂时挡住了视线"；把它弹掉等于宣布它作废——可它后面**可能还有机会配得上**（例如 `[` 和更右边的 `]`）。

**铁证（我实测的）**：拿官方样例 2 去试两种写法：

| 写法 | 输入 `([)` 的输出 | 判定 |
|---|---|---|
| **不弹栈（标准写法）** | `()[]()` | ✅ **与官方样例完全一致** |
| 对不上也弹栈 | `([])` | ❌ **与官方样例不符** |

⭐ 注意 `([])` 看起来"更短、更合理"，但**它就是错的**——洛谷给的答案是 `()[]()`。
**这条是本题唯一真正的"思维陷阱"，记住它这题就过了。**

## 五、骨架（只给关键几行，完整代码你自己敲）

```cpp
const int N = 105;
char s[N];
bool mk[N] = {false};      // 标记：这一位是不是"已经配好对"
int  st[N], top = 0;

scanf("%s", s);                       // 长度 ≤ 100，无空格，直接读
int n = strlen(s);

for (int i = 0; i < n; ++i) {
    if (s[i] == '(' || s[i] == '[') st[++top] = i;                 // 左括号：入栈
    else if (top && ((s[st[top]] == '(' && s[i] == ')') ||
                     (s[st[top]] == '[' && s[i] == ']'))) {        // 栈顶类型对得上
        mk[st[top]] = mk[i] = true; --top;                          // 配对 → 打标记 → 弹出
    }
    // else：对不上 ⇒ 什么都不做（★ 千万、千万别 --top）
}

for (int i = 0; i < n; ++i) {
    if (!mk[i] && s[i] == ')') putchar('(');   // 落单的右括号：前面补一个左括号
    if (!mk[i] && s[i] == ']') putchar('[');
    putchar(s[i]);
    if (!mk[i] && s[i] == '(') putchar(')');   // 落单的左括号：后面补一个右括号
    if (!mk[i] && s[i] == '[') putchar(']');
}
putchar('\n');
```

## 六、三个注意点

| # | 注意 | 为什么 |
|---|---|---|
| 1 | **类型对不上时不要弹栈** | 第四节，样例 2 钉死的 |
| 2 | **用标记数组，别去改原字符** | 有人想用 `s[i]++` 当标记——实测 `'(' + 1 == ')'`，正好把左括号变成右括号，后面全乱。老老实实开 `bool mk[]` |
| 3 | **补的位置别写反**：右括号补在**前**、左括号补在**后** | 写反了输出就不是规则序列 |

（数据规模很小：长度 ≤ 100，`O(n)` 就够，不用担心性能。）

## 七、⭐ 一句必须告诉你的"诚实话"：这个算法**不是**"最少添加"

题面写着"**添加最少的括号**"，但**这个标准算法在 25% 的串上并不是最短的**。

**实测（穷举所有长度 1~8 的串，共 87380 个）**：

| 检查 | 结果 |
|---|---|
| 输出一定是规则序列 | **87380 / 87380** ✅（0 例外） |
| 原串一定是输出的**子序列** | **87380 / 87380** ✅（0 例外） |
| 标准法补的个数 **>** 理论最少（用区间 DP 算的"最长规则子序列"） | **22026 个 = 25.21%** ⚠️ |

**最小的反例就是官方样例 2 本身**：

| 输入 | 标准法输出（补 3 个） | 更短的合法答案（补 1 个） |
|---|---|---|
| `([)` | `()[]()` ← **官方答案** | `([])` |
| `[(]` | `[]()[]`（补 3 个） | `[()]`（补 1 个） |

⇒ **为什么官方选更长的那个？** 因为题面还有一句：
> "……把你找到的规则序列输出即可。**因为规则序列可能不止一个，因此要求输出的规则序列中嵌套的层数尽可能地少。**"

`()[]()` 的**嵌套层数是 1**，`([])` 是 **2** —— 这就是它选前者的依据（"层数最少"优先于"补得最少"）。

⇒ **结论：千万不要自作聪明去写"求最少添加"的区间 DP**——那样你会输出 `([])`，被**判 WA**。**照第五节写就对了。**

## 八、自查（先自己想，再展开）

<details>
<summary>① 输入 `)(` 输出什么？</summary>

`()` + `()` = **`()()`**。
两字符都落单：`)` 栈空没得配 → 前面补 `(`；`(` 没人来配 → 后面补 `)`。
</details>

<details>
<summary>② 输入 `([]` 输出什么？</summary>

**`()[]`**。
配对过程：`(` 入栈 → `[` 入栈 → `]` 与栈顶 `[` **配对**（标记 1、2，弹出）。
输出：下标 0 的 `(` 落单 ⇒ `()`；下标 1、2 有标记 ⇒ `[]`。合计 `()[]`（补 1 个）。
</details>

<details>
<summary>③ 输入 `([)]` 输出什么？</summary>

**`()[()]`**。
配对：`(` 入栈 → `[` 入栈 → `)` 看栈顶是 `[`，**对不上**（不动）→ `]` 看栈顶是 `[`，**配对**（标记 1、3，弹出）。
输出：`(` 落单 ⇒ `()`；`[` 有标记 ⇒ `[`；`)` 落单 ⇒ `()`；`]` 有标记 ⇒ `]` ⇒ `()[()]`（补 2 个，正好等于理论最少）。
</details>

<details>
<summary>④ 为什么"对不上就弹栈"是错的？</summary>

因为被弹掉的那个左括号**并没有被用掉**——它只是暂时在栈顶挡路，后面可能还有机会配上（典型：`[` 与更右侧的 `]`）。
弹掉它 = 白白作废一个本来能配对的左括号 ⇒ 结果和官方答案不一致（样例 2：得 `([])` 而非 `()[]()`）。
</details>

<details>
<summary>⑤ 如果把"对不上的栈顶"弹掉、同时还把它标记成落单，结果会变吗？</summary>

会变（就是第四节的错误版本）。
栈顶作废后，后面的右括号会去配**更里层**的左括号，于是配对结构整个改变 ⇒ 输出 `([])`，与官方样例 2 的 `()[]()` 不符。
</details>

## 十一、追问："如果第一个字符就是右括号呢？"（2026-09-29 实测）

### 11.1 正确行为：靠"判空"直接跳过它

第一个字符是右括号时，**栈是空的** ⇒ `else if (top && ...)` 里那个 **`top &&`**（或 `stack` 版的 `!st.empty()`）让条件直接短路 ⇒ **什么都不做**，这个字符保持"落单"状态 ⇒ 输出时在它**前面补一个左括号**。

> 一句话：**右括号开头不需要任何特殊处理——判空这一句就是为它准备的。**

**实测（正确写法）**：

| 输入 | 输出 | 补了几个 |
|---|---|---|
| `)` | `()` | 1 |
| `]` | `[]` | 1 |
| `)(` | `()()` | 2 |
| `))(` | `()()()` | 3 |
| `)()` | `()()` | 1 |
| `)())` | `()()()` | 2 |
| `][` | `[][]` | 2 |
| `][(` | `[][]()` | 3 |
| `)))))` | `()()()()()` | 5 |

规律：**每个落单的右括号各自单独补一个左括号**，所以连续几个右括号开头就是 `()()()...`。

### 11.2 ⚠️ "忘写判空"会怎样：去读一个**根本不存在的栈顶**

栈空时栈顶不存在，而你写了 `s[st[top]]` ⇒ 读到一个**未初始化或陈旧的下标**。两种常见写法实测：

| 写法 | 栈空时实际读到的是 | 穷举长度 ≤ 6（共 5460 个串）输出**不合法**的比例 |
|---|---|---|
| **1 基**：`st[++top] = i`，读 `st[top]` | `st[0]` —— 1 基下**从没写过**，恒为 0 ⇒ 等于拿 **`s[0]`** 去和当前字符比 | **432 个 = 7.91%** ❌ |
| **0 基**：`st[top++] = i`，读 `st[top]`（忘了 `-1`） | `st[top]` 是**下一个空槽** ⇒ 未初始化 / 上一次留下的**陈旧下标** | **2767 个 = 50.68%** ❌（多串连跑时） |

**反例（1 基写法）**：

| 输入 | 正确输出 | 忘判空输出 | 后果 |
|---|---|---|---|
| `())` | `()()` | **`())`** ❌ | 第三个 `)` 被"假配对"标记成已配对 ⇒ 不再补括号 ⇒ **输出根本不是规则序列** |
| `[]]` | `[][]` | **`[]]`** ❌ | 同上 |

### 11.3 ⭐ 一个**反直觉**的实测结论

> **"第一个字符是右括号"恰恰是最安全的情形。**

因为忘判空时读到的是 `s[0]`，而它是**右括号** ⇒ 和右括号**永远配不上** ⇒ 侥幸地和正确写法一模一样（实测 `)`、`)(`、`))(`、`)()` 在两种错误写法下都"侥幸给对"）。

真正翻车的是**第一个字符是左括号**的情形（`())`、`[]]`）。

⇒ **但这份运气绝对不能依赖**，三个理由：

1. **换成 `std::stack` 的 `top()`**：**空栈上调用 `top()` 是标准规定的未定义行为**（读越界内存）—— 可能读到垃圾、也可能直接崩，**跟你 `s[0]` 是什么毫无关系**。
2. **用 `st[top]`（0 基忘了 `-1`）**：读到的是**陈旧下标**，行为依赖历史。我实测同一个程序里**连续处理多个串**时，**以右括号开头的反例就出现了**：`))(` → 输出不合法的 `)()(`、`)[(` → `()][`、`][(` → `][`。
3. 所以：**判空不是"保险"，是必须。**

### 11.4 骨架里的那一句就是它

```cpp
// 数组版
else if (top && ((s[st[top]] == '(' && s[i] == ')') ||
                 (s[st[top]] == '[' && s[i] == ']'))) { ... }
//        ^^^^^ 就是防"第一个字符/栈空时来了右括号"的

// std::stack 版
else if (!stk.empty() && match(stk.top(), s[i])) { ... }
//        ^^^^^^^^^^^^^^ 同理，缺了它就是 UB
```

<details>
<summary>⑥ `)))` 输出什么？</summary>

**`()()()`**。三个 `)` 全部落单（每次看栈都是空的），各自补一个 `(`。
</details>

<details>
<summary>⑦ `][(` 输出什么？</summary>

**`[][]()`**。`]` 落单 → `[]`；`[` 落单 → `[]`；`(` 落单 → `()`。
</details>

<details>
<summary>⑧ 忘写判空时，为什么"以右括号开头"反而侥幸不错？</summary>

因为读到的那个"假栈顶"等价于 `s[0]`（1 基下 `st[0]` 恒为 0），而 `s[0]` 是**右括号** ⇒ 和任何右括号都配不上 ⇒ 恰好等价于"什么都不做"的正确行为。
⚠️ 这是**巧合**，不是设计：换成 `std::stack::top()`（UB）或 0 基 `st[top]`（陈旧值）就会翻车。
</details>
