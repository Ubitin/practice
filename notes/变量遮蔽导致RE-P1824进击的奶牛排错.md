# 变量遮蔽导致崩溃（RE）—— P1824 进击的奶牛排错

> 触发点：P1824 提交后不是 WA 而是**崩溃**——程序没有任何输出。代码在 `test_\01.cpp`。
> 一句话：**main 里 `vector<long long> a(n,0);` 遮蔽了全局的 `vector<long long> a;`**，于是 `main` 把数据读进了**局部 a**，而判定函数 `p()` 读的是**全局 a**——它始终是空的，`a[0]` 就是解引用空指针。
> 实测：退出码 **-1073741819 = 0xC0000005 = ACCESS_VIOLATION**；`g++ -Wshadow` 会**直接指出**这一行。
> 演示程序：`test_\01_p1824_check.cpp`；修正版：`test_\01_p1824_fixed.cpp`（**原文件 `test_\01.cpp` 保持原样未改动**）。

---

## 一、症状：程序崩溃，不是算错

| 输入 | 期望 | 原码实测 |
|---|---|---|
| `5 3` / `1 2 8 4 9` | 3 | **无任何输出** |
| `2 2` / `1 10` | 9 | **无任何输出** |
| `3 2` / `5 5 5` | 0 | **无任何输出** |

而且**退出码不是 0**：

```
退出码 = -1073741819
       = 0xC0000005   ← Windows 的 ACCESS_VIOLATION（访问违规）
```

> **判题三态先分清**：**WA** 有输出但不对；**TLE** 超时；**RE** 运行崩溃（无输出 / 非零退出码）。
> 看到"一点输出都没有"，第一反应应该是 **RE**，而不是"算法错了"。

## 二、定位：`-Wshadow` 让编译器直接说出来

```powershell
g++ -std=gnu++17 -O2 -Wall -Wshadow 01.cpp -o cur.exe
```

**实测输出（原文）**：

```
01.cpp: In function 'int main()':
01.cpp:38:22: warning: declaration of 'a' shadows a global declaration [-Wshadow]
   38 |     vector<long long>a(n,0);
      |                      ^
01.cpp:4:18: note: shadowed declaration is here
    4 | vector<long long>a;
      |                  ^
```

编译器把两个 `a` 都指出来了：**全局的在第 4 行，遮蔽它的局部变量在第 38 行。**

> `-Wshadow` 不在 `-Wall` 里，**必须显式加**。它专抓这类"重名"事故，强烈建议每个题目都开。

## 三、机制：发生了什么

你的代码里有两个同名的 `a`：

```cpp
// 第 4 行：全局作用域
vector<long long> a;            // ← 空 vector

bool p(long long x){
    long long last = a[0];      // ← 这里用的是【全局 a】
    ...
}

int main(){
    cin >> n >> m;
    vector<long long> a(n, 0);  // ← 第 38 行：main 里的【局部 a】，遮蔽了全局
    for(...) cin >> a[i];       //   数据读进了【局部 a】
    sort(a.begin(), a.end());   //   排序的也是【局部 a】
    long long ans = find(l, r);
}
```

**名字查找规则**：`p()` 在函数内部找不到 `a`，就往**全局作用域**找，找到那个空的全局 `a`。而 `main` 里的 `a` 是**局部变量**，只对 `main` 可见，**`p()` 根本看不见它**。

**实测复刻**：

```
局部 a（main 里读取+排序用的）: size = 5
全局 a（p() 实际读到的）      : size = 0     ← 永远是空的
```

### 为什么是崩溃而不是 WA

`std::vector` 默认构造时**不分配内存**，`data()` 通常是 `nullptr`。对空 vector 取 `a[0]` 等价于：

```cpp
*(a.data() + 0)   →   *(nullptr)   →   解引用空指针
```

`operator[]` **不做边界检查**，所以不会有任何报错——直接由操作系统判定为访问违规，进程被杀。

> 记住：**`vector::operator[]` 越界是 UB，不是"抛异常"。** 想让它检查就用 `.at()`（会抛 `std::out_of_range`），但机试里基本不用。

## 四、第二个隐藏 bug：`find(long l, long r)` 的 32 位溢出

```cpp
long long find(long l, long r){        // ← 形参用 long，不是 long long
    while(l <= r){
        if(p(mid = (l + r) >> 1)) ...  // ← l + r 按 long 算
```

**本机实测**：

```
sizeof(long)      = 4 字节        ← Windows/MinGW-w64 是 LLP64 模型
sizeof(long long) = 8 字节
LONG_MAX          = 2147483647
```

你的 `main` 传的是 `r = 2e9`。考虑一次真实中间状态 `l = 1000000001`、`r = 2000000000`：

| 算法 | 结果 |
|---|---|
| `long long` 正确和 | **3000000001** |
| 用 32 位 `long` 算 | **-1294967295** ← 溢出，符号都翻了 |

于是 `(l + r) >> 1` 得到的 `mid` 是垃圾值，**二分直接跑偏**。

> ⚠️ **这个 bug 在你本机（Windows/MinGW）会炸，但在洛谷（Linux/LP64）上 `long` 是 64 位，反而侥幸不炸。**
> 这就是"本地 AC、提交 WA"（或反过来）的经典成因之一。**解决办法只有一个：别用 `long`，一律 `long long`。**

## 五、修正

三处改动：

### ① 只保留**一个** `a`（删掉 main 里的重名声明）

```cpp
vector<long long> a;          // 全局：p() 和 main 共用同一个

// main 里改成：
a.resize(n);                  // ✅ 往全局 a 里放数据
for (ll i = 0; i < n; ++i) cin >> a[i];
```

### ② `find` 的形参改成 `long long`

```cpp
long long find(long long l, long long r){
    long long ans = 0;
    while (l <= r) {
        long long mid = (l + r) >> 1;      // 括号别省；全是 long long
        if (p(mid)) { ans = mid; l = mid + 1; }
        else r = mid - 1;
    }
    return ans;
}
```

### ③ 顺手把上界收紧（可选）

```cpp
long long hi = a[n-1] - a[0];   // 答案不会超过「最远两个牛棚的距离」
```
比 `2e9` 少跑一两轮，也顺便避免"上界过大 + `int/long` 溢出"的隐患。

### 完整修正版（`01_p1824_fixed.cpp`）

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

ll n, c;
vector<ll> a;                 // ★ 只保留这一个 a

bool ok(ll d) {               // 最小间距 d 时最多能放几头牛
    ll cnt = 1, last = a[0];  // 第一头放最左边
    for (ll i = 1; i < n; ++i) {
        if (a[i] - last >= d) { ++cnt; last = a[i]; }   // 贪心：能放就放
        if (cnt >= c) return true;
    }
    return cnt >= c;
}

int main() {
    ios::sync_with_stdio(false); cin.tie(nullptr);
    cin >> n >> c;
    a.resize(n);
    for (ll i = 0; i < n; ++i) cin >> a[i];
    sort(a.begin(), a.end());

    ll lo = 0, hi = a[n - 1] - a[0];
    while (lo < hi) {
        ll mid = lo + (hi - lo + 1) / 2;   // 上取整（配 lo = mid）
        if (ok(mid)) lo = mid;
        else         hi = mid - 1;
    }
    cout << lo << '\n';
    return 0;
}
```

## 六、你代码里**做对了**的部分

别全盘否定，这几处是对的：

| 检查项 | 判定 |
|---|---|
| `p()` 的贪心：第一头放最左，之后每头放在第一个 ≥ `last + d` 的位置 | ✅ 标准解法，正确 |
| 二分的是**值域**（最小距离）而不是数组下标 | ✅ 避开了上一轮那个坑 |
| `mid = (l + r) >> 1` 写在**条件里**，每轮都重新赋值 | ✅ 没有上一轮的死循环问题 |
| `sort` 了 | ✅ 贪心必须基于有序位置 |
| `ans = 0` 有初值 | ✅ 比 P1873 那个题解稳 |

**只有两个 bug**：变量遮蔽（致命）和 `long` 形参（隐患）。

## 七、如何自查这类问题

### 1. 编译时永远带上这三个开关

```powershell
g++ -std=gnu++17 -O2 -Wall -Wextra -Wshadow 01.cpp -o 01
```

`-Wshadow` 专抓变量遮蔽——**这次它一句话就把 bug 指出来了，比我读代码快得多。**

### 2. 看退出码，区分 WA / RE

| 退出码 | 含义 | 常见原因 |
|---|---|---|
| `0` | 正常结束 | — |
| `-1073741819` / `0xC0000005` | **访问违规**（Windows） | 空指针、数组越界读写 |
| `-1073741571` / `0xC00000FD` | **栈溢出** | 递归太深、大数组开在函数内（应放全局） |
| `-1073741676` / `0xC0000094` | **整数除零** | 除数没判 0 |
| Linux 上 `139` | SIGSEGV 段错误 | 同"访问违规" |
| Linux 上 `136` | SIGFPE | 除零 |
| Linux 上 `134` | SIGABRT | `assert` 失败、`std::vector::at` 越界抛异常 |

> PowerShell 里看退出码：`& .\01.exe; $LASTEXITCODE`

### 3. "无输出 + 非零退出码" 的排查顺序

1. 数组/`vector` 是不是空的就取下标了？
2. 有没有**同名变量遮蔽**？（`-Wshadow`）
3. 递归深度是否过大？
4. 函数内是不是开了大数组？（应移到全局）

### 4. 一条预防规则

> **全局变量一旦声明，`main` 里就不要再写一遍同名声明。**
> 要么全用全局（机试最省事），要么全用局部——**绝不混着来**。

## 八、自查

1. `main` 里写 `vector<long long> a(n,0);` 时，函数 `p()` 里的 `a` 指的是哪一个？为什么？
2. 为什么这次是**崩溃**（RE）而不是 WA？空 `vector` 的 `a[0]` 到底做了什么？
3. 哪个编译选项能让编译器主动告诉你"这里有变量遮蔽"？它在 `-Wall` 里吗？
4. `sizeof(long)` 在你本机是多少？和 `sizeof(long long)` 差在哪？为什么 `l + r` 用 `long` 会溢出？
5. 退出码 `-1073741819` 是什么错误？`-1073741571` 呢？分别对应哪类代码问题？

**答案要点**
1. 指**全局**那个（空的）。因为 `main` 里的 `a` 是局部变量，只对 `main` 可见；`p()` 内部找不到 `a` 就往外层作用域找，找到全局的。这是**名字查找规则**，不是"就近取最新定义"。
2. 因为 `std::vector` 默认构造不分配内存，`data()` 通常是 `nullptr`，`a[0]` 等价于 `*(nullptr)` → 解引用空指针 → 操作系统判定访问违规、杀进程。`operator[]` 不做边界检查，所以连"越界"都不会提示。
3. `-Wshadow`。**不在** `-Wall` 里，必须显式加。
4. 本机 4 字节（Windows 是 LLP64 模型），`long long` 是 8 字节。`l + r` 在 `l=1e9+1, r=2e9` 时等于 3e9，超过 `LONG_MAX = 2147483647` → 溢出成负数 → `mid` 变垃圾值。洛谷是 Linux（LP64），`long` 是 64 位，所以侥幸不炸。
5. `-1073741819 = 0xC0000005` 是**访问违规**（空指针、越界读写）；`-1073741571 = 0xC00000FD` 是**栈溢出**（递归过深、函数内开大数组）。
