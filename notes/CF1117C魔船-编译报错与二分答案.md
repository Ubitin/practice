# CF1117C Magic Ship · 你的编译错误 + 正解（二分答案 + 风的前缀和）

> **触发点**：你问"我代码怎么编译错误了"（`test_\01.cpp`，`ll ti[1e9][1e9]`）。
> **一句话结论**：**编译错误与语法无关，纯粹是数组太大**——`1e9 × 1e9 × 8 字节 = 8×10¹⁸ 字节`，编译器连"元素个数"这个常量都写不进指令里，于是**汇编器报错**（`value of 6f05b59d3b20005d too large for field of 4 bytes`，那个十六进制数正是 `8e18`）。
> ⭐ **更重要的**：这题的坐标范围是 `±10⁹`，**二维数组在数学上就不可能开出来**（边长 2×10⁹，元素个数 4×10¹⁸）。正解是 **二分答案 + 风的前缀和**，一个坐标数组都不需要。

---

## 一、先把编译错误钉死

```cpp
const ll maxn = 1e9;
ll ti[maxn][maxn];        // ← 罪魁祸首
```

| 量 | 值 |
|---|---|
| 元素个数 | `1e9 × 1e9 = 1e18` |
| 字节数 | `1e18 × 8 = 8e18` ≈ **800 万 TB** |

**实测报错原文**（`g++ -O2 -std=c++17 -Wall -Wextra`）：

```
01.cpp: In function 'dot wind(char)':
01.cpp:21:1: warning: control reaches end of non-void function [-Wreturn-type]
C:\...\ccKbRAUv.s:225: Error: value of 6f05b59d3b20005d too large for field of 4 bytes at 0000000000000035
C:\...\ccKbRAUv.s:229: Error: value of 6f05b59d3b20006f too large for field of 4 bytes at 000000000000004f
...（共 11 条同类 Error）
```

把 `0x6f05b59d3b200000` 换算成十进制，正是 **8×10¹⁸** = `sizeof(ti)`。

**验证**：我只把 `const ll maxn = 1e9;` 改成 `2005`、并在 `wind()` 末尾补上 `return {0,0};`，编译**立刻通过（退出码 0）**。
⇒ **编译错误的唯一原因就是这个 `maxn`。**（对照文件 `test_\01_minsize_probe.cpp`）

### ⚠️ 但"把 maxn 改小"并不是解法

本题坐标范围 **`x, y ∈ [-10⁹, 10⁹]`**，`n ≤ 10⁵`：

```text
网格边长 = 2×10⁹ + 1
元素个数 = (2×10⁹)² = 4×10¹⁸
字节数   = 3.2×10¹⁹ 字节
```

**宇宙里没有这么多内存**——不是"开大一点"的问题，而是**"这题不该用坐标矩阵"**。
（判据：只要坐标范围 ≥ 10⁷ 量级，任何 `[坐标][坐标]` 的二维数组都要先怀疑。）

### 顺带：`wind()` 缺 return（编译器已经警告了）

```cpp
dot wind(char c){
    if(c == 'U') return {0,1};
    else if(c == 'D') return {0,-1};
    else if(c == 'L') return {-1,0};
    else if(c == 'R') return {1,0};
}   // ← 走到这里没有 return ⇒ 返回垃圾值（UB）
```

`-Wall` 的 `control reaches end of non-void function` 说的就是它。补 `return {0,0};` 即可。

## 二、正解：二分答案 + 风的前缀和

### 2.1 思路（三步）

**第 1 步：把"风"变成前缀和。**
设风序列为 `s[0..n-1]`（周期 `n`）。预处理：

```text
px[i], py[i] = 前 i 天的风净位移（i = 1..n）
fx = px[n], fy = py[n]        // 一个完整周期的风位移
```

**第 2 步：算"如果船自己不努力，d 天后会被吹到哪"。**

```text
full = d / n,  rem = d % n
Wx(d) = fx * full + px[rem]   // ★ 完整周期 O(1) 算，不必模拟 d 天
Wy(d) = fy * full + py[rem]
```

**第 3 步：判断 d 天够不够。**
船每天最多自己走 1 格（可走四个方向，也可以不动，用于抵消风），所以：

```text
d 天后船能到达的区域 = 以 (x1+Wx, y1+Wy) 为圆心、半径 d 的菱形
⇒ 能到达 ⟺ 曼哈顿距离 |x2-(x1+Wx)| + |y2-(y1+Wy)| ≤ d
```

⭐ **为什么这不是"近似"？** 船自己每天能改变的水平/垂直距离之和恰好是 1（走一格）或 0（不动），
所以 d 天里它能"修正"的曼哈顿距离正好是 `0..d` 之间的**每个整数都能取到** ⇒ 条件既必要又充分。

**判定函数对 d 单调**（d 越大越容易满足）⇒ **二分答案**。

### 2.2 代码（新建 `test_\magicship_fixed.cpp`，**没动你的 `01.cpp`**）

```cpp
ll x1, y1, x2, y2, n;
cin >> x1 >> y1 >> x2 >> y2 >> n;
string s; cin >> s;

vector<ll> px(n + 1, 0), py(n + 1, 0);          // 风的前缀和
for (ll i = 1; i <= n; ++i) {
    ll dx = 0, dy = 0;
    if (s[i-1] == 'U') dy = 1;  else if (s[i-1] == 'D') dy = -1;
    else if (s[i-1] == 'L') dx = -1; else if (s[i-1] == 'R') dx = 1;
    px[i] = px[i-1] + dx;  py[i] = py[i-1] + dy;
}
ll fx = px[n], fy = py[n];

auto ok = [&](ll d) {                            // ★ 判定：d 天能否到达
    ll full = d / n, rem = d % n;
    ll wx = fx * full + px[rem], wy = fy * full + py[rem];
    return llabs(x2 - (x1 + wx)) + llabs(y2 - (y1 + wy)) <= d;
};

ll lo = 0, hi = 4000000000000000000LL / n * n;   // 安全大上界
if (!ok(hi)) { cout << -1 << "\n"; return 0; }   // 大上界都不行 ⇒ 永远到不了
while (lo < hi) {                                // 找最小可行 d
    ll mid = lo + (hi - lo) / 2;
    if (ok(mid)) hi = mid; else lo = mid + 1;
}
cout << lo << "\n";
```

**复杂度 `O(n + log(上界))`**，与坐标大小无关。

### 2.3 ⚠️ 你原码里另外两处会 WA 的地方（即使把数组改小也过不了）

| 位置 | 问题 | 后果 |
|---|---|---|
| `ll t = ti[ux][uy];` + `wind(wing[t])` | `wing` 是 `string`，`t` 会**无限增长** | `wing[t]` **下标越界**（`string::operator[]` 越界是 UB，可能崩、可能乱读）⇒ 必须写 `wing[t % n]` |
| `if(nx < 0 \|\| nx > rif \|\| ...)` | 判界用的是 `rif = 1e9`（"坐标上限"），但数组只有 `maxn` 那么大 | 只要 `maxn` 比 `1e9` 小，**判界就失效 ⇒ 越界读写全局数组**（典型的"静默错"） |
| `if(t <= n)` | `t` 是"到达时间"，用 `t <= n` 当边界很可疑（第一天是 t=0） | 天数一旦超过 n 就不再推风 ⇒ 逻辑错位 |

⭐ 这三处合起来说明一件事：**BFS 建在坐标空间上，在这个数据范围下根本不成立**（既开不下数组，也没法用坐标当状态）。这题必须换模型——也就是上面那套二分。

## 四、这题给你的一般教训（比这一题的解法更值钱）

| # | 教训 | 具体判据 |
|---|---|---|
| 1 | **数组维度先看坐标范围** | 坐标能到 `10⁹` ⇒ 任何 `[坐标]` 维度的数组都开不出来；能开的上限大致是 `元素个数 ≤ 2×10⁸` |
| 2 | **"编译错误"要先分类** | 语法错（`error: expected ...`）／模板错／**内存与常量太大（汇编器报错、`too large for field`）**——最后一类几乎都是数组尺寸写错 |
| 3 | **循环里用到的下标要有取模** | 风/季节/周期数组必须 `s[t % n]`；否则 `string[]` 越界是 UB |
| 4 | **判界要用"数组的实际大小"，不能用"题目给的坐标上限"** | `rif = 1e9` 与 `maxn` 不一致 ⇒ 越界静默发生 |
| 5 | **坐标转换类题别建矩阵** | 见到"±10⁹ 坐标 + 求最少步数/时间"就该想：二分答案、前缀和、坐标压缩、或直接用数学判定 |
| 6 | **二分答案的判定要能 O(1)/O(n) 算** | 本题判定 = 前缀和 + 曼哈顿距离，`O(1)`；这类"单调性 + 便宜判定"就是二分的信号 |

## 五、自查

<details><summary>Q1：为什么 `ll ti[1e9][1e9]` 报的是"汇编器错误"而不是"内存不足"？</summary>

因为编译器**还没到分配内存那一步**就失败了：它要把"数组元素个数"作为常量写进生成的汇编指令里，而这个常量是 `1e18`，超出了指令中 4 字节立即数能表示的范围，于是汇编器报 `value of ... too large for field of 4 bytes`。
换句话说：**这个错误发生在"生成代码"阶段，而不是"运行/链接"阶段**——所以它不是"运行时会爆"，而是"根本编不出来"。

</details>

<details><summary>Q2：为什么不能把坐标平移/压缩成 0..2e9 再用 1D 数组？</summary>

平移不改变数量：边长仍是 2×10⁹。
一维数组倒是能开（2×10⁹ 个 `int` ≈ 8 GB，仍然过大），但本题的 BFS 需要的是**二维状态**（位置 = 两个坐标），降到一维就是把坐标打包成一个整数 `u = x * K + y`，`K` 还是 2×10⁹ 量级 ⇒ 打包后的 `u` 有 4×10¹⁸ 种取值 ⇒ 照样不可能开数组。
**根本原因**：本题的状态空间大小 = 坐标范围²，与坐标范围是平方关系。

</details>

<details><summary>Q3：正解的判定 `|x2-(x1+Wx)| + |y2-(y1+Wy)| <= d` 为什么是充分必要的？</summary>

- **必要性**：d 天里船自己的总位移的曼哈顿长度最多是 d（每天最多走 1 格），而风把它带到了 `(x1+Wx, y1+Wy)`；两者的合成要到终点，距离不能超过自己走的量 ⇒ 距离 ≤ d。
- **充分性**：曼哈顿距离为 `k ≤ d` 时，先花 `k` 天沿两个轴走完差值（先走轴、再走另一轴），剩下的 `d-k` 天原地不动（或一对方向来回抵消）即可 ⇒ 一定能到。
（注意：船可以"不动"，所以天数多了不会溢出到别处。）

</details>

<details><summary>Q4：上界为什么取 `4e18 / n * n` 而不是随便一个大数？</summary>

因为要防止二分时 `mid` 附近的运算溢出（`fx * full` 里 `fx` 最大 `1e5`、`full` 最大 `d/n`，`d` 若取到 `9.2e18` 就会溢出 `long long`）。
取 `4e18 / n * n` 既是 `n` 的倍数（方便整数周期）、又远小于 `LLONG_MAX ≈ 9.2e18`。
更朴素的做法是取 `1e18`，也够用（本题答案的量级是 `(坐标差之和)/1 + 风的对抗`，最坏 `≈ 2×10⁹` 加上风的影响，绝不会接近 `1e18`）。

</details>

<details><summary>Q5：怎么自己发现"这题不能用 BFS 建网格"？</summary>

看两个数：**坐标范围 `10⁹`** 和 **要求的"最少时间" `≈10⁹`**。
- 状态数 = 坐标范围² = `4×10¹⁸` ⇒ 枚举不可能；
- 时间步 = `10⁹` ⇒ 模拟也不可能。
⇒ 剩下的路只有"**用数学/前缀和直接算**"或"**二分答案把问题变成判定**"。这也是本题最该条件反射的一点。

</details>

<details><summary>Q6：`wing[t]` 与 `wing[t % n]` 的差别到底在哪？</summary>

`t` 是到达某格的时间，会一路涨到答案量级（本题可达 `10⁹`）。`wing.size() == n ≤ 10⁵`。
- 写 `wing[t]`：`t ≥ n` 时是**越界访问**（`std::string::operator[]` 不做边界检查，`t == size()` 时返回 `'\0'`，`t > size()` 是 UB）⇒ 可能读到乱字符、可能崩。
- 写 `wing[t % n]`：把无限的时间轴折到周期上，符合"风按周期循环"的题意。
⚠️ 另外注意下标约定：你的 `ti[起点] = 0`，所以"第 1 天"用的是 `wing[0]`——写的时候要和自己定的时间定义对齐。

</details>
