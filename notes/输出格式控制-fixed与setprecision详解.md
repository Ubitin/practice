# 输出格式控制：fixed / setprecision / 宽度对齐

> 起因：你做"年龄与疾病"时**统计全对、格式全错**（缺段标签、百分比没保留两位小数）。这类"算法对、输出格式错"是机试最冤的丢分。
> 所有结论均已用 g++（C++17）实测（验证程序 `test_\09.cpp`）。头文件：`<iomanip>`（`<bits/stdc++.h>` 已包含）。

---

## 0. 为什么值得专门学

在线评测**逐字符比对输出**：`1-18: 100.00%` 写成 `1-18:100.00%`、`100%`、`100.0%` 全部判错。输出格式的每一个空格、冒号、小数位都是得分点。

## 1. 工具箱总览（5 个操纵符管 5 件事）

| 操纵符 | 作用 | 用法示例 |
|---|---|---|
| `setprecision(n)` | 精度（见 §2） | `setprecision(2)` |
| `fixed` | 定点表示：精度=小数位数 | `fixed << setprecision(2)` |
| `setw(n)` | 输出宽度（**一次性**！） | `setw(10)` |
| `setfill(c)` | 填充字符（配合 setw） | `setfill('0')` |
| `left` / `right` | 左/右对齐 | `left << setw(10)` |

## 2. 精度：setprecision 的两种模式（最重要）

**默认模式 = 有效数字**（不管小数点在哪）：
```cpp
cout << setprecision(3) << 123.456;    // 123    （3 位有效数字）
cout << setprecision(3) << 1234.56;    // 1.23e+03（位数不够就变科学计数法！）
```

**fixed 模式 = 小数点后固定位数**：
```cpp
cout << fixed << setprecision(2) << 123.456;   // 123.46（四舍五入）
cout << fixed << setprecision(0) << 3.7;       // 4
```

> **记忆公式：`fixed << setprecision(k)` = 小数点后 k 位**。这是机试里 90% 的精度需求（百分比、价格、分数）。
> 恢复默认：`cout << defaultfloat;`。

**一个坑**：fixed 模式下 `0.0001234` 保留 2 位小数会输出 `0.00`（实测）——**很小的数别用 fixed 乱截**，除非题目真要求。

## 3. 宽度与填充

```cpp
cout << setw(10) << 42 << "|";          // "        42|" 右对齐（默认）
cout << setw(10) << left << 42 << "|";  // "42        |" 左对齐
cout << setfill('0') << setw(5) << 42;  // "00042" 前导补零
```

**实战场景：时间补零**（输出 `09:05:00`）：
```cpp
int h = 9, m = 5, s = 0;
cout << right << setfill('0')
     << setw(2) << h << ":" << setw(2) << m << ":" << setw(2) << s << "\n";
```

## 4. 状态持久性速查（本讲义最易错的点）

| 操纵符 | 是否持久 | 说明 |
|---|---|---|
| `setw(n)` | **一次性** | 只对下一个输出生效，之后自动失效 |
| `setprecision` | 持久 | 设置后一直生效，直到再改 |
| `fixed` / `scientific` | 持久 | 同上 |
| `setfill(c)` | 持久 | 同上 |
| `left` / `right` | **持久** | 同上 |

**实测踩坑记录**（验证程序里真实发生过）：忘记 `left` 是持久的，导致后面的 `setfill('0') << setw(5) << 42` 输出成 `42000`（左对齐 + 右侧补零），时间也变成 `90:50:00`。

> 经验法则：**固定格式类操纵符（fixed/precision/fill/left）都是持久的，用完记得还原；setw 是一次性的，每次都要写。**

## 5. 浮点陷阱（为什么竞赛要 fixed）

```cpp
cout << fixed << setprecision(20) << 0.1 + 0.2;   // 0.30000000000000004441
```
double 的 0.1+0.2 不是精确的 0.3。所以**判浮点输出必须用 fixed + setprecision 限位**，否则结果不可控；比较浮点相等也要用"差值 < 1e-9"而不是 `==`。

## 6. printf 对照（C 课程必考，机试备用）

| 需求 | cout | printf |
|---|---|---|
| 宽度 5 右对齐 | `setw(5) << x` | `%5d` |
| 宽度 5 左对齐 | `left << setw(5) << x` | `%-5d` |
| 前导补零 | `setfill('0') << setw(5)` | `%05d` |
| 两位小数 | `fixed << setprecision(2)` | `%.2f` |
| 宽度+精度 | 组合 | `%8.2f` |
| 科学计数法 | `scientific` | `%e` |

实测：`printf("%5d|%-5d|%05d\n", 42,42,42)` → `   42|42   |00042`。

## 答案与解析

**E1** → `123`（默认模式=有效数字，123.456 的 3 位有效数字）。
**E2** → `123.46`（fixed=小数点后 2 位，四舍五入）。
**E3** → `cout << setfill('0') << right << setw(5) << 42;`（别忘了 `right`，否则左对齐补在右边成 `42000`）。
**E4** → `70`（left 是持久的：7 左对齐，'0' 填在右侧）。
**E5** → `setw` 一次性。例：`cout << setw(8) << 1 << 2;` 第二个数没有宽度（实测 `[       1][2]`）。
**E6** → 修正代码（`test_\01_age_fixed.cpp`）：
```cpp
const char* label[4] = {"1-18", "19-35", "36-60", "61-"};
cout << fixed << setprecision(2);
for (int j = 0; j < 4; j++)
    cout << label[j] << ": " << (double)cnt[j] / n * 100 << "%\n";
```

## 附：机试输出自检清单（提交前 30 秒）

1. 题目要几位小数？→ `fixed << setprecision(k)` 有没有写？
2. 有没有**段标签/前缀/分隔符**（如 `1-18:`）？逐字符对一遍样例。
3. 空格、换行、末尾空格是否符合？`endl` vs `'\n'`（endl 会刷新缓冲，循环里慢）。
4. 整数百分比会不会被整除吞掉？（`(double)cnt / n` 而不是 `cnt / n`）
5. 浮点输出有没有 fixed？（裸输出 0.1+0.2 是不可控的）

---

**一句话总结**：机试输出格式三件套——**`fixed << setprecision(k)` 管小数位、`setw` 管宽度（一次性）、`setfill('0')` 管补零（配 `right`）**；写完先对照样例逐字符检查，再提交。
