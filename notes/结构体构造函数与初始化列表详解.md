# 结构体构造函数与初始化列表详解（`Node(int l, int r, int s, int v) : ... {}` 与 `Node() {}`）

> **触发点**：2026-10-03，你贴了一段平衡树结点代码，问"这个结构体内部第三至第五行是在干什么？语法知识有什么"。
> **判定**：那三行是 **①带参构造函数 + 初始化列表**、**②默认构造函数**。它们不是"可有可无的装饰" —— **删掉 `Node() {}` 这段代码直接编译不过**（实测），而初始化列表写错顺序会踩 **UB**（实测崩过一次）。
> **一句话**：`Node(...)` 是**装配说明书**（怎么说，就怎么造）；`Node() {}` 是**留一个"不带参数也能造"的口子**，因为后面要开全局数组 `t[MAXN]`。

---

## 一、先把这段代码摊开逐行看

```cpp
struct Node {
    int left, right, size, value, num;                                    // ① 5 个数据成员
    Node(int l, int r, int s, int v)                                      // ② 带参构造函数（声明）
        : left(l), right(r), size(s), value(v), num( 1 ) {}               // ③ 初始化列表 + 空函数体
    Node() {}                                                             // ④ 默认构造函数
} t[MAXN];                                                                // ⑤ 顺便定义全局数组
```

| 行 | 名字 | 干什么 |
|---|---|---|
| ① | 数据成员 | 左右儿子编号、子树大小、权值、**该权值出现次数** |
| ② | **构造函数** | 名字和类型同名、**没有返回类型**；`Node a(1,2,3,4);` 时自动调用 |
| ③ | **初始化列表** | 冒号开头、逗号分隔、`成员名(初值)`；在函数体之前执行 |
| ④ | **默认构造函数** | 不带参数的构造函数；为了 `t[MAXN]` 能建出来 |
| ⑤ | 全局数组 | 定义 `MAXN` 个 `Node`，每个都要能"不带参数构造" |

**它在平衡树里干什么**：`left/right` 是左右儿子，`size` 是子树大小，`value` 是权值，`num` 是这个权值出现了几次。
典型用法（实测可跑，见 §七）：新建一个叶子结点只写一行

```cpp
t[++tot] = Node(0, 0, 1, v);      // 左右儿子 0、子树大小 1、权值 v、出现次数 1
```
⇒ 这就是构造函数的价值：**一行把新结点"装配"到合法状态**，不会漏字段。

## 二、第 ③ 行的核心：**初始化列表** vs 「在函数体里赋值」

两种写法看起来一样，实际不一样：

```cpp
Node(int l, int r, int s, int v) : left(l), right(r), size(s), value(v), num(1) {}   // A：初始化列表
Node(int l, int r, int s, int v) { left = l; right = r; size = s; value = v; num = 1; } // B：函数体赋值
```

对 `int` 这种内置类型，两者**结果一样、性能也一样**（都是写一次内存）。但**成员是"类类型"**（比如 `string`、`vector`）时差别就出来了 —— 实测（用一个带计数的类当成员）：

| 写法 | 构造函数调用 | 赋值调用 |
|---|---|---|
| **初始化列表** `c(7)` | **1 次** | 0 次 |
| 函数体赋值 `c = Count(7)` | **2 次** | **1 次** |

🍜 类比：**初始化列表 = 下单时就说清楚要什么，工厂直接按单生产**；函数体赋值 = **先给你一台默认配置的机器，再让你自己拆了重装**。

### 2.1 有四种情况**只能**用初始化列表（函数体赋值根本写不出来）

| # | 情况 | 例子 |
|---|---|---|
| 1 | `const` 成员 | `const int id;` ⇒ 只能 `: id(x)` |
| 2 | **引用**成员 | `int& ref;` ⇒ 只能 `: ref(x)` |
| 3 | 没有默认构造函数的类类型成员 | `vector<int> v;` 想在构造时给大小 ⇒ `: v(n)` |
| 4 | 基类初始化（继承时） | `: Base(x)` |

⇒ 结论：**养成"一律写初始化列表"的习惯**，比记这四条规则更省事。

### 2.2 `num( 1 )` 是什么？

`num` **不在参数列表里**，作者直接把它固定初始化成 `1`。
在平衡树里 `num` 表示"这个权值出现了几次"，而**新建结点当然是第 1 次出现** ⇒ 写成 `num(1)` 就不用每次调用都传这个参数了。
（写成 `num( 1 )` 那个空格是书上/题解里的**排版风格**，跟语法无关，别被吓到。）

## 三、⚠️ 顺序陷阱：初始化顺序**只看声明顺序**

这是初始化列表**唯一**真正坑人的地方：

```cpp
struct OrderDemo {
    int first, second;                                   // 声明顺序：先 first、后 second
    OrderDemo() : second(mark("second")), first(mark("first")) {}   // 列表里故意先写 second
};
```

**实测输出**：
```
真实初始化顺序：first -> second
初始化列表书写顺序：second -> first
```
⇒ **谁先声明，谁先初始化**；初始化列表里的书写顺序**被忽略**。
而且编译器会用 **`-Wreorder`** 警告提醒你：

```
warning: 'OrderDemo::second' will be initialized after [-Wreorder]
warning:   'int OrderDemo::first' [-Wreorder]
warning:   when initialized here [-Wreorder]
```

**这个坑为什么危险**：如果你写成 `first(second + 1)`（`first` 的初值用到 `second`），因为 `first` 先初始化、此时 `second` **还没构造** ⇒ **UB**。
⚠️ 我自己写第一版实验时就真崩了（用 `string` 做成员，在 `b` 构造前读 `b`）—— **进程直接没输出**。这是个"看起来只是顺序不同、实际会炸"的典型。

> ✅ 好习惯：**初始化列表按声明顺序写**（本例这样写就没有警告）：
> ```cpp
> int first, second;
> OrderDemo() : first(mark("first")), second(mark("second")) {}
> ```

## 四、第 ④ 行：`Node() {}` —— 为什么**删不掉**

### 4.1 它是什么

**默认构造函数**：不带参数的构造函数。它的存在让 `Node x;`、`Node arr[100];` 这种"不给参数就造对象"的写法成立。

### 4.2 ⚠️ 为什么这里**必须**有它（实测：删了就编译不过）

规则：**只要你自己写了任何一个构造函数，编译器就不再自动生成默认构造函数**。

因为第 ⑤ 行有 `} t[MAXN];` —— 定义这个**全局数组**时，每个元素都要**默认初始化**（等于"不带参数构造"）⇒ 必须有默认构造函数。
把 `Node() {}` 删掉后编译实测：

```
error: no matching function for call to 'Node::Node()'
   11 | } t[MAXN];
      |         ^
  • there are 3 candidates
    • candidate 1: 'Node::Node(int, int, int, int)'
      • candidate expects 4 arguments, 0 provided
    • candidate 2: 'constexpr Node::Node(const Node&)'      ← 只有拷贝构造
```

⇒ 这就是那句"写了带参构造，还得补一个默认构造"的由来。

### 4.3 `Node() {}` 里什么都没写，成员为什么是 0？

因为它**没有初始化任何成员**。全局数组仍然是 0，靠的是另一条规则：**全局/静态对象先整体零初始化，再执行构造函数**。实测：

| 对象 | 各成员的值 |
|---|---|
| 全局数组 `t[0..4]` | `left=0 right=0 size=0 value=0 num=0`（**全是 0**）|
| 局部 `Node x;` | `left=-1028582464 right=545 size=-1394087735 value=32761 num=2118574320`（**垃圾值**）|

⚠️ 所以：**局部变量不会自动变 0**（而且 GCC 会直接警告 `-Wuninitialized`：5 个成员全中）。
如果这个结构体要在函数内部当局部变量用，建议把默认构造写成下面任一种：

```cpp
Node() : left(0), right(0), size(0), value(0), num(0) {}   // 显式给 0
Node() = default;                                           // C++11：让编译器生成默认版本
// 或者（C++11 起）直接在成员声明处给默认值，最省事：
//   int left = 0, right = 0, size = 0, value = 0, num = 1;
```

## 五、这一小段代码里，你能学到的语法点清单

| # | 语法点 | 一句话说明 |
|---|---|---|
| 1 | **构造函数** | 名字 = 类型名、**无返回类型**、创建对象时自动调用 |
| 2 | **初始化列表** | `: 成员(初值), ...`，**先于函数体执行**，是"初始化"不是"赋值" |
| 3 | **默认构造函数** | 无参构造；**写了别的构造函数后，编译器就不再自动生成它** |
| 4 | `= default`（C++11） | "请编译器生成默认版本"，比手写空 `{}` 更明确 |
| 5 | **成员默认初值**（C++11） | 直接在声明处写 `int num = 1;`，可省掉默认构造 |
| 6 | **初始化顺序** = 声明顺序 | 与初始化列表书写顺序无关；不一致时 GCC 报 `-Wreorder` |
| 7 | **全局零初始化** | 全局/静态对象先整体清零，再跑构造函数；**局部对象不清零** |
| 8 | **拷贝构造 / 拷贝赋值** | 不自己写时编译器自动生成（按成员逐个拷贝）⇒ `t[++tot] = Node(...)` 能成立 |
| 9 | 聚合类型（aggregate） | 一旦有"用户提供的构造函数"，就不再是聚合类型，不能用 `{...}` 按成员顺序直接初始化 |
| 10 | 访问控制 | `struct` 默认 `public`；`class` 默认 `private`（这里全是 struct，所以外部能直接 `.left`）|

## 六、最常见的 5 个坑（对照自查）

| # | 坑 | 后果 | 避免 |
|---|---|---|---|
| 1 | 只写了带参构造，忘了默认构造 | **编译错误**（数组/容器建不出来） | 补 `Node() {}` 或 `Node() = default;` |
| 2 | 初始化列表顺序与声明顺序不一致 | `-Wreorder` 警告；**若初值互相依赖 ⇒ UB/崩溃** | 按声明顺序写 |
| 3 | 以为"空默认构造会把成员清零" | 局部对象是**垃圾值** | 显式初始化为 0，或用成员默认初值 |
| 4 | 成员是 `const` / 引用，却想用函数体赋值 | 编译错误 | 必须用初始化列表 |
| 5 | 类类型成员用函数体赋值 | 多一次默认构造 + 一次赋值（实测 1 次 vs 3 次调用） | 用初始化列表 |

## 八、自查

<details>
<summary>① `Node() {}` 里什么都没写，为什么全局数组 `t[]` 全是 0，而局部 `Node x;` 是垃圾值？</summary>

因为**全局/静态对象有"先零初始化、再跑构造函数"这条规则**：`t[MAXN]` 在程序启动时先被整体清零，然后（空的）默认构造函数跑一遍（什么都没改）⇒ 仍是 0。
而**局部对象不做零初始化**，默认构造又什么都没写 ⇒ 成员是"不确定值"（读它是 UB，GCC 会警告 `-Wuninitialized`）。
</details>

<details>
<summary>② 为什么删掉 `Node() {}` 会编译不过？</summary>

因为**你自己写了带参构造函数之后，编译器就不再自动生成默认构造函数**。而 `} t[MAXN];` 这个全局数组要求每个元素都能"不带参数构造" ⇒ 找不到无参构造 ⇒ 报 `no matching function for call to 'Node::Node()'`。
（同理：`vector<Node> v(n);` 也会因为同样的原因报错。）
</details>

<details>
<summary>③ 初始化列表 `: left(l), right(r), ...` 与函数体里 `left = l;` 有什么区别？</summary>

- **语义**：初始化列表是"**构造/初始化**"（对象在此刻诞生）；函数体里是"**赋值**"（对象已经用默认构造诞生过一次了）。
- **性能**：内置类型（`int`）没区别；**类类型成员**要"先默认构造、再赋值"，多一轮开销（实测：1 次构造 vs 2 次构造 + 1 次赋值）。
- **能力**：`const` 成员、引用成员、无默认构造的类类型成员、基类 —— **只能用初始化列表**。
</details>

<details>
<summary>④ `num( 1 )` 那个空格是什么意思？</summary>

纯粹是**排版**（书上/题解里为了好看加的），语法上就是 `num(1)`，即"用 1 初始化 `num`"。它让新建结点的"出现次数"默认是 1，调用方不必传这个参数。
</details>
