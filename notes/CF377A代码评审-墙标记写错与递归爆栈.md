## 一、你改对的那一行：为什么原来"必错"

```cpp
// 原来（错）
temp = '#' ? wall[j][i] = 1 : wall[j][i] = 0;
// 现在（对）
temp == '#' ? wall[j][i] = 1 : wall[j][i] = 0;
```

**为什么原来必错**——关键在运算符优先级：`?:` 比 `=` 高，所以那一行实际是这样结合的：

```cpp
temp = ( '#' ? (wall[j][i] = 1) : (wall[j][i] = 0) );
//        ↑↑↑
//        条件写成了【字符常量 '#'】，它的值是 35，非 0 ⇒ 恒为真！
```

于是 **每一格都被标成"墙"**，跟网格里真正的 `#` 一点关系都没有。

后面就连锁反应了：

```
wall 全是 true
  → dfs 从起点出发，四个方向全是"墙" ⇒ 一步都走不出去
  → 后序名单 cnt 只有 1 项（就起点自己）
  → 循环 for(i=1;i<=k;++i) 里，cnt[2..k] 全是 {0,0}（全局数组默认零初始化）
  → 真正写进去的 'X' 只有一个（就是起点那格），其余全写到 c[0][0]（这个坐标永远打印不到）
```

### 探针实测（把上面每句都量化）

| 探针项 | 实测值 | 应该是 |
|---|---|---|
| 网格里真正的 `'#'` | **1** 个 | 1 |
| `wall[][]` 被标成 1 的格子 | **12** 个（= 3×4 全部） | 1 |
| dfs 走完后序名单长度 `timer` | **1** | 11（= 空格数） |
| 写 `'X'` 的坐标 | `(1,3)` `(0,0)` | 两个真实的空格 |
| checker 判定 | **FAIL：变成墙的格子数 = 1，题目要求恰好 2** | OK |

### 为什么当时"看着挺像对的"

它只放了一个 `X`，而且**恰好放在起点那格**上 —— 输出是

```
....
..#.
X...
```

看上去"只是一处小错"，很容易让人以为"方向数组/边界/连通性写错了"，从而**往完全错误的方向排查**。这就是为什么这题**必须写 checker**：人眼根本判不出来。

### ⭐ 其实编译器早就提醒你了

用 `-Wall`（`-Wparentheses` 就在 `-Wall` 里）编译原版，第 43 行会连报两条：

```
cf377a_user_v3.cpp:44:37: warning: suggest parentheses around assignment used as truth value [-Wparentheses]
   44 |             temp = '#' ? wall[j][i] = 1 : wall[j][i] = 0;
      |                          ~~~~~~~~~~~^~~
cf377a_user_v3.cpp:44:54: warning: suggest parentheses around assignment used as truth value [-Wparentheses]
   44 |             temp = '#' ? wall[j][i] = 1 : wall[j][i] = 0;
      |                                           ~~~~~~~~~~~^~~
```

**改成 `temp == '#'` 之后，这两条警告完全消失**（只剩下 `tx/ty 可能未初始化` 那条）—— 这是"改对了"最硬的证据：编译器认了。

> **教训（一句话）**：**`=` 和 `==` 写错，编译器一定会警告，但只在 `-Wall` 下**。
> 以后每一份代码都这么编一下，10 秒钟的事：
> ```
> g++ -O2 -std=c++17 -Wall -Wextra -Wshadow -o a.exe a.cpp
> ```
> 零警告再交。上面这个 bug 在这一步就被拦住了，根本轮不到 WA。

## 三、⚠️ 唯一真正的风险：递归会爆栈

你的 `dfs` 是递归的，而 `n,m ≤ 500` 时**空格可以连成一条长蛇**（我造了 **500×500 蛇形走廊**，深度 ≈ **125250**）。

**实测同一份代码、同一个输入，只差一个编译参数**：

| 编译方式 | 结果 |
|---|---|
| `g++ -O2 -std=c++17`（默认） | **退出码 -1073741571 = `0xC00000FD`（栈溢出），输出 0 字节**（一行都没打印） |
| `g++ -O2 -std=c++17 -Wl,--stack,268435456` | **exit 0，41ms，checker 判 OK** ✅ |

原因：**Windows 默认栈只有 1MB**（见讲义 `CF1006E军事问题-先根序与子树连续区间`、`图DFS深度优先搜索-动画讲解`，同一个坑），12.5 万层递归 × 每层几十字节 ≈ 8MB，直接踩穿。

**怎么处理（二选一）**：
1. **本地编译加参数**（最快）：
   ```
   g++ -O2 -std=c++17 -Wl,--stack,268435456 -o a.exe a.cpp
   ```
   评测机（Linux）栈通常大得多，不加也多半能过 —— 但**你在本地会看到"一行输出都没有"，极易误判成代码写错而白排查**。
2. **改成显式栈的迭代 DFS**（最稳，两边都不怕）：讲义 `CF377A迷宫-反着删格子的连通构造` §四有现成骨架。

## 四、三件"顺手改一下"的事

### 1. `tx, ty` 没给初值（GCC 直接警告）

```cpp
ll tx,ty;          // ← 警告：'tx' may be used uninitialized
```
本题数据保证至少有一个 `'.'`，所以**碰不到**；但一行就能消掉警告、也免掉万一：
```cpp
ll tx = 1, ty = 1;
```

### 2. `break` 只跳出内层循环 → 你的起点不是"第一个空格"

```cpp
for(ll i = 1;i<=n;++i){
    for(ll j = 1;j<=m;++j){
        if(c[j][i] == '.'){ tx = j; ty = i; break; }   // ← 只跳出 j 这层
    }
}
```
所以 `tx,ty` 最后是 **"最后一个含 `.` 的那一行里、最靠左的空格"**，而不是全局第一个空格。

- **只要输入的空格是连通的，从哪个空格出发都对**，所以本题没影响 ✅
- 但不连通时会露馅，实测两组：

| 输入 | 你的输出 | 判定 |
|---|---|---|
| `5 3 3`：上 6 格一块 + 下 3 格一块 | 起点落在下面那块，正好把 **整块 3 格**删掉 | ✅ OK（**侥幸**：底部块大小恰好 = k） |
| `6 3 3`：上 3 格一块 + 下 6 格一块 | 起点落在下面那块，只删掉它的一半 | ❌ **FAIL：剩下的空格不连通，只有 6/12 能互相走到** |

（题面保证有解、数据里初始空格连通，所以这两组只是"如果数据不规范会怎样"。⚠️ **注意：把起点改成"真正的第一个空格"（打磨版那样）在多块数据上同样会挂**，只是挂法不同 —— 实测 `two.txt`（上 6 下 3、k=3）从上面那块删 ⇒ 只剩 3/6 连通；`two_big.txt` 同理只剩 3/12。**"从哪个空格出发都行"这句话的前提就是输入连通**。想彻底稳，就把起点搜索改成"找到第一个就跳两层"或者用 `goto`/标志位。）

### 3. 你把网格存成了 `c[列][行]`（转置）

```cpp
cin>>temp; c[j][i] = temp;      // i 是行、j 是列 ⇒ 存成了 c[列][行]
...
cout<<c[j][i];                  // 打印时又转回来 ⇒ 输出是对的
```
**存和取用的是同一套映射，所以自洽**（我用非方阵 5×9、1×5、5×1 都验过，全对 ✅），而且判界 `nx>m / ny>n` 也正好配套。

但它是个**埋雷**：以后你只要把读入改成 `c[i][j]`（更符合直觉），**边界条件就必须同时改成 `nx>n / ny>m`**，漏改一个就是越界或漏搜。建议现在就统一成 `c[行][列]`。

顺手还能把 dfs 里那两段绕的 if 合成一行：

```cpp
// 你的写法（对，但绕）
if(!wall[nx][ny]){ if(blank[nx][ny]) continue; }
if(wall[nx][ny]) continue;
// 等价的一行
if(wall[nx][ny] || blank[nx][ny]) continue;
```

另：`cnt[maxn * maxn]` = **252004** 个位置，刚好装得下 500×500 的 **250000** 个空格 ✅（上一轮提醒的"名单要按 n*m 开"你已经改对了；实测 25 万空格的最大用例跑通、checker OK）。

## 六、自查


<details><summary>Q1：为什么 `temp = '#' ? A : B` 里的条件恒为真？</summary>

`?:` 的优先级比 `=` 高，所以它是 `temp = ('#' ? A : B)`。条件就是字符常量 `'#'`，它的值 = 35（非 0）⇒ **恒为真**。跟 `temp` 里存了什么、跟网格是 `.` 还是 `#` **完全无关**。
写成 `temp == '#'` 才是"比较"，结果才会随 `temp` 变化。

</details>

<details><summary>Q2：为什么这个 bug 的后果是"只放了一个 X"，而不是乱码或崩溃？</summary>

三条链：① `wall` 全 true ⇒ dfs 一步都走不出去 ⇒ 名单只有起点 1 项；② `cnt` 是**全局数组**，`cnt[2..k]` 默认是 `{0,0}`（不是随机值，所以不崩）；③ 写出 `c[0][0]`，而下标 0 永远不会被打印循环访问到（循环是 1..n / 1..m）⇒ 那 k−1 次写入"消失"了。
**"不崩 + 只错一点点"是最难查的一类 bug**，所以必须靠 checker 而不是肉眼。

</details>

<details><summary>Q3：`-Wall` 当时给的是什么警告？为什么它是关键线索？</summary>

`-Wparentheses`：`suggest parentheses around assignment used as truth value`（"建议给用作真值的赋值加括号"），第 43 行连报两条（两个分支各一条）。它几乎就是在说"你把 `==` 写成 `=` 了"。`-Wall` 就包含这条，不需要额外开。

</details>

<details><summary>Q4：为什么我本地跑蛇形迷宫"一行输出都没有"？</summary>

退出码 `0xC00000FD` 是 **Windows 栈溢出**（STACK_OVERFLOW）。递归深度 12.5 万层 × 每层几十字节 > 默认 1MB 栈。**这是"代码对、环境不够"**，加 `-Wl,--stack,268435456` 或改迭代 DFS 即可。别去改算法。

</details>

<details><summary>Q5：我的输出和官方样例不一样，会被判错吗？</summary>

不会。CF377A 是**特判（special judge）**题，题面明说"如果有多个答案，输出任意一个"。样例输出是 `#.. / ... / ..X`，你输出 `#.X / X.. / ...`，**两者都合法**。所以我给的是 `cf377a_check.py`（校验"恰好 k 个新墙 + 原墙没动 + 剩余空格连通 + 空格数对"），而不是比对固定输出。

</details>

<details><summary>Q6：这题的数据会像 `6 3 3` 那样分成两块吗？</summary>

不会。① 题面保证"一定存在合法答案"，② 通行题解（含我的参考解）**全都只从一个空格搜一次** ⇒ 反推评测数据里初始空格是连通的。（详见讲义 `CF377A迷宫-反着删格子的连通构造` §十）

</details>
