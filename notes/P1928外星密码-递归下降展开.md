# P1928 外星密码 —— 递归下降展开（教材例 11-6）

> 题目：洛谷 [P1928 外星密码](https://www.luogu.com.cn/problem/P1928)。
> 压缩规则：连续的 D 个相同子串 X（**2 ≤ D ≤ 99**）压缩成 `[DX]`，而 X 里还能继续压缩（可嵌套）。
> 例如 4 个 `CB` 可写成 `4CB` 或 `2[2CB]`。给压缩串，求**原文**。
> 一句话解法：**遇到 `[` 就"进去读一层"（递归），遇到 `]` 就"交回这一层"（return）**。
>
> 🎬 **配套动画**：`figures/P1928-展开动画.html`（双击用浏览器打开，无需联网）——把"输入光标 / 递归栈 / 当前层产物 / 最终结果"四块同步演示，可播放、暂停、单步、回退、调速，也能自己输入测试串。页面对**非法格式**（如把 D 写在方括号外的 `3[CBCB]`）会给出提示。

## 一、为什么这题天生适合递归

压缩串的语法是**自相似**的：一个"压缩区" `[DX]` 里面装的 X，还是同一种结构（普通字符 + 压缩区）。
所以可以用**同一个函数**处理任意一层，靠"读到哪儿了"来决定何时结束：

| 递归三要素 | 在这道题里 |
|---|---|
| ① 同一个函数处理同构子问题 | `expand()` = "读并展开**一层**" |
| ② 边界（停止条件） | 读到 `]` → 本层结束，`return` 这一层的 X；读到 EOF → 最外层结束 |
| ③ 分解后合并 | 遇到 `[`：读重复次数 D → 递归拿到内层 X → 把 X 重复 D 次拼进结果 |

**谁在记"读到哪了"？** 不是下标，也不是参数，而是**输入流（cin）自己的位置**——
`expand()` 每读一个字符，流的位置就前进一格；递归进入/返回时，流停在原处，因此"接着往下读"天然正确。
这是递归下降解析最漂亮的一点：**不用显式传递解析进度**。

## 二、代码（教材版，逐行注释）

```cpp
#include <iostream>
#include <string>
using namespace std;

string expand() {                  // 读入并展开"一层"
    string s = "", X;
    char c; int D;
    while (cin >> c) {             // 持续读字符，直到 EOF（流读完）
        if (c == '[') {            // ① 发现压缩区
            cin >> D;              //    读重复次数（2~99，可能是两位数）
            X = expand();          //    递归展开内层，拿到完整的 X（只调用一次！）
            while (D--) s += X;    //    把 X 重复拼 D 次
        }
        else if (c == ']')         // ② 压缩区结束
            return s;              //    本层的 X 交回给上一层
        else                       // ③ 普通字符
            s += c;                //    直接成为这一层 X 的一部分
    }
    return s;                      // ④ EOF：最外层结束，返回完整原文
}

int main() {
    cout << expand();
    return 0;
}
```

| 代码点 | 说明 |
|---|---|
| `while (cin >> c)` | 一直读到没有字符（EOF）。**它顺带会跳过空白字符**（见坑 ②） |
| `cin >> D` | 直接把 `2`~`99` 读成整数；**不能只读一个字符**，否则两位数会被拆错 |
| `X = expand()` | 递归**只调用一次**，把内层完全展开后再重复拼接（这是本题最关键的写法） |
| `while (D--) s += X` | 用 `+=` 追加（均摊 O(1)），比 `s = s + X` 更省 |
| `return s`（`]` 处） | 这一层的 X 完成，交回上层 |
| `return s`（末尾） | 最外层读完整个输入后的返回 |

## 三、展开顺序（对应教材图 11-8）

以 `ABF[4RA[2A]B[3C]]` 为例，递归是"先钻到底，再逐层拼回来"：

```
第 1 层读取:  A B F  →  遇到 '[', D=4  →  递归进入
   第 2 层读取:  R A  →  遇到 '[', D=2  →  递归进入
      第 3 层读取:  A  →  遇到 ']'  →  返回 "A"
   第 2 层: X = "A", D=2 → 得到 "AA"；继续读 B → 遇到 '[', D=3 → 递归进入
      第 3' 层读取: C  →  遇到 ']'  →  返回 "C"
   第 2 层: X = "C", D=3 → 得到 "CCC"；遇到 ']' → 返回 "RA" + "AA" + "B" + "CCC"
第 1 层: X = "RAAABCCC", D=4 → 拼 4 遍；遇到 ']' → 返回
最终: ABF + RAAABCCC×4
```

**要点：`]` 是"逐层返回"的信号，`[` 是"再钻一层"的信号**——两种括号刚好对应递归的"下钻/回退"。

## 四、实测（g++ 16.2）

| 输入 | 输出 | 说明 |
|---|---|---|
| `AC[3FUN]` | `ACFUNFUNFUN` | **官方样例** ✓ |
| `ABF[4RA[2A]B[3C]]` | `ABF` + `RAAABCCC`×4 | 教材例子 ✓ |
| `[2[2[2AB]]]` | `AB`×8 | 三层嵌套 ✓ |
| `[12XY]` | `XY`×12 | 两位数 D ✓ |
| `ABCDEF` | `ABCDEF` | 无压缩区 ✓ |
| `A B` | `AB` | ⚠️ **空格被吞掉了**（`cin >>` 跳过空白），见坑 ② |

## 五、坑（都实测过）

### ① 别把递归写在重复拼接里：`while (D--) s += expand();` ❌

教材专门标注了这句"不能这样写"。实测对比（输入 `AC[3FUN]`）：

```
正确：X = expand(); while (D--) s += X;   →  ACFUNFUNFUN  ✅
错误：while (D--) s += expand();          →  ACFUN         ❌（少了 2 段）
```

原因：**每次调用 `expand()` 都会继续往输入流里读**。第一次调用读到 `]` 返回了 `FUN`；
第二次调用时流已经到末尾，返回空串 → 结果只拼了一段。正确做法是**展开一次，重复拼接展开结果**。

### ② `cin >> c` 会跳过空白字符

实测 `A B` → 输出 `AB`。本题输入不含空格，所以教材写法没问题；
但若原文里可能有空格，必须改用 `cin.get(c)` 或 `getchar()`（那样连空格、换行都读进来）。

### ③ 其它注意

- `D` 范围 2~99：用 `cin >> D` 读整数，不要只读一个字符；
- 递归返回只允许发生在 `]` 和 EOF 两处，别提前 `return`；
- 输出长度可能指数级膨胀 → 总复杂度 O(答案长度)；深度 = 嵌套层数（本题很浅，不会爆栈）；
- 若输入多组，注意最外层 `return` 之后流的状态。

## 六、教材给出的递归/递推取舍（值得记住）

> 如果能将大任务分解成若干**规模较小、形式与结构与原问题一致**的任务，就可以考虑递归；
> 当问题规模足够小或到达边界条件时停止。分解完之后还要把结果逐层合并、上报，解决最大规模的问题。
> 有些问题**递推策略和递归策略都能解决**，但有些问题只能把大问题分成小问题、却**很难建立递推式**——
> 这种情况下就应当使用递归。

对照本题：很难写出"从短串推到长串"的递推式（因为嵌套结构是**树形**的），
但递归下降几乎是把语法直接翻译成代码——这就是该类问题选递归的理由。

## 七、自查

1. 为什么 `X = expand(); while (D--) s += X;` 不能写成 `while (D--) s += expand();`？
2. `expand()` 靠什么记住"当前读到哪了"？为什么不需要把下标当参数传进去？
3. 什么情况下这段代码会丢掉原文中的空格？怎么改？
4. 这题为什么用递归比用递推自然？

答案提示：1. 每次调用都会继续消耗输入流，第二次调用读到的是流的后续内容（通常已到 EOF，返回空串）。2. 靠 `cin` 输入流的当前位置；递归进入/返回时流位置原样保留。3. 当原文含空格时（`cin >> c` 跳过空白）；改成 `cin.get(c)` 或 `getchar()`。4. 语法是自相似的树形结构，递归下降可直接按语法写；递推缺少"从小规模推到大规模"的自然顺序。
