# 辗转相除求 gcd · 那行 `while (b) { t = a % b; a = b; b = t; }` 到底在干什么

> **触发点**：你问"`test_\01_fraction_fixed.cpp` 的第 9 行是在干什么"。
> **一句话结论**：第 9 行是**欧几里得算法（辗转相除法）**的核心——反复把 `(a, b)` 换成 `(b, a % b)`，直到 `b == 0`，此时 `a` 就是最大公约数。
> **它的价值**：把"最坏要在 10¹⁸ 个数里试除"压成"**最多约 90 次迭代**"（实测同一对数：辗转相除 < 0.001 ms，**试除法 132 ms**）。

---

## 一、那三行逐字解释

```cpp
while (b) { ll t = a % b; a = b; b = t; }
```

| 片段 | 作用 |
|---|---|
| `while (b)` | `b == 0` 就停（此时 gcd 已经在 `a` 里） |
| `ll t = a % b;` | 先存余数——因为下一句 `a = b` 会把 `a` 覆盖掉 |
| `a = b;` | 把 `b` 挪到 `a` |
| `b = t;` | 把余数挪到 `b` |
| 整体 | 一次迭代 = `(a, b) → (b, a % b)` |

### 手推 `gcd(12, 8)`

| 轮次 | a | b | t = a % b | 迭代后 |
|---|---|---|---|---|
| 起 | 12 | 8 | — | — |
| 1 | 8 | 4 | 4 | (12,8) → (8,4) |
| 2 | 4 | 0 | 0 | (8,4) → (4,0) |
| 停 | **4** | 0 | | 返回 a = **4** ✅ |

### 再手推 `gcd(21, 14)`

`(21,14) → (14,7) → (7,0)` ⇒ 返回 **7** ✅

### 为什么这么做是对的（一句话直觉）

> 若 `d` 整除 `a` 也整除 `b`，则 `d` 必然整除 `a - k·b`，特别地整除 `a % b`。
> ⇒ **`gcd(a, b) = gcd(b, a % b)`**，两数的公约数集合不变，但数字越变越小 ⇒ 必收敛。

## 二、第 7、8 行（`if (a < 0) a = -a;`）为什么必要

因为 **C++ 的 `%` 保留符号**：`-12 % 8 == -4`（不是 4）。

- 负数直接进循环 ⇒ 得到**负的 gcd** ⇒ 再拿去做 `x /= g` 会把分数符号搞反；
- 所以做法是：**进门先把两个数变成非负**，再跑标准辗转相除。

⚠️ **但这一条要说清楚**：`if (a<0) a=-a;` 是**为了得到非负结果**，不是"负数会让循环不执行"——
见下面第三节的更正。

## 四、连带必须知道的两件事

### 4.1 `lcm` 必须先除后乘（否则溢出）

```cpp
ll lcm_(ll a, ll b) {
    ll g = gcd_(a, b);
    if (g == 0) return 0;
    return a / g * b;        // ✔ 先除后乘
    // return a * b / g;     // ✘ a*b 先溢出：a,b 都到 1e9 时 a*b 已到 1e18 贴上限
}
```

### 4.2 C++17 标准库已有，一行顶整段

```cpp
#include <numeric>
ll g = std::gcd(a, b);      // 自带处理正负，返回非负
ll l = std::lcm(a, b);      // 内部先除后乘，溢出安全
```

**实测**：`std::gcd(999999999999999989, 1000000000000000000) = 1` ✅、`std::gcd(-12, 8) = 4` ✅（**它自己会把符号处理成非负**）。
⇒ 所以手写那 6 行可以简化成一行 `std::gcd(x, y)`（前提：`abs(x)`、`abs(y)` 不溢出 `long long`，分数题的数量级下没问题）。

## 五、手写模板（背这个）

```cpp
ll gcd_(ll a, ll b) {
    if (a < 0) a = -a;                            // % 保留符号，先取绝对值
    if (b < 0) b = -b;
    while (b) { ll t = a % b; a = b; b = t; }     // 辗转相除 O(log)
    return a;                                     // b==0 时 a 就是 gcd
}
ll lcm_(ll a, ll b) {
    ll g = gcd_(a, b);
    return g ? a / g * b : 0;                     // ★ 先除后乘
}
```

**分数化简的标准三步**（就是你第 9 行所在函数的用法）：

```cpp
ll g = gcd_(x, y);          // ① 求 gcd（内部对绝对值做）
x /= g; y /= g;             // ② 同除
if (y < 0) { x = -x; y = -y; }   // ③ 符号统一放分子
```

⚠️ 边界：`gcd(x, 0) = |x|`；`gcd(0, 0) = 0`（标准库也一样）；分子为 0 的分式要特判输出 `0/1`。

## 六、自查

<details><summary>Q1：为什么 `t = a % b` 必须先存下来？</summary>

因为下一句 `a = b` 会把 `a` 覆盖掉。如果写成
`a = b; b = a % b;`，那么第二句里的 `a` 已经是新的 `b` 了，算出来是 `b % b = 0`，循环立刻结束、结果是错的。
⇒ 顺序必须是"**先算余数存起来 → 再移位**"。

</details>

<details><summary>Q2：辗转相除为什么是 O(log)？最坏情况是什么样的？</summary>

每次迭代 `(a, b) → (b, a % b)`，而余数 `a % b < b/1`，更精确地说 `a % b < b` 且当 `a < 2b` 时 `a % b = a - b`，两个数之和至少按斐波那契式下降 ⇒ 迭代次数约 `O(log_φ min(a,b))`。
**最坏情况就是相邻斐波那契数**（如 `F(90), F(89)` 附近）——那时候迭代次数最多（约 90 次）。
⭐ 这也是实测里 `gcd(99999999, 100000000)`（互素、要退到最后）最慢的原因，但它也只是"最慢"，仍然是微秒级。

</details>

<details><summary>Q3：`gcd(0, 0)` 是多少？`gcd(0, 5)` 呢？</summary>

`gcd(0, 5) = 5`（`while(b)` 第一次就 `b=5` 非 0，迭代后 `(5, 0)` ⇒ 返回 5；实际手算：`5` 是 0 和 5 的最大公约数）。
`gcd(0, 0)` 按定义为 0（所有数都能整除 0，约定最大公约数为 0），`std::gcd(0,0)` 也返回 0。
⚠️ 所以 `lcm_(0, b)` 要返回 0，避免除零。

</details>

<details><summary>Q4：为什么 `lcm = a / g * b` 就安全？</summary>

因为 `g = gcd(a,b)` 整除 `a`，所以 `a / g` 是精确的整数除法（不会丢精度）。
而 `a / g * b = lcm(a,b)`，且中间值 `a/g ≤ a`、结果 `≤ a*b/g` 是最小公倍数本身，**不会出现"中间值比答案还大"的情况**。
反过来 `a * b / g` 的中间值 `a*b` 可能比答案大 `g` 倍 ⇒ 容易溢出。
（`std::lcm` 内部就是按先除后乘实现的。）

</details>

<details><summary>Q5：分数题的化简，为什么要把符号统一到分子？</summary>

因为输出格式通常要求分母为正（`-1/2` 而不是 `1/-2`）。
另外比较分数大小时，分母为正才能用交叉相乘判断；分母为负会把不等号方向搞反。
⇒ `if (y < 0) { x = -x; y = -y; }` 就是这个作用。

</details>

<details><summary>Q6：如果题目要"区间 gcd"（多次询问某一段的 gcd），怎么办？</summary>

三种做法：
1. **前缀 gcd 不可行**（gcd 没有逆运算，不能像前缀和那样相减）；
2. **稀疏表（ST 表）**：`st[k][i] = gcd(a[i..i+2^k-1])`，`O(n log n)` 预处理、`O(1)` 查询（gcd 可重复计算，所以 ST 表适用）；
3. **线段树**：`O(n)` 建树、`O(log n)` 每次查询，**支持单点修改**（ST 表不支持修改）。
⇒ 不修改就 ST 表，要修改就线段树。
</details>
