# 先序 / 后序 / 层序：三种"名单"到底是什么

> **一句话**：**同一趟遍历，把"记录"这个动作放在"进门时"还是"出门时"，就得到先序名单或后序名单；改用队列一圈圈走，就得到层序名单。**
> 所谓"名单"，就是把遍历过程中"记下来的点"按先后排成的一张表。**名字取决于"什么时候记"，不取决于走法。**

---

## 一、定义：只看"什么时候把点记下来"

| 名单 | 什么时候记 | 一句话性质 |
|---|---|---|
| **先序**（又叫先根、前序）| **一进格子就记** | **父亲一定排在儿子前面** |
| **后序** | **四个方向都看完、要退出去时才记** | **儿子一定排在父亲前面** |
| **层序** | 用**队列**一圈圈走，出队时记 | 按"离起点的远近"排（近的在前）|

代码上只差 **`push_back` 写在哪一行**：

```cpp
void dfs(int u) {
    vis[u] = true;
    ord.push_back(u);                 // ← 写在这里 = 先序名单
    for (int v : 邻居) if (!vis[v]) dfs(v);
    ord.push_back(u);                 // ← 写在这里 = 后序名单
}
```
（所以"后序名单"就是**每个点"退回来"那一刻**记下来的顺序；在讲义「CF1006E」里我们叫它 `tout` 的顺序——**按结束时间排序**，是同一个东西。）

---

## 二、同一张迷宫，三种名单各长什么样（实测）

用 CF377A 那张 4×5 小迷宫（16 个空格）：

| 名单 | 前 6 个 | 总数 |
|---|---|---|
| **先序** | `(0,0) (1,0) (2,0) (3,0) (3,1) (3,2) …` | 16 |
| **后序** | `(0,1) (0,2) (0,3) (0,4) (1,4) (2,4) …` | 16 |
| **层序** | `(0,0) (1,0) (0,1) (2,0) (0,2) (3,0) …` | 16 |

看头几个就能感受到差别：
- 先序从**起点**开始，沿着"第一次走的路"往前铺
- 后序从**最深的末端**开始往回排（起点排在最后）
- 层序从**起点**开始，但按"一圈一圈"往外铺

---

## 三、关键差别：删"前 k 个"时，哪种名单能保住连通？（实测 20000 组随机迷宫）

| 策略 | 失败组数 |
|---|---|
| **A：后序名单，删前 k 个** | **0** ✅ ← CF377A 用的就是这个 |
| **B：层序名单，删后 k 个**（离起点最远的那批）| **0** ✅ |
| C：**先序**名单，删前 k 个 | **3838 组 ✗** |
| D：层序名单，删**前** k 个（最近的一圈）| **2900 组 ✗** |

**先序为什么容易挂**：先序名单的前缀是**"从起点出发一路走过去的那条路"**（父亲排在儿子前面）⇒ 删掉它等于**把必经之路挖空** ⇒ 剩下两块被切断。

最小反例（7×2，k=6）：
```
..
..
..
..
..
#.
..
```
DFS 先序的前 6 个恰好是左列 `(0,0)…(4,0)` 加 `(4,1)` —— 正好把上下两部分**切开** ⇒ 校验器判「剩余空格不连通」。
（后序则相反：前缀都是**最深的末端**，儿子在父亲前面 ⇒ 删掉的一定是"整棵小树枝"，主干不动。）

**层序删后缀为什么也对**：层序按远近排，删掉"最远的 k 个"之后，**留下来的每个点，它更近的邻居（BFS 树上的父亲）必然还在** ⇒ 顺着能一层层回到起点。

## 四、三种名单各自擅长什么（背这张表）

| 名单 | 典型用途 |
|---|---|
| **先序** | **子树 = 一段连续区间**（讲义 CF1006E：答案 = `ord[tin[u] + k - 1]`）；树上路径/前缀类问题 |
| **后序** | **删点保连通**（CF377A）；**树形 DP**（先把儿子算完再算爹）；表达式求值；有向图判环（回边）|
| **层序** | **无权最短路**（BFS）；按距离分层统计（"各层有多少点"）；多源扩散 |

> 一句话选型：**要"区间"用先序，要"从叶子往回处理"用后序，要"距离/最少步数"用层序。**

## 五、自查（先做完再翻答案）

1. 先序名单和后序名单，代码上只差什么？
2. "父亲一定排在儿子前面"是哪种名单？"儿子一定排在父亲前面"是哪种？
3. 为什么"删先序名单的前 k 个"很容易把图切断？用一个形状说明。
4. CF377A 为什么必须用后序？CF1006E 里用的是哪种？两者名单的用途差别在哪？
5. 求"最少走几步"该用哪种？

<details>
<summary>答案</summary>

1. 只差 `ord.push_back(u)` 的位置：写在**递归之前**是先序，写在**递归之后**（四个方向都看完）是后序。
2. 先序 → 父亲在前；后序 → 儿子在前（所以后序的最后一个永远是起点/根）。
3. 因为先序的前缀就是"从起点出发一路深入的那条路"，删掉它 = 把**必经之路**挖空。例如一条 2 列的长条（左列上 5 格 + 右列 7 格，中间有一个缺口），先序前 6 个正好是左列加右上第一格，删完上下两块就断开。
4. CF377A 要"删掉一些点但保持剩下的连通"，**只有后序前缀保证删的是"整棵完整子树"**（儿子排在父亲前面）⇒ 主干必然还在。CF1006E 用的是**先序**（要的是"子树在名单上连续"这个性质，配合时间戳区间取第 k 个）。
5. **层序**（BFS 队列顺序），因为层序天然按"离起点的步数"从小到大排。
</details>
