# 3 或 5 的倍数之和 · 你的 2341 是怎么来的（`ans` 没清零）

> **触发点**：你贴题面问"这道题 100 的输出真的是 2318 吗？为什么我是 2341"。
> **一句话结论**：**2318 是对的（样例不会错），你的 2341 = 23 + 2318** —— 你的 `ans` 是**全局变量**、写在 `while(t--)` **外面**，处理第 2 组时**没有清零**，于是把第 1 组的答案又加了一遍。**单独跑 `n = 100` 你的代码输出就是 2318**（实测），一放进多组数据就错。
> ⚠️ 而且这题**即使清零了也过不了**：`for(i=3;i<n;++i)` 逐个枚举，在 `T ≤ 1e5, n ≤ 1e9` 下要跑约 **1e14 次**循环（本机估算 ≈ **27.8 小时**），必须换 **O(1) 的容斥公式**。

---

## 一、先回答"2318 是不是真的"

**是真的。** 手算给你看（`< 100` 的 3 或 5 的倍数）：

| 类别 | 有哪些 | 个数 | 和 |
|---|---|---|---|
| 3 的倍数 | 3, 6, …, 99 | `⌊99/3⌋ = 33` | `3 × (1+2+…+33) = 3 × 561 =` **1683** |
| 5 的倍数 | 5, 10, …, 95 | `⌊99/5⌋ = 19` | `5 × (1+2+…+19) = 5 × 190 =` **950** |
| **15 的倍数（被数了两次）** | 15, 30, …, 90 | `⌊99/15⌋ = 6` | `15 × (1+…+6) = 15 × 21 =` **315** |

**并集 = 1683 + 950 − 315 = 2318** ✅

用 `1+2+…+m = m(m+1)/2` 这一条就能算，不需要真的把 3+6+9+… 一项项加出来。
（顺带核对 `n = 10`：`< 10` 的倍数是 3、5、6、9，和 = **23** ✅，与样例一致。）

---

## 二、你的 2341 是哪来的：`ans` 跨组累计

你的 `test_\01.cpp`：

```cpp
ll n, t;
ll ans = 0;                       // ← ★ 全局变量，整个程序只有这一个

int main(){
    cin >> t;
    while(t--){
        cin >> n;
        for(ll i = 3; i < n; ++i){
            if(i % 3 && i % 5) continue;
            ans += i;             // ← ★ 一直往上加，从来不归零
        }
        cout << ans << "\n";      // ← ★ 打印的是"从第一组到当前组的累计和"
    }
}
```

**逐组追一下**（这是最直观的证据，实测输出一模一样）：

| 组 | n | 本组应该加的 | `ans` 的实际值 | 正确输出 | 你的输出 |
|---|---|---|---|---|---|
| 1 | 10 | 23 | 0 + 23 = **23** | 23 | **23** ✅（碰巧对） |
| 2 | 100 | 2318 | 23 + 2318 = **2341** | 2318 | **2341** ✘ |

**`2341 = 23 + 2318`** —— 一分不差。第一组是对的，因为那时 `ans` 恰好是 0。

### 实测对照（同一份代码、同一份输入）

| 输入 | 你的代码 | 修正版 | 正确 |
|---|---|---|---|
| `2 / 10 / 100`（题目样例） | 23、**2341** | 23、2318 | 23、2318 |
| `3 / 10 / 100 / 10` | 23、2341、**2364** | 23、2318、23 | 23、2318、23 |
| `1 / 100`（**单独跑**） | **2318** ✅ | 2318 | 2318 |

⭐ 看第 3 行：**单独跑 `n = 100` 你是对的**——这正好证明错的**不是公式、不是边界，而是"跨组不清零"**。多组数据一定要用两组以上去测，否则这个 bug 会完全隐藏。

## 三、⚠️ 第二个问题（更重要）：逐个枚举在这个数据范围下必然 TLE

题面范围：`T ≤ 1e5`、`n ≤ 1e9`。

- 你每组循环 `n − 3` 次 ⇒ 合计约 **1e5 × 1e9 = 1e14 次**；
- 本机实测：**单组 `n = 1e8` 就要 80 ms**，按这个速度 `T = 1e5, n = 1e9` 需要约 **27.8 小时**。

**所以这题的考点根本不是"怎么写循环"，而是"怎么不写循环"** —— 用等差数列求和公式把每组压到 O(1)。

---

## 四、正解：容斥公式，每组 O(1)

### 公式三步

```text
① 设 m(k) = (n − 1) / k        //  < n 的 k 的正倍数个数（k, 2k, …, m·k）
② 设 S(k) = k · m(m+1) / 2     //  这些倍数之和 = k × (1+2+…+m)
③ ans = S(3) + S(5) − S(15)    //  3 的倍数 ∪ 5 的倍数：15 的倍数（公倍数）被数了两遍，减一次
```

**为什么是 `(n-1)/k` 而不是 `n/k`**——题面要的是"**小于 n**"：
- `n = 10, k = 3`：`(10-1)/3 = 3` ⇒ 3, 6, 9（正确，9 < 10）；若用 `10/3 = 3` 也对，但 `n = 9` 时 `9/3 = 3` 会把 9 算进去（9 不小于 9），`(9-1)/3 = 2` 才对 ⇒ **必须减 1**。
- 为什么用**容斥**：15 的倍数同时是 3 和 5 的倍数，直接相加会**重复计算**（实测重复量 = 315）。

### 代码（新建在 `test_\01_m35_fixed.cpp`，**未改动你的 `01.cpp`**）

```cpp
ll sumMul(ll n, ll k) {          // 所有 < n 的 k 的正倍数之和
    ll m = (n - 1) / k;
    return (ll)k * m * (m + 1) / 2;
}
int main() {
    ll t; cin >> t;
    while (t--) {
        ll n; cin >> n;
        ll ans = sumMul(n, 3) + sumMul(n, 5) - sumMul(n, 15);   // ★ 每组重新算
        cout << ans << '\n';
    }
}
```

**两处纪律**（正是你踩的坑）：
1. **`ans` 必须写在 `while(t--)` 里面**——多组数据的答案绝不能跨组累计；
2. `n`、`ans`、`sumMul` 的中间量**全用 `long long`**：`n = 1e9` 时答案是 `233333333166666668 ≈ 2.33e17`，**已经超过 `int`**（`INT_MAX ≈ 2.1e9`）好几亿倍。

## 六、自查

<details><summary>Q1：为什么"单独跑 n=100 是对的"，一多组就错？</summary>

因为 `ans` 只在**程序开始时**初始化过一次（`ll ans = 0;` 是全局变量，全程序唯一）。第一组结束时它变成 23，第二组在 23 的基础上继续加 ⇒ 23 + 2318 = 2341。
**判据**：凡是"多组数据"的题，答案变量必须**在每组开头重置**（写在 `while(t--){}` 内），或者在循环体内用局部变量重新定义。

</details>

<details><summary>Q2：为什么不写成 `n / k` 而要写 `(n - 1) / k`？</summary>

题面是"**小于 n**"（不含 n 本身）。
`n = 9, k = 3`：`9/3 = 3` 会把 9 算进去（错，9 不小于 9）；`(9-1)/3 = 2` 正确（只有 3、6）。
`n = 10, k = 3`：`(10-1)/3 = 3` ⇒ 3、6、9 ✔。**一律写 `(n-1)/k` 就永远不会错。**

</details>

<details><summary>Q3：为什么最后要减 `S(15)`？</summary>

`S(3)` 把 15、30、45… 算了一次，`S(5)` 又把它们算了一次 ⇒ **每个 15 的倍数被加了两遍**，必须减掉一遍（这就是最简单的**容斥原理**：`|A ∪ B| = |A| + |B| − |A ∩ B|`，而 `A ∩ B` 恰是 15 的倍数）。
实测这个重复量在 `n = 100` 时是 **315**，不减的话会输出 `1683 + 950 = 2633` 而不是 2318。

</details>

<details><summary>Q4：`k * m * (m + 1) / 2` 会不会溢出？</summary>

不会，但要**全程 long long**。
`n = 1e9, k = 3`：`m ≈ 3.33e8`，`k·m·(m+1) ≈ 3 × 3.33e8 × 3.33e8 ≈ 3.3e17` —— 远小于 `LLONG_MAX ≈ 9.2e18` ✔；但**远超 `INT_MAX ≈ 2.1e9`**，任何一处用了 `int` 都会溢出。
⚠️ 写法上把 `k` 放最前面并强转成 `(ll)k` 是个习惯：`m * (m+1)` 先算也不会溢出（≈1.1e17 < 9.2e18），关键是**别让中间结果被截成 int**。

</details>

<details><summary>Q5：这题属于什么题型？以后怎么一眼认出来？</summary>

**"求某个范围内满足整除条件的数之和"** ⇒ 永远先想三件事：
1. 个数 = `⌊上界 / k⌋`（注意开闭区间 → 是 `n/k` 还是 `(n-1)/k`）；
2. 和 = `k × (1 + 2 + … + m) = k·m(m+1)/2`（等差数列）；
3. 多个条件叠加用**容斥**（3 或 5 ⇒ 加 3、加 5、减 15）。
**判据**：只要看到 `n ≤ 1e9` 而你打算写 `for`，就该停下来——**范围超过 1e7 的枚举基本都要换公式或换算法**。

</details>

<details><summary>Q6：如果把条件改成"3 或 5 或 7 的倍数"，公式怎么改？</summary>

三个集合的容斥：`S(3)+S(5)+S(7) − S(15) − S(21) − S(35) + S(105)`。
即：**奇数个集合交 ⇒ 加，偶数个 ⇒ 减**，各交集合的除数是相应 lcm 的乘积。

</details>
