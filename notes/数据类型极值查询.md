# 如何查询数据类型的最大值 / 最小值

> 三种查法：**`<limits>` 的 `numeric_limits<T>`（推荐）**、C 风格宏（`INT_MAX` 等）、固定宽度宏（`INT32_MAX`）。
> ⚠️ 最大的坑：**浮点的 `min()` 不是最小负数，而是最小正数**——要拿"最负数"必须用 `lowest()`。
> 本文所有数值均为本机（g++ 16.2 / 64 位 Windows）实测。

---

## 一、推荐方式：`numeric_limits<T>`（`<limits>`，C++11 起，`bits/stdc++.h` 已含）

```cpp
numeric_limits<int>::max();          // 最大值
numeric_limits<int>::min();          // 最小值（对整数 = 最负值）
numeric_limits<int>::lowest();       // 最负有限值（对浮点才有区别，C++11）
```

| 类型 | `max()` | `min()` | `lowest()` |
|---|---|---|---|
| `int` | 2147483647 | −2147483648 | −2147483648 |
| `long long` | 9223372036854775807 | −9223372036854775808 | 同 |
| `unsigned` | 4294967295 | **0** | 0 |
| `size_t` | 18446744073709551615 | **0** | 0 |
| `char`（有符号） | 127 | −128 | −128 |
| `short` | 32767 | −32768 | −32768 |
| `double` | 1.797693e+308 | **2.225074e−308**（最小正数！） | **−1.797693e+308** ✔ |
| `float` | 3.402823e+38 | 1.175494e−38（最小正数！） | −3.402823e+38 ✔ |

### ⚠️ 陷阱 1：浮点 `min()` 是"最小正规格化数"

```
numeric_limits<double>::min()    = 2.225074e-308    ← 最小【正】数，不是最负数！
numeric_limits<double>::lowest() = -1.797693e+308   ← 真正的"最小"（最负）值 ✔
```
想初始化"最大/最小"的浮点累加器，写：
```cpp
double mx = numeric_limits<double>::lowest();   // ✅
double mn = numeric_limits<double>::max();      // ✅
// double mn = numeric_limits<double>::min();   // ❌ 那是 2.2e-308，几乎是最小正数
```
（整数类型的 `min() == lowest()`，都可以用。）

### 顺带常用的其它成员

```cpp
numeric_limits<double>::epsilon();     // 2.220446e-16：1.0 与下一个可表示浮点数的间隔（浮点 eps 判等用）
numeric_limits<double>::infinity();    // +∞（前提 has_infinity 为真）
numeric_limits<double>::has_infinity;  // true
numeric_limits<int>::is_signed;        // true / false（unsigned 是 false）
numeric_limits<long long>::digits10;   // 19：十进制下能保证的位数（≈ 秒算长度上限）
```

## 二、C 风格宏（`<climits>` / `<cfloat>`）

```cpp
INT_MAX   INT_MIN        // 2147483647 / -2147483648
LLONG_MAX LLONG_MIN      // 9223372036854775807 / -9223372036854775808
UINT_MAX  ULLONG_MAX     // 4294967295 / 18446744073709551615
SHRT_MAX  CHAR_BIT       // 32767 / 8（一个字节多少 bit）
DBL_MAX   DBL_MIN   DBL_EPSILON   // 1.797693e+308 / 2.225074e-308 / 2.220446e-16
```
实测确认：`INT_MAX == numeric_limits<int>::max()`、`INT_MIN == numeric_limits<int>::min()` 都成立 ✓（两套写法等价）。

> 固定宽度类型还有 `<cstdint>` 的 `INT32_MAX / INT64_MAX / UINT64_MAX` 等，语义最明确，跨平台最安全。

**用哪个？** 竞赛里 `INT_MAX` / `LLONG_MAX` 打得最快；泛型/模板代码里用 `numeric_limits<T>`（`T` 可变时宏写不出来）。

---

## 三、竞赛高频用法：INF 哨兵（0x3f 技巧）

最短路径、DP 初始化常用"无穷大"，但 `INT_MAX` 相加会溢出。惯用做法是 `memset` 填 `0x3f`：

```cpp
int dp[1005];              memset(dp, 0x3f, sizeof(dp));   // 每个 = 1061109567
long long dq[1005];        memset(dq, 0x3f, sizeof(dq));   // 每个 = 4557430888798830399
const int INF = 0x3f3f3f3f;
```

实测：`2 * 1061109567 = 2122219134 < INT_MAX(2147483647)` ✓；
`2 * 4557430888798830399 = 9114861777597660798 < LLONG_MAX` ✓
——**两倍也不溢出**，这正是选 `0x3f` 而不是 `INT_MAX` 的原因（松弛/相加操作安全）。

## 四、必须记住的五个溢出/sentinel 坑

| 坑 | 实测现象 |
|---|---|
| `unsigned` 回绕 | `numeric_limits<unsigned>::max() + 1 == 0`；倒序循环写 `for (unsigned i = n-1; i >= 0; --i)` 是死循环 |
| `INT_MIN / -1` | 数学结果 2147483648 超出 int → **UB**（本机得 −2147483648） |
| `abs(INT_MIN)` | 返回 −2147483648（同样溢出） |
| 用 `INT_MAX` 当 INF 再相加 | `INT_MAX + 1` 溢出；两两相加必炸 → 改用 `0x3f3f3f3f` 或 `long long` |
| 浮点用 `min()` 当"最负数" | 见第一节，必须 `lowest()` |

另外两条格式/写法相关：
- `numeric_limits<T>::max` **是函数，要写 `()`**（不写括号编译报"函数不能当值用"）；
- `long long` 输出用 `%lld`（Windows 用 `%I64d`），用 `%d` 会截断/乱码。

## 四点五、"取值对了但输出错误"——症状对照表（全部实测）

拿到极值后**打印方式不匹配**，是"方法没错但结果不对"的头号原因。对照下面症状即可定位：

| 你看到的症状 | 原因 | 实测证据 | 正确写法 |
|---|---|---|---|
| 打印出来是**空白/乱码字符** | 用 `cout` 打印 `char`/`unsigned char` 的极值 → 按**字符**输出 | `cout << numeric_limits<char>::max()` → `[]`（不可见字符） | `cout << (int)numeric_limits<char>::max()` → `127`；unsighed char → `255` |
| `long long` 极值打印成 **-1** | 用 `%d` 配 `long long` | 警告 `format '%d' expects 'int', but argument has type 'long long int'`；输出 `-1` | 用 `%lld`（Windows `%I64d`） |
| 打印 `int` 极值却"**碰巧正确**" | 用 `%lld` 配 `int` —— **UB，只是这次高 32 位恰为 0** | 实测输出 `2147483647`（看着对，实则不可靠） | 类型与占位符严格配对 |
| 浮点极值打印成 **0.000000** | 用 `%f` 配整数 | `printf("%f", INT_MAX)` → `0.000000` | `%d` 配整数、`%f/%lf` 配浮点 |
| 想取"最负的 double"却得到 **2.22507e-308** | 用了 `min()` | `min()` 是最小**正数** | 用 `lowest()` |
| INF 加法后出现**负数** | 用 `INT_MAX` 当 INF 相加 / `memset(0x7f)` | `INT_MAX+1 = -2147483648`；`0x7f` 两倍 = `-16843010` | `const int INF = 0x3f3f3f3f;`（两倍 = 2122219134 仍安全） |
| 编译直接报错 | 漏了函数括号 `numeric_limits<int>::max` | error: invalid use of member function | 写 `numeric_limits<int>::max()` |
| 转成 `int` 后变成 **-1** | 把极值塞进更小的类型 | `(int)stoll(to_string(LLONG_MAX))` → `-1` | 保持原类型，别降级 |

**排查口诀**：先确认"打印出来的是不是你以为的那个类型"——**要用 `%lld` 就用 `long long`，要用 `%d` 就传 `int`；`char` 一定要 `(int)` 强转**。
另外记得编译时加 `-Wall -Wformat`：上面 3 条 printf 不匹配都会**直接报警告**，等于免费帮你抓错。

### char 系列专项修法（最常遇到的一种）

```cpp
char c = numeric_limits<char>::max();                  // 127 = DEL 控制字符
unsigned char uc = numeric_limits<unsigned char>::max(); // 255
cout << c;              // ❌ 输出不可见字符（看起来"啥都没有"）
cout << uc;             // ❌ 本地码页下输出乱码
```

原因：`std::cout << char` 走的是**按字符输出**的重载（`operator<<(char)`），而 `numeric_limits<char>::max()` 返回类型就是 `char`，所以它被当"字符"打印。实测五种正确写法，输出均为 `127 / 255`：

| 写法 | 结果 |
|---|---|
| `cout << (int)c` | 127 ✓ |
| `cout << +c`（一元 `+` 触发整型提升） | 127 ✓ **最短技巧** |
| `cout << static_cast<int>(c)` | 127 ✓ |
| `printf("%d", c)`（变参自动提升为 int） | 127 ✓（`printf` 天然安全） |
| `cout << to_string((int)c)` | `"127"` ✓ |

补充两条：
- **`int8_t` / `uint8_t` 就是 `signed char` / `unsigned char` 的别名**（实测 `sizeof` 都是 1、`is_same` 为真）→ 打印字节、哈希值时同样要 `(int)`；
- `bool` 不踩这个坑：`cout << numeric_limits<bool>::max()` 输出 `1`。

## 五、自查

1. `numeric_limits<double>::min()` 是什么？想初始化"最小浮点"该用哪个成员？
2. 为什么竞赛里 INF 常用 `0x3f3f3f3f` 而不是 `INT_MAX`？
3. `numeric_limits<unsigned>::min()` 是多少？`unsigned` 从 0 减 1 会怎样？
4. 反过来写 `numeric_limits<T>::max()` 时最容易漏什么？

答案：1. 最小**正**规格化数（2.2e−308），不是最负值；要最负值用 `lowest()`（−1.8e308）。2. `0x3f3f3f3f = 1061109567`，两倍相加（2122219134）仍小于 `INT_MAX`，松弛操作不会溢出；而 `INT_MAX + INT_MAX` 直接溢出。3. 0；减 1 会**回绕**成 4294967295。4. 漏写函数调用的括号 `()`。
