# CF 1486D Max Median —— 思路完全错位，以及一个隐蔽的中位数定义陷阱

> 触发点：Codeforces 1486D 提交后 WA。代码在 `test_\01.cpp`。
> 一句话：**原码算的是"整个数组里第 t 大的数"，而题目要的是"某个连续子段的中位数"**——它彻底忽略了"子段必须连续、长度至少 k"这个核心约束。
> 实测反例：`n=5, k=3, a={5,1,1,1,5}` → 原码输出 **5**，正确答案是 **1**（且两种中位数定义下正确答案都是 1）。
> 正确解法 `test_\01_cf1486d_fixed.cpp`、验证程序 `test_\01_cf1486d_check.cpp`（**原文件 `test_\01.cpp` 保持原样未改动**）。

---

## 一、原码在做什么

```cpp
priority_queue<int> dp;                    // 大根堆
for (ll i = 0; i < n; ++i) { ll x; cin >> x; dp.push(x); }   // 全部 n 个数进堆

ll t = (k + 1) / 2;                        // t = ⌈k/2⌉
t = k - t + 1;                             // t = ⌊k/2⌋ + 1

ll ans = 0;
while (t--) { ans = dp.top(); dp.pop(); }  // 弹出 t 次，取最后弹出的
cout << ans;
```

**它做的是**：把 n 个数全放进大根堆，弹出 `⌊k/2⌋+1` 次，输出最后弹出的那个 ——也就是**整个数组的第 (⌊k/2⌋+1) 大**。

**它没有做的**：题目要的是"**某个长度 ≥ k 的连续子段**的中位数"，而原码**完全没有"子段"这个概念**——它既不关心元素是否连续，也不关心长度约束。

> 换句话说：原码把"在所有合法子段里挑一个中位数最大的"错读成了"在整个数组里挑第 t 大的数"。

## 二、反例实测

`n=5, k=3, a = {5, 1, 1, 1, 5}`

```
原码输出          = 5
正确答案(下中位数) = 1
正确答案(上中位数) = 1
```

把所有长度 ≥ 3 的子段列出来看：

| 子段 | 元素 | m | 下中位数（第 ⌈m/2⌉ 小） |
|---|---|---|---|
| [1..3] | {1,1,5} | 3 | 第 2 小 = **1** |
| [1..4] | {1,1,1,5} | 4 | 第 2 小 = **1** |
| [1..5] | {1,1,1,5,5} | 5 | 第 3 小 = **1** |
| [2..4] | {1,1,1} | 3 | 第 2 小 = **1** |
| [2..5] | {1,1,1,5} | 4 | 第 2 小 = **1** |
| [3..5] | {1,1,5} | 3 | 第 2 小 = **1** |

**5 从来没有出现在任何子段的"中间位置"**——但原码输出了 5。

## 三、为什么官方样例能过？（这是最容易骗过自己的地方）

`n=5, k=3, a={1,2,3,4,5}`：原码输出 **4**，正确答案也是 **4**。凑巧相等。

**它们在什么时候必然相等？** 当 `n == k` 时：

- 唯一合法的子段就是整个数组
- 它的下中位数 = 第 ⌈k/2⌉ 小
- 原码输出的"第 (k − ⌊k/2⌋) 大" = 第 ⌈k/2⌉ 小
- **两者恰好相等**

**实测**：随机取 `n == k` 的 2000 组，原码与正确解**一致 2000 组（100%）**。

> 也就是说：**只有"没有选择余地"时它才对。** 而 CF1486D 的样例恰好是 n=5, k=3…
> 等一下——样例 n=5 ≠ k=3，按上面的分析它不该对。这里相等的真实原因是：样例数组是**严格递增**的 `1,2,3,4,5`，此时最大中位数恰好等于全局某个次序统计量。**这是数据巧合，不是逻辑正确。**

**实测统计**（20000 组随机数据，k < n）：

```
原码          与正确答案不符 2822 组（全部是【偏大】2822 组）
正确解         不符 0 组
```

**错误率约 14%，且 100% 偏大**——这是"忽略了长度/连续性约束"的典型症状：约束一放宽，答案只会变大。

## 四、正解：二分答案 + 转 ±1 + 前缀最小值

### 第 1 步：二分答案

答案一定落在 `[1, max(a)]` 内（单元素子段的中位数就是它自己）。二分 `x`，判定"**是否存在中位数 ≥ x 的子段**"。

### 第 2 步：把"中位数 ≥ x"翻译成"子段和"

令

$$b_i=\begin{cases}+1,& a_i\ge x\\ -1,& a_i<x\end{cases}$$

关键等价：

$$\text{长为 } m \text{ 的子段中位数} \ge x \iff \text{该段中} \ge x \text{ 的元素个数} \ge m-\left\lceil\frac{m}{2}\right\rceil+1 \iff \sum b > 0$$

**逐档核对**（下中位数 ⌈m/2⌉ 的定义）：

| m | 中位数位置 | 需要 ≥ x 的个数 | b 的和 |
|---|---|---|---|
| 2 | 第 1 小 | 2 | 2 > 0 |
| 3 | 第 2 小 | 2 | 1 > 0 |
| 4 | 第 2 小 | 3 | 2 > 0 |
| 5 | 第 3 小 | 3 | 1 > 0 |

### 第 3 步：前缀最小值

要判断"是否存在 `i < j` 使 `j - i ≥ k` 且 `pre[j] - pre[i] > 0`"：

$$\iff pre[j] > \min\{pre[i] : 0 \le i \le j-k\}$$

用一个变量滚动维护这个最小值即可，判定 O(n)。

### 代码

```cpp
vector<int> pre(n + 1);
auto check = [&](int x) -> bool {
    pre[0] = 0;
    for (int i = 0; i < n; ++i)
        pre[i + 1] = pre[i] + (a[i] >= x ? 1 : -1);

    int mn = INT_MAX;
    for (int j = k; j <= n; ++j) {
        mn = min(mn, pre[j - k]);      // ★ 只把下标 ≤ j-k 的纳入候选
        if (pre[j] > mn) return true;
    }
    return false;
};

int lo = 1, hi = mx;
while (lo < hi) {
    int mid = lo + (hi - lo + 1) / 2;  // 上取整（求最大可行值）
    if (check(mid)) lo = mid;
    else            hi = mid - 1;
}
cout << lo;
```

**总复杂度 O(n log n)。**

## 五、⚠️ 一个很隐蔽的陷阱：两种中位数定义对应不同的判定

**这道题最大的暗坑在这里。** 偶数长度时"中位数"有两个自然取法，而它们对应**不同的判定条件**：

| 定义 | 名称 | "中位数 ≥ x" ⟺ 子段和 |
|---|---|---|
| 第 $\lceil m/2\rceil$ 小（偶数取**偏小**的） | **下中位数** | $\sum b > 0$（**严格**） |
| 第 $\lceil (m+1)/2\rceil$ 小（偶数取**偏大**的） | **上中位数** | $\sum b \ge 0$ |

**手算核对**（m = 2）：

- 下中位数 = 第 1 小 = `min`。`median ≥ x` ⟺ 两个都 ≥ x ⟺ 和 = 2 > 0 ✓
- 上中位数 = 第 2 小 = `max`。`median ≥ x` ⟺ 至少一个 ≥ x ⟺ 和 ≥ 0 ✓

**为什么这个坑特别危险**：

> CF1486D 的官方样例 `n=5, k=3, a={1,2,3,4,5}` 在两个定义下答案**都是 4**。
> **样例根本区分不出你用的是哪一种定义！** 必须回去看题面原句怎么写。

代码里就是改一个字符：

```cpp
if (pre[j] >  mn) return true;   // 下中位数 ⌈m/2⌉
if (pre[j] >= mn) return true;   // 上中位数 ⌈(m+1)/2⌉
```

> ⚠️ **我自己第一次也把这两个搞反了**：写完之后实测 `n=4, k=2, a={1,2,3,4}`，程序给了 4，而下中位数的正确答案是 3（子段 `[3,4]` 的 `min` = 3）。**一步实测立刻把方向性错误抓出来了**——如果我只看样例，这个错误会一路带到提交。

## 六、坑清单

| # | 坑 | 症状 |
|---|---|---|
| 1 | **把"子段的中位数"做成"全局次序统计量"** | 本题原码：完全忽略连续性与长度约束，实测 14% 数据错、100% 偏大 |
| 2 | 前缀最小值取成 `pre[0..j-1]` | 少了 `-k`，允许了长度 < k 的子段 → 答案偏大 |
| 3 | 搞反上下中位数定义 | 只在偶数长度子段上出错，样例常常区分不出（本样例就是） |
| 4 | `b_i` 判据写成 `a[i] > x` 而不是 `>= x` | 差一个等号，答案偏小 |
| 5 | 二分下界取 0 | 若 `a_i ≥ 1` 则答案 ≥ 1，下界写 1 更安全 |
| 6 | 二分写成 `while(l<r)` 却用下取整配 `l=mid` | 死循环 |
| 7 | 只看样例就提交 | 本题样例在两种定义、以及原码错误做法下**都是 4** |

## 七、自查

1. 原码算的到底是什么？它忽略了题目的哪一条核心约束？
2. 为什么 `n == k` 时原码恰好是对的？
3. "长为 m 的子段中位数 ≥ x" 为什么等价于"该段 ±1 序列的和 > 0"？把 m=2,3,4,5 都验一遍。
4. 为什么前缀最小值只能从 `pre[0..j-k]` 里取，不能从 `pre[0..j-1]` 里取？
5. 下中位数和上中位数对应的判定条件分别是什么？为什么这道题的样例区分不出它们？

**答案要点**
1. 算的是整个数组的第 (⌊k/2⌋+1) 大。忽略了"选出的元素必须构成**连续子段**"以及"长度 ≥ k"这两条约束。
2. 因为 `n == k` 时唯一合法子段就是整个数组，此时"全局第 ⌈k/2⌉ 小"与"整个数组的下中位数"恰好是同一个数——原码是在"没有选择余地"的情况下蒙对的（实测 2000/2000 一致）。
3. 中位数是第 ⌈m/2⌉ 小 ≥ x，意味着至少有 `m − ⌈m/2⌉ + 1` 个元素 ≥ x。记 #≥x = c、#<x = m−c，则 c − (m−c) = 2c − m。m=2 需 c≥2 → 2>0；m=3 需 c≥2 → 1>0；m=4 需 c≥3 → 2>0；m=5 需 c≥3 → 1>0。全部 > 0 ✓
4. `pre[j] - pre[i]` 对应的子段是 `i+1 .. j`，长度 `j - i`。要长度 ≥ k 就必须 `j - i ≥ k`，即 `i ≤ j - k`。取到 `j-1` 就等于允许长度 1 的子段，答案会虚高。
5. 下中位数（第 ⌈m/2⌉ 小）⟺ 和 > 0；上中位数（第 ⌈(m+1)/2⌉ 小）⟺ 和 ≥ 0。因为 CF1486D 样例的最大中位数在两种定义下都等于 4（不管取偏小还是偏大的那个中间元素），所以样例无法区分。
