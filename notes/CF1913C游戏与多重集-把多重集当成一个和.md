# CF1913C Game with Multiset · 你的判据 `(w & p) == w` 为什么错

> **触发点**：你让我搓边界数据来查代码哪里错了。我直接读了 `test_\01.cpp`，**不用试就能指出来**——不过还是用对拍和穷举把证据做实了。
> **一句话结论**：你把**多重集压缩成了一个"和"**（`p += (1LL << v)`），再用 `(w & p) == w` 判。**"和"丢掉了"有几个"的信息**：两个 `1` 一相加就变成 `2` 了，从此你再也看不到"手上还留着一个 `1`"。**最小反例只要 3 行**：

```
3
1 0
1 0
2 1
```

正确答案 `YES`（多重集里明明白白有一个 `1`），你的程序输出 `NO`。

## 一、你的代码（`test_\01.cpp`，25 行）

```cpp
ll m, p = 0;          // ← p 是【所有元素的和】
ll t, v;
...
if (t == 1) {
    p += (1LL << v);              // ← 问题在这：把元素"加进和"里，丢了数量
} else if (t == 2) {
    if ((v & p) == v) cout << "YES\n";        // ← 问题在这：把"和"的二进制当成了"可选集合"
    else if ((v & p) != v) cout << "NO\n";
}
```

`1 x` 加的是 $2^x$（**x 是指数**，这块你写对了：`1LL << v`）。但 `p` 一旦只是**和**，多重集的"可重数"就没了。

---

## 二、为什么"和"不行：进位会把数量信息吃掉

| 多重集 | 和 `p` | 查询 `w` | 真值 | 你的输出 | 为什么错 |
|---|---|---|---|---|---|
| `{1,1}` | 2 | 1 | **YES** | **NO** ✘ | `1 & 2 = 0`；但集里就有一个 1 |
| `{2,2}` | 4 | 2 | **YES** | **NO** ✘ | `2 & 4 = 0` |
| `{16,16}` | 32 | 16 | **YES** | **NO** ✘ | `16 & 32 = 0` |
| `{4,1,1}` | 6 | 5 | **YES** | **NO** ✘ | `5 & 6 = 4 ≠ 5`；但 4+1=5 |
| 300 个 1 | 300 | 1 | **YES** | **NO** ✘ | `1 & 300 = 0` |
| `{2,2,2}` | 6 | 6 | YES | YES ✔ | 凑巧对：2+2+2=6 的和恰好等于 `p` 的位 |

一句话：**`p` 的二进制只记录"能合成出哪些 2 的幂"，原始元素的身份已经被进位吃掉了。**

## 三、穷举扫描：错得有多系统（实测）

`cf1913c_probe.cpp`：把 `1/2/4/8/16` 各取 0..5 个的**所有**多重集 × **所有** w 全枚举，逐个对比"真值（子集和 DP）"与"你的判据"：

| 指标 | 数值 |
|---|---|
| (多重集, w) 组合总数 | 599,225 |
| ✘ **真值 YES 你输出 NO（漏判）** | **393,640 = 65.7%** |
| ✘ 真值 NO 你输出 YES（多判） | **0** |
| 最小"漏判"反例（扫描顺序） | 多重集 `{16,16}`，和 = 32，查 `w = 16` |

**这就是你这个 bug 的精确画像：`(w & p) == w` 是一个"充分但不必要"的条件。**

- 满足它 ⇒ 答案一定是 YES（在这个范围内**没有反例**，因为"和的位"总能被拆成若干元素）；
- 但答案是 YES ⇒ 大量情况**不满足**它。

所以你的程序**只会"少说 YES"，永远不会"多说 YES"**——在评测上表现为：一大片本该 `YES` 的地方输出 `NO`（WA），而且小样例往往看不出来。

> **为什么小样例/随手试能过？** 只要每个 $2^x$ **最多出现一次**，`p` 的二进制就等于"存在性向量"，此时你的判据**恰好完全正确**。一旦出现重复元素（两次 `1 0`、三个同样的值……）就开始错。这也是为什么这类 bug 特别隐蔽。

## 四、正确解法：按指数存**个数** + 进位贪心（6 行）

```cpp
ll cnt[40] = {0};                 // cnt[i] = 多重集里 2^i 的个数
if (t == 1) {
    cnt[v]++;                     // ★ 存"个数"，不要存"和"
} else {
    ll have = 0;                  // 当前可用的 2^b 个数（含低位进位来的）
    bool ok = true;
    for (int b = 0; b <= 30; ++b) {          // w ≤ 1e9 < 2^30
        have += cnt[b];
        if ((v >> b) & 1) {                  // w 的第 b 位是 1 → 必须消耗一个 2^b
            if (have == 0) { ok = false; break; }
            --have;
        }
        have >>= 1;                          // 剩下的两个 2^b 合成一个 2^(b+1)
    }
    cout << (ok ? "YES\n" : "NO\n");
}
```

**为什么对（一句话不变式）**：从低位往高位扫，处理第 $b$ 位时 `have` 恰好等于「用所有 $\le 2^b$ 的元素能拼出多少个 $2^b$」（因为两个 $2^b$ 等于一个 $2^{b+1}$，可以一路进位上来）；`w` 的第 $b$ 位是 1 就必须当场拿出一个顶上，拿不出就无解。
这个过程等于**把所有元素按"面额"重新记了一遍账，一个都没丢**。

5. 正解里 `have >>= 1` 为什么必须写在"扣掉 w 的这一位"**之后**？
6. 为什么这道题的 w 只扫到第 30 位就够？

<details>
<summary>答案</summary>

1. 你的判据：`1 & 2 = 0 ≠ 1` → 输出 `NO`。正确答案 `YES`（集里就有一个 1）。
2. 因为 `2+2+2 = 6`，而 `p = 6`，刚好 `6 & 6 == 6`。**巧合**——`w` 恰好等于总和时才成立。
3. **不会**。穷举 599,225 组里"多判"**0 例**：`(w & p) == w` 成立时答案必为 YES。你的条件**充分但不必要** ⇒ 症状永远是"该 YES 说 NO"。
4. **对**。每个值最多一个时，`p` 的二进制就是"存在性向量"，所有子集和恰好等于 `p` 的所有子掩码 ⇒ 判据完全正确。这就是"随手试几个样例发现不了"的原因；也说明**修复的关键是"重数"**。
5. 反例：`cnt[0] = 1`（一个 1），查 `w = 1`。若先合并再扣位：`have = 1 → have >>= 1 → 0`，然后第 0 位需要 1 个却 `have == 0` → 误判 NO。正确顺序是"先扣掉 w 要的那一个，剩下的再两两进位合并"。
6. 因为 `w ≤ 1e9 < 2^30`，二进制最多到第 29 位；扫到 30 已经留了余量。（注意是 **w 的位数**决定扫描上界，不是元素个数。）
