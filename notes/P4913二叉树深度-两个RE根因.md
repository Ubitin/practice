# P4913 二叉树深度 —— RE 的两个根因：槽号越界 + 递归爆栈

> **触发点**：2026-09-30，你问"为什么我的代码会 RE"。
> **判定**：❌ **两个独立的 RE 根因，都不是"差一点"，而是必然崩**：
> ① **`ris[]` 的"堆式槽号"设计** ⇒ 深度 ≥ **21** 就写出界（实测：chain n=20 正常、**n=21 崩**）；
> ② **递归深度 = 树高** ⇒ 链状树 n=1e6 要递归 100 万层 ⇒ 爆栈（隔离实测：按节点编号 + 递归 → **0xC00000FD**）。
> ✅ 修法：**去掉 `ris[]`、直接用节点编号存左右儿子**；**DFS 改手写栈迭代**。

---

## 一、题目

- 输入 `n`（`n ≤ 10^6`），接下来 `n` 行，第 `i` 行给 **`i` 号节点的左右儿子编号**（`0` 表示没有这个儿子）。
- 输出这棵二叉树的**深度**（根算第 1 层）。

---

## 二、实测：你的代码在什么数据上崩（退出码是关键线索）

| 数据 | 正确深度 | 你的结果 | 退出码 |
|---|---|---|---|
| chain（链）n = 20 | 20 | **20** ✅ | 0 |
| chain n = **21** | 21 | **崩溃** | **0xC0000005**（访问违规）|
| chain n = 25 | 25 | 崩溃 | 0xC0000005 |
| chain n = 1e6 | 1000000 | 崩溃 | 0xC0000005 |
| balanced（完全二叉树）n = 1e6 | 20 | **20** ✅ | 0 |
| random n = 1e6 | 48 | **崩溃** | 0xC0000005 |

⭐ **崩溃阈值正好卡在"深度 21"** —— 这个数字就是破案钥匙（下面根因①会解释为什么偏偏是 21）。

> `0xC0000005` = 访问违规（读/写了不属于自己的内存）；`0xC00000FD` = 栈溢出。**两种 RE 的"病因"不同**，这个区别是本题的关键。

---

## 三、根因①：`ris[]` 的槽号按"完全二叉树编号"增长 ⇒ 越界写

```cpp
ris[d.l] = 2 * ris[i];        // ← 左儿子的"槽号" = 父槽号 × 2
ris[d.r] = 2 * ris[i] + 1;    // ← 右儿子 = 父槽号 × 2 + 1
```

这是**完全二叉树的堆式编号**（根 = 1，左儿子 = 2i，右儿子 = 2i+1）⇒ **深度 d 的节点，槽号能到 `2^d`**。
而 `p[]` / `ris[]` 只开了 `1e6 + 5` 格。探针实测（`p4913_check\p4913_slot_probe.cpp`）：

| 数据 | 最大槽号 | 数组格数 | 结论 |
|---|---|---|---|
| chain n = 20 | 524,288 | 1,000,005 | 塞得下 ✅ |
| chain n = **21** | **1,048,576** | 1,000,005 | **越界**（写出界约 **1.1 MB**）❌ |
| chain n = 25 | 16,777,216 | 1,000,005 | 越界约 **378 MB** ❌ |
| chain n = 30 | 536,870,912 | 1,000,005 | 越界约 **12.8 GB** ❌ |

**出界的就是这一句**：`p[ris[i]] = d;` —— `node` 有 3 个 `ll`（**24 字节**），下标 `1048576` 时写入位置已在数组末尾外 **1.1 MB**，那里是未映射内存 ⇒ **0xC0000005 访问违规**。

> ⭐ **为什么 `balanced n=1e6` 反而没事**：完全二叉树的深度正好是 **20**（2²⁰ = 1,048,576 ≈ 1e6），槽号最大也不过 1e6，**恰好塞得下**。
> ⇒ "样例能过"完全是**数据恰好浅**的假象；链状 / 随机数据一交就崩。

### 3.1 而且这套槽号**完全没必要**

`p[]` 本来就是"按节点编号存儿子"的数组（`d.id = i` 也印证了这一点）。既然输入给的就是**节点编号**，直接用编号当下标就行 —— 槽号这一层转换纯属自找麻烦（还引入了 `2^深度` 的爆炸）。

---

## 四、根因②：递归深度 = 树高 ⇒ 链状树必爆栈

- 即使把槽号问题修好，`dfs` 仍会**递归到"树高"那么深**；而 `n ≤ 1e6` ⇒ 链状树要递归 **100 万层**。
- **隔离实测**（只把存储换成"按节点编号"，**仍然递归**，其他照旧）：

| 程序 | 数据 | 结果 |
|---|---|---|
| 按节点编号 + **递归** `dfs` | chain n = 1e6 | **0xC00000FD 栈溢出** ❌ |
| 按节点编号 + **手写栈迭代** | chain n = 1e6 | **1000000** ✅ |

⇒ 所以**必须改两处**：修了槽号不修递归，依然 RE。

> 这正是你在 **CF377A** 上踩过的老坑（讲义 `CF377A代码评审-墙标记写错与递归爆栈`、画像 §2.4 记录在案）。

## 五、修法（两处，都很短）

### 5.1 存储：去掉 `ris[]`，直接用节点编号（关键几行）

```cpp
const ll maxn = 1e6 + 5;
ll l[maxn], r[maxn];                    // 第 i 个节点的左右儿子编号（0 表示没有）
...
for (ll i = 1; i <= n; ++i) cin >> l[i] >> r[i];
```

### 5.2 求深度：手写栈迭代（不递归）

```cpp
vector<pair<ll,ll>> st;                 // (节点, 该节点的深度)
st.push_back({1, 1});                   // 根：节点 1，深度 1
ll ans = 0;
while (!st.empty()) {
    auto [u, d] = st.back(); st.pop_back();
    ans = max(ans, d);
    if (l[u]) st.push_back({l[u], d + 1});      // ⚠️ 必须先判 0（0 表示没有儿子）
    if (r[u]) st.push_back({r[u], d + 1});
}
cout << ans << '\n';
```

### 5.3 为什么手写栈不会爆

`vector` 的内存开在**堆**上（能用到几百 MB），而递归用的是**栈**（Windows 默认 1 MB、Linux 常见 8 MB）⇒ 100 万层递归必然溢出，100 万个 `pair<ll,ll>` 只占 16 MB。
（也可以换成 BFS 逐层数；或"深度数组 + 从叶子往上递推"。）

## 六、四个要点（下次直接照这个 checklist 走）

| # | 要点 |
|---|---|
| 1 | 只要看到 **n ≤ 1e6 的树 / 图**，**递归一律换手写栈**（C++ 默认栈只有 1–8 MB，约 1–8 万层就爆）|
| 2 | ⚠️ **别用"完全二叉树编号（2i / 2i+1）"当数组下标** —— 深度 d 就要求到 `2^d` 格；n = 1e6 只允许深度 ≤ 20 |
| 3 | 输入里 `0` 表示"没有儿子"，压栈前**必须判 `if (l[u])`**（不判会把 0 号当节点，导致死循环/越界）|
| 4 | 数组按下标**上界**开：这里下标是节点编号 ≤ n ⇒ `maxn = 1e6 + 5` ✅（**这条你做对了**）|

## 八、自查

<details>
<summary>① 为什么 chain n=20 能过、n=21 就崩？（说出那个临界数字的来历）</summary>

槽号按堆式编号增长：深度 d 的节点槽号到 `2^(d-1)`（根在深度 1，槽号 1）。
- n=20 ⇒ 最深槽号 `2^19 = 524,288` ≤ 1,000,005 ✅
- n=21 ⇒ 最深槽号 `2^20 = 1,048,576` > 1,000,005 ❌ **越界**
所以临界点正好是 **21**。这也解释了为什么 `balanced n=1e6`（深度 20）侥幸能过。
</details>

<details>
<summary>② 如果只修 `ris[]`（改用节点编号）但保留递归，交上去会怎样？</summary>

**照样 RE，但错误码换成 `0xC00000FD`（栈溢出）**。因为链状数据要递归 n = 1e6 层，远超 C++ 默认栈能承受的层数。
⇒ **两个根因必须一起修**。实测证据见第五节的控制组。
</details>

<details>
<summary>③ 手写栈为什么不会爆栈？</summary>

`vector` 的内存分配在**堆**（可用空间是几百 MB 级），而递归调用帧占用的是**栈**（Windows 默认 1 MB、Linux 常见 8 MB）。
n = 1e6 时手写栈最多同时存 1e6 个 `pair<ll,ll>` = 16 MB（堆里毫无压力），而 1e6 层递归帧早就把栈冲垮了。
</details>

<details>
<summary>④ 这题还有别的写法吗？</summary>

有，三种都行：
1. **手写栈迭代 DFS**（本文推荐，最直观）；
2. **BFS 分层**：队列里存 `(节点, 深度)`，或按层循环数层数；
3. **深度数组递推**：`dep[1] = 1`，按"父节点先于子节点"的顺序（输入恰好是 1..n，而儿子编号任意 ⇒ 不能直接顺序推），更稳的是拓扑/BFS。
⚠️ 但**不能用递归**（原因见根因②）。
</details>
