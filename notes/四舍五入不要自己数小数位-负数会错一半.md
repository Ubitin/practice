# 你的 `g()` 对不对？—— **非负数 100% 对，负数错一半**

> **触发点**：你问 `01.cpp` 里 `g()` 的"四舍五入"是否正确。
> **一句话结论**：
> ✅ **非负数：完全正确** —— 网格 410 个用例 **0 错**，`12.5 / 0.5 / 100.5` 这些 `.5` 边界也全对（甚至在 `0.49999999999999994` 这个著名刁钻值上比标准库 `llround` 还准）。
> ❌ **负数：错一半** —— 300 个负数用例错 **150** 个，规律极干净：**十分位是 5~9 的全错**（`-12.7` 你给 `-12`，标准答案是 `-13`）。
> **根因**：`long long u = x;` 是**向零截断**而不是向下取整（`-12.7 → -12`），于是 `x*10` 也是负的、`temp` 也是负的 ⇒ `temp < 5` **永远成立** ⇒ 负数永远"四舍"，从不"五入"。

---

## 一、逐行拆解你的 `g()`

```cpp
long long g(double x){
    long long u = x;            // ①
    long long temp = x * 10;    // ②
    temp %= 10;                 // ③
    if(temp < 5) return u;             // ④
    else if(temp >= 5) return u + 1;   // ⑤
}
```

| 行 | 你想做的 | 实际做的 | 判定 |
|---|---|---|---|
| ① | 取整数部分 | **向零截断**：`12.7→12` ✓；**`-12.7→-12`**（不是 −13）| ⚠️ 负数的基准点就错了 |
| ② | 拿到十分位 | `x*10` 是 `double`，赋给 `long long` 时截断 ⇒ 得到 `10k+d` | 非负数下 ✓（\|x\| 不大时）|
| ③ | 取最后一位 | 正数：`127%10 = 7` ✓ 正是十分位；**负数：`-127%10 = -7`** | ⚠️ 负数拿到负值 |
| ④ | 四舍 | 正数 ✓；**负数时 `-7 < 5` 恒成立** ⇒ 直接 return | ❌ 负数永远"舍" |
| ⑤ | 五入 | 正数 ✓ | — |
| — | — | **函数结尾没有兜底 `return`** | ⚠️ GCC 实测警告 `control reaches end of non-void function [-Wreturn-type]` |

> 一句话：**你的"看十分位"思路本身没问题，坏在"负数的十分位是负数"**。

## 三、负数到底该往哪边走？—— 取决于题目约定

数学上的"四舍五入"通常按**绝对值**做：`|-37.77| = 37.77 → 38`，再加符号 ⇒ **−38**。C 语言里两种主流做法也都给 −38：

| 写法 | `.5` 的规则 | `-37.77` | `-12.5` | `12.5` | 备注 |
|---|---|---|---|---|---|
| `printf("%.0f", x)` | 就近**取偶** | −38 | −12 | **12** | 实测：`0.5→0`、`2.5→2`、`12.5→12` |
| `llround(x)` | **远离 0** | −38 | **−13** | **13** | 与"四舍五入"最贴近 |
| `(ll)(x + 0.5)` | 一律往上 | **−37** ✘ | −12 | 13 | **负数整体是错的** |
| 你的 g | 负数一律截断 | **−37** ✘ | −12 | 13 | 非负与上面一致 |

⇒ **如果题目里有负温度（风寒指数这类题很常见），你的答案会成片偏大 1**（少减了一次）。
⇒ **如果题目保证输入非负**（或 `t` 的下界 ≥ 0），那你的 `g` 没问题，不用改。

> ⚠️ 这一条**必须对着题目原文确认**：`t` 的范围是多少？有没有负数样例？——这是唯一能决定"要不要改"的信息。

## 四、别自己数小数位：一行就够

```cpp
#include <cmath>
long long g(double x) { return llround(x); }      // ★ 正负都对（.5 远离 0）
// 或者干脆不转型，直接输出：
printf("%.0f\n", w);                              // 就近取偶，正负也对
```

⚠️ 两者对**恰好 `.5`** 的处理不同（见上表：`12.5` → `llround` 给 13、`printf` 给 12）。本题的 `w` 很难恰好落在 `.5` 上，一般不影响；**换题遇到 `.5` 就要按题目的参考解口径选一个**。

> 附一个冷知识：`llround(0.49999999999999994)` 在 libm 里返回 **1**（它是严格小于 0.5 的最大 double，正确答案是 0）——**你的手写版在这个值上反而是对的**。
> 所以"标准库一定更好"也不绝对；但**负数**这一关，手写版必须先自己解决"基准点是截断还是向下取整"的问题。
