# P2392 考前临时抱佛脚 —— 「不选」那条分支为什么不能写成 `else`

> 触发点：你在 `test_\01.cpp` 的注释里问：
> ```cpp
> if((nowtime + a[k]) <= (sum / 2)){   //  为什么不能写成：else{
>                                       //      if ... nowtime -= a[k];
>                                       //      else dfs(k + 1);
>                                       //      }
>     nowtime += a[k];
>     dfs(k + 1);
>     nowtime -= a[k];

## 一、先看清你那两行 `dfs` 各自代表什么

```cpp
void dfs(ll k){
    if(k > maxdeep){ maxtime = max(maxtime, nowtime); return; }

    if((nowtime + a[k]) <= (sum / 2)){   // ① 分支 A：选第 k 题
        nowtime += a[k];
        dfs(k + 1);
        nowtime -= a[k];
    }

    dfs(k + 1);                          // ② 分支 B：不选第 k 题
}
```

这道题的子问题是：**在"两份用时都不超过 sum/2"的约束下，让左脑那份尽可能大**（这样 `max(左,右) = sum - 左` 才最小）。

所以本质是「**挑一个子集，使其和尽量接近但不超过 sum/2**」——这是**子集枚举**，每道题都有**选 / 不选**两种可能：

| 代码位置 | 含义 |
|---|---|
| ① 的 `nowtime += a[k]; dfs(k+1); nowtime -= a[k];` | **选**第 k 题，然后往下走 |
| ② if 外面的那句 `dfs(k+1);` | **不选**第 k 题，直接往下走 |

**② 是 ① 的平行分支，不是 ① 的"备胎"。** 它必须**无条件执行**——因为"选"和"不选"是地位平等的两种可能，不存在"能选就不许不选"的道理。

## 二、写成 `else` 到底改变了什么

```cpp
if (nowtime + a[k] <= sum/2) { 选; dfs; 撤销; }
else { dfs(k+1); }              // ❌ 只有"装不下"才允许不选
```

看条件：**装得下 → 强制选；装不下 → 才不选。**

这就是经典的「**能装就装**」贪心。而"最大子集和不超过容量"这个问题里，**贪心是错的**——因为它拒绝了"这一件先不拿，腾出空间给后面更合适的"这种可能。

## 三、手算对比：就用题面样例的科目 4

样例第 4 科是 `[2, 4, 3]`，`sum = 9`，`sum/2 = 4`（整数除法）。

**正确答案**：挑子集和 ≤ 4。
- `{}` = 0、`{2}` = 2、`{3}` = 3、**`{4}` = 4** ✓、`{2,4}` = 6 ✗（超）、`{2,3}` = 5 ✗、`{4,3}` = 7 ✗
- 最大可行和 = **4** → 该科用时 `9 - 4 = ` **5**

**`else` 版本实际走的路径**：

```
k=1（a=2）: 0+2=2 ≤ 4  → 装得下，【强制选】      nowtime=2
k=2（a=4）: 2+4=6 > 4  → 装不下 → 才走「不选」    nowtime=2
k=3（a=3）: 2+3=5 > 4  → 装不下 → 才走「不选」    nowtime=2
走到头 → maxtime = 2
```

**它从来没有考虑过「不选 2、改选 4」这条路**（因为第 1 步装得下就被强制选了）。于是得到 2 而不是 4 → 该科用时 `9 - 2 = 7`，**多了 2**。

**整题**：正确 20 → `else` 版 **22**。**连题面样例都过不了。**

> 这个例子最妙的地方：最优解 `{4}` 恰好就是"**跳过前面那个小的**"。而 `else` 版的写法从结构上就禁止了这一步。

## 四、再看一个更直白的例子

科目用时 `[6, 5, 5]`，`sum = 16`，`sum/2 = 8`。

| 方案 | 子集和 | 是否 ≤ 8 |
|---|---|---|
| `{6}` | 6 | ✓ |
| `{5,5}` | **10** | ✗ 超了 |
| `{6,5}` | 11 | ✗ |

正确答案是 **6**（这份题里最好的就是 6）。

再看 `[6, 5]`，`sum = 11`，`sum/2 = 5`：

| 方案 | 子集和 | 是否 ≤ 5 |
|---|---|---|
| `{6}` | 6 | ✗ |
| `{5}` | **5** | ✓ |
| `{}` | 0 | ✓ |

最优是 **5**（只拿 5）。但 `else` 版在第 1 题就会强制选 6……

```
k=1（a=6）: 0+6=6 > 5  → 装不下 → 只能不选 ✓（这次恰好对）
k=2（a=5）: 0+5=5 ≤ 5  → 强制选 → nowtime=5 ✓
```
这组两版都对。**说明 `else` 版的错误只在"能选但选了反而更差"的输入上暴露**——这正是它阴险的地方：随手造几组数据很可能测不出来。

## 六、注释里那半句 `nowtime -= a[k]` 更不能写进 `else`

你注释里想的可能是「在 `else` 里也要撤销一下」。**这在语义上说不通**：

`nowtime -= a[k]` 的作用是**抵消刚刚那次 `nowtime += a[k]`**。而在 `else` 分支里，`if` 条件为假 → `nowtime += a[k]` **从来没执行过** → 这时再做 `-= a[k]` 就是**凭空减**。

举例：`nowtime = 0`，`a[k] = 5`，容量 4。

```
if 条件：0 + 5 = 5 > 4  → 假 → 走 else
若在 else 里写 nowtime -= 5  →  nowtime 变成 -5   ❌
```

`nowtime` 是"已选子集的和"，它**不可能为负**。一旦变负，后面所有 `nowtime + a[k] <= sum/2` 的判断全部失真，`maxtime` 记录的就是垃圾。

> **口诀：`-=` 只能配对"刚刚真的 `+=` 过"的那一次。** 撤销语句必须紧跟在它的正向操作后面，**不能"另起炉灶"**。

## 七、回溯法的通用形态

你已经写对了的那个形态，值得当成模板记牢：

```cpp
void dfs(int k) {
    if (k > n) { 结算; return; }        // 走到头 → 记录

    // 分支 1：对第 k 个元素「做点什么」（选它）
    if (/* 做了之后仍然合法 */) {        // ← 合法性剪枝
        做选择;
        dfs(k + 1);
        撤销选择;                        // ★ 与"做选择"严格成对
    }

    // 分支 2：对第 k 个元素「什么都不做」
    dfs(k + 1);                          // ★ 无条件！这是独立的第二条路
}
```

**两条分支是「并列的两条路」，不是一个 `if-else`。** 只要把它们写成 `if / else`，就等于宣布"第一条走通了就不许走第二条"，搜索树被砍掉一半，必然漏解。

### 状态：`if` 那层剪枝安全吗？

安全。因为**所有 `a[k]` 都是正数**，一旦 `nowtime + a[k] > sum/2`，加上去之后**只会更大**，后面再也不可能降回容量以内 → 这条分支可以安心剪掉。

> ⚠️ 但如果题目里允许**负数或 0** 的用时，这个剪枝就**不成立**了（加了可能还能降回来），得换成无剪枝的完整子集枚举。

## 九、坑清单

| # | 坑 | 后果 |
|---|---|---|
| 1 | **把"不选"写成 `else`** | 退化成贪心，漏掉"当前不选、留给后面"的最优解（本题样例就错） |
| 2 | **在 `else` 里写 `nowtime -= a[k]`** | 那时根本没加过，`nowtime` 变负 → 后续判断全错 |
| 3 | 忘了 `nowtime -= a[k]` | 回溯状态不干净，`nowtime` 只增不减 → 后续容量判断全假 |
| 4 | `dfs(k+1)` 写在撤销**之前** | 下一层看到的是已经撤销的状态 |
| 5 | 把 `sum/2` 当成"必须凑到"的目标 | 是**不超过**的上限，取最大可达值即可 |
| 6 | 答案写成 `max(maxtime, sum-maxtime)` 与 `sum-maxtime` 混用 | 其实等价（因 `maxtime ≤ sum/2`），但换题时容易写错；用 `sum - maxtime` 更短 |
| 7 | 误以为"能选就选"总是好 | 反例：容量 4、元素 `[2,4,3]` 时 `{4}` 优于 `{2}` |
| 8 | `s_i` 很大时还用子集枚举 | 会 TLE，应改 0/1 背包 |

## 十、自查

1. 你代码里 if 外面那句 `dfs(k + 1)` 代表什么？写成 `else { dfs(k+1); }` 会变成什么？
2. 用容量 4、元素 `[2,4,3]` 手算一遍两种写法，最优子集分别是多少？
3. 为什么在 `else` 分支里写 `nowtime -= a[k]` 是错的？拿 `nowtime=0, a[k]=5, 容量=4` 演算一下。
4. `if (nowtime + a[k] <= sum/2)` 这层剪枝为什么可以安全地剪掉"选它"的分支？
5. 什么样的情况下这层剪枝就不安全了？
6. 这题的正统解法是什么？复杂度多少？什么时候必须换？

**答案要点**
1. 代表「**不选**第 k 题、直接进入第 k+1 题」这条独立分支。写成 `else` 就变成"只有装不下时才允许不选"，即「能装就装」的贪心，会漏掉"跳过当前、留给后面"的更优组合。
2. 容量 4、元素 `[2,4,3]`：正确写法能枚举到 `{4}` → 最大和 **4**；`else` 版第 1 步就强制选了 2，之后 4 和 3 都装不下，只能得到 **2**。样例第 4 科因此从 5 变成 7（整题 20 → 22）。
3. 因为在 `else` 分支里 `if` 条件为假，`nowtime += a[k]` **从未执行**，此时再 `-= a[k]` 就是凭空减：`nowtime` 由 0 变成 -5。而 `nowtime` 是"已选子集的和"，不可能为负；一旦为负，后面所有容量判断都失真。
4. 因为所有用时都是**正数**：一旦 `nowtime + a[k] > sum/2`，加上它之后和只会更大，后面再也不可能降回容量以内，所以这条分支可以放心剪掉。
5. 当元素**可能为 0 或负数**时。那时加进去还可能"变回来"，剪枝会漏解。
6. **0/1 背包**：容量 `sum/2`、布尔 `dp`、内层**倒序**，复杂度 `O(s_i × sum/2)`。当 `s_i` 变大（例如上百）时，`2^{s_i}` 的子集枚举必然超时，必须换成背包。
