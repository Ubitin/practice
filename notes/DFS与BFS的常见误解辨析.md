# DFS 与 BFS 的常见误解辨析

> 触发点：你的理解是——"**DFS 是用较高的效率去搜索所有合法的方案；BFS 是只搜索满足特定性质（比如路径最短）的方案**"。
> 判定：**方向对了一半。** "DFS 常用于枚举所有方案""BFS 常用于求最短路"这两个**关联**是对的；但"效率较高"和"只搜索满足特定性质的方案"这两处**说法是错的**，而且第二处恰好是 BFS 最容易被误解的地方。
> 实测程序：`test_\bfs_vs_dfs_myth.mjs`。
> 相关：`BFS广度优先搜索-马的遍历动画讲解`、`DFS深度优先搜索与回溯-数独动画讲解`（两个可交互动画）。

## 一、逐句判定

| 你的说法 | 判定 | 说明 |
|---|---|---|
| DFS 常用于搜索**所有合法的方案** | ✅ **对** | 这是 DFS 的招牌场景（配合回溯） |
| DFS **用较高的效率** | ❌ **不对** | 时间上两者同阶；"枚举所有方案"本身往往是指数级的**低效**做法。DFS 真正的优势是**空间省**和**容易剪枝** |
| BFS 常用于求**最短路径** | ✅ **对** | 无权图最短路的标准工具 |
| BFS **只搜索满足特定性质的方案** | ❌ **恰好说反了** | **BFS 也是穷举整个可达状态空间**，只是**按距离由近及远**搜。它不是"挑着搜"，而是"一个不落地搜，但按顺序" |

## 二、⚠️ 最大的误解：BFS 并非"只搜一部分"

**BFS 之所以能求出最短，恰恰是因为它足够"笨"——老老实实按距离排队，绝不跳跃。** 它的"聪明"不在筛选，而在**顺序**。

### 实测（8×8 棋盘，起点 (1,1)，马走法）

```
棋盘上总共 64 格，BFS 一共处理了 64 格 —— 也就是【全部】都访问了
队列最大长度 = 31
```

**BFS 把整块棋盘都搜了一遍。** 它并不"知道"哪个点会成为目标，所以只能按层推进。

那"只求一个点的最短路"时它能不能提前停？能——**但停下来之前它已经把前面所有层都搜完了**：

| 目标点 | 它的最短步数 | 停下前已处理的格数 | 占全盘 |
|---|---|---|---|
| (2,3) | 1 | 3 | 5% |
| (4,4) | 2 | 5 | 8% |
| (1,4) | 3 | 31 | 48% |
| (8,1) | 5 | 61 | 95% |
| **(8,8)** | **6** | **64** | **100%** |

> 目标越远，BFS 搜得越多；**最远的目标意味着它必须搜遍全盘**。
> 所以 BFS 不是"只搜满足特定性质的方案"，而是"**把近的都搜完了，所以第一次碰到目标时就已经是最短的**"。

**换个说法**：BFS 的提前退出是"**到终点为止**"，不是"**只搜相关的**"。它前面那一堆层，一格都没少搜。

## 三、⚠️ "DFS 效率较高"也不准确

### 时间上：两者同阶

如果搜索空间相同，DFS 和 BFS 的时间复杂度都是"**每个可达状态访问一次**"——O(状态数 × 分支数)。DFS 并不会因为"按深度走"就更快。

### "枚举所有方案"本身常常是低效做法

这是关键：**要枚举 2^n 个方案，就得付 2^n 的代价**，这跟用 DFS 还是别的无关。

**实测**（P2392 每科 s 道题，枚举所有左右脑分配方案）：

| s | 子集枚举 2^s | 0/1 背包 DP（s×sum/2） | 倍差 |
|---|---|---|---|
| 10 | 1,024 | 5,000 | 0.2× |
| 20 | **1,048,576** | **20,000** | **52×** |
| 25 | 33,554,432 | 31,250 | 1074× |
| 30 | **1,073,741,824** | **45,000** | **~24000×** |

> **同一个问题，"枚举所有方案"比"用 DP 直接算"慢了上万倍。**
> 所以 DFS 的价值是「**通用**」——不管题目多奇怪，你总能枚举；**不是「高效」**。
> 当问题有更好的结构（DP、贪心、数学公式）时，**枚举方案往往是最后的选择**。

### DFS 真正省的是**空间**

| | DFS | BFS |
|---|---|---|
| 需要存什么 | **一条当前路径** | **整个待扩展的层** |
| 空间量级 | O(深度) | O(最宽层) |
| 数独实测 | 最大栈深 **16**（= 格子数） | — |
| 8×8 马 BFS 实测 | — | 队列峰值 **31** |

**实测队列峰值随棋盘增长**：

| 棋盘 | 格数 | BFS 队列峰值 |
|---|---|---|
| 4×4 | 16 | 6 |
| 6×6 | 36 | 20 |
| 8×8 | 64 | 31 |
| 10×10 | 100 | 37 |
| 12×12 | 144 | 42 |

> 这就是为什么"状态空间巨大、只求连通性/枚举"时用 DFS：**它只用一条路径的内存**。
> 而 BFS 在状态爆炸时会 MLE——因为整层都得存在队列里。

## 四、⚠️ "所有方案 vs 特定性质"这个二分不成立

**两者都能做对方的事，只是成本不同。**

### DFS 也能求最短路（只是慢得离谱）

**实测**：8×8 棋盘求 (1,1) → (2,3) 的最短步数

```
DFS：答案 1，递归调用 2931 次
BFS：答案 1，只处理了 3 个点
```

**同一个答案，BFS 快约 1000 倍。** DFS 得把所有路径都试一遍才能确定哪条最短。

### BFS 也能"数方案数"

**实测**：用 BFS 分层累加"最短路径条数"

```
(1,1) → (4,4) 最短 2 步，共 2 条最短路径
```

做法：`d[nx][ny] == d[x][y]+1` 时 `ways[nx][ny] += ways[x][y]`。**这就是 BFS 在数方案个数**——在"按层递推"这一点上，BFS 天然适合。

> 所以：**区别不在"搜什么"，而在"按什么顺序搜，从而哪个操作变便宜"。**

## 五、正确的区分（一张表）

| | DFS（深度优先） | BFS（广度优先） |
|---|---|---|
| 数据结构 | **栈**（或递归） | **队列** |
| 访问顺序 | 按**深度**：一条路走到底 | 按**距离**：由近及远，一圈一圈 |
| **搜索范围** | **整个可达状态空间** | **整个可达状态空间**（一样是全搜） |
| 第一次到达某点 | ❌ **不保证最短** | ✅ **就是最短**（因为前面层都处理完了） |
| 空间 | **O(深度)** ← 省 | O(最宽层) ← 可能爆 |
| 天然擅长的 | 枚举所有方案、连通性、**回溯+剪枝** | **无权最短路**、按层递推（如数最短路径条数） |
| 什么时候吃亏 | 求最短路（要枚举所有路径） | 空间爆炸、需要"路径约束"的剪枝 |

**一句话的本质**：

> - **DFS 的优势来自"深度 + 可撤销"**：它天然维护一条"当前路径"，所以能做**路径上的剪枝**（数独的行列块冲突、八皇后的对角线），并且撤销得干干净净。
> - **BFS 的优势来自"顺序"**：按距离递增访问，使得"**第一次到达**"这个事件自动携带了"**最短**"的信息。代价是要存整层。
> - **两者都不是"选择性搜索"**——都是全搜，只是顺序不同、因此哪个副产品（最短距离 / 路径约束）来得便宜不同。

## 六、决策表：什么时候用哪个

| 问题 | 选 | 理由 |
|---|---|---|
| 求无权图最短步数 | **BFS** | 第一次到达即最短 |
| 求最短路径的**条数** | **BFS** | 按层累加 `ways` |
| 枚举所有方案 / 方案数（规模小） | **DFS** | 回溯增量维护当前解，不用为每个方案复制状态 |
| 判断连通性 / 连通块 | 都行 | BFS 要存整层，DFS 更省内存 → 倾向 **DFS** |
| 数独 / 八皇后 / 排列组合 | **DFS** | 需要沿路径剪枝 + 撤销 |
| 迷宫最短路 | **BFS** | DFS 会绕远路 |
| 状态空间极大、只求"能不能到" | **DFS** | BFS 队列会 MLE |
| 有更好的结构（DP/贪心/数学） | **都不用** | 枚举是最后手段（实测慢上万倍） |

## 七、自查

1. "BFS 只搜索满足特定性质的方案"这句话哪里错了？用 8×8 棋盘的实测数据说明。
2. BFS 能提前退出吗？"提前退出"省掉的是什么、没省掉的是什么？
3. 为什么说"DFS 效率较高"不准确？如果想表达 DFS 的优势，应该怎么说？
4. DFS 能不能求最短路？实测比 BFS 慢多少倍？
5. BFS 能不能数方案数？怎么数？
6. 数独/八皇后为什么用 DFS 而不是 BFS？
7. 记忆没上限的大状态空间里，为什么倾向 DFS？

**答案要点**
1. 反了。BFS **也把可达状态全搜一遍**——实测 8×8 棋盘求最短路时 BFS 处理了全部 **64** 格（队列峰值 31）。它不是"挑着搜"，而是"按距离由近及远一个不落地搜"。
2. 能——当目标点第一次被**弹出**时就可以停（此时它的最短距离已确定）。省掉的是"目标之后的层"；**没省掉的是目标之前的所有层**（目标是 (8,8) 时，前面 64 格全搜了）。
3. 时间上两者同阶；而"枚举所有方案"本身往往是指数级低效（实测 s=30 时比 DP 慢约 24000 倍）。DFS 真正的优势是**空间只需 O(深度)**（数独实测栈深 16）**且容易沿路径剪枝**。
4. 能——枚举所有路径取 min。实测 8×8 求 (1,1)→(2,3) 最短步数：DFS 递归 **2931** 次，BFS 只处理 **3** 个点，**差约 1000 倍**。
5. 能。BFS 按层递推，`d[nx][ny] == d[x][y]+1` 时 `ways[nx][ny] += ways[x][y]`。实测 (1,1)→(4,4) 最短 2 步共 2 条。
6. 因为需要**沿当前路径做约束剪枝**（行列块冲突/对角线），而且 DFS 天然能干净地撤销回退；BFS 的状态散在队列里，很难做这种路径约束。
7. 因为 BFS 要**存整层**，状态爆炸时队列会 MLE；DFS 只存一条路径，空间 O(深度)。
