# memset 与 resize 复杂度对比：谁更快？先看清语义再谈复杂度

> 起因：你问 `v.resize(n)` 和 `memset(arr, 0, n)` 谁的复杂度低——这个问题**先有一个语义陷阱**，拆开后结论和直觉可能不同。
> 演示程序：`test_\27.cpp`（5000 万个 int ≈ 200MB 实测，g++ C++17 -O2）。

---

## 0. 先说结论（三句话）

1. **渐进复杂度都是 O(n)，没有谁更低**——两者都是"线性扫一遍"。
2. **但 n 的含义不同**：`memset` 的 n 是**字节数**，`resize` 的 n 是**元素个数**——直接比数字没有意义。
3. **常数上现代编译器几乎打平**（memset ≈ fill ≈ assign，实测 6.3~6.8ms/200MB）；唯一例外：**`resize(0)` 清空 int 容器近似 O(1)**，比 memset 快一个量级。

## 1. 语义陷阱：memset 按"字节"，resize 按"元素"

```cpp
int arr[100];
memset(arr, 0, 100);      // ❌ 只清了 100 字节 = 25 个 int！
// 实测：arr[0..24] 是 0，arr[25..99] 原封不动（25/100 被清零）
memset(arr, 0, sizeof(arr));          // ✅ sizeof(arr)=400 字节 = 100 个 int
memset(arr, 0, 100 * sizeof(int));    // ✅ 或写元素个数 × sizeof
```

**memset 的第三参数永远是"字节数"**，清 `n` 个 int 要写 `n * sizeof(int)`（这是 memset 最经典的翻车点）。
（第二个参数——"字节值"本身是什么，见 **§6**。）

`v.resize(n)` 则是把 vector 变成恰好 n 个元素——语义完全不同：
- 变大：多余的新元素被初始化为 0（int）；
- 变小：尾部元素被"销毁"。

## 2. 复杂度拆解（重点）

| 操作 | 渐进复杂度 | 说明 |
|---|---|---|
| `memset(p, 0, bytes)` | **O(bytes)** | 按字节写，bytes = 元素数 × sizeof |
| `std::fill(v.begin(), v.end(), 0)` | O(n) | 按元素赋值 |
| `v.assign(n, 0)` | O(n) | 重新填充（若容量不足另有 O(n) 扩容） |
| `v.resize(更大)` | O(新元素数) | 初始化新增部分；可能触发扩容 O(n) |
| **`v.resize(更小)`** | **近似 O(1)（int）** | 平凡析构只改 size 指针，不逐个"干活" |

**为什么 resize(0) 对 int 是近似 O(1)**：`int` 的析构是"空操作"，`vector<int>::resize(0)` 实际上只是把 `size` 指针改回开头——实测 200MB 的 vector 清空耗时 **0.00ms**，而 memset 同样大小的内存要 **6.3ms**。这不是标准保证的复杂度（标准说"与删除元素数成线性"），但平凡类型上主流实现都这么优化——**知道即可，别依赖标准承诺**。

## 3. 实测数据（200MB = 5000 万个 int，3 次取最小）

| 操作 | 耗时 |
|---|---|
| `memset(raw, 0, N*sizeof(int))` | 6.34 ms |
| `std::fill(v.begin(), v.end(), 0)` | 6.82 ms |
| `v.assign(N, 0)` | 6.74 ms |
| `v.resize(0)`（清空） | **0.00 ms** |
| `v.resize(N, 0)`（重新填满） | 7.02 ms |

**注意**：memset 只比 fill 快 7%——老教材"memset 比 fill 快好几倍"的说法在现代编译器**已不成立**（`std::fill` 对 int 数组会生成和 memset 同级的 SIMD 代码）。不要为了"快"而牺牲可读性去混用 memset。

## 4. 实战选型（什么时候用哪个）

| 场景 | 推荐 | 理由 |
|---|---|---|
| 清空一个 `vector<int>`（多组数据重置） | `v.clear()` 或 `v.resize(0)` | 对 int 近似 O(1)，比重新 memset 快 |
| 清零 C 数组（计数数组） | `memset(a, 0, sizeof(a))` | 最直接；**记得 sizeof** |
| 清零后还要重新填 | 先 memset/fill，再正常赋值 | 避免 resize 反复改大小 |
| 重置 vector 为全 0 且保持大小 | `fill(v.begin(), v.end(), 0)` | 类型安全、语义清晰，性能与 memset 同级 |
| 元素是非平凡类型（string 等） | **绝不 memset** | 会破坏对象内部结构，必须 fill/assign |

## 5. 记忆钩子

> **memset 数"字节"，resize 数"元素"；复杂度都 O(n)，别指望谁"更低"——真正快的只有 resize 缩小（int 上近似 O(1)）和 memset 的正确写法 `sizeof(arr)`。**

**一句话总结**：两者渐进都是 O(n)，直接回答"谁复杂度低"没有赢家；真正的坑在**单位**（字节 vs 元素）——清零数组记得 `memset(a, 0, sizeof(a))`，清空 int 容器用 `resize(0)` 反而更快（实测 0ms vs 6ms），非平凡类型永远用 fill/assign 而别碰 memset。

## 6. 补充：`memset` 的第二个参数 —— **「字节值」到底是什么**

> **一句话**：**1 字节 = 8 个二进制位，能表示 0~255；「字节值」就是"这 8 位填什么"。**
> `memset(p, v, n)` 会先把 `v` **截成 1 个字节**（相当于 `(unsigned char)v`，只留低 8 位），再把这**一个**字节原样复制 `n` 遍。它完全不知道你的元素是 int 还是 long long。

### 6.1 一个字节有多大（实测）

| 单位 | 位数 | 能表示的整数 | 实测 |
|---|---|---|---|
| 1 位（bit）| 1 | 0 / 1 | |
| **1 字节（byte）** | **8** | **0 ~ 255**（=0xFF）| `sizeof(char) = 1` |
| 4 字节（int）| 32 | | `sizeof(int) = 4` |
| 8 字节（long long）| 64 | | `sizeof(long long) = 8` |

### 6.2 `memset` 具体干了什么：1002 是怎么变成 0xEA 的

```
1002 = 0b1111101010        （10 位）
只留低 8 位 → 0b11101010 = 234 = 0xEA          ← 这就是「字节值」
memset(b, 1002, sizeof(b)) ⇒ 把 0xEA 复制 8 遍
8 个字节拼起来 = 0xEAEAEAEAEAEAEAEA = -1519143629599610134
```

### 6.3 同一个字节值，填进不同宽度会变成什么（实测表）

| `memset` 第二参数 | 实际填的每字节 | `int`（4 字节）| `long long`（8 字节）|
|---|---|---|---|
| `0` | 0x00 | 0 | 0 |
| `-1` | 0xFF | −1 | −1 |
| `1` | 0x01 | 16843009 | 72340172838076673 |
| `0x3f` | 0x3F | 1061109567 | 4557430888798830399 |
| `0x7f` | 0x7F | 2139062143 | 9187201950435737471 |
| `0x80` | 0x80 | −2139062144 | −9187201950435737472 |
| **`1002`** | **0xEA** | **−353703190** | **−1519143629599610134** |
| `255` | 0xFF | **−1** | **−1** |
| `256` | **0x00** | **0** | **0** |

⭐ 表里藏着两个彩蛋：

- **`memset(p, 255, ...)` 和 `memset(p, -1, ...)` 结果完全一样**（255 & 0xFF = 0xFF）；
- **`memset(p, 256, ...)` 等于 `memset(p, 0, ...)`** —— 想"填 256"的人会把整块内存**清零**（256 的低 8 位是 0）。

### 6.4 顺带：一个数在内存里就是若干字节拼起来的（小端序）

| 值 | 内存里的字节（低地址 → 高地址）|
|---|---|
| `int 0x12345678` | `78 56 34 12` |
| `int 1` | `01 00 00 00` |
| `int -1` | `FF FF FF FF` |
| `long long -1` | `FF FF FF FF FF FF FF FF` |

低地址放**低位**字节，这叫**小端序**（x86 与评测机都是这个顺序）。这也解释了为什么 `memset(-1)` 能正确表示 −1：全 1 就是"所有位都是 1"，与字节顺序无关。

### 6.5 回到结论：为什么只有 0 / −1 / 0x3f / 0x7f 能用 memset 填

因为它们**这 8 位全都一样**（0x00、0xFF、0x3F、0x7F），复制 4 遍、8 遍之后拼出来的仍然是"同一个数"；其它值的各位不一样，复制出来就变成另一个数了。

## 7. 字节值**怎么算**：一句话 `v & 0xFF`

> **结论：字节值 = `v & 0xFF`** —— 也就是"**只留 v 的低 8 位**"。
> 等价写法：`(unsigned char)v`。数学上就是 `v − 256·⌊v/256⌋`（写起来麻烦，不推荐）。
> ⚠️ **不能用 `v % 256`** —— C++ 的 `%` 会保留符号，负数直接错（实测 `-1 % 256 = -1`，而正确是 `255`）。

### 7.1 四种算法对照（实测，重点看负数）

| v | `v & 0xFF` ✅ | `(unsigned char)v` ✅ | `v % 256` ❌ | `v − 256·⌊v/256⌋` ✅ |
|---|---|---|---|---|
| 1002 | **234** | 234 | 234 | 234 |
| 1000 | 232 | 232 | 232 | 232 |
| 255 | 255 | 255 | 255 | 255 |
| **256** | **0** | 0 | 0 | 0 |
| **-1** | **255** | 255 | **−1** ✘ | 255 |
| **-2** | **254** | 254 | **−2** ✘ | 254 |
| **-1002** | **22** | 22 | **−234** ✘ | 22 |

（`-1002 = -256×4 + 22` ⇒ 22 = 0x16）

### 7.2 手算的三条路（**1002 → 0xEA**）

**① 十进制：减去整数个 256**

```
1002 ÷ 256 = 3 余 234        （256×3 = 768，1002 − 768 = 234）
⇒ 字节值 = 234 = 0xEA
其它：1000 → 232 = 0xE8 ；70000 = 256×273 + 112 → 112 = 0x70 ；300 → 44 = 0x2C
```

**② 二进制：只留低 8 位，再按权相加**

```
1002 = ...0000 0011 1110 1010
低 8 位 = 1110 1010
按 128/64/32/16/8/4/2/1 加权：128 + 64 + 32 + 8 + 2 = 234 = 0xEA ✓
（-1 是 32 位全 1，低 8 位 = 1111 1111 = 255 = 0xFF）
```

**③ 位运算（代码里就用这个）**

```cpp
int b = v & 0xFF;        // 或 (unsigned char)v
```

### 7.3 反过来：某个字节值会被填成什么数（还原公式）

| 目标宽度 | 公式 | 例子（b = 0xEA）|
|---|---|---|
| `int`（4 字节）| `0x01010101u × b` | 0xEAEAEAEA = **−353703190** |
| `long long`（8 字节）| `0x0101010101010101ULL × b` | 0xEAEAEAEAEAEAEAEA = **−1519143629599610134** |

**实测验证**：

- 穷举 **256 个字节值 × 2 种宽度 = 512 组**，公式与真实 `memset` **全部一致（错 0 组）** ✔
- 穷举 `v ∈ [−200000, 200000]` 共 **400001 个**：`memset(p, v, …)` 与 `memset(p, v & 0xFF, …)` **完全一致（不一致 0 组）** ✔

> 这条公式能让你**不编译就能算出** memset 的结果：
> `memset(b, 1002, sizeof(b))` ⇒ `1002 & 0xFF = 0xEA` ⇒ `0x0101010101010101 × 0xEA = 0xEAEAEAEAEAEAEAEA = −1519143629599610134` ✓ 与实测一致。

## 8. 代码实现：字节值转换**四件套**

### 8.1 四个工具函数（可直接抄）

```cpp
#include <bits/stdc++.h>
using namespace std;

// ① 取一个整数的「字节值」（低 8 位）
inline unsigned char lowByte(long long v) {
    return (unsigned char)(v & 0xFF);        // ⚠️ 别写 v % 256：负数会错（-1%256=-1，应 255）
}

// ② 字节值 b → 某种宽度被 memset 填出来的完整数值（编译期也能算：constexpr）
template <class T>
T fillPattern(unsigned char b) {
    using U = make_unsigned_t<T>;
    U u = 0;
    for (size_t i = 0; i < sizeof(T); ++i) u = (U)((u << 8) | (U)b);
    T out;
    memcpy(&out, &u, sizeof(T));             // 用 memcpy 回填：避免有符号左移溢出与实现定义转换
    return out;
}
// 手写特例（更快，与上面等价，实测一致）
inline int       fillPatternInt(unsigned char b) { return (int)(0x01010101u * (unsigned)b); }
inline long long fillPatternLL (unsigned char b) { return (long long)(0x0101010101010101ULL * (unsigned long long)b); }

// ③ 这个值能不能用 memset 填出来？（判据：它的每个字节是否都相同）
template <class T>
bool memsetSafe(long long v) {
    T x;
    memcpy(&x, &v, sizeof(T) < sizeof(v) ? sizeof(T) : sizeof(v));
    const unsigned char* p = reinterpret_cast<const unsigned char*>(&x);   // 读对象表示是标准允许的
    for (size_t i = 1; i < sizeof(T); ++i) if (p[i] != p[0]) return false;
    return true;
}

// ④ 反推：想让 memset 填出 want，该填哪个字节？做不到返回 -1
template <class T>
int patternFor(T want) {
    const unsigned char* p = reinterpret_cast<const unsigned char*>(&want);
    for (size_t i = 1; i < sizeof(T); ++i) if (p[i] != p[0]) return -1;
    return p[0];
}
```

### 8.2 三个容易写错的地方

| 细节 | 说明 |
|---|---|
| **`fillPattern` 为什么先拼 `unsigned` 再 `memcpy`** | 若直接用 `T（int）` 左移，`0xFF << 24` 会**移进位符号位** → 有符号溢出是 UB；先在无符号里拼好，再按字节拷回，完全避开 |
| **读字节为什么用 `unsigned char*`** | 标准明确允许用 `char`/`unsigned char` 指针读任意对象的**对象表示**；但 `char` 在多数平台是**有符号**的，读到 0xEA 会变成 −22，所以要用 `unsigned char` |
| **取字节值为什么不用 `% 256`** | C++ 的 `%` 保留符号（`-1 % 256 = -1`）；`& 0xFF`（或 `(unsigned char)v`）才符合"取低 8 位"的语义 |

### 8.3 实测验证（`test_\byte_convert.cpp`，零警告）

| 检查项 | 结果 |
|---|---|
| ① `lowByte(v)` vs 内存里的**真实字节**，`v ∈ [−300, 300]` 共 601 个 | 不一致 **0** ✅ |
| ② `fillPattern<T>(b)` vs **真实 memset**：256 个字节值 × {int, long long, short, unsigned int, 两个手写特例} | **1536 组，不一致 0** ✅ |
| ③ `memsetSafe<int>(v)` vs 暴力"4 个字节是否相等"，`v ∈ [−200000, 200000]` 共 400001 个 | 不一致 **0** ✅ |
| ④ 上一条 400001 个值里**能被 memset 填出来的只有 2 个**（`0` 和 `−1`）| 说明"能 memset 的值"在整数里**极稀少** |

### 8.5 调试小工具：打印任意对象的每个字节

```cpp
template <class T>
void dumpBytes(const char* name, const T& x) {
    const unsigned char* p = reinterpret_cast<const unsigned char*>(&x);
    printf("  %-22s 字节: ", name);
    for (size_t i = 0; i < sizeof(T); ++i) printf("%02X ", p[i]);
    printf("\n");
}
// 实测：int 1002 → EA 03 00 00 ；long long -1 → FF FF FF FF FF FF FF FF ；int 0x3F3F3F3F → 3F 3F 3F 3F
```

### 8.6 实战判据（一句话）

> **想填的值不是"每个字节都一样"⇒ 用 `fill` 或循环，别用 `memset`。**
> 拿不准就用工具④试一下：`if (patternFor<int>(INF) < 0) 用 fill;`

```cpp
fill(&a[0][0], &a[0][0] + N * M, INF);            // 一维 / 摊平的二维数组
for (int i = 0; i < N; ++i) for (int j = 0; j < M; ++j) a[i][j] = INF;   // 最直白
std::fill(v.begin(), v.end(), INF);               // 容器
```

2. **−1519143629599610134**（= 0xEAEAEAEAEAEAEAEA）。
3. 因为直接对**有符号** `T` 左移，`0xFF << 24` 会把 1 移进符号位 → **有符号整数溢出（UB）**；先在无符号类型里拼好（无符号溢出是良定义的），再用 `memcpy` 按字节拷回，既正确又不用做实现定义的窄化转换。
4. **不行**。`1002` 的四个字节是 `EA 03 00 00`，不是"每个字节都一样"（工具④会返回 −1）⇒ 只能用 `fill` 或循环赋值，或者改用 `int` 数组 + 别的哨兵（如 `0x3f3f3f3f`，它**可以**用 `memset(a, 0x3f, sizeof(a))`）。
5. 用 **`unsigned char*`**。两者读"对象表示"都是标准允许的，但 `char` 在多数平台是**有符号**的，读到 0xEA 会显示成 −22（打印/比较都会出错）。
</details>

## 9. 速查：某个字节值对应的"值"是多少

### 9.1 实例：字节值 **215**

```
215 = 0xD7 = 0b1101 0111 = 128+64+16+4+2+1
```

`memset(p, 215, n)` 之后，把内存当成不同宽度读出来分别是（实测，并与公式对照）：

| 读成什么 | 值 | 十六进制 |
|---|---|---|
| `int`（4 字节）| **−673720361** | 0xD7D7D7D7 |
| `unsigned int` | 3621246935 | 0xD7D7D7D7 |
| `long long`（8 字节）| **−2893606913523066921** | 0xD7D7D7D7D7D7D7D7 |
| `unsigned long long` | 15553137160186484695 | 0xD7D7D7D7D7D7D7D7 |
| `short`（2 字节）| −10281 | 0xD7D7 |
| `unsigned short` | 55255 | 0xD7D7 |
| 单字节（就是字节值本身）| 215 | 0xD7 |

公式对照：`0x01010101u × 215 = −673720361` ✔、`0x0101010101010101ULL × 215 = −2893606913523066921` ✔（与真实 memset 一致）

> ⚠️ **注意区分「字节值 215」和「想把内存填成整数 215」**：
> `memset(a, 215, sizeof(int))` 得到的是 **−673720361**，**不是 215**！
> 想得到整数 215（= 0x000000D7，4 个字节各不相同）**memset 根本做不到** ⇒ 只能用 `fill` 或循环。

### 9.2 常用字节值速查表（实测）

| 字节值 | 十六进制 | 二进制 | `int` 结果 | `long long` 结果 |
|---|---|---|---|---|
| 0 | 0x00 | 00000000 | 0 | 0 |
| 63 | 0x3F | 00111111 | 1061109567 | 4557430888798830399 |
| 127 | 0x7F | 01111111 | 2139062143 | 9187201950435737471 |
| 128 | 0x80 | 10000000 | −2139062144 | −9187201950435737472 |
| **215** | **0xD7** | **11010111** | **−673720361** | **−2893606913523066921** |
| 234 | 0xEA | 11101010 | −353703190 | −1519143629599610134 |
| 255 | 0xFF | 11111111 | −1 | −1 |

**看表规律**：只有 `0x00 / 0xFF`（以及 `0x3F / 0x7F` 这类**刻意选的**全同字节）能得到"整齐"的值；其它字节值（如 0xD7）填出来的都是"看起来毫不相干"的大数（负数居多）。

### 9.3 自查

1. 字节值 215 的十六进制和二进制分别是什么？
2. `memset(a, 215, 4)` 之后 `a[0]` 是多少？为什么不是 215？
3. 想用 memset 把 `int` 数组填成 215，行不行？该怎么写？

<details>
<summary>答案</summary>

1. **0xD7**；二进制 **1101 0111**（= 128+64+16+4+2+1 = 215）。
2. **−673720361**（= 0xD7D7D7D7）。因为 memset 把**每个字节**都填成 0xD7，四个字节拼起来就是 0xD7D7D7D7，这与十进制 215（= 0x000000D7）完全不同。
3. **不行**。215 = 0x000000D7，四个字节不全相同 ⇒ 必须用 `fill`/循环：`for (i) a[i] = 215;` 或 `fill(a, a + n, 215);`
</details>
