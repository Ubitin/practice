# P2058 海港（NOIP2016 普及组）—— 队列里到底装什么？

> **触发点**：2026-09-28，你在做 [P2058 海港](https://www.luogu.com.cn/problem/P2058)，原话是"**我知道要用队列做，但不知道如何建模**"。
> **一句话结论**：队列里装的**不是船，是乘客**——每个元素揣两个信息 `(到达时刻 t, 国籍 x)`；再配一张 `cnt[国籍]` 计数表和一个 `ans`（窗口内不同国籍数），**只在计数 0↔1 变化时改 `ans`**。
> **判据**：官方样例 `3 4 4` ✅、边界样例 `3 3 3 4` ✅、vs 独立暴力 **30000 轮不一致 0** ✅、极限 Σk=3e5 **3 ms** ✅。

## 一、题目（30 秒版）

海港按时间记录了 `n` 艘船：第 `i` 艘在 **`t_i` 秒**到达，船上有 `k_i` 名乘客，国籍分别是 `x_{i,1} … x_{i,k_i}`。
对**每一艘船**，统计 **24 小时（86400 秒）内**到达的所有乘客里，一共有**几个不同国家**。

**形式化条件（题面原文）**：统计满足 `t_i − 86400 < t_p ≤ t_i` 的船 `P` 上的所有 `x_{p,j}`，输出不同数的个数。

| 约束 | 值 |
|---|---|
| `n` | ≤ 10⁵ |
| `Σk_i` | ≤ 3×10⁵ |
| `x_{i,j}` | 1 ~ 10⁵ |
| `t_i` | **严格递增**，≤ 10⁹ |

**两组样例**：

```
样例1 输入          样例1 输出
3                   3
1 4 4 1 2 2         4
2 2 2 3             4
10 1 3

样例2 输入          样例2 输出
4                   3
1 4 1 2 2 3         3
3 2 2 3             3
86401 2 3 4         4
86402 1 5
```

## 二、为什么"知道用队列"却建不出模（你的卡点在哪）

你脑子里大概已经有"**新船进队、老船出队**"的画面了，但**队里到底存什么**没定下来：存船？存时刻？存国籍？

一旦开始想"船过期了怎么办"就会卡住——**一艘船上有好几个人，"船过期"到底是几个人过期？**

> ⭐ 关键跳跃：**把船拆开，让人当队列元素**。
> 同一艘船上的人**时刻完全相同**，所以他们会**同时过期**，拆开完全不会出错。拆开之后，队列里每个元素长得一模一样 `(t, x)`，事情立刻变简单。

## 三、建模三步（这题的全部）

### 第 1 步：先问"窗口是什么"

窗口是**时间**窗口（最近 86400 秒），**不是**"最近多少艘船"。
⇒ 所以每个元素身上**必须带 `t`**：要不要淘汰它，只由**时刻**决定，跟它是第几艘船无关。

### 第 2 步：队列里装什么 = **乘客**

| 元素 | 内容 | 为什么 |
|---|---|---|
| 每个**乘客** | `(t, x)`：到达时刻 + 国籍 | 统计对象是"**国籍**"、过期判据是"**时刻**"——两个信息都长在这一个人身上 |

队列的性质正好对上：

- 新船到了 → 船上**每个人**从**队尾**进队（`t` 天然非降，因为题面保证 `t` 递增）
- 该淘汰的人 → 一定在**队头**（越老越先过期）→ 从**队头**扔掉

> ⭐ 一句话：**这个队列维护的就是"当前窗口内的人"这个集合**。因为时间有序，所以"谁该走"只需要看队头——这就是"为什么这题要用队列"的答案。

### 第 3 步：计数表 + **增量**维护答案（这题的另一半）

光有队列还不够：你要的是"**有几种国籍**"，不是"有几个人"。两种做法：

| 做法 | 复杂度 | 结果 |
|---|---|---|
| 每艘船到了就把队里所有人重扫一遍、用 `set` 数一遍 | O(n × Σk) = **3×10¹⁰** | ❌ TLE（💭 按实测线性外推 ≈ **12–18 分钟**，限制 1 s） |
| **`cnt[国籍]` 计数表 + `ans` 增量维护** | O(n + Σk) | ✅ 实测 **3 ms** |

增量规则就是**两行**（全题最该背的两行）：

```cpp
// 进队：这个国籍从"没有"变成"有"了 → 国家数 +1
if (cnt[x]++ == 0) ++ans;
// 出队：这个国籍从"有"变回"没有"了 → 国家数 -1
if (--cnt[x] == 0) --ans;
```

> ⭐ **判据：只在 0 ↔ 1 之间变化时才动 `ans`**。同一个国家来第 2、第 3 个人，`ans` 不变——这就是"计数表"而不是"布尔表"的原因：**你既要知道"有没有"，也要知道"走了之后还剩不剩"**。

## 四、骨架（只给关键几行，完整代码你自己敲）

```cpp
const ll WIN = 86400;
ll  qt[300005], qc[300005];    // ⚠️ 队列按 Σk 开（3e5），不是按 n 开（1e5）
int cnt[100005] = {0};         // 国籍 ≤ 1e5
int head = 0, tail = 0;
ll  ans = 0;

for (int i = 1; i <= n; ++i) {
    ll t; int k; cin >> t >> k;
    for (int j = 1; j <= k; ++j) {
        ll x; cin >> x;
        qt[tail] = t; qc[tail] = x; ++tail;        // ① 新船上的人，从队尾进来
        if (cnt[x]++ == 0) ++ans;                  // ② 计数 0→1，国家数 +1
    }
    while (head < tail && qt[head] <= t - WIN) {   // ③ 队头过期的人走人（⚠️ 取等也要走）
        if (--cnt[qc[head]] == 0) --ans;           //    计数 1→0，国家数 -1
        ++head;
    }
    cout << ans << "\n";
}
```

💭 **顺序说明**：新乘客的时刻就是 `t_i`，而窗口要求 `t_p > t_i − 86400`，这对新乘客**永远成立**（因为 86400 > 0）。
⇒ 所以"**先 push 再 pop**"和"**先 pop 再 push**"都对，两种写法不会有区别。

## 五、边界：为什么是 `<= t - 86400`（题面写了，但要读懂）

题面的形式化条件是 `t_i − 86400 < t_p ≤ t_i`：

> 时刻**恰好等于** `t_i − 86400` 的乘客**不在窗口内** ⇒ 必须弹掉
> ⇒ 弹出判据写 **`qt[head] <= t - 86400`**（**取等要弹**）

**用样例 2 手算一遍**（这组样例存在的意义就是考这个边界）：

| 第几艘 | `t` | 窗口 `(t−86400, t]` | 窗口内的船 → 国籍 | 输出 |
|---|---|---|---|---|
| 1 | 1 | (−86399, 1] | 船1：[1,2,2,3] | **3** |
| 2 | 3 | (−86397, 3] | 船1,2：[1,2,2,3,2,3] | **3** |
| 3 | 86401 | (1, 86401] | 船1 的 `t=1` **不满足 `>1` ⇒ 被踢出**；剩船2,3 → [2,3,3,4] | **3** |
| 4 | 86402 | (2, 86402] | 船2 的 `t=3 > 2` **留下**；船2,3,4 → [2,3,2,3,3,4,5] | **4** |

⚠️ 若把判据写成 `< t - WIN`（漏了取等），第 3 艘船会多留下船 1 ⇒ 输出 **4**（错）。
**一个"差 1 秒"的边界，就是这题唯一的边界考点。**

## 六、你最容易踩的三个坑（对照你的 8 类坑）

| # | 坑 | 属于哪一类 | 症状 |
|---|---|---|---|
| 1 | **队列数组按 `n` 开**（1e5），而不是按 `Σk` 开（3e5） | **① 数组容量开小** | **实测：跑到第 33335 艘船左右就 `0xC0000005` 崩，100000 行只输出了 33620 行** |
| 2 | 弹出判据写成 `< t - WIN`（漏取等） | ⑦ 判定写反 / ③ 边界少判一边 | **样例 1 照样过**（样例 1 根本没发生过期！），到样例 2 第 3 行才暴露 |
| 3 | 忘了"只在 0↔1 变化时改 `ans`"（例如进队就无条件 `++ans`） | ⑦ 判定写反 | 同一国家来多人时，国家数虚高 |

⚠️ **第 1 条是本题最阴的地方**：队列元素的个数上界是 **`Σk = 3×10⁵`**，不是 `n`。
你习惯的"按维度开数组"在这里会直接翻车——而且**这次它不是静默错，是硬崩**（见第七节实测）。

💭 **不想算这个上界怎么办**：可以直接用 `queue<pair<ll,ll>>`（或用 `deque`），标准库会自己扩容，就不用纠结开多大；代价是比数组模拟慢一些、内存碎片多一些。`Σk ≤ 3e5` 这么小，两种都随便过。

## 八、自查（先自己想，再展开对照）

<details>
<summary>① 队列里能不能装"船"（每艘船一个元素，元素里挂着一串国籍）？</summary>

**能，而且同样正确**。同一艘船的人时刻相同、会**同时过期**，所以以船为单位淘汰不会出错；只是每个元素里要挂一串国籍，出队时要**逐个** `--cnt` 并检查 0。
以乘客为单位更整齐（元素等长、代码更短），所以通行写法都用乘客。
</details>

<details>
<summary>② 为什么新船上的人不可能"一进队就过期"？</summary>

新乘客的时刻就是 `t_i`，而窗口要求 `t_p > t_i − 86400`。因为 `86400 > 0`，这个不等式对 `t_p = t_i` 永远成立。
⇒ 所以 push 和 pop 的先后顺序**怎么排都对**。
</details>

<details>
<summary>③ 国籍范围是 1e5，`cnt` 开 100005 够吗？如果国籍能到 1e9 呢？</summary>

**够**（合法下标最大 `100000`）。
若国籍到 1e9 ⇒ **开不了数组**，要改用 `unordered_map<int,int>` 或先把国籍**离散化**（排序去重后映射成 1..m）；代价是常数变大。本题 `x ≤ 1e5` 就是为了让你直接用数组。
</details>

<details>
<summary>④ 如果题目改成"最近 30 分钟内"，代码要改哪几处？</summary>

**只改一个常量**：`WIN = 30 × 60 = 1800`。其余一行都不用动 —— 这就是"**参数化窗口**"的好处，也是为什么建模时要先问"窗口是什么"。
</details>

<details>
<summary>⑤ 如果题面**不保证 `t` 递增**，这套写法还成立吗？</summary>

**不成立**。整套写法的前提是"**最老的人一定在队头**"；`t` 一旦乱序，队头就不一定是最老的，"该走的人"可能藏在队中间。
那时要么先按时间排序（但题目要按输入顺序输出答案，排序后要记住原下标），要么换数据结构（如按时间维护的有序容器）。**本题题面明确保证 `t_{i-1} < t_i`，所以这一步不用做。**
</details>

**③ 拿你的源码加 3 行 `fprintf` 打印地址（算法一字未改）**：

### 11.6 提炼两条铁律（写进自查清单）

**铁律 1：数组长度写"最大值 + 1"，不是"最大值的数量级"。**
题面写 `1 ≤ x ≤ K` ⇒ **下标最大值就是 K** ⇒ 数组长度必须是 **`K + 1`**（习惯写 `maxn = K + 5`）。
💭 为什么特别容易错：`≤` 是"包含"，而数组下标从 0 开始 —— **两个方向都要 +1**。看到 `≤ K`，长度就写 `K + 1`。

**铁律 2：全局数组越界 = 踩隔壁的全局变量。**
本题实测踩到了 `n`（循环计数），于是症状变成"**不崩、不报错、只错 1**"，而且**只有在"国籍恰好是边界值 100000"的乘客出现时才发作**（全靠那 3 个乘客）。
⇒ 你自查的话术要从"最大能有多少个元素"升级成**两句**：
① **最大能有多少个元素**（队列按 `Σk` 开，不是按 `n`）
② **下标的最大值是多少**（计数数组按 `值的最大值 + 1` 开）

⭐ 同一份数据上，"少开 1 格"和"少开一个量级"的后果**完全不对称**：

| 写法 | 后果 |
|---|---|
| 队列按 `n`（1e5）开，实际要 `Σk`（3e5） | **第 ~33335 艘船直接 `0xC0000005` 崩**（见 §六） |
| 计数数组按 `1e5` 开，值最大就是 `1e5` | **静默少 1，5592 行错，编译器零警告** |

⇒ **"崩"反而是好事，"静默"才是这题真正的杀手。**
