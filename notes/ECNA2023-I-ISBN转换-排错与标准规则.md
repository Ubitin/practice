## 一、题面规则（官方口径）

**ISBN-10（10 位数字）**：`d1..d10`，校验位是 `d10`。

```
S = 10*d1 + 9*d2 + 8*d3 + ... + 2*d9 + 1*d10        权重从 10 递减到 1
合法 ⇔ S ≡ 0 (mod 11)
```

**`X` 的特殊含义**：模数是 11，所以校验位取值可以是 `10`——记为单个字符 `X`。
例：`039428013X` 合法（`X` 代表 10）。**ISBN-13 没有这个约定**。

**连字符规则（本题的关键）**：ISBN-10 严格由**四个部分**组成（校验码是最后一部分），相邻部分可用 `-` 分隔，因此：

1. 最多 3 个 `-`；
2. 不得以 `-` 开头或结尾；
3. 不允许出现连续 `-`；
4. **若有 3 个 `-`（四部分全部分开），必须有一个 `-` 紧挨在校验码之前**
   → 即最后一段必须只有 1 位字符（校验码）；
   *少于 3 个 `-` 时，校验码可以并入前一段*（例如 `0-39-428013X`、`3540425802` 都合法）。

**ISBN-13 换算**：① 前缀加三位数 `978`；② 去掉原校验码；③ 按 ISBN-13 规则算新校验码。

```
S = 1*d1 + 3*d2 + 1*d3 + 3*d4 + ... + 3*d12 + 1*d13     奇数位×1，偶数位×3
合法 ⇔ S ≡ 0 (mod 10)      → 新校验码 = (10 - s12 % 10) % 10（前 12 位）
```

**输出格式**：保留原有连字符位置，并在新增的 `978` 后追加一个连字符：
`"978-" +（原串去掉末位校验码）+ 新校验码`。

## 三、原代码的 6 处问题

| # | 代码 | 问题 |
|---|---|---|
| ① | `else if(isbn10[i]=='X') sum[t] += 10;` | **越界写**：`sum` 只有 t 个元素（下标 0..t-1），写 `sum[t]` 是 UB；且 `X` 的 10 分**丢了**。应为 `sum[k]` |
| ② | `else if(count(...)==3){ if(位置错) cout<<"invalid\n"; }` | 位置**对**时整个分支**什么都不做**——既不转换也不输出。四段式 ISBN（如 `3-540-42580-2`）正是 3 个连字符 → 直接漏答 |
| ③ | `temp = '0' + a;` 其中 `a = 10 - (sum%10)` | 当 `sum%10 == 0` 时 `a = 10` → `'0'+10 = ':'`，输出冒号。必须写 `(10 - s%10) % 10` |
| ④ | `if(sum[k] % 11) invalid` | 用的是**不加权数字和**，题面要求**加权和**（权重 10..1） |
| ⑤ | ISBN-13 校验位也用不加权求和 | 应用 1、3 交替权重 |
| ⑥ | 结构校验不全 | 位数、`X` 只能在末位、连字符不在首尾/连续都要查（原代码只查了"3 连字符时末位前是 '-'"，这**一条是对的**） |

### ④ 的证据

| 字符串 | 数字和 %11 | 加权 %11 | 真相 |
|---|---|---|---|
| `0-306-40615-2` | **invalid** ❌ | valid | 真实有效的 ISBN-10 |
| `9000000002` | **valid** ❌ | invalid | 伪造（数字和 11 恰好被 11 整除） |

## 四、最终修正版（`test_\01_isbn_fixed2.cpp`，样例 4/4 通过）

```cpp
static bool okStruct(const string& s){
    int hy = (int)count(s.begin(), s.end(), '-');
    if(hy > 3) return false;                                  // ① 最多三个
    if(s.front() == '-' || s.back() == '-') return false;     // ② 不得在首尾
    for(size_t i = 1; i < s.size(); ++i)
        if(s[i] == '-' && s[i-1] == '-') return false;        // ③ 不得连续
    if(hy == 3 && s[s.size() - 2] != '-') return false;       // ④ 三段分隔 → 校验码独占最后一段
    return true;
}
// 加权校验：S += (11 - 已见数字数) * v；X 只允许末位且记 10；数字必须恰好 10 个
// ISBN-13 校验码：first12 = "978" + 前 9 位，权重 1,3,... ，check = (10 - S%10) % 10
// 输出："978-" + 原串去掉末位 + 新校验码
```

## 五、这次的教训（值得记住）

1. **题面拿不到时不要"猜着实现还说验证通过"**：我第一版按国际标准 ISBN 规则写，结果漏了这道题特有的结构规则④（"三段分隔后校验码必须独占最后一段"），样例第 1 行就错。
2. **症状特征**：`invalid` 判少了——凡是"该拒没拒"的错误，都优先怀疑**合法性判定缺条件**；反过来"该收没收"则是条件过严。
3. **结构规则要逐条对着题面抄**：最多几个、能不能在首尾、能不能连续、某处是否必须有一个——这类"格式题"最容易漏条。

## 六、自查清单

- [ ] 校验位一律 `(10 - s % 10) % 10`，别漏 `% 10`
- [ ] ISBN-10 用**加权**和（权重 10..1）；ISBN-13 用 **1/3 交替**权重
- [ ] `X` 只允许出现在 ISBN-10 **末位**，值 10
- [ ] 数字个数必须**恰好 10**
- [ ] 连字符四条：≤3、不在首尾、不连续、**3 个时校验码独占最后一段**
- [ ] 输出保留原连字符并在 `978` 后补 `-`：`"978-" + 原串去掉末位 + 新校验码`

**唯一实质差别就是"数字个数必须恰好 10"这一条检查。**

### 为什么缺这一条会 WA（实测）

题面允许输入行的长度是 **10~13 个字符**，字符为数字/`-`/`X`，因此测试里完全可能出现
11、12、13 个数字（例如真正的 ISBN-13），或"9 个数字 + 1 个连字符"这类**长度合法但数字个数不是 10** 的候选。
它们都应输出 `invalid`。而只靠"加权和 ≡ 0 (mod 11)"判断时：
`cnt` 超过 10 后权重 `(11 - cnt)` 会变成 **0、−1、−2**（负数）继续累加，某些串恰好被 11 整除 → 被判合法。

实测（两版同跑）：

| 输入 | 期望 | 用户重写版 | 修正版 |
|---|---|---|---|
| `0000000000`（10 位） | 合法 | `978-0000000002` ✅ | `978-0000000002` ✅ |
| `00000000000`（11 位数） | `invalid` | `978-00000000002` ❌ | `invalid` ✅ |
| `03064061527`（11 位，前 10 位是合法 ISBN-10） | `invalid` | `978-03064061527` ❌ | `invalid` ✅ |
| `00000000-0`（9 位 + 连字符） | `invalid` | `978-00000000-2` ❌ | `invalid` ✅ |
| `0000000000000`（13 位） | `invalid` | `978-0000000000002` ❌ | `invalid` ✅ |

### 一行补丁（用户自行决定是否加）

```cpp
// 在 check10() 里、`if(s%11) return false;` 之前加：
if(cnt != 10) return false;        // 数字（含 X）必须恰好 10 个 —— 长度 10~13 不等于数字 10 个！
```

其他小建议（非致命）：
- `main` 里 `check10(isbn10, d)` 调了两次（第 80、83 行），第二次可删；
- `exact()` 未校验字符集（题面已保证只有数字/`-`/`X`），如需更稳可在 `check10` 里对非法字符直接返回 false。

> 通用教训：**"字符串长度" ≠ "数字个数"**。凡是带分隔符的格式判定，务必分别检查"总长度/分隔符数量/有效载荷个数"三件事。
