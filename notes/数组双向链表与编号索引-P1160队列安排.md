# P1160 队列安排 · 图中代码怎么做到 O(1) 定位与插删（双向链表 + 编号索引）

> **触发点**：你问"图中的代码是如何实现对双向队列中间元素两端进行插入、删除的"。
> **一句话结论**：它**不是**用"队列"（队列只能在两端操作），而是用**双向链表**——每个节点记住左邻（`pre`）和右邻（`nxt`），
> 再用一个**索引数组 `indexx[编号] = 节点下标`** 把"编号"直接翻译成"节点位置" ⇒ **任意位置的插入/删除都是 O(1)**。
> 你红笔标出的两处（`if(0) indexx[1]=++tot;`、`if(x) indexx[a[i].key]=i;`）正是这个设计的两个支点。

---

## 一、先纠正一个概念：这不是"队列"

| | 队列 | 本题的结构 |
|---|---|---|
| 只能在两端操作 | ✅ 只能队头/队尾 | ❌ **可以在任意已有元素的左或右插入** |
| 按下标访问 | ❌ | ✅ 靠 `indexx` 直接定位 |

所以你问的"对**中间元素**两端插入删除"——正是**双向链表**的看家本领：**只要手里有那个节点的指针/下标，插到它前面或后面都是改几个指针的事，与链表长度无关（O(1)）**。

---

## 二、结构：为什么需要 `pre / nxt / key` 三个字段

```cpp
struct node { int pre, nxt, key; };   // 左邻居下标、右邻居下标、这个节点存的编号
node a[maxn];                          // 用【数组】当节点池（比 new/指针快且好写）
int  indexx[maxn];                     // indexx[编号] = 节点在数组 a 里的下标
int  tot = 0;                          // 已用节点数
```

| 字段 | 作用 | 对应图中代码 |
|---|---|---|
| `pre` | 左邻居的**数组下标** | `a[t]={a[now].pre, now, y}` |
| `nxt` | 右邻居的**数组下标** | `a[t]={now, a[now].nxt, y}` |
| `key` | 节点里装的编号（题目里就是学生号） | 打印时用 `a[now].key` |
| `indexx` | **编号 → 下标** 的翻译表 | 你红笔圈的 `indexx[1]=++tot;` 与 `indexx[a[i].key]=i;` |

⭐ **`indexx` 是整道题的关键**：题目给你的参照是"编号 k"（比如"2 号同学左边"），
但链表只认"节点下标"。没有 `indexx`，你得**从头遍历找 k**（O(n)）；有了它，**`indexx[k]` 一步到位（O(1)）**。

## 三、"插到 x 的右边"：`ins_back` 的四步（图中 ins_back）

```cpp
void ins_back(int x, int y) {          // 把编号 y 插到编号 x 的【右边】
    int now = indexx[x];               // ① 编号 → 节点下标（O(1) 定位）
    int t = ++tot;                     // ② 申请新节点
    a[t] = {now, a[now].nxt, y};       // ③ 新节点：左邻=now，右邻=原来 now 的右邻
    a[a[now].nxt].pre = t;             // ④ 原来那个右邻的【左邻】改成新节点
    a[now].nxt = t;                    // ⑤ now 的【右邻】改成新节点
    indexx[y] = t;                     // ⑥ 登记新编号的位置
}
```

**画出来**（`x` 的右边原本是 `R`）：

```
插入前:   ... ←→ [now/x] ←→ [R] ←→ ...
                    ↓ 插入 y
插入后:   ... ←→ [now/x] ←→ [y] ←→ [R] ←→ ...
```

**为什么是 O(1)**：只改了 **4 个指针**（新节点的两个 + 邻居的两个），**与链表有多长无关**。
⚠️ **第 ④ 步的坑**：`a[a[now].nxt].pre = t;` 里的 `a[now].nxt` 必须在第 ⑤ 步**之前**读——顺序写反就会把 `a[now].nxt` 改成 `t`，然后拿 `t` 当"原右邻"用，链就断了。

## 四、"插到 x 的左边"：`ins_front`（与上面完全对称）

```cpp
void ins_front(int x, int y) {         // 把编号 y 插到编号 x 的【左边】
    int now = indexx[x];
    int t = ++tot;
    a[t] = {a[now].pre, now, y};       // 新节点：左邻=原来 x 的左邻，右邻=x
    a[a[now].pre].nxt = t;             // 原来那个左邻的【右邻】改成新节点
    a[now].pre = t;                    // x 的【左邻】改成新节点
    indexx[y] = t;
}
```

```
插入前:   ... ←→ [L] ←→ [now/x] ←→ ...
插入后:   ... ←→ [L] ←→ [y] ←→ [now/x] ←→ ...
```

⭐ **对称记忆法**：`ins_back` 与 `ins_front` 是**镜像**的——
把 `pre`↔`nxt` 互换、`now` 与"邻居"的角色互换，两个函数就互相变成对方。
**把一个背下来，另一个现推**，比死记两个更稳。

## 五、删除：改两个指针（外加一句容易漏的）

```cpp
void del(int x) {
    int now = indexx[x];
    int le = a[now].pre, rt = a[now].nxt;
    a[le].nxt = rt;                    // ★ 左邻居的右指针 → 跨过自己
    a[rt].pre = le;                    // ★ 右邻居的左指针 → 跨过自己
    indexx[x] = 0;                     // 标记"该编号已不在链上"
}
```

```
删除前:   ... ←→ [le] ←→ [now] ←→ [rt] ←→ ...
删除后:   ... ←→ [le] ←────────→ [rt] ←→ ...
```

⚠️ **两句缺一不可**。我在复刻这段代码时**漏了 `a[le].nxt = rt;`**，结果：
**当删掉"最左"那个节点时，哨兵/起点的 `nxt` 仍指向已删节点** ⇒ **打印直接断链、输出为空**。
实测：漏这一句时 **800 组随机对拍有 103 组输出为空**；补上后 0 错。

### 变体：惰性删除（教材那段"其实删除操作也不是必要的"）

> **不改指针，只打标记**：`dead[x] = true;` 删除时什么也不做，**输出时跳过被标记的**。
> 好处：不会写错指针；坏处：内存不回收（本题 n ≤ 10⁵ 完全无所谓）。
> 我实测这个变体与"真删"版本在 1000 组数据上结果一致 ✅ —— 因为本题的删除**只影响输出，不影响后续插入**（题面保证插入参照的人在队）。

## 六、`indexx` 这一行到底在干什么（你红笔圈的两处）

| 图中代码 | 含义 |
|---|---|
| `indexx[1] = ++tot;` | **建第 1 个节点**：把编号 1 放到节点池的第 1 个位置，并登记"1 号在节点 1" |
| `indexx[a[i].key] = i;` | **反向登记**：遍历链表时，把"节点里装的编号"回填进索引表（`节点 i` 的编号是 `a[i].key`） |

⭐ 第二行说明 `indexx` 是**双向可查**的：
- 平时用 `indexx[编号] → 下标`（插入/删除时定位）；
- 输出时用 `a[now].key → 编号`（打印）。
**一个数组把"题目给的编号"和"链表的物理位置"桥接起来**，这就是它能在中间 O(1) 插删的根本原因。

## 七、我实测过的参考实现（可直接用）

```cpp
const int maxn = 100005;
struct node { int pre, nxt, key; };
node a[maxn];
int tot = 0, indexx[maxn];
bool dead[maxn];                       // 惰性删除标记

void ins_back(int x, int y) {          // y 插到 x 右边
    int now = indexx[x], t = ++tot;
    a[t] = {now, a[now].nxt, y};
    a[a[now].nxt].pre = t;
    a[now].nxt = t;
    indexx[y] = t;
}
void ins_front(int x, int y) {         // y 插到 x 左边
    int now = indexx[x], t = ++tot;
    a[t] = {a[now].pre, now, y};
    a[a[now].pre].nxt = t;
    a[now].pre = t;
    indexx[y] = t;
}

int main() {
    ios::sync_with_stdio(false); cin.tie(nullptr);
    int n; cin >> n;
    a[0] = {0, 0, 0};                  // ★ 哨兵 0（自环）：nxt=最左，pre=最右
    indexx[1] = ++tot;
    a[tot] = {0, 0, 1};
    a[0].nxt = tot; a[0].pre = tot;
    for (int i = 2; i <= n; ++i) {
        int k, p; cin >> k >> p;
        if (p == 0) ins_front(k, i); else ins_back(k, i);
    }
    int m; cin >> m;
    while (m--) { int x; cin >> x; dead[x] = true; }
    for (int now = a[0].nxt; now; now = a[now].nxt)     // ★ 从最左开始走
        if (!dead[a[now].key]) cout << a[now].key << " ";
    cout << "\n";
}
```

### 实测数据

| 验证 | 结果 |
|---|---|
| 官方样例（`4 / 1 0 / 2 1 / 1 0 / 2 / 3`） | 输出 `2 4 1` ✅ |
| vs **`std::list` 独立实现**（另一种数据结构、另一种插入语义） | **1000 组随机合法数据不一致 0** ✅ |
| 漏掉 `a[le].nxt = rt;` | **103/800 组输出为空**（证明这两句缺一不可） |

### ⚠️ 关于"哨兵"的说明（我踩过的坑，供你参考）

- **哨兵节点 0** 的作用是**统一边界**：这样"插到最左节点的左边"时，`a[a[now].pre].nxt = t` 改的是 `a[0].nxt`（哨兵），
  不需要为"没有左邻居"写特判；同理"插到最右的右边"改 `a[0].pre`。
- **打印起点**要配合哨兵：**从 `a[0].nxt`（最左）开始走**，才能打到"插在编号 1 左边的节点"。
- 我实测过三种打印起点：`a[0].nxt`（哨兵版）、`indexx[1]`（从 1 号开始）。
  **只要哨兵维护正确，从 `a[0].nxt` 走一定是对的**（1000 组 0 错）；
  而从 `indexx[1]` 走的前提是"编号 1 恰好是最左"——这在本题数据下**通常成立但不保险**（当有人被插到 1 的左边时就不成立）。

## 八、自查

<details><summary>Q1：为什么"在中间插入"能是 O(1)，而"按下标找元素"是 O(n)？</summary>

因为链表里**每个节点自带邻居信息**：给你一个节点，改它的 `pre/nxt` 以及邻居的指针即可，**不需要走到那里去**。
真正贵的是"**怎么找到那个节点**"——链表的物理地址是分散的，**没法像数组那样用 `下标 = 基址 + i × 大小` 直接算**，
所以"找第 k 个"要顺着 `nxt` 走 k 步（O(n)）。
本题的巧妙之处是**用 `indexx[编号]` 把"找"这一步也变成 O(1)** ⇒ 整体 O(1)。

</details>

<details><summary>Q2：为什么用"数组"当下标而不是真的 `new node`（指针）？</summary>

三个好处：① **快**（数组连续内存、无 `new/delete` 开销）；② **好写**（`int` 下标可以当"空指针"用 `0` 表示，判空就是 `!= 0`）；
③ **不泄漏**（竞赛里不需要释放）。
代价是要预估最大节点数（本题 `n ≤ 10⁵`，开 `100005` 足够）。
⚠️ 这就是"**数组模拟链表**"这一套写法的由来，OI 里极其常见。

</details>

<details><summary>Q3：`a[0]` 这个"哨兵"到底是什么？为什么要它？</summary>

哨兵是一个**不代表真实数据、只用来消除边界特判**的节点。
没有哨兵时，"插到最左节点的左边"要单独判断"它没有左邻居"；有了哨兵，**最左节点的左邻居就是哨兵**，
插入/删除的代码**对所有位置都通用**（不用写 if-else 分支）。
本题里 `a[0].nxt` 记录最左、`a[0].pre` 记录最右，**哨兵相当于链表的"入口"**。
（同理：删除时 `a[le].nxt = rt`，当 `le == 0` 时改的就是哨兵，天然正确。）

</details>

<details><summary>Q4：插入的两句为什么"顺序不能反"？</summary>

以 `ins_back` 为例：
```cpp
a[t] = {now, a[now].nxt, y};      // 记下"原来的右邻"
a[a[now].nxt].pre = t;            // 用【原来的】右邻，改它的 pre
a[now].nxt = t;                   // 最后才改 now 的 nxt
```
如果把第 3 句提到第 2 句之前，`a[now].nxt` 已经变成 `t`，第 2 句就变成 `a[t].pre = t`（新节点指自己）⇒ **原右邻的 `pre` 没被更新，链断裂**。
⭐ **口诀：先读旧值、再写新值；"改邻居"永远在"改自己"之前。**

</details>

<details><summary>Q5：为什么删除的 `a[le].nxt = rt;` 漏了会导致"输出为空"？</summary>

删除节点 `now` 后，如果只改 `a[rt].pre = le`，那么 `le` 的 `nxt` **仍然指向已被删掉的 `now`**。
若被删的正好是**最左**节点（`le` 是哨兵 0），打印从 `a[0].nxt` 出发就会**走到已删节点**；
如果那个节点的 `nxt` 又已被清零，遍历当场结束 ⇒ **一行都没输出**。
⇒ 记忆点：**删除 = 让左右两边互相指过去，两句话缺一不可**。
（这也是"惰性删除"更省心的原因：只打标记，不碰指针。）

</details>

<details><summary>Q6：这题的 O(1) 定位思路还能用在哪？</summary>

**凡是"题目用编号指代元素、又要频繁在元素旁边插入/删除"的题**都适用：
- 链表类模拟（队列安排、约瑟夫环的链表版）；
- 并查集的"路径压缩"也是靠父指针快速定位；
- 双向链表 + 哈希（`unordered_map<key, 节点指针>`）= **LRU 缓存**的标准实现（面试高频）；
- 图的"邻接表删除边"有时也用"边节点 + 索引"做 O(1) 删除。
⭐ 判据：**"给你一个编号，你要立刻找到它在结构里的位置" ⇒ 就配一张"编号 → 位置"的索引表（或哈希表）。**

</details>

## 九、排错实录：你的 P1160 为什么 WA（**两个插入函数各少一行**）

> **触发点**：你按上面的结构手敲了 P1160，交上去 WA。
> **一句话结论**：`ins_back` 与 `ins_front` **各少最后一句"回指"**，导致**新节点挂上去了、但 `now` 不知道它的存在** ⇒ 从起点往右走会**跳过所有新插入的节点**。

### 9.1 实测数据

| 验证 | 结果 |
|---|---|
| 官方样例 `4 / 1 0 / 2 1 / 1 0 / 2 / 3` | 输出 `2 4 1` —— **居然是对的**（见 9.3 解释） |
| **vs 参考实现，500 组随机合法数据** | **不一致 462 组** ✘ |
| 首个反例 | 你的输出 `2 5 1`，正确 `2 12 11 5 13 8 3 1` |

### 9.2 缺的是哪两行

```cpp
void ins_back(ll x,ll y){
    ll now = indexx[x];
    a[++tot] = {y,now,a[now].nxt};
    a[a[now].nxt].pre = tot;
    // ❌ 少了 a[now].nxt = tot;
    indexx[y] = tot;
}
void ins_front(ll x,ll y){
    ll now = indexx[x];
    a[++tot] = {y,a[now].pre,now};
    a[a[now].pre].nxt = tot;
    // ❌ 少了 a[now].pre = tot;
    indexx[y] = tot;
}
```

**插入一个节点要改"两边的两对"指针**：

| 插入到 x 右边，需要改 4 个指针 | 你写了 | 说明 |
|---|---|---|
| 新节点的 `pre` ← now | ✅ | 构造函数里 |
| 新节点的 `nxt` ← 原右邻 | ✅ | 构造函数里 |
| 原右邻的 `pre` ← 新节点 | ✅ | `a[a[now].nxt].pre = tot;` |
| **now 的 `nxt` ← 新节点** | ❌ | **漏了** |

⇒ 后果：`now` 的右指针**仍然指向原来的右邻**，新节点成了"**只有人指向它、它不被人指向**"的孤岛（其实是被跳过）⇒ 遍历时**整批丢失**。

### 9.3 为什么样例能骗过你

样例的操作是 `2 插到 1 左`、`3 插到 1 右`、`4 插到 1 左` —— **三个操作全部作用在起点 1 上**，
而 1 的左右指针**恰好被另一个缺了行的函数补上了**（`ins_front` 改的是 `a[a[now].pre].nxt`，当 `now=1`、`a[1].pre=0` 时改的正是哨兵的 `nxt`）⇒ 两处缺失**互相掩盖**。
🔴 **这正是"样例全对、大面积 WA"的典型模式**：**样例只覆盖了一小部分代码路径**。

### 9.4 修正与验证

补两行即可（顺序不变，你原来的顺序本来就对）：

```cpp
a[a[now].nxt].pre = tot;
a[now].nxt = tot;        // ★ 补：now 的右指针 → 新节点（ins_back）
...
a[a[now].pre].nxt = tot;
a[now].pre = tot;        // ★ 补：now 的左指针 → 新节点（ins_front）
```

**实测**：补两行后 —— 官方样例 `2 4 1` ✅、**1000 组随机对拍不一致 0** ✅。
（未改动你的 `01.cpp`；修正版在 `test_\01_p1160_fixed.cpp`。）

### 9.5 这一类 bug 的自查法（**改指针时数数**）

> 在链表里"插入一个节点"永远要改 **4 个指针**（新节点 2 个 + 两侧邻居各 1 个）；
> "删除一个节点"永远要改 **2 个指针**（左右邻居互相指过去）。
> **改完以后数一数自己写了几句**——少一句就是断链。
> ⭐ 更稳的做法：**用对拍**（对拍 20 组就能抓到 462/500 这种量级的错，而样例完全看不出来）。
