# BST（二叉搜索树）详解 —— 从定义到「为什么机试几乎不用手写」

> **触发点**：2026-10-03，你要求"详解 BST"。
> **一句话结论**：BST = **每个节点都满足「整个左子树 < 它 < 整个右子树」**的二叉树；最大卖点是 **中序遍历 = 从小到大有序**。
> **但它有个致命弱点**：**顺序插入会退化成一条链**（实测 n=1e5 时树高 = **100000**，而不是理想中的 17）⇒ 查找从 O(log n) 变成 O(n)，**差 2400 倍**，而且**递归写法还会爆栈**（实测深度 2e5 时 `0xC00000FD`）。
> ⇒ **机试结论：要"有序集合"直接用 `set/multiset`（红黑树）；只有需要「第 k 小 / 排名」时才手写，而且应该直接写 Treap/FHQ，别写朴素 BST。**

---

## 一、定义：BST 到底是什么

**二叉搜索树（Binary Search Tree，简称 BST）**：一棵二叉树，对**每个**节点都满足

```
左子树里所有值  <  该节点的值  <  右子树里所有值
```

🍜 **生活化类比**：图书馆按书名的字典序排书架。
你想找《算法导论》：站在中间那本书前看一眼书名——比它靠前就去左边架子，比它靠后就去右边架子。**一眼排除一半**，这就是 BST 的全部威力来源。

### ⚠️ 注意是"整个左子树"，不是"左儿子"

| 写法 | 合法吗 | 说明 |
|---|---|---|
| `左儿子 < 父 < 右儿子` | ❌ **不够** | 这是"局部有序"，**中序遍历不一定有序** |
| `左子树所有值 < 父 < 右子树所有值` | ✅ 正确定义 | 这才是 BST |

反例：`10` 的左儿子 `5`，`5` 的右儿子 `12` —— 局部看 `5 < 10` ✓，但 `12` 在 10 的左子树里却比 10 大 ⇒ 中序输出 `5, 12, 10` **不是有序的** ⇒ 查找会走错路。

## 二、从定义直接得到的三条性质

| # | 性质 | 用处 |
|---|---|---|
| 1 | **中序遍历 = 从小到大有序** | 一切"排序/第 k 小/区间"类需求的根基（实测见 §七 [A]）|
| 2 | 从根走到某个值的**路径唯一** | 查找的比较次数 = 该节点的**深度** |
| 3 | **最小值 = 一路向左到底；最大值 = 一路向右到底** | `begin()/end()` 的实现 |

**实测**：随机插入 2000 个数（含大量重复）后中序遍历 → **有序 ✅**，且查找全部命中 ✅。

## 三、五个基本操作（只给关键几行，完整代码自己敲）

数据结构（和你上次问的那个平衡树结点是同一套字段）：

```cpp
const int MAXN = 200005;
struct Node { int l, r, sz, cnt, val; } t[MAXN];   // l/r: 左右儿子编号(0=空) sz: 子树元素个数 cnt: 本值重复次数
int tot = 0, root = 0;                             // 用【数组 + 编号】而不是指针：更快、更好调
inline void pull(int u) { t[u].sz = t[t[u].l].sz + t[t[u].r].sz + t[u].cnt; }
inline int newnode(int v) { ++tot; t[tot] = {0, 0, 1, 1, v}; return tot; }   // ★ 新建节点（下面每个操作都要用）
```

### 3.0 先说清 `newnode`（上次漏写，这里补上）

```cpp
inline int newnode(int v) { ++tot; t[tot] = {0, 0, 1, 1, v}; return tot; }
```

它干三件事：**分配一个新下标 → 把字段初始化成"叶子节点" → 返回这个下标**。

| 部分 | 含义 |
|---|---|
| `++tot` | **数组模拟**：节点编号从 1 开始递增（不用 `new`/指针，更快也更好调试）|
| `t[tot] = {0, 0, 1, 1, v}` | 花括号按**声明顺序**逐个填：`l=0, r=0, sz=1, cnt=1, val=v` ⇒ 左右儿子为空、子树大小 1、本值出现 1 次 |
| `return tot;` | 返回新节点下标，调用方用它当儿子指针（所以 `ins` 里写 `u = newnode(v);`）|
| `inline` | 只是"建议内联"的提示，短函数写不写都行 |

**三个隐含前提（实测已验证）**：

| # | 前提 | 为什么重要 |
|---|---|---|
| 1 | **下标 0 是"空指针"哨兵**，且 `t[0]` 全为 0（全局零初始化）| 所以 `pull` 里写 `t[t[u].l].sz` **不需要判空**：儿子为空时 `t[u].l == 0`，而 `t[0].sz == 0` 正好就是"空子树的元素个数"。实测：`t[0]: l=0 r=0 sz=0 cnt=0 val=0` ✅ |
| 2 | 花括号 `{0,0,1,1,v}` 的顺序**必须与 struct 声明顺序一致** | 声明 `int l, r, sz, cnt, val;` ⇒ 依次是 `l=0, r=0, sz=1, cnt=1, val=v`。**顺序写错不会报错，只会静默错**（本例里 `sz` 和 `cnt` 恰好都是 1，所以写反了也看不出来；一旦以后改动其一就会出怪 bug）|
| 3 | 能这么写，是因为 `Node` 是**聚合类型**（**没有**用户提供的构造函数）| 一旦给 `Node` 加上构造函数（像上次那个平衡树结点），`t[tot] = {0,0,1,1,v}` 就**编译不过**了：实测报 `error: no match for 'operator=' (operand types are 'Node' and '<brace-enclosed initializer list>')`。那时要改成 `t[tot] = Node(0, 0, 1, v);` |

**实测（`newnode_probe.cpp`）**：依次插入 `50, 30, 70, 30, 80` 后

```
t[1]: l=2 r=3 sz=5 cnt=1 val=50     ← 根；左儿子 t[2]、右儿子 t[3]
t[2]: l=0 r=0 sz=2 cnt=2 val=30     ← 30 出现两次 ⇒ cnt=2、子树大小 2
t[3]: l=0 r=0 sz=2 cnt=1 val=70     ← 右儿子 t[4]
t[4]: l=0 r=0 sz=1 cnt=1 val=80
根子树大小 = 5 ✅（元素总个数 50,30,70,30,80 正好 5 个）
```


### 3.1 查找（迭代写法，不需要递归）

```cpp
bool find_(int u, int v) {
    while (u) { if (v == t[u].val) return true; u = (v < t[u].val) ? t[u].l : t[u].r; }
    return false;
}
```
👀 **这就是"一眼排除一半"**：`v < 当前值` 往左，否则往右。循环次数 = 深度 ⇒ 复杂度 = 树高。

### 3.2 插入

```cpp
void ins(int& u, int v) {                 // ★ 传引用：才能把新节点"接"到父节点的儿子上
    if (!u) { u = newnode(v); return; }   // 走到空位 → 建节点挂上
    if (v == t[u].val) { ++t[u].cnt; ++t[u].sz; return; }   // 重复值：只加计数
    if (v < t[u].val) ins(t[u].l, v); else ins(t[u].r, v);
    pull(u);                              // ★ 回溯时更新子树大小
}
```
⭐ `int& u` 这个引用参数是**全篇最关键的一行**：它让"当前这个儿子指针"可以被直接改写，避免写一堆 `if (父的左儿子是空的) …`。

### 3.3 删除：**三种情况**（这部分最容易写错）

| 情况 | 处理 |
|---|---|
| ① 叶子（没儿子） | 直接摘掉（把父的儿子指针置 0）|
| ② 只有一个儿子 | **让儿子顶替自己的位置**（"孙子接爷爷的班"）|
| ③ 有两个儿子 | 找**中序后继**（右子树里最左的节点）或**中序前驱**（左子树里最右的），把它的值/计数复制到当前节点，再递归删掉那个后继 |

```cpp
void del(int& u, int v) {
    if (!u) return;
    if (v < t[u].val) { del(t[u].l, v); pull(u); return; }
    if (v > t[u].val) { del(t[u].r, v); pull(u); return; }
    if (t[u].cnt > 1) { --t[u].cnt; --t[u].sz; return; }   // 有重复：只减计数
    if (!t[u].l) { u = t[u].r; return; }                   // ①/② 没有左儿子
    if (!t[u].r) { u = t[u].l; return; }                   // ② 没有右儿子
    int s = t[u].r; while (t[s].l) s = t[s].l;             // ③ 找中序后继
    t[u].val = t[s].val; t[u].cnt = t[s].cnt;              //    后继"提上来"
    t[s].cnt = 1;                                          //    让递归去真删那个后继
    del(t[u].r, t[s].val);
    pull(u);
}
```

**实测（三种情况逐个验证）**：

| 操作 | 结果 |
|---|---|
| 删叶子 `20`（原 `{20,30,40,50,60,70,80}`） | `{30,40,50,60,70,80}` ✅ |
| 删单儿子 `30`（原 `{20,30,50,70}`） | `{20,50,70}` ✅ |
| 删两儿子 `50`（原 `{20,30,40,50,60,70,80}`） | `{20,30,40,60,70,80}`，**中序后继 60 顶上**，根变 60、`size` 仍是 6 ✅ |

> 💭 **为什么用"中序后继"顶上？** 因为要保住 BST 性质：顶上来的人必须"比左子树都大、比右子树都小" ——
> **右子树里最小的那个**（中序后继）正好满足；同理**左子树里最大的那个**（中序前驱）也可以。两种都行。

### 3.4 前驱 / 后继（"小于 v 的最大值 / 大于 v 的最小值"）

```cpp
int pre(int u, int v) { int a = INT_MIN; while (u) { if (t[u].val < v) { a = t[u].val; u = t[u].r; } else u = t[u].l; } return a; }
int suc(int u, int v) { int a = INT_MAX; while (u) { if (t[u].val > v) { a = t[u].val; u = t[u].l; } else u = t[u].r; } return a; }
```
思路：一路往下，**只有"当前值比 v 小"时才把它记成候选前驱**，然后继续往"更接近 v"的方向走。

### 3.5 第 k 小 / 排名（**必须额外维护 `sz`**）

```cpp
int kth(int u, int k) {                       // 第 k 小（1-based）
    while (u) {
        int ls = t[t[u].l].sz;                // 左子树有多少个数
        if (k <= ls) u = t[u].l;              // 答案在左边
        else if (k <= ls + t[u].cnt) return t[u].val;   // 落在当前节点
        else { k -= ls + t[u].cnt; u = t[u].r; }        // 扣掉左边+自己，去右边找
    }
    return INT_MIN;
}
int rank_of(int u, int v) {                   // v 的排名 = 比 v 小的个数 + 1
    int res = 1;
    while (u) {
        if (v <= t[u].val) u = t[u].l;
        else { res += t[t[u].l].sz + t[u].cnt; u = t[u].r; }
    }
    return res;
}
```
⭐ **`sz` 是"第 k 小/排名"的命根子**：插入、删除的**回溯路径上**都必须 `pull(u)`，漏一处数值就全错。

## 四、复杂度：期望很好，最坏很惨（实测数据）

我用同一份代码建了 n = 100000 个节点的树，量树高：

| 插入顺序 | 树高 | 查找代价 |
|---|---|---|
| **随机**（6 个种子） | **38 / 39 / 40 / 40 / 42 / 46**（平均 40.8） | 期望 **O(log n)** |
| **顺序** 1,2,3,…,n | **100000**（= n，**彻底退化成一条链**） | **O(n)** |
| **逆序** n,…,2,1 | **100000** | **O(n)** |
| 完全平衡（理想值，参考） | **17** | O(log n) |

⇒ **最坏 / 期望 ≈ 2400 倍**（实测 100000 次比较 vs 41 次比较）。

🍜 类比：**顺序插入 = 每次都往书架最右边塞新书**，最后变成一条"走廊"，找书只能从头走到尾。

### 4.1 怎么解决"退化" ⇒ **平衡树**

| 名称 | 一句话 | 机试常见度 |
|---|---|---|
| **Treap**（树堆） | BST + 随机优先级 + 旋转，靠随机性把树高控制在 O(log n) | ⭐⭐⭐ 最常考/最好写 |
| **FHQ Treap**（无旋 Treap） | 用 split/merge 代替旋转，能轻松做区间操作 | ⭐⭐⭐ 现在的主流 |
| **Splay**（伸展树） | 每次访问把节点转到根，均摊 O(log n) | ⭐⭐（LCT 前置）|
| **AVL / 红黑树** | 严格平衡；**STL 的 `set/map` 就是红黑树** | 手写几乎不考 |

## 五、重复值怎么办（三种策略，选一种并贯彻到底）

| 策略 | 做法 | 评价 |
|---|---|---|
| ① `cnt` 计数 | 同一个值只建一个节点，加一个 `cnt` 字段 | ⭐ **推荐**，也是平衡树标准做法（本文用这个）|
| ② 允许重复插入 | 相等时固定往右（或往左）走，多建节点 | 简单，但树会更胖；`multiset` 就是这种语义 |
| ③ 不允许重复 | 相等就忽略 | `set` 语义 |

## 六、退化不只让复杂度变差，**还会爆栈**（实测）

树高 = 递归深度。所以朴素 BST 一旦退化，**递归写法会 RE**：

| 链的深度 | 递归中序遍历 | 递归求树高 |
|---|---|---|
| 100000 | 侥幸没崩（帧很小，约 1.6 MB） | 侥幸没崩 |
| **200000** | **0xC00000FD 栈溢出** ❌ | **0xC00000FD 栈溢出** ❌ |

⚠️ **顺带一个反直觉发现（也是我自己实验的教训）**：
`-O2` 会把**尾递归**优化成循环 ⇒ **递归插入在 1e5 的链上完全没崩**（实测 `ins_R` / `ins_L` 都 exit 0）。
所以我第一版实验"以为递归很安全"是错的 —— **别用"尾递归没崩"来证明递归安全**，要看**最深的非尾递归路径**（比如遍历、求高、自底向上 `pull`）。
（这与 P4913 那次实测一致：n=1e6 的链 + 递归 `dfs` ⇒ `0xC00000FD`。）

## 七、机试实战：**什么时候手写 BST，什么时候直接用 STL**

| 你的需求 | 用什么 | 说明 |
|---|---|---|
| 有序集合 / 判存在 / 插入删除 / **前驱后继** | **`set` / `multiset`** ✅ | 红黑树，**保证** O(log n)，还不用自己维护 |
| 键 → 值 映射、按 key 查找 | `map` / `unordered_map` | — |
| **第 k 小 / 排名（`order_of_key`）** | STL **没有** ⇒ 三选一 | ① **pb_ds** 的 `__gnu_pbds::tree`（一行模板，考场最省事）② 手写 **Treap / FHQ** ③ 树状数组 / 权值线段树（值域小或可离线）|
| 区间和 + 动态插入删除 | 手写平衡树，或 树状数组 + 离线 | — |

⭐ **结论（很实用）**：**机试里 90% 的"BST 题"直接用 `set/multiset` 就能过**（比如求前驱后继、判存在、动态第 k 小——最后这个用 pb_ds）。
**手写朴素 BST 几乎只有教学价值**：它会被链状数据卡成 O(n²) TLE。真要手写，就直接写 **Treap/FHQ**。

**与你做过的题的联系**：
- **P2234 营业额统计** = 动态找"前驱/后继" = BST 的核心操作。你用"排序 + 从 n 倒序 + 双向链表"离线做法，效果等价且更快；用 `multiset` 也能做。
- 本文的 BST 前驱/后继与 `std::multiset` 对拍 **16000 次操作，不一致 0** ✅。

## 八、常见 6 个坑

| # | 坑 | 后果 |
|---|---|---|
| 1 | 只保证"左儿子<父<右儿子"，不是"整个左子树<父" | 中序不再有序，查找走错路 |
| 2 | 删除有两个儿子的节点时，忘了**真正删掉**那个后继（或忘了 `pull`） | 元素数不对 / `size` 错乱 |
| 3 | 插入/删除的**回溯路径上漏了 `pull(u)`** | 第 k 小、排名全线错 |
| 4 | 重复值的处理策略不统一（一会儿计数一会儿新建） | 计数/排名错 |
| 5 | 拿**朴素 BST** 去交"普通平衡树"题（P3369 等） | 被链状数据卡成 TLE |
| 6 | 递归实现在退化数据上爆栈（实测深度 2e5 就崩） | RE |

## 九、自查

<details>
<summary>① 为什么性质是"整个左子树都小于它"，而不是"左儿子小于它"？</summary>

因为查找/中序有序都依赖**全局有序**。如果只有"左儿子 < 父 < 右儿子"，深层节点可能跑到错误的一侧：
例如根 `10`、左儿子 `5`、`5` 的右儿子 `12` —— 局部满足 `5 < 10`，但 `12` 在 10 的左子树里却比 10 大 ⇒ 中序输出 `5,12,10`，**不再有序**，查找 12 时也会被"往左走"的规则误导。
</details>

<details>
<summary>② 删除有两个儿子的节点，为什么"中序后继"能顶上？用"中序前驱"行不行？</summary>

顶上来的人必须"**比左子树都大、比右子树都小**"。
- 右子树里**最小**的（中序后继）满足：比左子树所有值大（因为比根大）✓，比右子树剩下的都小 ✓。
- 左子树里**最大**的（中序前驱）同样满足 ✓。
⇒ **两种都行**，随便选一种，但实现要一致。
</details>

<details>
<summary>③ n = 100000 顺序插入后树高多少？查找最坏比较多少次？</summary>

树高 = **100000**（= n，一条右链）。查找最坏要比较 **100000** 次 —— 而随机插入只要约 **41** 次，**差 2400 倍**。
这就是为什么需要平衡树。
</details>

<details>
<summary>④ 机试里要"第 k 小"，STL 里有现成的吗？</summary>

**没有**（`set/map` 不提供 `order_of_key`/`find_by_order`）。三条路：
1. **pb_ds**：`__gnu_pbds::tree<int, null_type, less<int>, rb_tree_tag, tree_order_statistics_node_update>`，直接用 `order_of_key` / `find_by_order`（考场最省事）；
2. 手写 **Treap / FHQ Treap**（需要会写，但一次写好就是万能模板）；
3. 树状数组 / 权值线段树（值域小、或能离线离散化时最稳）。
</details>
